# 封面缓存与两道闸门进共享目录：两个实例共用同一份（v0.9.94，2026-11-14）

v0.9.90 给 `/api/cover` 加了三层：同一张只抓一次（LRU + 负缓存）、一个账号每分钟最多抓几张、
整机同一刻最多几张在上游。三层都写在进程里。v0.9.78 起「在跑几条重活」已经是共享目录里的租约，
v0.9.93 又把画布的排队位搬了过去——只剩封面这一路还是「每个实例各一份」：
两个实例各自缓存 64 张 / 24MB（实际 128 张 / 48MB），同一张封面各抓一次；
**「整机 4 张在上游」实际是 8 张**；一人每分钟 120 次实际是 240 次。

v0.9.94 把三层一起挪进共享目录：两个实例看同一个缓存、同一个在途数、同一个账号窗口。
写法和租约、排队位同一套（一个条目 = 一个文件，mkdir 出来的目录锁，pid 死了立刻清），
没有引 Redis、文件锁库或消息队列。

## 问题

| | 名额 / 排队位（v0.9.93 起） | 封面缓存 / 在途数 / 账号窗口（v0.9.90~v0.9.93） |
| --- | --- | --- |
| 存在哪 | 共享目录里的文件 | 进程内的 `Map` 与计数器 |
| 两个实例看到的是 | 同一个数 | 各一份 |
| 缓存条目上限 64 / 24MB 的含义 | — | 每进程 64 / 24MB（叠起来 128 / 48MB） |
| 「整机 4 张在上游」 | — | 每进程 4 张（叠起来 8 张） |
| 「一人每分钟 120 次」 | — | 每进程 120 次（叠起来 240 次） |
| 同一张封面 | — | 两个实例各抓一次、各占一份内存 |

后果不是「数字不好看」，是三件实事：模板库一屏 40 张封面翻两次 = 80 次上游请求，
两个人同时翻就有一百多张图同时在这台 2 核 / 1.86GB 的机器上过；缓存各存一份等于 48MB；
账号额度翻倍之后，按账号做的防滥用变成了摆设。

## 做法

1. **一张封面 = 共享目录里的一个文件**。文件名是 `sha256(URL)` 前 32 位，内容是
   `VQCOVER1 {json}\n` + 图片字节；json 里只有 `type` 与 `expiresAt`。
   **URL 本身不落盘**（封面地址可能带签名参数，缓存不是凭据该待的地方），账号 id 同样只存哈希。
2. **写是原子的**：先写同目录临时文件再 `rename`，读的人永远看不到半张图；
   读的时候校验魔数与头，坏文件立刻删掉按 miss 处理。
3. **淘汰按 mtime 从旧到新**，条目上限与字节上限都是整机口径：先无锁看一眼有没有超，
   超了才进锁里现算一遍再删——绝大多数 `put` 不进锁，两个实例同时淘汰也不会各删一份。
   命中时 `utimes` 把 mtime 往后挪（「最久没用过」而不是「最早抓进来」）。
4. **在途槽位 = `<pid>-<ts>-<seq>.slot` 文件**：占槽位 = 锁里数一遍、没满就写下自己那一条；
   满了按 80ms 轮询到 `waitMs`（默认 5 秒）再拒。pid 不在了立刻清，20 秒没心跳按泄漏清；
   抓取本身 15 秒超时，槽位每 5 秒摸一次 mtime，写窄了会误清、写宽了会白堵 20 秒。
5. **账号窗口 = 每个账号一个 `.win` 文件**（开始时间 + 次数），读改写在那把跨进程锁里做；
   文件数超过 2048 时顺手清过期的。**拿不到锁时放行**并记 `lockMiss`——这一层是防滥用，不是安全边界，
   宁可多抓一张，也不要把图片墙挂死。
6. **锁复用**：`heavy-lease.mjs` 抽出通用的 `withDirLock(dir, fn)`，租约、排队位、封面用同一招
   （mkdir 一个 `.lock` 目录，拿到的人做「数一下 + 写一行」，做完 rmdir；拿锁的进程死了 2 秒按陈旧锁清）。
7. **报告分两层写**：`entries / bytes / inFlight / accounts` 是整机（`scope: lease`），
   `hits / misses / waiting` 是本进程（`countsScope: process`）；目录用不了整体退回进程内并如实报 `process`。
   后台 `/api/admin/waterline` 多一个 `cover` 段；网关新增只读
   `GET /api/gateway/v1/covers`（服务令牌）：不带参数回整份报告，带 `?key=<封面地址>`
   回「这一张在不在缓存里」（哈希 + 字节 + 过期时间，**不回地址本身**，不计命中、不打上游）。

## 证据

### A. 本地两实例对照（真实 HTTP、假上游、零网络零额度）

两个真进程各自把真实的 `cover-proxy` 挂在 HTTP 上，喂同一个假上游；旧臂是
`git archive HEAD` 出来的 v0.9.93 源码，新臂是这一版，脚本、场景、端口各一对。

| 场景 | 旧（v0.9.93，8791/8792） | 新（v0.9.94，8793/8794） |
| --- | --- | --- |
| 同一张封面：先 A 再 B | A `miss`、B `miss`；上游被调 **2 次**（1 + 1） | A `miss`、B `hit`；上游被调 **1 次**（1 + 0） |
| 两个实例各自缓存了几张 | 各 1 张（两份，互不知道） | 各报 1 张（同一份，`scope: lease`） |
| 6 张不同封面并发抓（每实例名额 2） | 6 张全 200；上游同时 **4 张**（每实例 2 张） | 6 张全 200；上游同时 **2 张**（整机 2 张） |
| 一个账号每分钟 3 次，5 张分给两个实例 | **5 张全放行**（3 + 2，各算各的） | 前 **3 张 200**，第 4、5 张 **429 `limited` / `Retry-After: 60`** |
| 报告里的口径 | 没有 `scope` 字段（进程内） | `scope: lease`、`countsScope: process`、两个不同的 pid、同一个 dir |

## 坑

1. **CI 抓到的是真 bug，不是环境问题**：`test/wait-queue.test.mjs`「名次按入场顺序」在 CI 上失败
   （`1 !== 2`）——v0.9.93 的入场时间是毫秒，同一毫秒连着登记两张票时名次退化成按哈希排，
   先来的可能排第二。本地跑了十几次都没撞上（哈希顺序恰好对），CI 撞上了。
   修法是本进程内严格递增（同毫秒第二张记 +1ms），并加一组「同一毫秒连着登记 6 张」的回归用例；
   跨进程恰好撞同一毫秒时仍按 pid/哈希并列（两个进程同时到，谁先谁后本来就不确定）。
2. **对照脚本自己的 bug 差点被当成产品行为**：`coverUrl(url, key)` 忘了把 `key` 拼进查询串，
   所有请求都记在 `user:1` 名下，第三阶段（每分钟 3 次）整段 429。重跑前把 key 拼上，
   新臂的结果才是「前 3 张 200、后 2 张 429」。
3. **PowerShell 会把内联 `node -e` 的引号拆坏**（`$()`、`\${}` 和嵌套引号）：把脚本写成文件再跑，
   远端脚本先 `sed -i 's/\r$//'` 再 `bash`。
4. **oxlint 连未使用的常量与函数也算**：`WIN_NAME_RE`、`readImageHeader` 写完忘了删，warning 15 → 17；
   删掉回到 15。
5. **跨账号那一层要单独想**：对外实例跑 `visionqa`、内部实例跑 root。目录 0777 才让两边都能写；
   visionqa 改不了 root 写出来的文件的 mtime（命中时那次 `utimes` 会 EACCES，代码里吞掉），
   所以跨账号命中不会把 LRU 顺序往后挪——按写入时间近似。`unlink` 只看目录权限，淘汰仍能删。
6. **命中是同步读盘**：1MB ≈ 1ms 的事件循环阻塞，上限 8MB（最坏 ~8ms）。命中路径不抢锁、不打上游，
   这是为「同一张图不在两个实例里各占一份内存」付的代价；要彻底不阻塞得把整个 `get` 改成异步。
7. **槽位的时间窗要留余量**：抓取 15 秒超时、心跳 5 秒、20 秒算泄漏。写窄了会误清正在抓的槽位
   （上游并发就会超），写宽了进程被杀之后要白等 20 秒。
8. **只读探针也要分清账号**：第一次用 root 写、两个实例读，只证明了「跨进程 + 跨账号读」；
   再跑一遍 `runuser -u visionqa` 才证明「visionqa 写、root 的实例读」。

## 发现但没做

- **仍只跨进程、不跨机器**：共享目录是本地磁盘，多机部署要另外的协调者（和租约、排队位一样）。
- **LRU 是近似**：按文件 mtime 从旧到新，跨账号命中不挪（见坑 5）；没有真正的访问频率。
- **命中同步读盘**：1MB ≈ 1ms、8MB ≈ 8ms；图片墙同时命中几十张会累计阻塞，异步化留给下一轮。
- **匿名请求共用一个账号窗口**：`/api/cover` 没登录时 cacheKey 是 `anonymous`，
  所有人共用一份每分钟 120 次的额度——一个人刷会把匿名额度用光。按 IP 分桶需要另存一张表，这次没做。
- **封面没有命中率告警**：只有 `hits / misses / evictions` 计数，没有「命中率掉到 50%」这种告警。
- **在途槽位是轮询不是令牌传递**：先来先得在 80ms 的粒度上近似。
- 上一轮遗留仍在：`flow_run` 没有排队位、多机计数（B2 最后一项）、评审缩图前后一致性（要真实评审授权）。

## 回退

- 应用：`bash /opt/visionqa/ops/rollback.sh --to 2`（v0.9.93），无 schema、无配置改动；
- 只想把封面这一路退回进程内：`VQ_COVER_SHARED=0`（报告里 `scope` 会如实写 `process`）；
- 换共享目录：`VQ_COVER_CACHE_DIR=/some/other/dir`（两个实例要指同一个）；
- 关单层：`VQ_COVER_CONCURRENCY=0`（关在途闸门）、`VQ_COVER_PER_MINUTE=0`（关账号窗口）；
- 缓存参数：`VQ_COVER_CACHE_ENTRIES` / `VQ_COVER_CACHE_MB` / `VQ_COVER_CACHE_TTL_MS` /
  `VQ_COVER_NEGATIVE_TTL_MS`；锁等待：`VQ_HEAVY_LEASE_LOCK_MS`。
