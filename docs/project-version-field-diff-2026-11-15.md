# 改过的节点，差在哪一项参数（v0.9.118，2026-11-15）

**①现成：** v0.9.117 已经能任选两版，列出「画布改 2 个（输入主题、写一句）」。但「改了什么」只到节点标题，提示词、温度、模型这些真正影响出图的参数还藏在画布里；想知道为什么输出变了，只能自己打开两版画布对。  
**②最省力：** 不新做配置编辑器，也不把两版全部节点塞进详情；沿用已有的节点 id 与指纹，在只读对照接口里多给一份「改过节点的参数前后」。位置、标题照旧不算改动。  
**③验收：** 改过的节点要逐项列出参数名与前后值；长提示词只截改动附近，不把 4000 字整段塞回弹窗；多 / 少节点不硬凑参数；反向对照前后要跟着翻；1440 与 390 不横向溢出；浏览器只发 GET。

## 这一轮补的是什么

- **参数级明细**：新增 `canvasFieldDetail(prev, next)`，按节点 id 对齐，只给改过的节点返回 `fields`。节点类型变了算一项；`config` 的每个键都比，标签用中文（输入文本 / 模型 / 温度 / 提示词 / 关键词 / 内容类型 / 条数 / 工具 / 条件 / 输出格式 / 评审档位 / 评审图片）。
- **长文本只截改动附近**：值不超过 260 字时原样给；超过时先找共同前后缀，各留 42 字上下文，改动本身最多 150 字，两端加省略号。截过就把 `truncated` 标成 `true`，页面不假装这是全文。
- **结构保持增量**：改过的节点仍沿用原来的 `{ id, title }`；参数明细挂在 `canvas.fields`，键是节点 id。没有参数改动时这个键不出现，旧的 `canvasDetail` / `canvasDelta` / `versionChanges` 口径与结构都不变。
- **弹窗直接读**：改过的节点从标题胶囊变成一块小卡片，标题右边写「N 项参数」，下面每行是「参数名 前值 → 后值」。画布标题同时写「3 → 3 节点 · 3 项参数」。
- **只读不变**：仍然只走 `GET /api/projects/:id/versions/compare`，不写作品、不写版本、不扣积分；当前版读现在的画布与脚本，归档版读自己的画布与开版快照。

## 踩到的坑

1. **不能把 4000 字提示词整段塞进响应**：两版各一段，多个节点就会把弹窗和网络一起拖慢；只截改动附近，并标 `truncated`。
2. **「值改过」不能只看 JSON 字符串**：空模型显示「跟随当前模型」、空内容类型显示「不限」，这样前后值相同就不列，避免把语义没变的对象键顺序当成改动。
3. **节点类型也是参数**：类型从输入换成大模型时，先列「节点类型 输入 → 大模型」，再列能对上的配置键，不假装只改了一个字段。
4. **多 / 少节点没有前后参数**：新增或删除的节点只出现在多 / 少里，不给空参数卡片；只有两边都存在且指纹不同的节点才挂 `fields`。
5. **没有参数改动就不带 `fields`**：保持旧调用方读到的 `canvas` 结构不变，测试里的深比较也不用重写。
6. **长文本箭头会换行**：1440 用「前值 → 后值」排在一行；390 改成纵向排列并把箭头旋转 90°，否则箭头会孤零零挂在第一行末尾。
7. **截图别覆盖上一轮的**：第一次跑沿用了 v0.9.117 的文件名，把上一轮的两张图覆盖了；先复制成新名字，再 `git checkout` 恢复旧图。交付截图必须用新的、能指认这一轮内容的文件名。
8. **全量测试顺序跑**：本地内存紧时并行会让全局名额用例判成 `MEMORY_PRESSURE`；用 `--test-concurrency=1` 顺序跑，948 条全过。

## 发现但没做

- 只比节点类型与 `config`，不比位置、标题、选中态；这两样仍然按「移动 / 改名不是新版本」处理。
- 参数值截断后没有「展开全文」入口；要看全文仍得打开那一版画布。
- 只比画布参数与脚本口播，不比评审结论、交付快照、运行输出或素材文件。
- 不支持跨作品对照，也不保存对照结果或生成分享链接。
- 生产没有登录账号做真实作品的两版对照；这一轮证据来自本地真浏览器 + 本地服务，零真实上游。
