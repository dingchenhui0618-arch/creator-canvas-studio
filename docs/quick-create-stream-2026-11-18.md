# 快捷创作：流式回答、随时停止、会话标题（r217 / v0.9.201）

日期：2026-11-18。上一版（r214）把「智能体」改成「快捷创作」一页 DeepSeek，但回答要等整段回来才显示：
首字通常一两秒就该出现，用户却要干等 5～40 秒，中途还不能停。这一版把这条链路做成真的流式。

## 一句话结论

对话现在**边生成边显示**（首段字通常一两秒到），右上角按钮变成**停止**，停止即断连、服务端中止上游并**全额退积分**；
上游不认流式时自动退回一次性回答，同一句话只扣一次费；左侧会话标题不再一律叫「新对话」。

## 契约

| 项 | 口径 |
| --- | --- |
| 接口 | `POST /api/chat/conversations/:id/messages/stream`，响应 `text/event-stream`，带 `X-Accel-Buffering: no` |
| 事件 | `open`（连接已建立）→ 若干 `delta`（`{"text":"…"}`，正文原样，含换行）→ `done`（整条会话 + 余额 + `truncated`）或 `error`（`code` / `error` / `stopped`） |
| 心跳 | 每 15 秒一行 `: ping`，防止思考模式首字很慢时被中间层当空闲连接掐掉（nginx `/api/` 读超时 300s） |
| 停止 | 客户端断开连接 → `res.on('close')` 中止上游 → 全额退回；**不保存半截回答**（用户看到的是自己按了停） |
| 失败 | 半路断流 / 上游报错 / 空回复：全额退回，用户那句话仍留在会话里 |
| 降级 | 上游对 `stream:true` 回 400/422 → 抛 `STREAM_UNSUPPORTED`，上层改走一次性请求，拿到整段一次性推进界面；只扣一次费 |
| 换 Key 的红线 | 已经吐过字之后出错**不换 Key 重打**（否则同一段回答会重复一遍）；没吐过字才换 |
| 截断 | `finish_reason=length` 但正文已经有了：回答照常保存并标 `truncated`；一个字都没有才算失败退款 |
| 扣费 | 与原来一致：发之前扣 1 积分，停止 / 失败全额退回；余额当场刷新 |
| 会话标题 | 第一句进来时用它的开头当标题（界面先建空会话再发第一句，以前标题一直停在「新对话」） |

## 改了哪些文件

- `server/chatcall.mjs`：新增 `chatCompletionStream()`——同一套候选 Key 解析与路由日志，读流、拆 SSE、拼增量；三条红线（不认流式不换 Key、吐过字不换 Key、截断有正文照常返回）都写在这里。
- `server/llm.mjs`：新增 `callTextModelStream()`——同一条模型链，失败才换模型；已吐字则不换。
- `server/chat.mjs`：拆出 `beginChat / finishChat / failChat`，一次性与流式共用扣费与退款口径；新增 `streamChatMessage()`。
- `server/routes/chat.mjs`：新增 `/messages/stream` 路由（SSE 头、心跳、断开即中止）。
- `src/api/chat.ts`：`streamChatMessage()` 按事件解析，`done` 返回整条会话；`AbortSignal` 即停止。
- `src/components/QuickChat.tsx`：逐字渲染 + 末尾光标；生成中发送键变停止键；新对话也先显示自己那句（否则空状态说明会和流式回答叠在一起）；失败 / 停止后以服务端为准重新拉会话。
- `src/styles/agents.css`：`.qc-bubble--stream` / `.qc-caret` / `.qc-send--stop`（含 `prefers-reduced-motion` 不闪）。

## 顺手修的两件事

1. **测试并发**：`npm test` 固定 `--test-concurrency=4`。本机空闲内存只剩 1.2GB，整套测试贴着上限跑：多一个测试进程就会让 media-gen 的「慢上游」用例假失败（实测同一份代码 0 条 / 4 条 / 5 条失败，失败集合每次都不一样）。固定并发后 1437/1437 稳定全绿，耗时 31s → 44s。
2. **冷却用例的连锁失败**：`test/media-gen.test.mjs` 的「Key 冷却」用例会把图片 Key 打进 60 秒冷却，以前失败时来不及解除，后面四条出图用例跟着全红。改成 `try/finally` 解除冷却：失败只报它自己一条。

## 边界（照实说）

- **没有真调真实上游**：本轮全部走本机假上游。真实 DeepSeek 的流式增量、思考模式的 `reasoning_content`、真实首字延迟都还没在端上验过（要花钱，等你授权）。
- 思考模式的推理过程**不显示**，只用于计数；正文照常流式。要展示「思考中…」再改。
- 回答仍是纯文本（`white-space: pre-wrap`），没有 markdown 渲染与代码高亮。
- 停止一律全额退：已经生成的部分**不保存**。如果你更想留半截，得改成「按已用 token 结算」，那是另一套口径。
- 降级路径下用户要等到整段回来才能看到字（上游不支持流式时没有别的办法），界面上仍是「正在回答…」。
- 线程滚动只在「你本来就在底部」时跟随；往上翻看长回答时不会被拽回底部（r217 一并改掉）。
