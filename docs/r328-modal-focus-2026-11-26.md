改之前只有「身份引导」兑现了它（r327），其余 16 个分布在 13 个文件里：**焦点根本没被收进来**、**Tab 一路走到遮罩后面**、

## 为什么抽一份共用实现，而不是再抄十六份

按「本机 → 项目内 → 标准库 → 社区」找过一遍：

- **项目内已有的**：只有 `OnboardingGate.tsx` 内联的一份（r327），没有可复用的工具。
- **抄 16 份**：改一次判定要改 16 处，且「改漏一处」不会有任何提示——这次要修的就是这种安静失效。
- **装 `focus-trap-react` 之类**：新依赖，且它自带一套 ref / onDeactivate / Esc 的约定，与现有 16 个组件的
  `ref`、`onClose`、`autoFocus`、各自的 Esc 写法正面打架，等于把 16 个文件重写一遍。
- **选的是**：`src/domain/focus-trap.ts` 放**不碰 DOM** 的判定（`planTab` 真值表 + 可聚焦选择器），
  `src/components/useModalFocus.ts` 放**只碰 DOM** 的接线。放弃的是「一个文件搞定」的紧凑，换来的是一条能被单测钉死的判定。

## 四个决定

1. **监听挂在捕获阶段**（`document.addEventListener('keydown', onKey, true)`）。页面上别处也有一堆 keydown（搜索框、表格、画布），
   冒泡阶段轮不到兜底。代价是：任何浮层里的输入框，Tab 也归弹窗管，所以真值表里留了 `pass`——落在中间一律交还浏览器。
2. **只有最上面那一层管键盘**（模块里一个 `trapStack`）。大图上再开一个确认框时，外层若照旧处理 Tab，会看到「焦点不在我这儿」，
   然后把焦点从内层抢回去——这类 bug 只在两层叠开时出现，很难在手工点测时抓到。
3. **锁滚按引用计数**（`scrollLocks`）。两层叠开、先关的那一层只减计数，计数归零才把 `body.overflow` 还原；
   各家自己存一份 `previous` 再还原的话，谁先关谁就把另一层的锁解开。
4. **Esc 也跟着搬家**。命令面板原来把 Esc 挂在输入框的 `onKeyDown` 上——Tab 一旦被兜住，焦点会落在列表项上，
   那一刻 Esc 就按不动了（before 里它的关闭方式是「点空白处再 Esc」）。现在 `onEscape` 在捕获阶段统一处理：
   after 四个弹窗都是**一次真 Esc 就关**。

关掉之后还焦（`restoreFocus`）是顺带修的一件：打开那一刻记下 `document.activeElement`，卸载时还回去。
before 里回收站与反馈关掉后焦点落在 `BODY`——键盘用户得从页首重新 Tab 一遍。

## 怎么量的

`scripts/shot-r328.mjs`（可提交的工具，`--phase before|after --dist <路径> --only <id> --narrow`）：临时 `DATA_DIR` + 真 SQLite +
真账号 + 空闲端口 + 无头 Chrome，**CDP 真输入**（`Input.dispatchKeyEvent` / `Input.dispatchMouseEvent`），
Tab/Shift+Tab/滚轮/PageDown/Esc 全部走真事件管线而不是 `el.click()`。

两个量法上的坑，都是这轮踩出来的：

- **1440×600 才量得到「背景在滚」**：1440×1000 下多数页面根本不够长。即便压到 600，外壳页的滚动容器是 `.vq-content`
  而不是 `document`（弹窗遮罩 `position: fixed` 挂在它外面，滚轮打不到它），所以**滚轮那一条在外壳页量不出**——
  版本页 before 的 `bgPx` 是 0 不代表没问题，可感知证据改用真按键 **PageDown**：before 滚了 `.vq-content` **952px**，after 0。
- **回收站页在空态只有 8px 可滚**：那一格标「量不出」，不标「通过」。宁可缺一格，也不拿一个量不出来的 0 当证据。

## 门禁与发布

新增 [test/modal-focus.test.mjs](../test/modal-focus.test.mjs) 三条：

1. **真值表** 14 个断言：一个能接焦点的都没有 → 留在容器上；焦点在外面 / 停在容器上 → 拉回来；
   第一个上 Shift+Tab → 跳到最后一个；最后一个上 Tab → 回第一个；停在中间 → 交给浏览器。
2. **覆盖扫描**：遍历 `src`，每个 `aria-modal="true"` 的标签**本身**必须挂 `ref`（按标签取，不按前后 400 字符取——
   相邻元素也有 `ref`，那样「新加一个没挂 ref 的浮层」就抓不到），且所在文件 `useModalFocus(` 的次数不能少于浮层数；
   另外数一遍带 `aria-modal` 的文件数 ≥ 13，防止扫描走空当成通过。
3. **反证**：凭空加一个没挂 ref 的浮层要被抓出来；删掉调用要让次数对不上；把 `preventDefault` 拿掉、
   监听退回冒泡阶段、去掉「只有最上层」判断、把 `getClientRects` 换回 `offsetParent`，每一条都必须让检查变红。
   写的时候第一版反证没红：`hook.replace('event.preventDefault()')` 命中的是处理 Esc 那一段，不是 Tab 那一段——
   改成钉住 `if (plan === 'pass') return` 之后的那几行才真的会红。

## 边界

- **身份引导没搬过来**。它自己那份是 r327 刚在生产上验过 21/21 的（连反证测试一起），这轮为了「统一实现」重写它不值得冒险。
  两套实现并存是这轮唯一的结构性欠账，下一轮再合，先改测试再改代码。
- **页面内画的 `role="dialog"` 不在范围内**：后台账号的「删除 / 改身份」展开条、聊天弹出的历史、画布便签、局部工作区的长期记忆——
  它们没有遮罩、跟页面同流，圈住焦点反而是错的。
- **版本脚本 / 两版对照的背景锁留在作品页那一层**：这两块也在作品页之外被别的页面复用，锁在自己身上会和页面那层的锁互相覆盖恢复。
- 只量了 4 个弹窗（其余 12 个靠覆盖测试保证接线一致）；只量了 1440×600 与 390×844。
- 真值表钉住的是「判定」，不是浏览器真实的 focus 行为；真正的行为由真浏览器取证负责，两边不互相冒充。
