# r298 · 模型统一：一个显示模型、几条通道兜底、按上游成本计价

日期：2026-11-23　版本：0.9.279（r298）

## 一句话

快捷创作里不再让用户挑上游型号：图片只有「VisionQA通用图片模型」，视频只有「VisionQA通用视频模型」；
底下自动走最便宜的通道，上游拒单才换备用通道；扣费不再写死 5 / 15 积分，按「上游成本 × 1.1」算。

## 用户定的口径（2026-11-23）

1. 快捷创作图片只用最便宜的 GeteAPI GPT Image；视频只用 SeeAPI Seedance 2.0 Fast；
2. 前端一律显示 `VisionQA通用图片模型` / `VisionQA通用视频模型`，不露上游型号；
3. 画布（无限画布）里每个模型用**全名**、同样一个模型不许出现两个名字（不再带「(直连)」这类后缀）；
4. 画布的图片、视频对普通用户全开；
5. 扣费统一写「积分」，算法 = 上游真实消耗 × 1.1（例：上游 5 元 → 55 积分）。

## 改了什么

### 1) 显示模型层（`server/media-models.mjs`）

| 显示模型 | id | 通道（按便宜→贵） | 单价 |
| --- | --- | --- | --- |
| VisionQA通用图片模型 | `visionqa-image` | gpt-image-2.6 → 2.5 → 2 | $0.028 / $0.048 / $0.048 一次 |
| VisionQA通用视频模型 | `visionqa-video` | seedance-2.0-fast → seedance-2.0 | ¥0.28614（480p）/ ¥0.61538（720p）/ ¥1.2714（1080p）每秒；备用 ¥0.35574 / ¥0.76507 / ¥1.72 |

- 界面拿到的 `/api/media/models` 每种能力只有一条，带 `label`、`channelCount`（几条路兜底）、
  `credits`（默认档价）与 `priceTable`（视频每个「时长 × 清晰度」的积分价）；
- 老记录里的上游 id（`gpt-image-2`、`seedance-2.0`）照样认，不迁数据；
- 「再来一次」按当前价重算，不按当初的花费。

### 2) 通道兜底（`server/media-route.mjs`）

- 只有三种情况才换下一条：上游 **400 / 404** 明确拒单、池里**没有声明这条上游模型的 Key**；
- **超时、结果不明、401/402/429/5xx、连不上：一律不换**。前两种上游可能已经接单计费，
  换一条就是重复付钱；后几种是 Key 或上游整体的问题，换模型也一样失败，还会把整池 Key
  打进 60 秒冷却，连累后面本来能成的请求。
- 出视频只在**建任务**这一步换通道；任务一旦建起来，后面轮询绝不重提。

### 3) 按成本计价（`server/media-pricing.mjs` + `config.billing`）

```
积分 = ceil(上游成本(元) × (1 + markup) × 每元积分)
     = ceil(成本 × 1.1 × 10)         # markup / pointsPerCny 都可在 config.billing 调
```

| 场景 | 上游成本 | 积分 |
| --- | --- | --- |
| 一张图（gpt-image-2.6） | $0.028 ≈ ¥0.20 | **3** |
| 视频 4 秒 480p（fast） | ¥1.14 | **13** |
| 视频 4 秒 720p（fast） | ¥2.46 | **28** |
| 视频 8 秒 480p（fast） | ¥2.29 | **26** |
| 视频 8 秒 720p（fast） | ¥4.92 | **55** |
| 视频 12 秒 1080p（写死档） | ¥15.26 | **168** |

- 取整只**向上**：宁可少赚不到 1 个积分，也不能让卖出去的价比上游成本低；
- 汇率、加价、每元积分只在一处：`config.billing.usdCny`（默认 7.2）、`billing.markup`（0.1）、
  `credits.pointsPerCny`（10）；改价不改界面、不改画布；
- 涨价的直接后果要说清：视频原来一口价 15 积分（8 秒 720p 其实是亏的），现在 8 秒 720p 是 55。
