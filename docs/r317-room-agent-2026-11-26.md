# 聊天室 1c：平台智能体在房间里真的能回话（r317 / v0.9.290）

日期：2026-11-26 · 版本：0.9.290 · 本轮 0 次真实上游调用、¥0

## 一句话

房间里加进去的平台智能体（「快捷创作」里那几个对话预设）现在会**接着人说的话回一句**：
一轮 1 积分、失败全额退回、只开了一个只读工具（读模板库），写操作与逐次批准留到 1d。

## 为什么是这一版

1b 上线后房间里只有「接进来的连接器」会说话：平台智能体挂在成员列表里、状态写着「平台智能体」，
但你跟它说话它不会回——这是当时主线上最假的一环。1c 就是把它补上，并顺手把「工具」的骨架立起来。

## 决定（这些会长期生效）

| 问题 | 决定 | 为什么 |
| --- | --- | --- |
| 谁回 | 房间只有 1 个平台智能体时，人每说一句它都接；有多个时只接被 @ 的那个；房主可关「自动接话」 | 一句话引出两个回合就是两笔积分、两段互相复读的废话 |
| 回几轮 | 只有「人 → 智能体」这一层，智能体之间不互相接话（maxDepth=1） | 两个智能体互道「收到」能把一屏刷满，而且每条都在花钱 |
| 多少钱 | 一轮 1 积分（与快捷创作对话同价），先扣后调，失败全额退回 | 一次真模型调用不能白送；失败还扣钱最伤人 |
| 没答上来 | 把原因作为一条 state=error 的消息留在房间里 | 静默失败会让人以为功能坏了；也要写清「积分已退回」 |
| 工具 | 只开 templates.list：只读、不花积分、只看自己账号的数据 | 先证明「模型要工具 → 我们执行 → 再回答」这条路是通的 |
| 工具协议 | 模型输出一行 JSON（tool / args），最多 2 轮 | 不依赖上游 function calling；换任何 OpenAI 兼容模型都能用 |
| 止血开关 | VQ_ROOM_AGENT=0 关掉全部平台回话；VQ_AGENT_TOOLS_DISABLE=templates.list 关掉单个工具 | 模型额度出问题时不用改代码、不用发版 |
| 上下文 | 最近 20 条消息 + 房间成员 + 预设自己的 systemPrompt / knowledge | 够它接住话题；再多只是烧 token |

## 七个工具，只开一个

| 工具 | 读写 | 状态 | 说明 |
| --- | --- | --- | --- |
| templates.list | 只读 | **已开** | 列出本账号最近的模板（标题 / 类型 / 来源 / 钩子） |
| projects.read | 只读 | 未接 | 读作品列表或单条作品 |
| assets.list | 只读 | 未接 | 产品资产与数字人资产 |
| web.read | 只读 | 未接 | 读公开网页正文 |
| media.image | 写 | 未接（1d） | 5 积分/张，要逐次批准 |
| media.video | 写 | 未接（1d） | 15 积分/条，要逐次批准 |
| review.run | 写 | 未接（1d） | 5 积分/轮，要逐次批准 |

没接的工具**调了也只回「这个工具还没开」**，不会假装执行、不会扣积分。
界面右栏照实写「平台智能体现在能用：读模板库 · 另外 6 个还没开」。

单测 15 条（node --experimental-sqlite --experimental-strip-types --test test/room-agent.test.mjs）：

- 工具：七个登记只有一个开、没接的调了只回「还没开」、环境变量只能往下关、只认一行 JSON；
- 谁回：一个平台智能体接每一句 / 多个只接 @ / 关掉自动接话只剩 @ / maxSpeakers 封顶 / 连接器成员永远不被选中；
- 一轮：扣 1 积分、消息是智能体发的、replyTo 指向人那句话；工具轮执行后结果进上下文、不写进房间；要没开的工具只回「还没开」；
- 失败：退款 + 一条 state=error + 正文写「积分已退回」；没积分不调模型、不留假回复；
- 安排：止血开关关着时什么都不做；打开后真落一条回复，并且先广播 typing(on) 再广播 typing(off)。

## 边界（这一版明确没做）

1. **逐次批准没有**：写操作工具一个都没接，所以现在也没有「点允许」的流程；1d 一起做。
2. **只有 1 个工具**：其余六个未接；「读模板库」也只能看自己账号的模板。
3. **平台智能体不回「智能体发的消息」**：连接器（codex / Claude）说的话不会引出平台智能体接话——避免两个来源互相复读、无限花钱。
4. **不做流式**：房间里一次性出现完整回复，打字提示只表示「在写」。流式要改 SSE 协议与消息落库方式，留到后面。
5. **截图里的模型是假的**：本地假 /v1，只为证明链路；真模型下的语气与长度没有在本轮验证过（模板库为空时它回的那句是脚本里写死的固定回复）。
6. **左栏未读与其它房间的预览不实时**：只有当前打开的房间里，左栏那一行预览会跟着更新。
7. **390 下左侧导航栏有既有裁切**：窄屏侧栏折成 68px 时，最左边一列还留着几个被切掉的字（r316 的 390 截图里就有，与本次无关，已记进待办）。
