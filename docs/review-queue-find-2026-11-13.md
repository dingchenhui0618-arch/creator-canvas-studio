# 评审待办的找法：按时间找、按标题搜（v0.9.25）

**结论**：工作台「评审等你看的」这一块现在有两种找法——按那次评审的时间限范围（全部 / 7 天内 / 30 天内），按作品标题搜关键字（空格分词、大小写不敏感）。两种都在服务端算，所以筛出来的数字与真正点得出来的行永远同一份；筛空时不会说「没有等你改的」，而是写「全部还有 N 条，只是不在这个范围里」。上一轮如实承认的「只列了最近 20 条」从此有了出口：超过 20 条时，限一个范围或搜一个词就够得着。

- 版本：`0.9.25`；发布包 `20261112-193723-v0.9.25-queue-find.tar.gz`；入口 `index-BKi-sa9S.js`。
- 提交：`df58729`（上一轮）之后的这一轮提交见仓库；测试 `274/274`，oxlint `0 error / 6 warning`，构建通过。
- 生产只读实测：队列 1 条、facets `1 / 1 / 1`、搜不到时 `total 0 / allTotal 1`、主卡不跟着筛选变；1440 与 390 都没有横向滚动。生产这一轮没有写任何数据。

## 一、上一轮留下的那条死路

v0.9.24 让队列不再静默吞掉第 4 条：首屏 3 条 + 「还有 N 条等你改」展开到 20 条，超过 20 条写「只列了最近 20 条」。那句话是诚实的，但它只是承认问题——真到三十几条待办时，人没有任何办法够到第 21 条以后。

这一轮补的是那条出口。做法与作品列表（v0.9.23）一致：能筛的字段必须是这一行上看得见的（作品标题），时间轴必须是这件事自己的时间（那次评审），筛选与计数同一口径。

## 二、六条口径

1. **时间范围按那次评审的时间算**，不按作品更新时间。等你看的是「结论出来的那一刻」，作品昨天被点开过不代表意见是新的。范围只有三档：全部时间 / 7 天内 / 30 天内；认不出的范围退回「全部」，不报错、不空列表。
2. **关键字只搜作品标题**。行上看得见什么就搜什么：标题、第几版、评过几次、什么时候——只有标题是文字，其余是数字。搜模板名会让人以为搜到了看不见的东西，所以不搜。分词与作品列表共用一份（`projectSearchTokens`）：空格是「都要命中」，大小写不敏感，最多 5 个词。
3. **计数与筛选同源**：三枚胶囊上的数字按关键字算、不按当前范围算。换一个范围，另一排数字仍然是真的——这与作品列表「计数按关键字算、不按当前状态算」是同一条规则。
4. **筛出来的数与全量分开**：接口同时给 `total`（筛出多少条）与 `allTotal`（不带任何筛选的全量）。筛着的时候界面写「筛出 2 / 全部 4 条」，筛空时写「全部还有 4 条等你改：把时间放宽到「全部时间」，或换个词就能看到」——不拿 0 冒充「没有等你改的」。
5. **主卡不跟着筛选变**：接口额外返回 `lead`（不带筛选的最新一条待办），工作台的「下一步」读它。筛队列是「找」，不该顺手把主卡换掉——本地实测：筛到只显示「iPhone 15 开箱」时，主卡仍是「咖啡店探店三分钟」。
6. **在服务端筛**：这一屏一次只取 20 条，前端只筛这 20 条会把「只列了最近 20 条」变成假话。筛选在 `server/review-queue.mjs` 里算，接口读 `range` 与 `q` 两个参数；不传就是原来的队列，一个字节都不变。

## 三、界面

- 工具栏接在区块说明下面：搜索框（作品标题，`/` 聚焦、`Esc` 清掉）+ 三枚带计数的胶囊 + 右侧「共 N 条等你改」；筛着的时候多一个「清掉筛选」，计数变成「筛出 2 / 全部 4 条」。
- 搜索框与作品页是同一个组件样式：v0.9.23 那套样式本来是作品页专属，这一轮搬进 `shell.css`（`.vq-toolbar / .vq-toolbar-search / .vq-toolbar-count / .vq-toolbar-reset`），两页共用一处定义，不再各抄一份。作品页的截图已核对，样子没有变。
- 打字等 220ms 再问、点胶囊立刻问；换筛选时把「展开」收回到首屏 3 条，避免筛完还停在展开态。
- 390：搜索框独占一行，胶囊与计数自己换行（工具栏高 126px），队列 290px 宽、页面 `scrollWidth == clientWidth`。
- 空状态分三种：筛空（写全量 + 清掉筛选）、已看过（写「看过不等于改过」）、拍过板（写胶囊与下一步按人的结论走）——后两种是上一轮就有的，这一轮没有改。

## 七、边界

- 不搜模板名、不搜评审正文：行上看不见的东西不假装能搜到；要按模板找去作品页。
- 不做「保存筛选」：筛选项是这一屏的，换页就回到全部时间 + 空关键字。
- 队列一屏仍是最多 20 条，没有分页：筛是为了把范围缩小，不是为了翻页；真要翻页是下一轮的事。
- 时间范围只有三档：更细的自定义区间（起止日期）没有做——现在没有让人填日期的必要，多一个输入框就多一处口径。
- 不做搜索建议、不做高亮命中词。
