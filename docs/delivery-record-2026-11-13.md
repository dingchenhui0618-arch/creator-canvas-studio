# 交付留痕：交出去的是哪一版、什么时候（2026-11-13）

结论：v0.9.22 起，「标记交付」不再只是一个开关，而是一条**交付记录**——哪一版、什么时候交出去。状态胶囊与主卡只在**当前这一版**交出去时才写「已交付」；交付了 v2 之后开 v3，v3 还没交，胶囊、待办、分享页、交付稿一起回到「在做 / 送评审」，版本对照里 v2 那一行留着「交付过 · 时间」。撤销（重新打开）会收回这一版的交付记录，不留一条假记录。

一句话：**交付是对某一版的宣布，不是对这条作品的永久标签。**

## 一、为什么是这一片

v0.9.19–v0.9.21 把「评 → 人拍板 → 交付」这条线接起来了，但交付这一端还是空的：

- 点「标记交付」只把 `status` 改成 `done`，没有记「交的是哪一版」——开新版之后作品还写着「已交付」，而新版一次都没评过、也没交出去；
- 收件人拿到交付稿与只读分享页，看到的「已交付」不知道是哪一版、哪一刻；
- 标错了没有干净的撤销：状态能改回去，但「交付过」这件事既没记录也没法撤回。

这一片补的是交付这一端的**事实**与**撤销**。交付记录落在作品上（`projects.json` 的 `deliveries`），不改版本、不改评审、不动画布。

## 二、口径（测试逐条钉住）

| # | 规则 |
| --- | --- |
| 1 | 标记交付 = 在作品上落一条交付记录：版次取当前这一版，时间由服务端现写（`{ version, at }`，最多 20 条，与版本上限对齐）。 |
| 2 | 同一版重复标记只更新时间，不堆重复记录；不同版本各留各的，最新一条就是「最近一次交付」。 |
| 3 | 「已交付」只在**当前这一版**有交付记录时成立（`deliveredCurrent()`）。交付了 v2 又开 v3：v3 没交，胶囊退回当前版的评审结论（或「在做」），待办照旧收它。 |
| 4 | 开新版 = 上一版收尾：若作品标着交付，先把上一版的交付记录补上（老数据没有时间就写空串），作品状态回到「在做」，交付时间仍然查得到。 |
| 5 | 重新打开 = 收回这一版的交付：撤掉当前这一版的记录，别的版本留着；胶囊、交付稿、分享页一起回到「这一版还没交」。标错了撤销之后，不残留一条「交付过」。 |
| 6 | 没有交付记录的老数据照旧：`status=done` 就是这一版交了，只是时间写「没记录」——不迁移、不凭空造一条带时间的记录。 |

服务端与前端各写一份同样的判断（`server/project-status.mjs` 的 `deliveryOf/deliveredCurrent`，`src/domain/project.ts` 的同名函数），与 v0.9.19 起状态胶囊的双写是同一套约定：一处改口径，另一处必须跟着改。

## 三、界面

1. **页头**：已交付时胶囊旁多一枚 `交付 v2 · 11-13 02:58`（等宽字、22px 高），悬停写清「重新打开会收回这一版的交付，开新版则把它留在上一版」；按钮在「标记交付 / 重新打开」之间切换。
2. **主卡（下一步）**：「这条已经交付」下面写明「交付的是 v2；画布与评审都留在记录里，开一版新的就回到「在做」，上一版的交付时间仍然查得到」。
3. **版本对照**：交出去过的版本在元信息行尾多一枚绿色「交付过 · 时间」胶囊；开新版之后，旧版这一枚仍在，新版没有。
4. **交付菜单**：「导出不会改状态：交出去之后点页头「标记交付」，会记下这一版与交付时间；开新版也查得到。」——导出是取产物，不是宣布交付。
5. **作品列表卡片**：胶囊写「已交付」，悬停补「交付 v2 · 11-13 02:58」；交付了旧版、开着新版的作品，卡片写当前版的状态。

尺寸（实测）：1440 宽页头 1158×132、主卡 1158×247、版本对照 1104×209；390 宽页头 306×275、版本对照单列；两档 `scrollWidth == clientWidth`。「交付过」胶囊 20px 高 / 11px 字，与评审结论胶囊同一档。

## 四、纸与导出

- **交付稿（Markdown）**：抬头多一行「交付：这一版已经交付 · v2 · 时间」/「这一版还没交付 · 上一版 v2 于 … 交付」/「还没交付过」；「交付」小节列出全部交付记录（`交付记录：v3 · 时间；v2 · 时间`）；版本对照表的版次列写「v2 · 已交付」，每版明细块多一行「交付：… 交出去过」。
- **A4 打印稿**：由同一份 Markdown 渲染，抬头事实表与版本表自动一致。
- **只读分享页**：交付看「这一版交没交」，交过 v1 又开 v2 的作品写「在做」，不写「已交付」。
- **模板详情的「用这条模板的作品」**：同样按当前版判断，多一个 `delivered` 字段，不再用 `status=done` 冒充已交付。

## 五、生产实测（真实数据，两次写入都当场撤销）

生产只有 1 条作品（毛衣折叠收纳法 · 第 2 版 · 2 次评审），交付前没有任何交付记录。

| 步骤 | 胶囊 | 页头交付 | 主卡 | 版本对照 v2 | 交付稿 |
| --- | --- | --- | --- | --- | --- |
| 标记前 | 评审 · 需人工确认（悬停「需人工确认 · 11/12 18:03 · 评过 2 次」） | 无 | 按评审意见改一版 / 继续画布 | 无 | 交付：还没交付过… |
| 标记交付 | 已交付（悬停「交付 v2 · 11-13 02:58」） | 交付 v2 · 11-13 02:58 | 这条已经交付（交付的是 v2） | 交付过 · 11-13 02:58 | 交付：这一版已经交付 · v2 · 2026-11-13 02:58；交付记录：v2 · 2026-11-13 02:58；表里 `v2（当前） · 已交付` |
| 重新打开 | 评审 · 需人工确认 | 无 | 按评审意见改一版 / 继续画布 | 无 | 交付：还没交付过… |

- 作品列表卡片：拍过之后胶囊「已交付」（悬停「交付 v2 · 11-13 02:58」），与「已停用」「V2」并排不挤。
- 390 宽：胶囊 + 交付胶囊同一行，按钮排两行，无横向滚动。
- 撤销后接口实测 `{ status: active, version: 2, deliveries: [] }`——生产回到交付前，没有残留记录；本轮不改评审、不动画布、不调模型、不扣积分。

本地演示数据（3 条作品 / 26 条评审 / 3 个版本）验了生产没有的两条路径：v2 交付后开 v3（胶囊「在做」、主卡「送评审」、v2 行留「交付过」）；v3 也交付后两版各留一枚，交付稿写「交付记录：v3 · 时间；v2 · 时间」。

## 六、边界（这一片刻意不做）

- 交付记录只记「版次 + 时间」，不记谁交的（单账号部署，界面写「你」）、不记收件人、不记交付渠道。
- 交付不要求评审通过、也不要求人工拍板：评审是标准，交付是决定，两者都留痕，但不互相锁死。
- 交付记录不写进只读分享页正文（只影响「已交付 / 在做」这一个词），分享链接仍是凭证。
- 不做「撤销任意一版的历史交付」：重新打开只收回当前这一版；更早版本的记录继续留着。
- 不做交付版本流水列表：版本对照里一枚胶囊 + 交付稿一行记录，够回答「哪一版交过」。

## 八、改到的文件

- `server/projects.mjs`：`normalizeDeliveries()`、`normalize()` 带出 `deliveries`、标记交付落记录、重新打开收回、开新版归档上一版。
- `server/project-status.mjs`：`deliveryOf()` / `deliveredCurrent()`，`projectStatus()` 只在当前版已交付时写「已交付」。
- `server/review-queue.mjs`：待办按「这一版交没交」排除，交付了旧版的新版照常进待办。

- `server/project-deliverable.mjs`：抬头「交付」行、交付小节（含全部记录）、版本表「已交付」、每版明细「交付：…」。
- `src/domain/project.ts`、`src/components/ProjectStatus.tsx`、`src/pages/ProjectPage.tsx`、`src/pages/OverviewPage.tsx`、`src/pages/TemplateLibraryPage.tsx`：前端同一口径、页头与版本对照的交付留痕、导出菜单说明、卡片悬停。
