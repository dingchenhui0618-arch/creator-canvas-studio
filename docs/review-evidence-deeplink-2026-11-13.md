# 评审的证据，一点就开（v0.9.17）

**结论**：作品页「版本对照」每一版下面逐条列出评过的那几次，点一条直接进那次的记录页——当时被检视的画面原图、问题锚点、结论与修正建议都在。地址栏是 `#/review/<评审 id>`，刷新、后退、把链接发给同账号的自己也落回同一条。历史评审只读；想接着评这一版，用「评这一版」进那条作品的评审页，新结论仍然挂在作品下。

## 之前是什么样

| 之前 | 现在 |
| --- | --- |
| 版本对照只写「2 次评审」，看不出是哪两次、评的是哪张图 | 每一版下面逐条列出：结论胶囊 + 时间 + 箭头，点一条进那次的记录页 |
| 右侧「评审」面板只有摘要，整行不可点 | 整行可点，面板顶部写明「点一条看当时的证据原图与问题锚点」 |
| 想找更早的一条评审，只能去评审页翻「最近评审」那 6 条 | 从作品页进不受这 6 条限制：作品名下最近 20 条都能点到 |
| 历史评审只能从左侧列表打开，地址栏里没有任何记录 | `#/review/<评审 id>` 就是入口，刷新 / 后退 / 分享链接都回到同一条 |
| 打开的历史评审还能「重新评审」，会落一条没归属的新记录 | 历史只读，动作换成「评这一版」，新评审回到那条作品、归属正确 |
| 模板帧被清理后，证据位置是一张破图 | 一块说明「评审时的画面已经不在了」，结论与锚点照旧显示 |

## 三个实现决定

1. **地址即入口，页面不另存一份「当前打开的评审」**。`#/review/<评审 id>` 解析成路由参数，评审页按 id 读一次记录：刷新、浏览器后退、复制链接重开，落到的是同一张图同一条结论。左侧「最近评审」点击也改走地址（不再直接调函数），所以点完之后地址栏、页面、后退三者始终一致。
2. **归属用记录自己的 `project`，不看「最近评审」列表**。上一轮给 `/api/reviews/:id` 也算了 `project`，这里正好用上：从作品页点进一条两个月前的评审，它不在最近 6 条里，归属照样写得出来（「毛衣折叠收纳法 · 第 2 版」）。
3. **历史评审只读，要接着评就回那条作品**。历史页原来的「重新评审」会在旧画面上跑一次、落一条没有 `projectId` 的新记录——分数花了、结论却不知道该记在哪条作品下。现在打开记录时主按钮换成「评这一版」，跳到 `#/review/project/<作品 id>`，新评审照样挂在作品下。

## 顺手修的三处

1. **证据原图被清理**：模板帧删掉、远程图片失效时，`<img>` 的 onError 把画面位置换成一块说明（虚线卡片：「评审时的画面已经不在了 / 模板帧被清理、或远程图片失效；这条结论与下面每条问题的锚点仍然有效」），不再显示一张破图。本地用一条 `media` 指向不存在文件的记录验过。
2. **手机上的评审面板**：390 宽时正文只有 240px，原来「结论胶囊 + 版次 + 摘要 + 时间」挤在同一行，摘要被压成四行窄条（行高 114px）。改成结论与版次一行、摘要独占下一行（行高 120px，但每行能读满 240px）。
3. **版本结论胶囊不换行**：390 宽时「需人工确认」曾被拆成两行、胶囊撑到 40px 高；补 `white-space: nowrap` 后两个宽度下都是 194×24，放不下就整枚换到下一行。

## 边界

- 评审历史仍存 200 条，评审页的「最近评审」只显示 6 条；作品页能点到的是**该作品名下最近 20 条**（作品详情接口的上限），不是全部 200 条。
- 记录不存在、或不属于当前账号（管理员除外）时，页面给「评审记录不存在」并留一个回评审页的出口，不显示半份结论。
- 作品删除后评审变「没记入作品」（上一轮的口径），点开仍然能看证据——只要原图还在。
- 这一轮**没有改服务端口径**：`/api/reviews`、`/api/reviews/:id` 的字段没变，页面只用已有的 `project` / `source` / `version`；也没有回写任何生产数据。
