## 规则（纯函数，`src/domain/review-anchors.ts`）

`reviewAnchorBadges(marks)` 按列表顺序逐个放编号：

1. 依次试 **左上 → 右上 → 左下 → 右下** 四个角，第一个和已放编号不打架的角就用它；
2. 打架的判据是归一化坐标下 `|Δx| < 0.04` 且 `|Δy| < 0.022`（16px 方块在 546×896 画面上
   约等于这个量），两个方向都贴太近才算撞；
3. 四个角都被占了，就沿**朝画面中心**的方向每圈错开 20px（右下角的框往左上挪，编号不会
   挪出画面），最多 5 圈；
4. 真放不下（十几个框挤在一处）时叠回左上角——**宁可压住也不隐藏编号**。

返回 `{ id, index, corner, ring, dx, dy }`，样式只负责摆：角位是四个 class，位移是
`--badge-dx / --badge-dy` 两个 CSS 变量，都有默认值（老数据、老浏览器不会摆错）。

顺手补的一条**旁证**：问题行加了 `面积 5.6%`（框住的宽×高占画面多少，0.1% 精度，
悬停说明「框越小越能指到具体位置」）。它不是新结论，只是让人一眼看出这条证据是
「指到具体一处」还是「整屏都在框里」。整屏时直接显示「整屏」，不再给一个没信息量的 98%。

## 边界

- 避让只在**编号之间**做，框线本身重叠时照旧叠着画（框是真坐标，挪了就不是证据了）。
- 阈值是按 546×896 的常见画幅定的；画幅极宽或极窄时「0.04 / 0.022」的等效像素会变，
  同一条问题可能在宽画幅上少换一次角（不会压住，只是提前换角）。
- 圈数上限 5：超过 20 个框挤在一处时仍会叠，但会叠在左上角而不是消失。
- 面积是 bbox 的宽×高，不扣除遮挡；斜放的框按外接矩形算。
- 编号仍按列表位置走，模型返回顺序变了编号就跟着变（这是上一轮就定下的规则）。
