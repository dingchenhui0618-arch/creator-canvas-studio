# 替你把要发给收包人的那段话写好（v0.9.143，2026-11-15）

上一版在收据里收了一句「这意味着什么、下一步做什么」。可下一步真要动手时，还是得自己组织语言：跟客户说哪一项不一样、请他怎么重验、两边各写了什么。这一版把那两三句话写出来，一键复制。

**一句话在前：对不上的那种差别下面多一个「复制这段话」，点一下就能粘到微信里发出去。**

## 复制出来的是哪句话

| 收据是哪种 | 复制出来的那段话（节选） |
| --- | --- |
| 只有哈希不对 | 「包名、版次、字节数都对得上，只有整包 SHA-256 不一样（你那边 aaaaaa…aaaa，我这边 debb04…353a），说明内容被改过或重新压过。麻烦解压交付包、打开里面那张「校验.html」，把收到的 zip 拖进去重验一遍，再把导出的收据发我。」 |
| 字节不对 | 「包名和版次都对得上，字节数不一样（你那边 250,142 B，我封的是 277,725 B）。多半没传全，或者解压后又压过。……」 |
| 版次或包名不对 | 「你发回来的收据上写的是 版次 v3、包名「旧的-交付包.zip」，我封的这一版是 版次 v4、包名「…」：两边不是同一份包。我把这一版的「交付包」和回执链接再发你一次，麻烦重下一份再验。」 |
| 他那边读不出来 | 「你发回来的收据我这边读不出来（校验页说包读不出来）。……我把这一版的包也重发一份，你看看是不是没下全。」 |
| 包对得上、结论不一样 | 「收据上五项都对得上，只有结论写「有问题」——这一份包是好的。麻烦按逐项的说法重贴一张，结论改成「都对得上」；要是你那边确实有一项对不上，把坏在哪一项告诉我。」 |
| 这张没带逐项 | 「收据里没带逐项，我这边看不出差在哪。……」 |

## 只在收据写过的范围内说

- **两边值照抄**：字节补千分位、哈希头尾两截，都取自收据上那五项；没有的值写「没写」，不替它填。
- **不编原因**：说的是「多半没传全，或者解压后又压过」这种收据能支持的解释，不写「你一定改过」。
- **不承诺赔补**：只说「我把这一版的包也重发一份」，不说几时到、不说谁的责任。
- **对得上时不出现**：收据对得上，这一块连按钮一起没有。
- **只读**：没有新接口、没有新字段、没有新的写入路径——话是从已经存下来的五项里拼出来的。

## 坑

- **「每段都能直接发出去」要写成断言**：第一版版次那段漏了「收据」两个字，读起来像在说包名而不是在读他的收据——测试里加了「每段都要说回收据」，当场抓到。
- **字节数不能把 `250142` 原样贴出去**：客户看的是 `250,142 B`，两边并排才好对；补千分位放在同一个函数里，界面上与话里同一口径。
- **剪贴板要真读一遍**：只断言按钮点了没用；headless 里用 CDP 授权 `clipboardReadWrite`，再 `navigator.clipboard.readText()` 读回来，三段话各自对一遍。
- **三种状态各复制各的**：不能拿哈希那段发给「读不出来」的人；三条各点一次、各读一次剪贴板。

## 发现但没做

- 只写中文、写死在代码里，没有可编辑的模板或称呼（客户的称呼得自己加）。
- 工作台那一行仍只有结论，没有「复制这段话」的入口（要先点进作品页）。
- 收包人那一侧（免登录回执地址）还是只说这一次。
- 复制完不会记「已经催过一次」，也没有提醒。
