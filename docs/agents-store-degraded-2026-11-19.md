# 智能体文件坏了：先备份、再降级，并把话说清楚（r268 / v0.9.250）

日期：2026-11-19 · 本轮没有真实上游调用，0 费用。

## 一、为什么这一份不能跟别的一样「读不出来就抛」

r265 / r267 已经把十份用户数据改成「只有文件不存在才算空库，读失败就停」，读失败时读写都不许动。
智能体存储（`data/agents.json`）当时留了个尾巴：文件坏了就把原件改名成 `agents.json.broken-<时间戳>`，
内存里给一个**空列表**。也就是说：

- 原件其实没丢（在备份文件里），但用户看到的是「一份预设都没有」；
- 用户随手新建一个，新文件里就只有这一条 —— 看起来像「历史全没了」，而且没有任何提示。

不直接照搬「读失败就抛」的原因：对话预设是每个创作页的入口，抛出去整站就不可用。
所以改成**先备份、再降级**，把「现在是降级数据」这件事摆到界面上。

## 二、这一轮的行为

| 情况 | 读 | 写 | 界面 |
| --- | --- | --- | --- |
| 文件不存在（第一次部署） | 四份默认预设 | 正常写 | 什么都不提示 |
| 文件坏了、备份挪得走 | 四份默认预设 | 允许，第一次写生成新文件 | 警告条：原文件已备份、现在显示默认预设、写一次会生成新文件；附备份文件名 |
| 文件坏了、**备份挪不走** | 四份默认预设 | 一律拒绝（`STORE_UNREADABLE`），一个字节都不写 | 警告条换失败色：为了不覆盖原文件，现在不能新建或修改，请联系管理员 |
| 顶层不是数组（以前会被当成空库） | 四份默认预设 | 同上 | 同上（走同一套备份 + 降级） |

- 「读」永远给得出东西，页面不白屏；「能不能写」跟着备份结果走。
- 说明通过 `GET /api/agents` 的 `storeNotice` 下发（健康时是 `null`），
  带 `degraded / canWrite / at / backup / message`。
- 警告条出现在「快捷创作」页头下方（输入卡同宽 900px）与「对话预设」编辑页顶部。
- 启动迁移 `migrateOwnership` 遇到写被拒时由既有 `try/catch` 接住，不会把进程带崩。

## 四、边界

- 说明只在「见过坏文件的那一次进程」里挂着：备份挪走之后，下一次启动看到的是 `ENOENT`，
  会按默认预设起一份干净文件，界面不再提示。原件一直在数据目录里（`agents.json.broken-*`）。
- 没有做「从备份自动修复」的入口，也没有后台一键恢复；要恢复只能把备份文件改回去并修好 JSON。
- 默认预设的 `ownerId` 为空（公共数据），这一点与第一次部署时一致，不是这轮引入的。
