# r325：提示条分档——失败不再挂对勾（v0.9.297）

一句话：全站 162 处提示里，**86 处自己说清了语气**；69 处「没做成」的提示不再挂着那个 ✓。

## 为什么改

r324 把停留时间拉长到「读得完」，副作用是把上一轮那个将就放大的问题照出来了：
「复制失败：浏览器没给剪贴板权限」前面挂着一个 ✓，等于当场说反话。上一轮记着没做，
理由是**只改一半比不改更乱**（一部分失败带语气、一部分不带，用户看到的是随机）。
这一轮把全站扫完，把该带的都带上。

## 改了什么

| 语气 | 什么时候用 | 图标 | 颜色 | 播报 |
| --- | --- | --- | --- | --- |
| `ok`（默认） | 动作做成了 | ✓ Check | `#ffffff` | `role="status"` |
| `fail` | 出错 / 被拒 / 名字为空 / 没权限 / 没建成 | ✕ X | `#ff9b9b` | `role="alert"` |
| `info` | 没发生动作，但也没出错（撤销栈本来就是空的、这一条本来就写着这个称呼） | ⓘ Info | `rgba(255,255,255,0.72)` | `role="status"` |

- **形状先分清，颜色只是补一层**：三种语气是三个不同的 SVG path，色觉不同的人也分得出来。
- 图标对读屏隐藏（`aria-hidden="true"`）：读屏听到的是文案本身（「名字不能为空」），不用再念一遍符号；失败那条换成 `alert`，因为「没做成」应该打断当前播报，不该排队等。
- **背景不换**：提示条固定在右下角，一改底色就像又弹了个新东西出来。
- 真源在 [src/domain/toast.ts](src/domain/toast.ts)：`ToastTone`、`ToastFn`（全站提示函数只有这一个签名）、`normalizeToastTone`（认不出的语气一律按 ok——宁可少标一次失败，也不要把成功画成失败）、`toastRole`。
- 深色底专用语义色：`--on-ink-fail` / `--on-ink-muted`。原来的 `--fail #a33838` 压在提示条的 `#111` 上对比度只有 1.9:1，等于没画；新的 `#ff9b9b` 是 **9.36:1**。
- **第二层包装也要透传**：工作流页（`CanvasPage`）与无限画布（`BoardPage`）各自还有一层 `const toast = useCallback(...)`，只改 `onToast` 不改它们，语气到这里就被吃掉了。

## 门禁抓到了四处漏网的

新增 [test/toast-tone.test.mjs](test/toast-tone.test.mjs)：**真源码扫描 + 反证**——凡是落在 `catch {}` 或 `.catch(回调)` 里的提示都必须带语气；类型上也不许再写 `(message: string) => void` 这种第二份签名。反证部分用一小段夹具让护栏变红，确认它不是空转。

第一遍照 `onToast(` 全站扫，门禁当场抓出 **BoardPage 两处**（「新建画布失败」「写入画布失败」）——它们走的是那一层自己的 `toast()`，按 `onToast` 扫根本扫不到。补上之后又抓出工作流页 catch 里两条：**「已退出排队 · 没有扣积分」「已停止等待这次运行」**——它们在 catch 里，但不是失败，是自己点了取消，改成 `info`。

## 教训

1. **第二层包装会把参数吃掉**：这一轮的坑不是「类型没声明」，而是「中间还有一层 `toast()` 没往后传」。
   只按 `onToast` 扫会漏掉工作流页与无限画布整整两页——**扫调用点要按「函数名全集」扫，不是按你以为的那一个名字扫**。
2. **撤销生产会话必须 `cd /opt/visionqa`**：第一次在 `/root` 下跑撤销脚本，`DATA_DIR` 落到了 cwd 下的空库，
   打印的是 `before 0 / removed 0 / after 0`——看起来「干净」，其实会话还在。
   `cd /opt/visionqa` 再跑才是 `before 1 / removed 1 / after 0`。**撤销的 0 有两种：删掉了，和没连上库。**
3. **行数别拿高度除行高**：`.vq-toast` 有 8px 内边距，36px 高 / 18px 行高会算成「2 行」，
   一条单行短文案也被记成换行。按文字节点自己的 `Range.getClientRects()` 数才是真行数。
4. 同一条提示一个账号只会弹一次：390 那一段要拿「进工作台自动弹的长提示」当样本，
   就得**另开一个同样状态（引导做完、还没建资产）的账号**，不能指望它再弹一遍。

## 边界

- 只有三档，没有 `warn`：运行「有节点失败」按 fail 处理（确实有东西失败了），不假装它是成功。
- 不传语气一律按 `ok`：升级不会把已有的成功提示改坏，但**新写的失败提示要自己记得带 `'fail'`**——门禁只兜得住 catch 里的。
- 语气只影响图标与播报方式，不改停留时长（时长仍是 r324 的「字数 × 60ms + 2.4s」）。
- 仍然是全局一条提示，后一条顶掉前一条，没有手动关掉。
