# 模板详情抽屉在手机上：正文从 13px 抬到 15px，底部四个按钮改成等宽两列（r232 / v0.9.216）

2026-11-19。改的是「模板库 → 点一条 → 抽屉」，也就是主线上「拆结构」那一步的全部内容：
开头钩子、脚本结构、分镜表、爆款分析、导出与分享。

## 结论

抽屉在 ≤820px 本来就是整宽的，问题不在宽度，在里面还是桌面排版：

- 正文一律 12.5–13px（口播、分镜画面、分析条目都是），手机上要凑近看；
- 关闭按钮 28×32，320 宽上只剩 22×32，比手指小一半；
- 底部四个动作 32px 高（删除 28px），还是右对齐的 flex 换行，两行参差、删除按钮比同行低 2px；
- 320 宽上「互动数据」原来挤成一行，改三列后「播放 128.4万」又被断成两行。

现在：正文 15px、说明 14px、元信息 13px，关闭按钮 40×40，底部四个按钮 48px 高、
等宽两列（主操作第一格，删除固定在右下角），互动数据 390 三列 / 320 两列且数字不折行。

## 实测（临时实例 + 三份示例模板，0 次真实上游调用）

390×844 与 320×844，设备像素比 2：

| 宽度 · 状态 | 抽屉 | 头部 / 底部 | 关闭 | 正文 | 容器内横向溢出 |
| --- | --- | --- | --- | --- | --- |
| 390 · 已解析 | 390×844 | 151 / 133（4 个动作两行） | 40×40 | 15px | 0 |
| 390 · 只存了链接 | 390×844 | 125 / 77（2 个动作一行） | 40×40 | 14px | 0 |
| 390 · 工作流模板 | 390×844 | 125 / 77 | 40×40 | 15px | 0 |
| 390 · 改编模式 | 390×844 | 151 / 77 | 40×40 | 输入框 16px | 0 |
| 320 · 已解析 | 320×844 | 148 / 133 | 40×40 | 15px | 0 |
| 320 · 已解析 · 分镜表 | 320×844 | 148 / 133 | 40×40 | 15px | 0 |

- 底部按钮：390 上每个 175×48，320 上每个 140×48；「套用到工作流」六个字 15px 加图标也放得下。
- 页面级 `documentElement.scrollWidth` 分别等于 390 / 320，正文容器 `scrollWidth == clientWidth`（389/389、319/319，差的 1px 是左边框）。
- 抽屉高度始终 844（贴满视口），正文区从 595px 降到 560px，滚动手感没变。

## 为什么每条选择器都加了 `.template-drawer` 前缀

这份抽屉的规则一半在 `src/App.css`，一半在 `src/styles/radar.css`；radar.css 是随模板库这个
懒加载分块后到的，同权重（0-1-0）写在 App.css 里会被它盖掉。实测踩了两次：`.drawer-stats` 的
14px 与 `.adapt-input` 的 16px 都没生效，`getComputedStyle` 仍报 13px / 14px。加上
`.template-drawer` 前缀（0-2-0）后才稳定生效。

## 一处顺带修的

320 宽上「互动数据」用三列网格时，单元格只有 96px，「播放 128.4万」被折成「播放 128.4 / 万」——
数字在中间断开，比原来更糟。改成：数字 `white-space: nowrap`，并且 ≤380px 退成两列
（144px 一格，两行三行都放得下）。

## 改动文件

- `src/App.css`：新增 `@media (max-width: 640px)` 与 `@media (max-width: 380px)` 两段模板抽屉规则（插在打印样式之前，不动桌面）。
- `test/template-drawer-mobile.test.mjs`：6 条断言（正文档位、触控目标、两列网格、互动数据列数与断行、改编输入框 16px、说明文字下限）。
- `package.json`：0.9.215 → 0.9.216。

## 边界

- 只量 390 / 320 / 1440；641–760 与 768 平板没逐屏量（抽屉在那两档仍是 580px 侧栏，本轮没改）。
- 抽屉里的抽帧是**占位图**：示例模板的 `frameUrl` 是本地生成的灰块（临时实例的数据），不是真抽帧。
- 640px 以下底部改成网格后，**键盘 Tab 顺序仍是 DOM 顺序**（改编 → 用它做作品 → 套用到工作流 → 删除），
  与视觉顺序差一格（视觉第一格是主操作）。这是 CSS `order` 的代价，取舍是手机上视觉层级优先。
- 只动了 CSS 与一条测试，没有新接口、没有改服务端；本轮 0 次真实上游调用、0 元。
