# 手机号验证码登录（2026-11-17，0.9.173）

## 做了什么

登录页新增「验证码登录」，后台新增「短信通道」。链路：

```
登录页 → 发送验证码 → POST /api/auth/sms/send
                              ├─ 号码不存在：回同一句话，不发码（不做账号探针）
                              └─ 号码存在：签发 6 位码（库里只存 sha256，5 分钟）→ 交给服务商
     → 输码 → POST /api/auth/sms/login → 校验 → [开了 2FA 就发 challenge] → 下发会话 cookie
```

## 服务商

| provider | 做什么 | 用在哪 |
| --- | --- | --- |
| `fake` | 不发真短信，把 `{at, phone, code}` 追加到 `DATA_DIR/sms-outbox.json`（只留最近 50 条，0600） | 本地开发、E2E、验收 |
| `aliyun` | 真发：`POST https://dysmsapi.aliyuncs.com/`，`Action=SendSms`、`Version=2017-05-25`、RPC 签名 HMAC-SHA1 | 生产（等资质/签名/模板批下来） |

阿里云签名的实现要点（`server/sms-send.mjs`）：

1. 公共参数 `AccessKeyId / Action / Format / RegionId / SignatureMethod=HMAC-SHA1 / SignatureNonce / SignatureVersion=1.0 / Timestamp(GMT, 秒级, 无毫秒) / Version`；
2. 业务参数 `PhoneNumbers / SignName / TemplateCode / TemplateParam(JSON 字符串)`；
3. 参数按名字典序排 `k=v`，值用百分号编码（空格 %20、星号 %2A、波浪号不编码），用 `&` 连接；
4. `stringToSign = POST & %2F & encode(query)`，`Signature = base64(HMAC-SHA1(secret + '&', stringToSign))`。

单测 `test/sms-config.test.mjs` 用固定 nonce / 时间戳手算了一遍 HMAC，与实现逐字节一致；**但没有对真实阿里云发过请求**（还没有签名与模板）。

## 安全取舍

- 库里只存码的 sha256；接口不回显码（单测断言过响应体里没有码）；
- 同号只留最新一枚码，发新码即作废旧码；
- 一个码最多试 5 次，错满即作废；文案会告诉用户「还可以试 N 次」；
- 限流：同一号码 60 秒冷却、1 小时 5 条；同一来源 1 小时 10 条；
- 开了两步验证的账号，短信码只替代口令，第二因子仍要过（`twoFactorRequired` + challenge，不下发 cookie）；
- 配置落盘 0600，接口只回「有没有密钥」+ AccessKeyId 掩码；换 AccessKeyId 必须重填密钥。

## 阿里云短信资质：做到哪一步

控制台（`https://dysms.console.aliyun.com/`）现状：服务已开通、账号「企业用户 / 正常」，**资质 / 签名 / 模板三项都还没提交**。

这一轮在「新增资质」表单里已经填好：

| 字段 | 值 | 来源 |
| --- | --- | --- |
| 资质用途 / 组织类型 | 自用 / 企业 | 默认 |
| 资质名称 | 企业简称 + 企业资质 | 手填 |
| 证件类型 | 企业营业执照 | 手选 |
| 上传证件 | 营业执照（OCR 识别通过） | 用户提供 |
| 企事业单位名称 | 营业执照上的企业名称 | OCR 自动 |
| 统一社会信用代码 | OCR 自动（不入文档） | OCR 自动 |
| 证件有效期 | 2026-09-21 → 2099-12-31（长期） | OCR 自动 |
| 法定代表人姓名 | 执照上那位 | 执照上有，手填 |

**卡住的三项（只有本人能给）**：

1. 法定代表人**身份证号** + 身份证有效期起止；
2. **管理员身份证**人像面、国徽面照片（各 ≤5MB，jpg/png）；
3. 提交时的**手机验证码**（阿里云发到管理员手机，我这边收不到）。

这三项齐了之后：资质提交 → 等审核（控制台提示 2 个工作日内，量大时更久）→ 申请签名 **VisionQA**（归属可用已备案域名）→ 申请验证码类模板（正文形如「您的验证码为 ${code}，5 分钟内有效」）→ 把 AccessKey、签名、模板 CODE 填进后台「短信通道」→ 发一条测试短信（约 ¥0.045）→ 登录页即出现验证码登录。

## 边界

- 生产未配置短信通道（`/var/lib/visionqa/sms.json` 不存在），线上登录页没有验证码入口；
- 没发过任何真实短信，没有产生短信费用；
- 后台通道表单在 390 宽是两列栅格自动折行，没有专门为手机重排；
- `fake` 通道只在本地/验收用，生产启用后 `sms-outbox.json` 不会出现（该文件只在 fake 通道写）。
