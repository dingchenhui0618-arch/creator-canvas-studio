# 快捷创作：消息里的链接，平台自己读（r219 / v0.9.203）

一句话：**消息里带网址时，平台先把那一页读成文字再问模型**；读到什么、多少字、为什么没读到，都留在会话里给用户核对。

## 为什么自己做，不再靠上游的 `deepseek_read_url`

r214 的对话把「读链接」当成上游服务端工具（`tools: [{type:'deepseek_read_url'}]`）发出去。两个问题：

1. **不是每把 Key 都认这个工具**：不认就是整条请求 400，用户点一下「读链接」就报错，而按钮看起来明明是开着的。
2. **读到了什么我们看不见**：上游读完只把结论塞进回答，用户没法核对，和 r218 附件「能自己看原文」的口径不一致。

所以 r219 起：读链接在平台本地做（`server/link-read.mjs`），上游工具只留联网搜索。对话请求体里不再出现
`deepseek_read_url`，行为不再取决于上游是哪一家。

## 契约

- 触发：消息文本里出现 `http://` / `https://`，且「读链接」开关打开。开关关着就一个页面都不抓，界面会提示。
- 数量与额度：一次最多读 **2 个**链接、每条 **12000 字**、两个合计 **12000 字**；超了标「已截断」/「没读」。
- 读到的文字与附件共用同一套上下文口径（`chat-store` 的 `docText`，只给最近 6 条留正文，
  单条 24000 字封顶），并在模型看到的那条消息里带标题：
  `【这一轮的链接】` + `【链接 1：<url>（<标题>），约 N 字】` + 正文。
- 会话里只留 metadata（`message.links`：url / finalUrl / title / ok / chars / truncated / note），
  **页面正文不进会话文件**；界面在你那句话下面显示胶囊（标题 + 字数，失败的是虚线「没读到」）。
- 失败不拖垮对话：某个链接打不开只变成一句「【链接 1：… 没读到：原因】」，这次对话照常回答、照常只扣 1 积分。

## 内网防护（这是本轮最要紧的代码）

用户的链接会由**服务器**去请求，所以相当于把服务器的网络位置借给用户用，必须挡住内网：

- 只认 `http:` / `https:`；地址里带账号口令的直接拒绝；
- 域名先解析，**只要有一个解析结果落在本机 / 局域网 / 链路本地（169.254）/ CGNAT（100.64/10）/ 组播 / 保留段**就拒绝；
  字面 IP 直接判；
- 最多跟 3 次跳转，**每次跳转的目标都重新过一遍上面的校验**（防止公网 302 跳到 `127.0.0.1` 或云元数据地址）；
- 8 秒超时、正文最多 3 MB、不执行脚本、不带 cookie（所以要登录才看得到的页面读不到）；
- 测试要读本机假页面时用 `VQ_LINK_ALLOW_PRIVATE=1`，**生产不要设**。

还没挡的：DNS rebinding（先解析成公网、真正连接时又指到内网）。要彻底堵需要把解析结果钉进连接里，
Node 的 fetch 目前做不到，先记在这里——本功能不带任何登录态，能拿到的只是内网页面的文字。

## 能读什么、读不了什么

| 类型 | 读法 | 说明 |
| --- | --- | --- |
| HTML 网页 | 去脚本/样式/注释，段落还原成换行，实体解码，取 `<title>` | 靠 JS 渲染的页面正文可能读不到，会明说「这个页面没读到正文」 |
| 纯文本 / JSON / XML | 原样清空白 | — |
| PDF | 复用 r218 的 PDF 文字层解析 | 扫描件 PDF 直说读不出，**不做假 OCR** |
| 压缩包 / 图片 / 视频 | 不读 | 回「这个链接不是网页（image/png），读不了」 |

## 边界

- 联网搜索仍走上游工具（`deepseek_web_search`），**至今没有真实上游验证过**；本轮的改动只是把「读链接」从这条不确定的链路上摘下来。
- 一次最多 2 个链接；页面正文不进会话文件，只进上下文（最近 6 条）。
- 不读需要登录、需要 cookie、需要执行 JS 才能出正文的页面。
- 不解析网页里的附件（PDF 之外的文件类型一律不读）。
