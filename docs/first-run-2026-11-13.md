# 新账号的第一屏：不铺空盒子、不把人送进空库（v0.9.42）

第 52 轮把上手引导改成了「一条作品的主线」，但那只管弹窗。关掉引导之后，第一次进工作台的人看到的是另一件事：
五块「还没有」（评审 / 交付 / 运行 / 模板库 / 分享）加三张空心开始卡，页头唯一的实心主按钮是「新建画布」——
而画布在这套模型里是作品里的一步，不是起点。作品页更直接：空状态写着「去模板库挑一条」，而模板库那时也是空的。
这一轮把这两处收掉：**空账号就说空，别铺空盒子；下一步要落在真的有东西的地方。**

## 二、什么叫「还什么都没有」

判据只有一处：`src/domain/first-run.ts` 的 `isFirstRun()`。六路计数——作品 / 画布 / 模板 / 运行 / 交付 / 分享——
**全都读到、并且都是 0**，才按空账号讲。少一路（`undefined`）不判空；任何一路读失败（`failed > 0`）也不判空。

这条规矩和引导那边是同一条：读失败时说「空」，等于把一次服务故障说成「你还没做过」，人会照着错的那一步走。
所以画布服务挂掉时，工作台宁可退回原来那套（每块写自己的空状态），也不冒充「新账号」。

## 三、四块「将来时」

空账号那一屏只留一块，四行对应主线后面的四步，名字与真实区块同名（测试会核对）：

| 区块 | 什么时候出现 |
| --- | --- |
| 评审等你看的 | 评过一版画面、结论是「需人工确认」或「不通过」的作品排在这里 |
| 交出去的 | 作品页点「交付这一版」；每一版按时间留在这儿，交付稿随时能打开 |
| 最近运行 | 画布跑一次运行，列出节点耗时与返回，并标出挂在哪条作品上 |
| 分享出去的链接 | 发给甲方的只读链接，汇总每条被打开过几次，停用后也留着 |

下面一句只说今天要做的一件事（从主卡进「发现」检索一条），钱只写事实：检索与解析按次扣，开画布、导出与分享不扣。

## 四、一屏只留一个实心主按钮

- 工作台：页头「新建画布」从实心降成描边，主位让给主卡的「去检索 / 继续这个作品 / 按意见改这一版」。
- 作品页：模板库空、手上也没有作品时，页头那颗「从模板开始」换成「去发现检索一条」并降为描边——
  因为下面空状态里已经有一颗同去向的实心按钮；有作品时页头仍是实心的「从模板开始」。
- 判据是「这一屏的下一步在哪」：空账号在空状态里，有数据在主卡里。

## 五、空作品页的三档

| 模板库条数 | 说什么 | 主按钮 |
| --- | --- | --- |
| 0（读到了，确实是空） | 作品要从一条拆好的模板开始，模板库现在也还是空的 | 去发现检索一条 |
| null（这次没读到） | 模板库的条数这次没读到：先看模板库有没有能用的那条；模板库也是空的，就从「发现」检索一条 | 去模板库 + 去发现检索一条（并排） |
| > 0 | 在模板库挑一条，点「用它做作品」 | 去模板库挑一条 |

第二档是这一轮特意留的：读失败不能断言「模板库是空的」，也不能只给一条可能走不通的路，所以两条都给。

## 六、顺手修两处

1. **画布接口的错误翻成人话**：`server/bdc.mjs` 里 `listCanvases()` 把 `fetch failed` / `ECONNREFUSED` 这类原始串直接回给界面，
   工作台就会显示「画布列表：fetch failed」。现在统一走 `canvasErrorMessage()`：画布服务没连上时说清「哪些功能不受影响、接下来做什么」；
   原始的英文与堆栈留在 `detail` 字段里，排障不丢线索；真的业务错误（例如 `canvas not found`）照原文传，不被误翻。
2. **390 的区块头**：标题与「看四步主线」并排时，标题被挤成「做完第一条，这几块会 / 自己出现」两截；窄屏改成上下两行。

## 九、测试与边界

`test/first-run.test.mjs` 7 条（新增，387 → 394）：

1. 六路都读到且都是 0，才算「什么都没有」；
2. 任何一路读失败都不算空（`failed > 0`、`counts: null`、`null`、`undefined` 四种）；
3. 少一路计数、或任意一路有数据，都不算空（六路各测一次）；
4. 画布服务没连上时给的是中文可行动的话，真业务错误照原文；
5. 工作台的判据接的是六个真实计数，交付读服务端总条数不是本页那一页长度，四块名字对得上页面里那四块；
6. 评审 / 交付 / 分享三块被关进「非空账号」分支里，页脚在条件外面；页头不再把「新建画布」按成实心；
7. 空作品页按模板库条数分流（0 / null / 有），且 `App.tsx` 把 `onDiscover` 接到了 `radar`。

`npm test` **394/394**；`npx oxlint src server test` **0 error / 6 warning**（与上一轮同样的六条历史告警）；`npx tsc -b` 干净；`npm run build` 通过。

边界：这一轮没有动计费表、接口语义与一级导航；没有真的跑检索 / 解析 / 评审，0 积分；
本地截图为了走到「六路都是 0」这一档，起了一个只回答「列画布=空」的假画布服务（`.tmp-qa/r53-canvas-stub.mjs`，不进仓库、不是产品代码）。
