# 视觉评审先问「评哪条作品的哪一版」（v0.9.37 / 2026-11-13）

结论先行：**视觉评审的第一屏不再问「从 26 张模板首帧里挑一张」，而是先把「我这条作品的这一版」摆出来。**
之前从侧栏进来，左边铺满 26 张别人的首帧、右边写一句「先选一张要被检视的画面」——按目标模式，评审回答的是
「这一版能不能发」，版本只属于作品；把「挑一张图」当成入口，等于把工具的位置放回了主线前面。
这一版把入口换成作品版本，模板首帧降级成左栏一个可展开的「单独评一张画面」。

- 发布包：`20261112-233656-2026-11-13-review-from-p.tar.gz`

## 一、改之前：这一页的第一屏在问什么

| 位置 | 改之前 | 问题 |
| --- | --- | --- |
| 右侧主区 | 「先选一张要被检视的画面」+ 三条说明 | 第一屏不认作品：主线的对象在这页没有出现 |
| 左栏 | 「被检视对象」26 个模板首帧，撑满一屏 | 26 张别人的图占掉最贵的位置；自己的东西要往下翻 |
| 从作品页进来 | 抬头写「记入作品：X」 | 说了记入哪条作品，却没把「这一版」当成主体 |

评审只认「一条作品 + 一个版次」：结论挂在作品下、交付稿写第几版、状态胶囊按版判，
唯独入口还是「一张图」。这一版不动评审本身的口径（规则、锚点、扣积分、判断层一个字没改），只改入口。

## 二、改法

**1）服务端现算一份候选：`GET /api/reviews/candidates?limit=1–12`**

- 只读、不落库、不检索、不扣积分；非 GET 回 405，生产未登录回 401（与 `/api/projects` 同一套）。
- 每行六件事，全部现算：`versionLabel`（第 N 版 / 还没开画布）、`hasCanvas`、
  `reviews.count/lastVerdict/lastAt`（**只算当前这一版**）、`status`（文案 + 语气 + 结论）、`delivered`、`updatedAt`。
- 返回 `{ total, withoutCanvas, items }`：`total` 是账号下全部作品数（不受 limit 影响），
  `withoutCanvas` 给说明句用；`limit` 夹在 1–12，非法值回默认 4。

**2）页面：首屏先给作品版本，模板首帧收进「单独评一张画面」**

- 右侧主区第一屏是「先选一条作品：评的是这一版能不能发」+ 候选行（最多 4 条）：
  作品名 · 第 N 版 · 评过几次/最近一次时间 · 状态胶囊 · 出口。
- 出口按有没有画布分开：有画布 → 「评这一版」进 `#/review/project/<id>`；
  没画布 → 「先开画布」进作品页；已交付但没画布的老数据 → 「打开作品」，不写一句自相矛盾的话。
- 底部「还有 N 条在作品里」直接去作品列表；首屏只给 4 条，不在这里做第二个作品列表。
- 左栏标题变成「单独评一张画面」，26 个模板首帧默认收起（点开才铺开，图片地址也在里面）；
  从作品页进来、或库里还没有作品时自动展开——那时不展开就没得选。
- 窄屏（≤1180 一列）把主区排到前面：手机首屏先看到「评哪条作品」，不是 26 张首帧。

**3）顺手修的三处**

- 页头说明改成这一页现在的职责（评这一版能不能发；单独评一张的结论不挂作品）。
- 作品上下文那条说明原来写「要评审的是你这一版的画面，不是原片首帧」，可下面能挑的恰恰是模板首帧：
  改成「把这一版要发的画面贴进来最准；没有截图时拿模板首帧也能评，但那是原片那一帧」。
- 390 宽：页面与卡片各 32 内边距一扣只剩 192px，胶囊与出口黏在一起；三段说明还是三栏各 70px 拆字。
  收成 16 内边距、说明改一列、图标顶到第一行。

## 三、口径（三条决定）

1. **候选 = 作品，不是「待办」。** 工作台那块「评审等你看的」只收结论为需人工确认 / 不通过的（`review-queue.mjs`）；
   评审页要的是「评哪一条」，所以已通过、还没评过、甚至已交付的都列出来，写清状态由人挑。
   两处不合并：一个是催办清单，一个是选对象清单。
2. **排序按最近改动。** 与作品列表同一顺序（`updatedAt` 倒序、同一时刻按 id）；不按结论猜用户想评什么。
3. **胶囊与计数不另算。** `reviewCandidates` 调 `reviewsForVersion` / `decisionFor` / `projectStatus` /
   `deliveredCurrent`（`server/project-status.mjs`），与作品卡片、工作台、交付稿同一处；版本划分之前记在 0 上的
   评审仍然折进 v1，不会出现「卡片写需人工确认、评审页写在做」。
