# 点一行落到那一版（v0.9.140，2026-11-15）

上一版把回执摊到工作台，清单顶上写着「有 1 次回执对不上：点那几行进去，看差在哪一项」。可真点进去只落在作品页顶上：得自己找到「交付档案」、展开那一版、再点「收据」，才能看到差在哪一项。一句让人点的话，背后要三次点击。

这一版把这句话兑现：**工作台的一行就是一次点击，落在那一版的档案上，收据已经摊开。**

## 一个地址

```
#/projects/<作品 id>/delivery/<交付记录 id>
```

- 刷新还在那一版；后退回到工作台；把地址贴给别人（同账号下）打开的也是那一版。
- 只认交付记录的 id，不认版次：同一版重新封过包会换一条记录，旧链接找不到就直说找不到，不按「最接近的版次」猜一个落下去。
- 缺任何一段（`#/projects/<id>/delivery`）都退回作品页本身——坏链接不该白屏。

## 落下去是什么样

- **档案展开到那一版**：那一行淡淡垫一层底，收据面板已经打开，不用再点一次。
- **顶上一句**：`从工作台点进来的这一条：v1 · 回执对不上，收据已经摊开。`；没收到回执的那版写「还没收到回执，下面可以贴一段收据对一遍」；没封过包的老交付写「这一版没封存包，只有交付记录」。
- **找不到也说话**：`从工作台点进来的那一条已经不在这份档案里了：可能这一版后来重新封过包。`（不标任何一行）
- **让开顶栏**：56px 顶栏会压住滚到顶的那一行，锚点补了 `scroll-margin-top: 64px`。
- **工作台这一头**：只有封过包的那几行，读屏文案才写「直接打开这一条交付档案」——没包的老交付不许这个诺。

没有新接口、没有新字段、没有新的写入路径：**新增的只有地址**。回执仍然是 v0.9.136–139 存下来的那些事实。

## 坑

- **「逐项比对摊在下面」是句大话**：有的回执只有摘要、没有逐项清单，写「收据已经摊开」才是真的（第一版文案就是错的，验收时按实际渲染改掉）。
- **页面不是 window 在滚**：shell 有自己的滚动容器，`window.scrollY` 一直是 0；量「滚到眼前」要量目标元素离视口顶多远。
- **顺滑滚动要等停稳**：刚触发就量，会量到半路（63 / 78 / 96 / 107 都出现过），脚本要连续两次读数差 < 2px 再算数。
- **锚点会被 56px 顶栏压住**：窄屏滚到那一行时行顶是 -3px，补 `scroll-margin-top` 之后才对。
- **回到工作台是新挂载**：清单又只排首屏 3 条，脚本要再点一次「看这几条」，否则等 6 行会一直等不到。
- **别用 `window.history.back()` 之后马上量**：hash 与首屏都要重新等。

## 发现但没做

- 不能按回执筛（想看「对不上的那几份」还要自己往下翻）。
- 深链只到「哪一版」，到不了「包里哪一条文件」（清单里点开某一条仍要自己找）。
- 没有「他贴完了」的提醒（仍缺 SMTP 与告警授权）。
- 回执流水仍不记「这一次比上一次改了哪一项」。
- 收包人那一页（`#/receipt/<token>`）仍是独立的公开页，回不到这条深链，也不需要回。

## 回退

`bash /opt/visionqa/ops/rollback.sh --to 1` → v0.9.139；`--to 2` → v0.9.138。地址多一段是纯客户端约定：旧版本读 `#/projects/<id>/delivery/<did>` 会忽略后面的段、照旧打开作品页，只是不落在那一版；没有任何数据迁移。
