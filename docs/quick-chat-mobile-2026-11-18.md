# 快捷创作：手机上的对话列表收成一条（r221 / v0.9.205）

日期：2026-11-18

## 用户反馈

> 手机宽度下会话列表占位太大，回答区被压到 48vh。

上一版（r220）把回答排成 Markdown 之后，长回答在手机上更难读：一屏 844 里，会话列表先占 200px，回答区被压到 48vh（约 405px），输入框还在这之下。列表里明明只有标题和「几条 · 时间」，却比回答还占地方。

## 改法

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 会话列表（≤900px） | 常驻一块，最高 200px | 收成一条 32px 的「历史对话」按钮（整块 50px），默认不展开 |
| 展开 | 无此动作 | 点那条按钮展开，列表最高 40vh、内部滚动，再点收起 |
| 选完一条 | 列表仍在原地 | 选完 / 点「新对话」自动收起，回答立刻占满宽度 |
| 按钮上的字 | — | 有当前会话时显示它的标题，没有时显示「历史对话」 |
| 「会话存在服务端…」提醒句 | 手机上占 40px | 手机上藏起来（右边就是条数，桌面照旧显示） |
| 回答区高度 | 48vh | **58vh**（844 高的手机上 405px → 490px） |
| 桌面（>900px） | 240px 左栏 | 完全不变；折叠按钮在桌面上 display: none |

### 为什么没改成「整页滚 + 输入框贴底」

原本想按主流手机对话那样：回答区不限高、整页往下滚、输入框 sticky 贴底。实测不成立：窄屏形态下真正滚的是文档本身（document.scrollingElement），而 .vq-content 虽然写了 overflow: auto，在窄屏却不滚（scrollHeight 与 clientHeight 都是 2740，实测）。sticky 的参照是最近那个 overflow 不为 visible 的祖先，它不动，按钮就不贴底——滚到 620px 时输入框 top=899，已经在屏幕外。桌面形态下 .vq-content 是会滚的（1647/844），所以这个问题只在窄屏成立。改成 position: fixed 又要按侧栏宽度写死左右边距，平板上还会错位，所以都不做。

回答区自己滚反而更适合这个页面：边生成边看时，新字进来只滚回答区，整页不跟着跳。

## 验收（本机临时实例 + 假上游 + 无头 Edge，0 次真实上游调用、0 元）

6 条会话、每轮一条提问 + 一段带标题/列表/表格/引用的回答，实测：

| 量什么 | 390×844 | 1440×900 |
| --- | --- | --- |
| 会话列表整块高度 | **50px**（收起）/ 396px（展开，列表 338px，上限 40vh） | 470px（240px 宽左栏，不变） |
| 折叠按钮 | 32px，宽度 161px，可见 | display: none（桌面不需要） |
| 回答区高度 | **490px**（改前 405px），上限 58vh | 504px（上限 56vh，不变） |
| 选完会话后列表 | display: none（自动收起） | 一直在（本来就是左栏） |
| 页面横向溢出 | innerWidth = scrollWidth = 390 | 1440 |

## 边界

- 手机上回答区仍是固定高度、内部滚动（58vh），不是「整页滚」；原因见上。
- 手机上输入框仍在回答区下方：页面头部（标题 + 方式页签 + 对话方式）本来就占约 300px，844 高的屏要看到输入框得往下滚一点。这是既有结构，本轮没动。
- 折叠状态只在窄屏生效：宽屏把窗口拉窄会看到列表收起，拉宽自动回到左栏，不丢数据、不重建会话。
- 展开状态不记忆：刷新页面回到收起（手机上默认收起是有意为之）。
- 只改了样式与一处状态，没有新接口、没改服务端、没动计费。
