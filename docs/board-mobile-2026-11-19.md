# 无限画布状态条：窄屏收口与三处溢出（r243 / v0.9.227）

2026-11-19。用户侧清单的最后一块：无限画布（`#/board`，外部那张自由画布 canvas.wavisionai.cn）上方只会留一条 42px 状态条，
这轮把它在 320 / 360 / 375 / 390 / 768 / 1024 六档量一遍、修到清零，1440 桌面一位不动。

## 结论

一句话：手机与平板上「字 12px、按钮 24px、装不下就顶出屏幕」这三件事都清了；
768 上整页横向滚动（912px）与 1024 上「新窗口」图标被压成 16×32 是这轮发现的真问题，
手机上的排队位胶囊和写笔记弹层各自顶出容器 30px 左右，也一起修了。

| 宽度 | 小字 | 点按区 < 40px | 兄弟重叠 | 内容溢出容器 | 整页宽度 | 状态条高度 |
| --- | --- | --- | --- | --- | --- | --- |
| 320 | 1 → **0** | 4 → **0** | 0 → 0 | 0 → 0 | 320 → 320 | 133 → 105 |
| 360 | 1 → **0** | 4 → **0** | 0 → 0 | 0 → 0 | 360 → 360 | 101 → 105 |
| 375 | 1 → **0** | 4 → **0** | 0 → 0 | 0 → 0 | 375 → 375 | 101 → 105 |
| 390 | 1 → **0** | 4 → **0** | 0 → 0 | 0 → 0 | 390 → 390 | 101 → 105 |

## 三处真问题

### ① 768 上整页被状态条撑出屏幕，1024 差 20px

状态条只在 ≤760 换行，761–1079 这一段是一条不换行的 flex。实测内容 780px：

- 768：格子只有 700px（去掉内边距 672px），整页 `scrollWidth` 变成 **912**，还能横向拖；
  溢出链是 `.bd-strip 844>700 → .bd-page → .vq-content → .vq-main → .vq-shell 912>768`。
- 1024：788px 的格子差 20px，唯一被挤掉的是「新窗口」图标键——`a.vq-button--icon` 被弹性收缩压成 **16×32**（只有半截可点）。

修法：≤1080 允许换行（`flex-wrap: wrap`、`height: auto`、`min-height: 52px`），
同时把「让位名单」从 4 个扩到 6 个：`.bd-label`（无限画布）、`.bd-sep`、`.bd-picker-label`（画布）、`.bd-url`（画布域名）
在 ≤1080 收起——面包屑里已经写着「无限画布」，下拉自己带着画布名，省下的 100px 让 768 与 1024 都能排成一行。

### ② 手机上排队位胶囊被裁掉半句

「在跑 3 · 排队 2（最久 12.4s）」是一枚 `white-space: nowrap` 的胶囊、`max-width: 320px`，
390 上宽度 320 直接顶出状态条右边缘，「（最久 1」被页面裁断，连省略号都没有。

修法：≤1080 给胶囊 `max-width: 100%; min-width: 0`（超了在自己身上省略），
≤560 把「（最久 12.4s）」单独包成一个 `.bd-queue-oldest` 收起（完整那句还在 title 上），手机上留「在跑 3 · 排队 2」=151px。

### ③ 561–760 这一段把按钮钉在 32px 宽（自己这轮差点漏掉）

原来 ≤760 那条规则把「新建 / 写笔记 / 专注」收成 32px 宽的图标方块。≤1080 只抬了高度，
宽度还是 32——600 与 700 上量出 **3 个 32×40**，宽度不够点。补一条 ≤760 的 `width: 40px`（放在 ≤560 之前，手机上再由 44px 盖过）。

### ④ 写笔记弹层按 100vw 算宽度，右边缘顶出 30px

`.bd-note` 原来是 `width: min(340px, calc(100vw - 48px)); left: 12px`。
它挂在状态条里（`position: absolute`），状态条只有 322px 宽，按视口算就会溢出：390 上整页 `scrollWidth` 420、320 上 352。

修法：≤560 改成按容器算 `width: min(340px, calc(100% - var(--space-6)))`。

## 改了什么

全部写在 `src/styles/board.css` 末尾的 ≤1080 / ≤560 两段里，选择器是这一页自己的类名
（board.css 只被 BoardPage 懒加载引用，本身就是页级作用域），1081 起一条规则都不进。

| 位置 | 改前 | 改后（≤1080 / ≤560） |
| --- | --- | --- |
| 状态条本体 | 42px 定高、不换行 | 换行，`min-height: 52 / 56px`，行距 8px |
| 连接状态胶囊、排队胶囊 | 12px / 24px 高 | **13px / 26 / 28px 高** |
| 「新建 / 写笔记 / 专注」 | 24px 高 | **40 / 44px 高** |
| 「新窗口」图标键 | 32×32，可被挤成 16×32 | **40×40 / 44×44，`flex: 0 0 auto`** |
| 画布选择器 | 自己不带高度 | 跟随全局窄屏 44px（这一页不写死） |
| 排队位胶囊 | `max-width: 320px` | `max-width: 100%`，手机上收掉「最久」 |
| 写笔记弹层 | 按 100vw 算宽度 | 按状态条自己算（`100% - 24px`） |
| 这一页的字 | 12px × 4 处 | 全部 13px |

顺带把状态条标成一组：`<div className="bd-strip" role="group" aria-label="无限画布状态条">`。
窄屏收起「无限画布」字样之后，读屏仍然知道这一条是什么。

## 桌面没动的证据

同一个 1440 视口、同一批选择器，改前改后 `getComputedStyle` 逐项比对，**12 项完全一致**：

| 选择器 | 改前 = 改后 |
| --- | --- |
| `.bd-strip` | 42px 高 / `0 12px 0 24px` / 1204px 宽 |
| `.bd-label` | 12px / 55×16 |
| `.bd-state` | 12px / 24px / 68 宽 |
| `.bd-picker-label` | 12px / 27 宽 |
| `.bd-action` | 13px / 24px 高 / `0 8px` |
| `.bd-url` | 12px / 104 宽 |

| `.bd-select .vq-select__trigger` | 13px / 30px 高 / 243 宽 |
| `.bd-frame` | 1204×802 |

1440 的整体数也不变：小字 11、点按区 20（都是桌面本来就有的侧栏与顶栏）、溢出 0、整页高 900。

## 边界

- 只测 Chromium 无头、1x DPR；七档 320/360/375/390/768/1024/1440，561–767 与 769–1079 没有逐档量。
- 画布本体是第三方应用（iframe，跨源），这轮**只量了我们这条状态条**，iframe 内部一行没碰。
- 状态条的量法用的是 8891 上的占位画布服务（列表 2 块、iframe 是一张说明页），
  不是真的 canvas.wavisionai.cn——状态条自己的排版与真画布无关，但「画布很长名字」这类极端值只验到 5 节点/两个画布。
- 排队中状态是拦截 `/api/canvas/queue` 注入的假数据（在跑 3、排队 2、最久 12.4s），没有真跑一次出图。
- 「写笔记」只验到弹层打开与排布，没有真的往画布写节点。
- 判据只有四类：小字、点按区、兄弟重叠、内容溢出。对比度、焦点环、读屏顺序没有量。
- 手机上把「画布域名」从状态条收掉了（完整地址还在连接胶囊的 title 上），1200 以上照旧显示。
