# 「去解析」：只存了链接的那条，现在一步就能往下走（v0.9.40）

结论先行：v0.9.39 把「还没解析」写成了一枚点不动的虚线胶囊，理由写着「去模板里点『去解析这条』」——
用户得自己跑去模板库找那一条。这一版把这条路接通了：**发现页那一行、模板库那张卡片，
各自都有一个「去解析」按钮，点下去就是解析弹窗**；解析完成时这条模板（如果它是从雷达「加入模板库」存下来的）
**原地升级成已解析模板**，不新开一条，回去那一行的下一步直接变成「开成作品」。

顺带修了两处只有真跑一遍才会发现的问题：从抽屉里点「去解析这条」时解析弹窗被抽屉遮罩压住（发灰、点不动）；
待解析模板的抽屉底部把一枚**禁用**的「套用到画布」摆在主按钮位置。

## 一、口径：解析完成是「原地升级」，不是「再存一条」

解析（雷达里叫「一键复刻」）落到 `createTemplate()`，它先在同一账号的模板里找 `kind: 'saved'` 且
`sourceId` 相同的那条：找到就**把它从列表里摘掉**，用新的 `replica` 顶上去，并且：

| 字段 | 解析后 |
| --- | --- |
| `id` | 新的（`tpl_xxxxxxxx`，解析结果自己的一格） |
| `createdAt` | **沿用旧的**（收藏时间不变） |
| `reuseCount` / `ownerId` / `shared` | 带过来（用过几次、归谁、是不是官方示例都不重置） |
| `sourceUrl` / `stats` | 带过来（原链接与互动数据不该因为解析一次就归零） |
| `structure` / `storyboard` / `frames` | 这次解析出来的 |

不去重的后果很具体：库里同一条原片会有两格，发现页「库里的原片」按 `sourceId` 认原片，
下一步会指回那条**没有脚本**的旧条目，于是永远停在「还没解析」。

这一版把这条口径钉进测试（`test/template-parse-upgrade.test.mjs`，4 条）：
原地升级后同一条原片只留一格、旧的 `id` 查不到了、原有互动数据与链接都在、
升级后 `canStartProject()` 立刻为真、`originEntry()` 给「开成作品」；
另一个账号收藏的同一条原片**不动**；没有可升级条目时照常新建一条。

## 二、两个入口，一个弹窗

| 入口 | 之前 | 现在 |
| --- | --- | --- |
| 发现页「库里的原片」那一行 | 虚线胶囊「还没解析」，点不动 | 虚线按钮「去解析」→ 打开这条模板的抽屉（`#/templates/<id>`），落在「还没解析」那一段 |
| 模板库卡片脚注 | 灰字「待解析」 | 虚线按钮「去解析」→ 直接开解析弹窗（不用先进抽屉） |
| 抽屉底部主操作 | 禁用的「套用到画布」占着主按钮位 | 「去解析这条」，点开同一个弹窗 |
| 抽屉「还没解析」段 | 段里重复一枚一样的按钮 | 只留说明（解析后会原地升级、不多出一格），并指出入口在底部 |
| 弹窗 | 从哪进都叫「一键复刻 / 开始复刻」 | 从待解析的模板进来叫「解析这条原片 / 开始解析」；从检索卡片进来仍是「一键复刻」 |

一个界面只留一个主按钮：抽屉里这枚在底部（滚不滚都在），段里的那句话改成指路；
卡片上这枚与「用这条改编」同位置、同尺寸、同圆角，只把描边改成虚线——表示「还没拆过」。

## 三、顺手修的两处

1. **解析弹窗被抽屉遮罩压住**：抽屉是 `createPortal(…, document.body)` 且 `z-index: 30`，
   而弹窗留在页面树里（`z-index: 40` 只在页面那层结算）。实测 `document.elementsFromPoint()`
   在弹窗中心第一个拿到的是 `drawer-backdrop`——弹窗发灰，点下去还会落到遮罩上把抽屉关掉。
   改成弹窗也 portal 到 `body`，两者在 body 这一层按 z-index 排队；举报弹窗同样处理。
   截图前量到 `replicate-head → replicate-modal → modal-backdrop → drawer-backdrop` 的顺序才收工。
2. **待解析模板的底部主按钮是一枚禁用按钮**：`套用到画布` 对没有脚本分镜的条目禁用是对的，
   但它同时还是 `button--primary`（黑色实心），把真正的下一步挤到了上面。现在这枚在待解析时整块换成「去解析这条」。

## 六、边界

- 这一轮**没有真的跑解析**：解析要下载视频、抽帧、调视觉模型，按次 10 积分。弹窗是打开的，
  但「开始解析」没点。生产这次可逆写入只写了「一条只有链接的模板」并删净。
- 「原地升级」是服务端既有行为，这一版没有改它的实现，只是把界面接上它、并用测试把口径钉住。
- 解析成功后界面会把抽屉切到升级后的那条（`onDone` 带回新的 `templateId`），但发现页那一行
  要等回到发现页时重新取一次（页面加载时现算），不是实时推送。
- 不判断「这条值不值得解析」，也不替用户决定要不要花这 10 积分。
