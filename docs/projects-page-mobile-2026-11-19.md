## 结论

「作品 → 作品项目」这一屏（交付列表）在 390 下的正文只有 240px 宽，原来：搜索框 32px、筛选胶囊 30px / 12.5px、状态胶囊 22px / 12px、时间 12px，卡片六格数据落到 74px 一格，「1,800 积分」被折成「1,800 积 / 分」，长标题一行就只剩十四个字加省略号。

这一轮只动 `src/styles/projects.css`（外加一个 1080 断点的附带修复），没有改 JSX、没有加接口、没有动服务端：

- 卡片内边距 24px → **16px**，正文从 240px 变成 **256px**；六格数据改成 **2 × 3**（一格 120px），数字与单位**不折行**。
- 标题 **18px 且最多两行**（原来 17px、一行省略号）；模板来源与「打开作品」**15px**，时间、版次、分享状态 **13px**。
- 状态胶囊 **28px / 13px**（token `--chip-pill-h` / `--chip-font` 在 `.vq-project-page` 上抬一档，不碰其他页面）。
- 搜索框 **44px / 15px**、清除按钮 **32×32**；筛选胶囊 **40px / 14px**；「共 N 条」**13px** 并靠右。
- 320 下卡头允许换行（胶囊 + 时间排一行要 230px，会把卡片的网格列撑宽、内容溢出卡片）。
- 附带修一处：**1024 下六格只有 44px 一格**，「1,800 积分」同样折行 —— 3 × 2 从 780 提前到 **1080**，1024 变成 96px 一格。

## 两条经验

1. **卡片溢出不等于页面溢出。** 320 下卡头（状态胶囊 + 不可断行的时间，合计 230px）会把卡片的网格列撑到 230px，内容溢出卡片；但 `document.scrollingElement.scrollWidth` 只有 375（Chromium 最小窗口宽），对着 `window.innerWidth` 检测会漏掉。手机走查要拿 `document.documentElement.clientWidth` 当基准，再看每个元素是否越过它。
2. **`flex-basis: 100%` 不代表能缩小。** 搜索框里那个 `<input>` 的默认宽度（20 字符 ≈ 209px）会变成搜索框的 min-content，`flex-basis: 100%` 被抬到 291px，320 下直接顶出 220px 的正文区；`min-width: 0` 才是那条开关。
3. 同一段媒体查询里给同一选择器写两条规则，测试（按选择器取第一条声明体）只会读到前一条 —— 补样式时合并到一条里写。
