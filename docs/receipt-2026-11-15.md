# 核对完，带走一句话：校验页的「收据」（v0.9.135，2026-11-15）

## 问题

前两版把校验页发到收包人手里（交付包 v0.9.133、分享离线包 v0.9.134）：他能自己算出「都对得上」或「哪一条坏了」。可这条路是单向的——收包人看完了，发件人仍然不知道；收包人要回话，只能截图、或者手打「我这边没问题」，谁也说不清他验的是哪一份、哪个版本、整包哈希是多少。

## 做法

核对出结果后，页面多一块**收据**（`server/package-verify-page.mjs`，交付包与分享离线包同一页，两个包都自动有）：

```
VisionQA 离线包核对 · 毛衣折叠收纳法 · 第三版 v4
包：VisionQA-毛衣折叠收纳法 · 第三版-v4-离线包.zip
结论：都对得上 · 9 个文件都对得上：字节数与 CRC32 都和打包时记下的清单一致。
整包：272,155 B · SHA-256 8e0620f1…
时间：2026-11-15 06:25
```

- **复制这段**：真点一下（用户手势）走 `navigator.clipboard.writeText`；被浏览器拒绝就退回「选中这段文字 + execCommand('copy')」，再不行就把它选中并提示按 Ctrl+C。三种情况都给出明确回话（已复制 / 已选中）。
- **存成 核对结果.txt**：`Blob` + `a[download]`，文件名带时间戳（`核对结果-20261115-0625.txt`），内容带 UTF-8 BOM——Windows 记事本直接双击中文不乱码。
- **坏包与读不出来也有收据**：坏的写「结论：有问题 · 1 个文件对不上」并列出前三条坏在哪（文件名 + 清单值）；截断的写「读不出来」，哈希一栏如实写「没算」，不冒充。
- **不联网**：文字在收包人自己的浏览器里拼出来，不上传、不要账号；打印时两个按钮自动收起（`@media print`）。
- **收据要写「哪一份」**：清单 JSON 里多带 `project: { title, version }`（纸面上本来就公开的信息），仍然整体过 `\u003c` 转义。

## 坑

1. **收据要等哈希算完再画**：SHA-256 是异步的，先把收据画出来就会留下「计算中…」；所以收据在 digest 的 then / 失败分支里才 append，页面上不会闪。
2. **剪贴板要用户手势**：`navigator.clipboard.writeText` 在 file:// 上也能用，但必须由真点击触发；程序化 `.click()` 会被拒。所以留了选中 + execCommand 的兜底，并在回执里说清楚。
3. **BOM**：不带 BOM 的 UTF-8 txt 在 Windows 记事本里中文会乱，所以写下 `\ufeff`。
4. **收据块不能进打印稿**：按钮在纸上没意义，`@media print` 里收起来；文字仍会打印（有人想把结论打在纸上）。
5. **清单多一个字段**：`packageVerifyManifest` 的形状没变，`project` 是 `packageVerifyHtml` 里补的，老测试仍按原形状断言。

## 发现但没做

- **没有自动回传**：收据是文本，要人自己贴到微信 / 邮件；没有「点一下发回发件人」的通道（那需要账号或服务端，就不离线了）。
- 收据不是结构化 JSON / 不是签名凭证，只是一段人话。
- 分享页上仍然没有「这份离线包的整包哈希」可对比（离线页不能反过来依赖在线地址）。
- 老包（v0.9.134 及以前生成）里的校验页没有收据。

## 回退

`bash /opt/visionqa/ops/rollback.sh --to 1` → v0.9.134；`--to 2` → v0.9.133。校验页是包里生成的静态文件，回退后新下载的包就回到没收据的版本，已下载的不受影响，没有数据迁移。
