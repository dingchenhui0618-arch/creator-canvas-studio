## 事故一：首屏白屏（约 15 分钟）

- **现象**：部署后公网页面空白，控制台一条 `SyntaxError: Unexpected token '("，at assets/index-*.js`；
  服务端 `/api/version` 正常回 0.9.289，health 全 true —— 所以只用 curl 测接口是发现不了的。
- **根因**：改版本号时用 PowerShell 的 `Set-Content -Encoding utf8`，PS 5.1 会写 UTF-8 **BOM**。
  `src/App.tsx` / `src/lib/clientErrors.ts` 用 `import pkg from '../package.json?raw'`，
  构建时把带 BOM 的原文原样塞进 bundle，模块顶层 `JSON.parse` 直接抛错 → 整棵树没挂上。
- **修**：`package.json` 重写成无 BOM；新增 `src/lib/package-version.ts`（抹 BOM + 失败返回空串，
  绝不再让首屏跟着死）；`test/package-version.test.mjs` 3 条钉住「文件不带 BOM」「带 BOM 也能读」「坏了只回空串」。
- **教训**：前端产物必须**在浏览器里真开一次**才算发完。这轮之后的复核脚本
  （`scripts/shot-r316-prod.mjs`）第一步就是读页面状态与 `Runtime.exceptionThrown`，
  白屏会直接报「聊天室页面没渲染出来」。

## 事故二：nginx 没把 `/visionchat.md` 与 `/mcp` 交给 Node

- **现象**：`https://visionqa.wavisionai.cn/visionchat.md` 回 **200 + `text/html` 875 B**（SPA 首页），
  而 `127.0.0.1:8799/visionchat.md` 是 200 + `text/markdown`。`/mcp` 同理：公网拿到的是 HTML，
  客户端解析 JSON-RPC 直接炸 —— 也就是说「把说明地址发给 agent」这条主线在生产上是断的。
- **根因**：vhost 只有 `/api/`、`/media/`、`/print/`、`/download/` 这几条反代，
  这两个新路径落进了 `location / { try_files $uri $uri/ /index.html; }`。
- **修**：`deploy/production/nginx-app.conf` 增加 `location = /visionchat.md`（含 5 个安全头 + `Cache-Control: max-age=300`）
  与 `location = /mcp`（`proxy_buffering off` + `proxy_read_timeout 300s`，因为收件箱在 MCP 里也会等最多 25 秒）；
  `scripts/check-nginx.mjs` 的 `REQUIRED_LOCATIONS` 加两条（缺了会写明后果），nginx 模板测试仍 20/20。
  线上是**外科手术式**补这两段（`/etc/nginx/conf.d/visionqa.wavisionai.cn.app.inc.bak-r316` 留了备份），
  `nginx -t` 通过后 `systemctl reload nginx`，没有整份覆盖。
- **顺带记下模板与线上的既有漂移**（这轮没动，避免混进这次发布）：
  线上 `access_log … visits;` 带 log format 名，仓库模板没有；线上 `/download/` 少三个安全头（Referrer-Policy / X-Frame-Options / Permissions-Policy）。
  下次动 vhost 之前先对齐这两处。

## 事故三（发布后自查发现）：解散房间不作废配对码

- `dissolveRoom` 只给房间打了墓碑、作废令牌，`pair_codes` 里那张码仍是「未撤销」。
  配对时会先查房间是否已解散（410），所以接不进来，但库里留着一张「看起来还能用」的码。
- 修：`agent-access.mjs` 新增 `revokePairCodesForRoom`（`revokePairCode` 也改用它），
  `dissolveRoom` 解散时一并作废；`test/agent-access.test.mjs` 加一条「解散后码必须全被撤销、再配 401」。
