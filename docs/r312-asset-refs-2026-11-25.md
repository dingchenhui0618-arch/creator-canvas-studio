# r312 · 资产引用接进模板与工作流节点（v0.9.285）

2026-11-25。用户原话：「资产接进模板和工作流节点里能真引用上，工作台再补一条常驻的建资产提示，
别只有侧栏入口。」

上一轮（r311）把「注册后先建资产」做出来了；这一轮解决的是它的下一个问题：**资产建了却用不上**。

## 一、一条引用，三处生效

```
asst_<base36 时间戳>_<4~12 位十六进制>:<槽位>     例：asst_mf3k2p_ab12cd:hero
```

| 面 | 存哪 | 怎么用 |
|---|---|---|
| 工作流·出图节点 | `config.assetRef` | 走 `/v1/images/edits`（multipart 参考图） |
| 工作流·出视频节点 | `config.assetRef` | 首帧参考（`referenceAssets` + `mode: image2video`） |
| 作品（模板展开的那条） | 作品对象 `assetRef` | 分景区选一次，「出这一镜」带图；开工作流时 `n_shot_NN` 节点继承 |
| 快捷创作 | `POST /api/media/generate` 的 `assets` | 与上传素材混在同一个数组里，资产引用按 1 张图算 |

解析与读取只有一个入口：`server/asset-ref.mjs`（`normalizeAssetRef` / `splitAssetRef` /
`readAssetReference` / `listAssetRefOptions`）。选择器读 `GET /api/assets/refs`，
**只列已经有图的槽位** —— 没生成的槽位不该出现在下拉里，选了才知道没图是让用户白点一次。

## 二、三条不肯让步的规矩

1. **先读资产，再扣钱。** 出图 / 出视频节点在进入 `runImageGeneration`（扣费在那里）之前就读参考图；
   读不到直接失败并 `400 ASSET_REF_MISSING`。`test/asset-ref.test.mjs` 用真实账号跑一次节点，
   断言余额一分不动。
2. **不许静默降级。** 资产没了就报错，绝不悄悄退回纯文生图 —— 那会让用户以为这张图用的是他的商品图。
   界面同理：节点里存着的引用失效时，下拉显示「原参考资产已不可用」，不换回空选项。
3. **只碰自己那一批节点。** 开工作流时按分镜建的是 `n_shot_01…`；改脚本同步 `assetRef` 时只认这个形状，
   用户从面板自己拉的出图节点一个字段都不动（有测试钉住）。

## 三、工作台的常驻提示

产品资产或数字人资产任一边为 0，工作台就一直摆着一条：产品 x 套 · 数字人 y 套 + 「去我的资产」。
两边都建好才消失，**没有关闭入口**；位置在「下一步」主卡之后，不抢主 CTA。

为什么不做成弹窗：r311 的引导弹窗已经会让用户点「以后再说」，再弹一次就是骚扰；
一条常驻但不挡路的提示，既不逼他，也不让他忘了。
