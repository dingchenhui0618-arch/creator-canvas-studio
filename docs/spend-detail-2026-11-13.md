# 作品的花费明细：哪一版、哪一次、哪几笔（v0.9.66）

2026-11-13 · 生产 v0.9.66c（入口 `index-D8kex-ij.js`）

## 问题

上一版（v0.9.65）给了两个合计：账号本月花了 349 积分、作品「毛衣折叠收纳法」花了 16 积分。
合计回答了「花了多少」，回答不了四件事：

1. 这 16 是哪几次评审、哪几次画布运行扣的；
2. 改一版要花多少（第 1 版和第 2 版各多少）；
3. 退过款的运行明明失败了，为什么合计里看不到它——人会先怀疑数字错了；
4. 这个月花了多少、上个月花了多少。

## 做法

作品页「花费」面板多一个「明细」按钮，**点开才读** `GET /api/projects/:id/spend`：
合计仍在作品详情里随首屏返回，不多打一次请求。

- **按版本**：第几版、评审几次多少积分、运行几次多少积分、合计。「改一版花多少」直接看得见。
- **逐笔**：时间、动作（视觉评审 / 画布运行）、第几版、评审结论或画布名、积分。
  退过款的那笔灰掉、金额划掉、标「已退回」——**逐笔（去掉退款）加总 = 上面的合计**，对得上的数字才可信。
- **累计 / 本月**两枚胶囊：本月按 **UTC 自然月**，与每月额度、后台成本页同一个月份口径。
  胶囊上的数字按全部记录算，切范围时不跟着缩水（服务端额外给 `byMonth`）。
- **没扣积分的运行**（画布探活、直连）列出来但写「未扣积分」：它是一次运行，次数要与作品页的
  「画布运行 N 次」对得上，金额是 0。

## 两个口径（与 v0.9.65 同源，不新增统计副本）

| 层 | 数据来源 | 归集方式 | 退款 |
| --- | --- | --- | --- |
| 评审 | 评审记录自己的 `credits.cost`、`version`、`createdAt` | 只认记着这条作品 `projectId` 的评审 | 评审本身不退款 |
| 画布运行 | 运行记录的 `credits.cost` / `refunded`、`startedAt` | 这条作品当前画布 + 所有归档版本的画布（跨版本），按 `flowId → 版本` 映射落到第几版 | 照样列出、标「已退回」，**不计入任何合计与月份** |

检索 / 一键复刻 / 智能体对话仍然只记在账号上：积分账本里没有作品，硬摊过来等于编数。

## 边界

- **单位是积分不是钱**：真实成本仍在后台「成本」页按手填单价折算。
- **只有评审与画布运行归得到作品**；检索 / 复刻 / 对话在设置页「本月花在哪」按动作看。
- 逐笔最多列最近 **120 笔**（更早的按月份切换看）。
- 「本月」是 **UTC 自然月**，不是浏览器本地日历月。
- 删掉作品会解绑评审：那几笔花费留在账号账本里、不再挂在任何作品上。
- 版本划分之前的老评审记的是 0 版，与作品页、交付稿同一套规则折进第 1 版。
