# 工作台多了一块「分享出去的链接」（v0.9.12）

上线：2026-11-12，生产 visionqa.wavisionai.cn，版本 0.9.12。

## 为什么做这个

v0.9.10 能看到一条链接被打开过几次，v0.9.11 能在停用后回看每一轮——但都要先点开作品。
作品多起来之后，「哪条分享过、甲方看没看」还是要逐个点。这一轮把这件事提到工作台：
一条作品一行，正在分享的那轮 + 停用的各轮合成一个累计，点一行再进作品看每一轮。

它回答的是**分享层面的「有没有人看」**，不是访问分析：只有次数、最近一次与客户端类别。

## 长什么样

工作台最下面、跑完「最近运行 / 模板库」之后：

- 标题下一行写「共 N 条作品分享过 · M 次打开。点开作品看每一轮。」；
- 每条作品一行：左边作品名 +「分享中 / 已停用 · 几轮链接 · 最近停用时间」，
  右边一个次数 +「次打开 · 最近 X（电脑浏览器 / 手机或平板 / 微信内打开）」；
- 正在分享的那行状态是绿点 +「分享中」；停用的写「已停用」；
- 没有分享过任何链接时是空状态，给一句「在作品页点分享」和回作品列表的按钮。

## 三个实现决定

1. **一条作品一行，累计各轮**。分享次数会随使用增长，按链接摊开就是一张流水账；
   汇总到作品层，行数跟作品数走。每一轮的明细留给作品的分享面板（v0.9.11）。
2. **只列最近活跃的 6 条作品，但总数与总次数按全部算**。工作台是「下一步点哪里」，
   不是报表；页面写「共 N 条作品分享过」，超出 6 条也不会让人以为只有 6 条。
3. **接口只回轮数与统计**：不返回 token、不返回记录键，也不返回每轮明细；
   归属沿用 `listProjects` 的同一套规则，谁能看这条作品，谁就能看它的汇总。
   排序按「最近有人打开」；都没打开过的看最近停用时间。

## 量到的

生产真实作品（「毛衣折叠收纳法」，三轮链接：2 次 + 1 次 + 1 次打开）：

| 读的地方 | 读数 |
| --- | --- |
| `/api/shares` | 1 行：`live: false`、`rounds: 3`、`visits.opens: 4`、`lastClient: desktop` |
| 响应体 | 没有 token、没有 `key`、没有 `shareHistory` |
| 旧地址 | 第三轮停用后 404，次数不再变 |
| 工作台 1440 | 区块 129px 高，行宽 1130px，`scrollWidth == clientWidth` |
| 工作台 390 | 区块 183px 高，行宽 290px，`scrollWidth == clientWidth`，标题右侧「全部作品」不换行 |

## 边界

- **次数不是人数**：和 v0.9.10 同一条线，没有账号就没有身份。
- **只汇总「分享过」的作品**：没开过分享的作品不出现，不用一行「—」占位。
- **删除作品后从汇总消失**：打开记录本身留在 `share-visits.json`，直到 200 条上限。
- **6 行只是显示上限**：总数与总次数按全部作品算；更多作品去作品列表逐个看。
- **明细不在这里**：每一轮的停用时间与打开情况在作品的分享面板里（v0.9.11），
  这里只给累计，避免工作台变成第二张报表。
- **打开记录上限 200 条**：被挤掉的旧轮次不再计入累计，这是记录本身的边界。
