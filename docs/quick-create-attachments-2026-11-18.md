# 快捷创作：脚本、Word、Excel、PDF 直接丢进来（r218 / v0.9.202）

2026-11-18。上一版把回答做成流式，但用户手里最真实的东西——一份口播脚本、一版 Word 的拆解稿、一张 Excel 的复盘表、
一份别人家的 PDF——还是只能自己复制粘贴。这一版把附件接进对话框。

结论：**拖进来的东西先在服务端读成文字，再连同问题一起问模型；读不出来就说清楚为什么，不拿空内容去问。**
解析全在本地做，原文不进聊天记录、不传给上游。

## 一、支持什么、到哪一步为止

| 格式 | 怎么读 | 读不到的 | 上限 |
| --- | --- | --- | --- |
| txt / md / csv / json / 日志 / srt / 常见代码 | 按内容解码（UTF-8 严格解，失败再试 GB18030），二进制内容比例过高就拒 | 编码怪到两种都解不开的文件 | 8 MB / 20000 字 |
| docx | 解 zip 取 `word/document.xml`，段落与换行还原 | 批注、脚注、图片里的字、表格合并细节 | 8 MB / 20000 字 |
| xlsx | 解 zip 取共享字符串 + 第一个工作表，单元格按制表符拼回 | 第二个以后的工作表、公式、格式 | 8 MB / 20000 字 |
| pdf | 解 FlateDecode 内容流，只取文字层（`Tj` / `TJ`） | **扫描件、图片里的字（不做 OCR）**；CID 字体可能读不出 | 8 MB / 20000 字 |

一条消息最多 5 个附件、合计 24000 字，超过部分标记「已截断」；每个账号最多留 20 份，超了顶掉最旧的。
抽出来的文字跟着那条消息一起进上下文，只给最近 6 条留正文——更早的只剩文件名。

## 二、接口

| 方法 / 路径 | 作用 | 关键点 |
| --- | --- | --- |
| `POST /api/chat/files` | 上传一个附件 | 原始字节 body + 文件名的百分号编码走 `x-file-name` header；不解析 multipart。返回 `{id,name,kind,kindLabel,bytes,chars,truncated,note,createdAt}` |
| `GET /api/chat/files` | 我最近传的附件 | 不带正文，只说明「读了什么、多少字」 |
| `GET /api/chat/files/:id` | 读一份的原文 | 归属校验，别人读不到（`FILE_NOT_FOUND`）；界面上点附件名就是它 |
| `DELETE /api/chat/files/:id` | 删一份 | 归属校验 |
| `POST /api/chat/conversations/:id/messages/stream` | 发消息时带 `files: ["cf_…"]` | 附件先解析、再扣费：附件本身不合规一分钱不扣；别人的 / 已删除的附件跳过，并在上下文里写明「这次没带上」 |

失败都是人话，不把二进制错误抛给用户：

| code | 状态 | 用户看到 |
| --- | --- | --- |
| `FILE_TOO_LARGE` | 413 | 「这个文件 9.1 MB，超过 8 MB 上限：先压一下或截取要用的部分」 |
| `FILE_TYPE` | 415 | 「这个文件按内容看不是文字…」 |
| `FILE_PDF_NO_TEXT` | 422 | 「这份 PDF 里没有可读的文字（多半是扫描件或图片导出的）…」 |
| `FILE_NO_TEXT` | 422 | 「这个文件里没有可读的文字…」 |
| `CHAT_FILES` | 400 | 「一条消息最多带 5 个附件」 |

## 三、界面

输入框上排多一个「附件」（虚线胶囊，和其他能力开关同一档）；选完文件后输入框上方出现胶囊，写名字 + 字数，
超上限的标「已截断」。点名字打开「平台读到的到底是什么字」的原文预览——解析错了用户得能自己看见，而不是只能信我们。
发出去以后，用户那条消息下面保留附件胶囊，点开还能回看。

## 五、边界（照实说）

- **没有 OCR**：扫描件 PDF 与图片里的字读不出来，会明确说读不出来。OCR 要调视觉模型（花钱），等用户授权。
- 没有图片理解进对话（传图直接问「这张图怎么样」），也没有语音。
- 表格只读第一个工作表、只取单元格的值；PDF 只读文字层，排版、表格结构不还原。
- 附件原文只在服务端留最近 20 份、只在最近 6 条消息的上下文里保留正文；更早的只剩文件名。
- 上传不经过杀毒；只按内容判断是不是我们认得的格式，不执行任何内容。
- 回答仍是纯文本（无 markdown / 代码高亮）——这是 r217 就写明的既有边界。
