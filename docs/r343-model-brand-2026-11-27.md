## 2. 画质三档：真调上游，按张计费

| 请求 | pattern 里带的 quality | image tokens | 耗时 | 这一次花掉 |
| --- | --- | --- | --- | --- |
| ① 不传 | 无 | 1056 | 23.2 s | ¥0.0157 |
| ② 快速 | `low` | 272 | 20.9 s | ¥0.0157 |
| ③ 标准 | `medium` | 1056 | 31.0 s | ¥0.0157 |
| ④ 高清 | `high` | 4160 | 19.8 s | ¥0.0158 |

四次都 HTTP 200。同批 6 张真图（含一次复跑与第 3 节那次参考图）余额 18.9378 → 18.8433，
即 **¥0.0945 / 6 张 ≈ ¥0.0157 一张**，与档位无关。

结论：

1. **档位真的生效**：image tokens 272 / 1056 / 4160 三档分明，说明上游认 `quality` 这个字段；
2. **默认 == 标准**：不传时是 1056，与 `medium` 完全一致，所以界面写「跟随默认就是标准档」是对的；
3. **现在没有加价的依据**：上游账单按张平铺，三档同价保持不动（用户口径：收到变化再改）；
4. 界面与提示词的措辞照第 3 条事实写：**三档同价，档位越高细节越多、出图越慢**，
   不再写「上游不收就失败」这种猜测句。

## 4. 对话里接着改参数

服务端（`server/chat.mjs` · `server/media-intent.mjs` · `server/chat-store.mjs`）：

* 会话里记下 `lastMediaTask`（最近一次生成）与 `mediaDefaults`（用户选过的档）；
* 只改参数的那一句（「改成 16:9」「换成 8 秒」「改成高清」）走 `parseParamChange`，
  **不带生成动词也能认**，且不再走文本模型——不额外扣对话那 1 积分；
* 认出来之后 = 用新参数**重放上一条任务**（复用同一张参考图，文件还在才算）；
  没有上一条、或与上一条能力不匹配 → 只记设置、不开任务，回答说清为什么；
  新值与旧值相同 → 不重跑、不二次扣费；
* 普通聊天句里出现参数词（「我把标题改成 16:9」）不会误触发：需要明确的改动语气。

新增 `test/r343-chat-params.test.mjs` **16 条**，四条反证（改坏即红）：

| 反证 | 改坏哪一行 | 结果 |
| --- | --- | --- |
| A | `parseParamChange` 直接 `return null` | 9 条红 |
| B | `if (explicit[key])` → `if (false && explicit[key])` | 3 条红 |
| C | `if (!previous || incompatible.length)` → `if (!previous)` | 3 条红 |
| D | `recentMediaTask` 不看 6 条消息窗口 | 1 条红 |

已知边界（照实写）：认不出的说法包括「我要 16:9 的封面」（数值后面跟名词）、尺寸 / 4K、
中文数字「改成八秒」、纯下拉选一下不说话；「上一条」只指这条对话里最近 6 条消息内的那次生成；
重放要求参考图文件还在，不在就先报错、不扣费。

### 5.3 接口里的模型 id（这一轮新补）

界面干净不等于用户看不到：`/api/models` 早先直接把配置里的原名（`deepseek-flash` 这类）当 id 发出去，
被问的、以及顺手打开 DevTools 的用户都看得见。现在改成**产品 id**，并在服务端做一次双向映射：

* 清单口径：同一类里第一个是 `visionqa-chat` / `visionqa-vision` / `visionqa-general`，
  第二个起加序号（`-2`、`-3`），与画布媒体模型沿用同一套 `visionqa-` 习惯；
* `publicModelName(内部名)` → 产品 id，`internalModelName(产品 id 或旧内部名)` → 内部名，
  认不出来原样返回（老偏好、老智能体记录里存的内部名不能因为改名就失效）；
* 出口统一过一遍：`/api/models` 的 `id / current / textModel / visionModel`、
  `/api/preferences` 的读写、`/api/agents` 的清单 / 单个 / 历史 / 回复里的 `model`、`attempted`、`lastModel`、
  `/api/local-agent/meta` 与 `/complete`；
* 入口也统一：凡是用户回传模型的地方（偏好、智能体创建 / 修改、对话）都先换回内部名再往下走，
  所以**对外改名没有改坏路由**。

新增 `test/r343-model-alias.test.mjs` **4 条**：清单无厂牌无内部型号（连 `current` 一起查）、
双向映射与旧数据兼容、同类多模型的 `-2` 编号不重复、偏好接口对内部名直接 400。
