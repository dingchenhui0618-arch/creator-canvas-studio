# 工作流在手机上是「按执行顺序的步骤清单」（r227 / v0.9.211）

## 结论

390 宽原来摆着一块 272×309 的画布：空状态（标题 + 两行说明 + 三个按钮 + 一句备注）比容器还高，
直接压在缩放按钮和底部连线提示上，文字互相盖住；节点面板一打开更糟——≤1024 的「1fr + 272px」
两列还在生效，清单/画布那一列只剩 **2px** 宽，整块看不见。现在 ≤760 不再画那块缩水画布，
改成**按执行顺序排的步骤清单**：几步、每步做什么、依赖第几步，一眼看得清；点一行就选中它，
下面的「节点检查器」照旧改参数。桌面（>760）画布完全没动。

## 三处问题与改法

| 现象（390 实测） | 根因 | 改法 |
| --- | --- | --- |
| 空状态文字压在「0 节点 · 0 连线」「+ 节点」和缩放按钮上，底部连线提示也被盖住 | `.cv-overlay` 绝对定位居中、内容比 309px 的容器高，没有裁剪也没有滚动 | ≤760 不渲染画布，改成步骤清单（画布连它的空状态、缩放手柄一起不出现） |
| 打开节点面板后清单只剩 2px 宽、整页 2955px，一大片空白 | `@media (max-width:1024px)` 里 `.cv-workspace:has(.cv-palette)` 仍是「1fr + 272px」两列，扣掉 272px 右栏后只剩 2px | ≤760 覆写为单列三行：面板 / 清单 / 检查器（73 / 544 / 420），整页 2955 → 1556 |
| 320 宽整页被撑到 367px（横向拖） | 积分预估那行是 `white-space: nowrap` 的等宽字，274px + 68 侧栏 + 48 内边距 | ≤760 允许折行（`max-width: 100%` + `overflow-wrap: anywhere`），320 下 innerWidth = clientWidth = scrollWidth = 320 |

顺带两处：

- **画布专属工具在手机上收起**（自动布局 / 适应工作流 / 缩放百分比）。画布都不显示了，
  留着只会让人以为能对着看不见的东西布局；节点数、连线数、加节点、撤销/重做照旧留着。
- **流程名不再被切**：28px 的字 12 个字要 336px，390 宽只剩 272、768 宽只剩 276，名字被切成「一条内…」。
  ≤900 降到 22px + 省略号，两档宽度都能读到全名。

## 边界

- 步骤顺序用与服务端 `topoSort` 同一套 Kahn 拓扑排序；**真跑的时候仍以服务端为准**。
  有环时按原顺序列出并标「这条流程有环，跑不起来」，不假装顺序正常。
- 手机上只能加节点、改参数、运行；**连线和位置仍然要在电脑上摆**——清单底部写明了这一点。
  新增的节点在清单里没有「依赖第 N 步」，就是一条独立起点，和服务端执行口径一致。
- 清单只显示标题、类型、模型显示名、比例/时长/分辨率与依赖步号；提示词等细节在下面的检查器里看。
- ≤760 换清单，768 及以上仍是画布（平板上一块 700px 宽的画布还能用），两档之间没有别的分支。
- 本轮的截图来自本机临时实例（临时 `DATA_DIR` + 内置假流程），不是生产数据。
