# 生成记录能删了（r282 / v0.9.264，2026-11-20）

## 为什么这一轮做删除

截图里那 6 条真实数据里有 4 条是失败任务。失败任务不进作品流（作品流只列成功产出），
但它们一直躺在「最近生成」里，**没有任何出口**：

- 生成 20 次、失败 12 次，左栏就是 12 条「失败 · 已退 5 积分」，把成功的那几条挤到看不见的地方；
- 每一条成功任务的结果文件都还留在磁盘上（图片 1～3 MB、视频 2～3 MB），删不掉也用不上；
- 作品流那边同理：能搜（r281）了，但删掉不要的成品只能绕去作品项目页，图片/视频根本删不了。

这一轮给「最近生成」和作品流补上同一条出口，**只做一件事，把边界写死**。

## 规则（四条，都写进代码与界面）

| 问题 | 结论 |
| --- | --- |
| 能删什么 | 只删「快捷创作」生成的图与视频（一条生成任务 = 元数据 + 结果文件） |
| 怎么删 | 点两下：第一下按钮变成红框「确认删掉」，第二下才真删（不可逆的动作不该一下点掉） |
| 删完怎样 | 记录与文件一起消失；它同时从「最近生成」与作品流里消失；已用掉的积分**不退**（删除不是「这单不算」） |
| 不能删什么 | 还在生成（processing）的服务端 409 拒；别人的 403；没登录 401；只删下载地址 405；工作流运行与无限画布不出删除按钮（它们属于各自应用） |

服务端只新增一个 DELETE /api/media/tasks/:id，其余全部复用既有实现：

- 归属判断与读任务走同一段（userId 不一致 403，不猜）；
- 释放的字节数是真实 stat 出来的（文件本来就不在就回 0，不编数字）；
- 删掉之后再读是 404 MEDIA_TASK_NOT_FOUND，再删一次也是 404（不是 200）；
- 记一条操作日志 media.task.delete（谁、哪条、什么类型、释放多少字节）。

## 界面上改了哪几处

1. **快捷创作 → 最近生成**每一行多一枚「删掉」（.agx-media-recent-del）：平时最淡，
   上膛后变 --danger 红框「确认删掉」；processing 那条按钮直接禁用，title 写「还在生成：等它跑完再删」。
   删完右栏如果正挂着这条，一起收掉；浮层正看着它也一起关掉。
2. **作品流 → 看大图浮层**多一枚「删掉这条」：只在浮层里给，卡片上不给——
   卡片上已经有「用作参考 / 下载 / 去出处」三枚，390 上只有 139px 宽；
   删除又是唯一不可逆的动作，放在「先看清这张、再说删不删」的那一屏最合适。
3. 删完**整页重取一次**列表：被删的那条很可能正是翻页游标（服务端按位置取，游标没了这一页就会是空的），
   与其留一个对不上的位置，不如从最近一页重排，并在行上写明「已删掉这条作品，释放 N KB」。
4. **≤560 那一排小动作抬到 32px**：「用作参考 / 下载 / 删掉」原来都是 24px 高，
   手机上是手指点的，这次跟着新按钮一起抬（和 r203 补过的那批一个标准）。

| 检查 | 结果 |

## 边界

- 删了找不回来：没有回收站、没有撤销（删除的是任务与文件本身，不是「藏起来」）；
- **不退积分**：那次生成已经花掉了，删记录不等于退款——界面与 title 都这么写；
- 参考素材是独立副本：把某条成品「用作参考」时传的是另一份文件，删任务不会连带删掉素材；
- 工作流运行与无限画布没有删除入口：那些记录属于各自应用，作品流只删自己真正拥有的那部分；
- 磁盘占用没有自动清理：这一轮只给出口，不替用户做决定（每个账号 60 个素材的上限仍在素材那边）；
- 本轮 0 次真实上游调用、0 费用。
