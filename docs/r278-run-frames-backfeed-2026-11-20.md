# 跑完工作流画的那 8 张，一键贴回分镜（r278 / v0.9.260，2026-11-20）

## 为什么修这一步

r277 让「开工作流」按分镜给每一镜建出图节点，跑一次能得到「复刻脚本 + 每镜一张画面」。
但跑完就断在这里：8 张图落在 `runs/<runId>/` 里，只有运行记录和运行抽屉看得到；
作品页的分镜还是「原片帧」。想把这 8 张变成「这一镜我打算这么拍」，只能一镜一镜点「贴画面」——
8 镜就是 8 次上传，等于把刚跑的那一次白跑了。

这一步补上，创作闭环（发现 → 复刻 → 模板 → 作品 → 画布 → 评审 → 交付）里
「画布 → 作品」那条虚线才真正连起来。

## 现在怎么用

两处入口，指向同一次运行：

1. **运行记录那一行**：「画了 8 张」旁边多一个「贴回分镜」。只有这次运行真的按分镜画成了图才出现。
2. **分镜面板上面一句**：「运行 run_xxx 按分镜画了 8 张，[贴回分镜]」。
   已经贴过这次运行的镜就不再提示——提示永远指向「还差这一步」的那一次。

一次请求贴完整批，不叫页面发 8 次。

## 规则

| 规则 | 做法 | 不满足时 |
| --- | --- | --- |
| 镜号从哪来 | 只认开工作流时按分镜建的节点 id `n_shot_NN` | 用户自己拉的出图节点没有镜号，不往分镜上硬塞 |
| 只贴画成的 | 只认 `status === 'success'` 且真有落盘路径的节点 | 跳过 / 失败的镜保持原样，它们的原因已经在运行记录里 |
| 镜号要在分镜里 | 第 4 镜的节点遇到 3 镜的模板不进 | 超出的一律忽略 |
| 同一镜重复 | 用户复制了节点：只算第一次 | 后一张不悄悄顶掉前一张 |
| 重贴同一次运行 | 已经记着 `from === runId` 的镜直接跳过，不复制第二份 | 提示「这 8 镜已经是这次运行画的图了，没有重复贴」 |
| 原来有画面 | 换掉，并说清换了几镜 | toast 里写「其中 N 镜原来有画面，换掉了」 |
| 归属 | 作品是我的 + 这次运行是我的 + 这次运行确实是这条作品的工作流跑出来的 | 404 / 409，各一句人话 |
| 图存哪 | 先复制成自己的上传素材（`uploads/<账号>/`）再记到作品上 | 运行目录是将来的清理对象，分镜上的画面不能跟着消失 |

## 顺手修掉的两个真问题

1. **「用回原片」以前点了会报错**。`shotFrameBlock` 把空 media 也当成「不是你的图」挡成 400，
   所以撤销入口一直在弹「画面要用自己上传的图」。现在传空 = 撤销（镜头号与分镜范围仍然核）。
   证据：本轮第一次用 HTTP 清分镜时拿到的就是 `400 MEDIA_INVALID`。
2. **运行行只写「2 积分」**，出图那 40 积分不显示——余额少了 42，页面上对不上账。
   现在那行写「2 积分 + 出图 40 积分 画了 8 张」。

## 边界

- **贴回也占上传额度**：每个账号 20 张 / 160 MB，超出会顶掉最早上传的那些图（包括别的作品的画面）。
  一条 8 镜作品贴两次就占 16 张。下一轮候选：给分镜画面单独一块存储，不挤上传额度。
- **字节是两份**：`runs/<runId>/` 和 `uploads/<账号>/` 各存一份，换来的是运行目录被清掉时分镜不受影响。
- **只贴分镜出图节点**：模板库「套用模板」那条路开出来的工作流仍是两个节点，没有可贴的图。
- **不改分镜本身**：贴的是「这一镜的画面」，模板与分镜文字一个字不动；要改分镜仍走模板改编。
- 本轮 0 次真实上游调用、0 费用。

## 踩坑

1. Chrome 在 `Emulation.setDeviceMetricsOverride` 下，页面滚动偏移不会反映到 `Page.captureScreenshot`——
   390 的截图永远停在页首。真窗口会被 Chrome 钳到最小 500 宽，所以窄屏那张用真窗口（500）、
   390 这一档用测量数字，别拿「截不到的图」当证据。
2. 只改 hash 不会重新加载页面：先种 cookie 再 `Page.navigate` 到 `#/projects/<id>`，登录态还是上一次判的，
   必须再 `Page.reload` 一次（或者直接用 `Network.setCookies` 在首屏之前种好）。
3. 上手引导遮罩会盖住整页，截图前先写 `vq_welcome_seen:<账号 id>`。
4. 页面真正的滚动容器是 `.vq-content`（桌面），窄屏下变成文档本身：滚动要两条都试，
   滚完以「元素真的进了视口」为准。
5. `Page.reload` / 跳转进行中发来的 `Runtime.evaluate` 会报 `Inspected target navigated or closed`，
   当成「再试一次」处理，别让一次等待失败把整趟验证打断。
