# 运行记录页窄屏：小字 13px、点按区 40/44px（r240 / v0.9.224）

2026-11-19。第 22 条 UX 清单项。上一轮（r239）把视觉评审从 22 处小字清到 0，
运行记录是清单里剩得不多的几页之一：390 宽 50 处 12px 的字、12 处不到 40px 的点按区，
768 / 1024 各 62 / 12。这一页还带着三处**在 320 上真坏掉**的布局，一并修了。

## 结论

| 宽度 | 页面（14 条运行 + 一条详情） | 运行对照弹层 | 页面高度 |
| --- | --- | --- | --- |
| 320 | 50/12 → **0/0** | 64/15 → **0/0** | 4243 → 3974 |
| 390 | 50/12 → **0/0** | 64/15 → **0/0** | 3027 → 3489 |
| 768 | 62/12 → **0/0** | 76/15 → **0/0** | 2580 → 2660 |
| 1024 | 62/12 → **0/0** | 76/15 → **0/0** | 900（外壳内部滚动，同改前） |
| 1440（不动） | 69/29 → **69/29** | 107/33 → **107/33** | 900 → 900 |

「50/12」= 小于 13px 的文字 / 不到 40px 的点按区。弹层那一列是整页连弹层一起量的（改前弹层里的小字原本就 ≥13px，
64 / 76 全是页面自己的，所以这一列主要看那 15 → 0 个点按区）。1440 是逐元素比对：
两次量的选择器、字号与宽高完全一致，只有侧栏的版本号从 v0.9.223 变成 v0.9.224。

390 变高 462px 是抬字号与「每行状态挪到第二行」的代价，换来的是标题和「作品 · 第几版」不再被右侧 70px 窄列挤成两段；
320 反而变矮 269px——输出的「字段 → 值」从塌成竖排单字的两列改成上下两行，值不再一个字占一行。

## 改了什么

主体做法与 r239 一致：**在 `.runs-page` 上把 shell 的原子档位抬一档**（这一页的字与按钮几乎全走
`.vq-mono` / `.vq-button--sm` / `.vq-select`），规则只写进 `src/styles/runs.css` 末尾三段媒体查询。

| 位置 | 改前 | 改后（≤1080 / ≤700 / ≤560） |
| --- | --- | --- |
| 统计条标签（总运行 / 本页成功 / 当前区间 …） | 12px | **13px** |
| 筛选标签（流程 / 状态） | 12px | **13px** |
| 筛选下拉里的选中值 | 12px（被标签样式打中） | **13px** |
| 行里的状态、耗时、时间（`.vq-mono`） | 12px | **13px** |
| 详情头的扣费 / 续跑信息（`.vq-mono`） | 12px | **13px** |
| 输出字段名（topic / product / hits …） | 12px | **13px** |
| 「原始返回」里的 JSON 与节点纯文本输出 | 12px | **13px** |
| 归到作品的标签、续跑预检的标签 | 12px | **13px** |
| 刷新 / 回作品 / 对照 / 查看这次运行 / 在工作流打开 / 翻页 | 28px | **40 / 44px** |
| 搜索框 | 34px（输入框 32） | **40 / 44px**（输入框跟着 40 / 44） |
| 「原始返回」折叠开关 | 27px | **40 / 44px** |
| 运行对照弹层的关闭按钮（390 被挤成 39px 宽） | 39×44 | **40×40 / 44×44，不参与收缩** |
| 运行对照弹层的「看改了哪几行」 | 24px | **40 / 44px** |

三处 320 上的真坏：

| 问题 | 原因 | 改法 |
| --- | --- | --- |
| 输出的「字段 → 值」塌成「一个字一行」 | 两列 `minmax(88px, 140px) + 1fr`，320 上键列吃掉 140px，值只剩 32px | ≤560 改单列，键在上、值在下 |
| 翻页的「1–12 / 14」折成四行 | `.vq-mono` 允许换行，320 放不下 | 区间一行、两个按钮一行各占一半，区间 `white-space: nowrap` |
| 每行右侧 70px 窄列把标题与版次挤成两段 | `grid-template-columns: 8px 1fr auto` | ≤700 状态/耗时/时间挪到第二行，标题拿到整行 |

另外补了一处**交互**：窄屏（≤1100）列表与详情是上下排的，详情落在整张清单下面。
以前点一行只有行变色，人在手机上以为没反应；现在点完把详情滚到眼前（`prefers-reduced-motion` 时不滚、直接跳），
桌面两栏并排不滚。实测 390：点第 6 条后 `window.scrollY` 0 → 2071、详情顶部 2071 → 0；
1440：点第 6 条后 `scrollTop` 仍 0、详情位置不动。

## 边界

1. 只量 Chromium（Edge 157）无头、1x；没在真机触屏、Safari、Firefox 上验证。
2. 量了 320 / 390 / 768 / 1024 / 1440；561–767、769–1079 没逐档量（规则按 1080 / 700 / 560 三个断点统一）。
3. 空态（还没有运行记录）、归到作品面板（`.runs-adopt` 展开态）、续跑预检的 loading / error 两种状态没截图：
   这些类的字号与按钮在规则里一并抬了，但没有界面证据，只有样式与单测；截图里只碰到续跑预检的 is-blocked 态。
4. 运行对照弹层（`.rc-*`）是运行记录页与工作流页**两处共用**的，改的是它自己文件末尾的窄屏段；
   工作流页开这个弹层时也跟着变好，但工作流页本轮没复量。
5. 只取点按区「宽或高 < 40px」这一条判据；点按区之间是否互相遮挡、是否在滚动容器外，本轮没做几何检测。
6. 截图里的作品名、运行 id、耗时、积分都是样例数据，不是生产账号的真实运行记录。
7. 本轮 0 次真实上游调用：没有出图、没有出视频、没有跑工作流（14 条运行记录是直接写的 `runs.json`）。
8. 详情「滚到眼前」只在「点行」这一处触发；翻页、筛选、刷新会把选中项重置回第一条，但不滚——那是换了一页内容，不是点了一条。
