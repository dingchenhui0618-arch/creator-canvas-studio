# 回退版记得自己从哪来，改动按底座算（v0.9.116，2026-11-14）

## 结论

v0.9.115 已经能「以旧版为底再开一版」。但那一版开出来之后，只有 toast 和画布名记得它从 v1 回来；刷新页面，版本行仍写「比 v3 画布改 1 个、脚本少 2 段」——看起来像一次有意的删改，而不是一次回到旧版。  
这一轮把来源写进数据，也让那一行的改动句改按底座算：**v4 从 v1 回来，就标「以 v1 为底」，并与 v1 对账**；再开 v5 之后，v4 归档了，来源仍跟着它走，v5 不继承。

## 为什么现在做

上一轮把「回得去」做出来了，但回退之后的现场仍可能被误读：

- 页面刷新，toast 没了，当前行只剩作品名；v4 究竟是从 v3 继续改，还是从 v1 回来的，看不出来。
- v4 是照 v1 复制的，相对 v3 当然「少 2 段脚本」。这行字没有错，但它回答的是「相对上一版」，不是用户此刻最想确认的「相对底座有没有改坏」。
- 再开一版之后，v4 归档；如果来源不跟着归档，连这一条线索也断了。

所以这一轮不是再加一个版本动作，而是把回退后的**对账基准**说清楚。

## 做了什么

### 1. 存储层：来源跟着版本走

- 作品新增可选字段 `basedOn`：当前这一版是从哪一版复制来的。`0` 表示正常接上一版，不是回退。
- 归档版本条目同样带 `basedOn`：开新版时，先把当前版的来源一起归档，再写新一版的来源。
- 正常开新版把 `basedOn` 归零；只有「以旧版为底」才写那一版的版次。
- 盘上的老数据没有这个字段：归一化时按 `0` 处理，不报错、不改变原有版本与脚本。

### 2. 接口：相邻口径不动，另给一份底座对账

- `versionChanges` 保持原样，仍然算「比上一版」。这是为了不破坏 v0.9.115 的前端：旧前端拿到的仍是它认识的标签与句子。
- 新增 `versionBaseChanges`：只给「底座不是上一版」的版本，值形如 `{ base: 1, text: "画布与脚本都没动" }`。
- 当前版读 `project.basedOn`，归档版读条目自己的 `basedOn`；底座版被删或已不在表里时不给这一项，页面回退到「比上一版」，不硬编一个查不到的基准。
- 底座就是上一版时不重复给：原来的相邻比较已经说对了。

### 3. 作品页：一枚来源胶囊，一句按底座算的改动

- 版本行元信息多一枚描边胶囊「以 v1 为底」，当前行与归档行都显示；它回答来路，不是状态，所以不用实心色，也不与交付/评审胶囊混在一起。
- 有底座对账时，改动句的标签从「比 v3」换成「比 v1」，文字用 `versionBaseChanges`；没有时完全维持原样。
- 390 宽下版本标题会被省略号截断，来源胶囊保持整枚可见；标题里的「· 以 v1 为底」被截掉也不影响识别。

### 4. 不做什么

- 不删除、不重排、不覆盖任何版本。
- 不回退评审、运行、交付记录：仍按各自版次保存。
- 不做任意两版的自由对照：这一轮只把「与底座」这一条最容易被误读的比较做准。
- 不改变「开一版新的」与「以这一版为底」的请求格式，旧前端不传 `from` 时行为与 v0.9.115 一致。

## 八条坑

1. **别改 `versionChanges` 的语义**：旧前端行标签固定写「比 v{n-1}」。把服务端句子悄悄改成对底座，旧页面会显示「比 v3 画布与脚本都没动」——比原来更错。新增 `versionBaseChanges`，新旧各读各的。
2. **底座就是上一版时不要重复给**：否则同一句话有两份来源，页面还要判断听谁。`versionBaseChangesOf` 直接跳过 `base === n - 1`。
3. **来源要跟着归档走**：归档当前版时把 `current.basedOn` 写进条目，新一版再写自己的来源；只写当前版，v4 归档后线索就断了。
4. **普通开版必须归零**：v5 接着 v4 改，不是「从 v1 回来」；继承上一版的 `basedOn` 会让 v5 也标错来源。
5. **底座要更早且存在**：归一化只认 `1..version-1`；开版时再确认那一版还在归档里。无效来源宁可当 0，也不让页面显示一个查不到的底座。
6. **当前行与归档行读不同字段**：当前行读 `project.basedOn`，归档行读条目自己的 `basedOn`；只读一边，刷新或归档后就会丢。
7. **改完注释要重跑测试**：整理重复注释时误删了 `const currentScript`，本地目标测试在改动之前跑过，没发现；CI 的 Node 22 / Node 24 全量测试抓到 14 条详情用例 `currentScript is not defined`。修复后才全绿。任何一次手改之后都要重跑，不能拿上一次结果交差。
8. **窄屏标题会截断，来源胶囊不能跟着截**：390 下 v4 的画布名被省略号截掉，胶囊要 `white-space: nowrap` 并保持在行内；两个动作仍按整组换行，断言左右缘不超出行。

## 发现但没做

- 不做任意两版自由对照：目前只把「当前版 / 归档版」与自己的底座比；想看 v1 与 v3，仍只能看各自的相邻句或旧版脚本弹窗。
- 不删除、不重排版本；20 版上限到了仍只能交付后开新作品。
- 不回退评审、运行、交付记录。
- 不支持跨作品以旧版为底。
- 只允许从有脚本快照的版本回退；更早的无快照版本只能打开画布手动改。
- 生产没有登录账号做真实回退与真实详情读取；生产证据只有版本、资源、401 与文件哈希，功能证据来自本地真浏览器 + 本地服务。
- 没有在真实模板 / 真实运行上验证。

## 回退

~~~bash
bash /opt/visionqa/ops/rollback.sh --to 1   # 回到 v0.9.115
bash /opt/visionqa/ops/rollback.sh --to 2   # 回到 v0.9.114
~~~

这一版只新增可选字段 `basedOn` 与只读响应 `versionBaseChanges`，不改已有字段含义；旧前端忽略新字段，回退后版本、脚本、评审、运行、交付都不受影响。注意：回退到 v0.9.115 后，如果旧代码再写作品索引，它不认识 `basedOn`，这个来源字段会丢失；丢的只是来源标记，画布与脚本快照都还在。
