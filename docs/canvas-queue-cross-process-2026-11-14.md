# 画布出图的排队位进共享目录：两个实例排同一条队（v0.9.93，2026-11-14）

## 结论

生产的画布出图有两道闸：**名额**（整机 2 条）和**排队位**（最多 8 条在等）。名额从 v0.9.78 起就是
两个实例共用一份租约，排队位却一直活在各进程自己的内存里——于是同一台机器上有两条互不知情的队：

- 「最多 8 条同时排」实际是每进程 8 条，两个实例叠起来最多 16 条连接压在这台 2 核机子上；
- 画布状态条上「在跑 2 · 排队 4」里的 4 只算当前实例的，另一个实例的 4 条它看不见；
- 空位一出现，谁先醒谁拿走：8799 上排着的七张，会被 8800 上后来的一张抢先（先来先得在跨进程时不成立）。

v0.9.93 把排队位搬进名额用的那个共享目录，两个实例排的是同一条队：**waiting / 名次 / maxWaiting
全部是整机口径**，名次按整机入场顺序，只有队首才去试名额。降级路径照旧：目录用不了就退回进程内，
并把 `queueScope` 如实报成 `process`。

## 现状（v0.9.83 留下的两处口径不一致）

| | 名额（heavy-lease，v0.9.78 起） | 排队位（v0.9.80 起） |
| --- | --- | --- |
| 存在哪 | 共享目录里的租约文件 | 进程内的 `Map` |
| 两个实例看到的是 | 同一个数 | 各一份 |
| maxWaiting 8 条的含义 | — | 每进程 8 条（实际最多 16） |
| 「我排第几」 | — | 只在当前实例内成立 |

名额本身没问题，问题出在**排队位与名额不是同一个口径**：名额告诉我「现在满了」，排队位却告诉我
「前面只有 2 张」——这个 2 是错的。

## 做法

### 1. 一条 waiter = 共享目录里的一个文件（`server/wait-queue.mjs`）

```
<租约目录>/waiters/<票号哈希16>-<pid>-<入场时间36>.wait
```

文件内容只有 `{ kind, pid, enteredAt, host, v }`：

- **不放票号**：票号是「查自己排第几」的凭据，而共享目录是全机器可读的；文件名里只出现
  `sha256(票号)` 的前 16 位，查一条按哈希找文件，不需要明文。
- **不放任务内容**：这里只数「谁在等」，不记 prompt、不记账号。

### 2. 与名额共用一把跨进程锁（`withLeaseDirLock`）

`heavy-lease.mjs` 原来只给「数名额 + 占名额」提供临界区，现在把同一个 `mkdir` 锁开放出来：

- **登记**在锁里做：先列出「现在几条在等」，再决定「让不让进、进的话排第几」。两个实例不会各自
  把「第 8 条」再放一条进来——这正是 `maxWaiting` 该挡住的事。
- **读**（快照 / 名次 / 前面还有几条）不加锁：等待循环每 350 毫秒读一次，抢锁会把闸门变成串行。
- **心跳**只 `utimes` 自己那个文件，也不抢锁。

### 3. 先来先得跨进程成立

`admitWaiting` 的顺序从「先试名额、满了再排队」改成「**先登记、再试名额**」：

```
登记 → 我是队首吗？不是 → 让出去（记 yielded，不写响应、不碰名额）
              └── 是 → try admit → 成了就出图；没成继续排
```

第一版写的是「先 admit，拿到名额就不排了」，本地对照一看就露馅：**空位一出现，后来者只要那一刻
先醒过来就能插队**——先来先得只在单进程内成立。改完之后 8799 上排着的七张会先把空位用完，
8800 上后来的一张只能排到第 8 位。

「让出去」记在 `yielded` 上，**不是拒绝**：它说明先来先得真的在生效，和「排满拒」是两回事。

### 4. 死掉的头名不能把整条队堵住

- 进程被 SIGKILL：靠 `pidAlive` 立刻清掉（不用等超时）；
- 进程还在、但等待循环不在了（长同步任务 / 卡死）：文件 4 秒没被心跳摸过就当泄漏清掉
  （等待 tick 是 350 毫秒，留了十倍余量）。

### 5. 报告把两层口径分开写

| 字段 | 口径 |
| --- | --- |
| `waiting` / `oldestWaitMs` / `queue[]` | 整机（共享目录），`scope: "lease"` |
| `entered` / `served` / `timedOut` / `full` / `abandoned` / `yielded` / `maxWaitMs` | 本进程，`countsScope: "process"` |

后台「运行水位」卡多一块 `queueRegistry`（目录、文件数、清理计数），排障时先看它：
「为什么看到 0 条」要么是目录没写成（`dirFail`），要么是清理把死 waiter 清掉了（`prunedDead`）。

## 证据

### A. 本地两实例对照（真实 HTTP，零付费假上游）

同一台机器起两个完整实例（同一份共享目录、各自 DATA_DIR），假上游 1200 毫秒回一张图，
名额 2 条、排队位 4 条、7 张图（A 4 张 + B 2 张 + 后补 1 张）。旧代码那一臂是
`git archive HEAD` 出来的 v0.9.92 源码，跑在同一套脚本上。

| 观察点 | 旧（v0.9.92，8795/8796） | 新（v0.9.93，8797/8798） |
| --- | --- | --- |
| 同一刻 A 报「几条在等」 | 3 | 4 |
| 同一刻 B 报「几条在等」 | 2 | 4 |
| 10 次采样两边是否一致 | 不一致（3/2、1/2、0/2…） | **逐次一致**（4/4、3/3、2/2） |
| 第 6 张（A 的第 4 张） | 200，排 A 的第 3 位，最后出了图 | **503 `SERVER_BUSY` / `queueFull` / `queueWaiting: 4`** |
| 上游被调用 | 7 次 | 6 次 |
| 上游并发峰值 | 2 | 2 |
| `queueScope` | `process` | `lease` |
| 共享目录里留下什么 | `waiters/` 不存在（队列在内存里） | 跑完只剩空的 `waiters/` |

旧代码那一臂里，A 上面的请求排第 1/2/3 位、B 上面的排第 1/2 位——**两套名次，同一条机器**。
新代码里第 6 张被拒时整机确实已经有 4 条在等（A 2 条 + B 2 条），而按每进程算 A 只有 2 条，
所以旧代码把它放了进来。被拒这一条**一次都没有碰上游**（上游计数 6 = 放行 6）。

## 坑

1. **PowerShell 把二进制管道当文本**：`git archive HEAD | tar -x` 出来的包直接坏（`bad header checksum`
   重试几百次）。改成 `git archive -o x.tar` 落盘再 `tar -xf`。
2. **对照脚本把自己的旧代码目录删了**：`BASE` 用 `r103-<label>`，而旧代码树也想叫 `r103-old`——
   脚本开头一句 `rm -rf BASE` 就把它清了。旧代码树改名 `r103-oldcode`，两边不再撞。
3. **旧代码树少了 `package.json` 起不来**：`server/index.mjs` 要读版本号，`git archive` 只导了
   `server/`，报 `ENOENT .../package.json`。补一份进去才跑起来。
4. **第一次改成「先登记」时忘了第一次尝试**：只把 gate 写进了循环里，`admitWaiting` 开头那次
   `admit` 仍然可以先抢名额——本地 FIFO 用例直接抓到（让出去 0 次、名额被占）。
5. **只读快照不能抢锁**：排队环每 350 毫秒读一次，8 条在等就是 20+ 次/秒；一开始读也加锁，
   把闸门变成了串行。现在只有登记加锁，读与心跳不加锁（删文件是幂等的）。
6. **票号不能明文落盘**：共享目录是全机器可读的（0777），票号是查自己名次的凭据，只存哈希。
7. **心跳窗口别贴太紧**：4 秒过期 / 350 毫秒一次心跳，中间还有抖动最多 120 毫秒；写窄了会误清活着的 waiter。
8. **oxlint 连 catch 参数未使用也算一条**：`catch (error) {}` → `catch {}`，否则 warning 从 15 变 16。

## 发现但没做

- **仍只跨进程，不跨机器**：共享目录是本地 tmpfs/磁盘，多机部署要另外的协调者（和租约一样）。
- **先来先得是「轮询 + 队首才许试」，不是令牌传递**：公平性够用（队首优先），但排到之后仍可能因为
  对方恰好在这一刻拿到名额而多等一个 tick；要做到严格，得给队首发令牌。
- **排队时长没有 SLO 告警**：只有 `maxWaitMs` 计数，没有「排队超过 60 秒」这种告警。
- **封面抓取缓存（cover-cache）还是进程内两份**：同一类问题，这次没一起搬。
- **画布状态条那句「（整机）」**：代码本来就是按 `queueScope` 渲染的，这一版它自动从「按进程算」
  变成「整机」，版式没动、不需要重新截图。
