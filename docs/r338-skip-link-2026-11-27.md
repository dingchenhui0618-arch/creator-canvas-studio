# 键盘那一层：把「量不到」的两处补成真读数，并给键盘用户一个「跳到主要内容」（r338 / v0.9.311）

日期：2026-11-27。用户这一轮的原话还是那句——「我主要是在一些小的细枝末节上」。
接着 r336（键盘焦点那一层）往下做：**那一层里唯一没读到的东西，这次读到了；读到的过程里，
量具自己错了三处。**

## 一、结论

1. **r336 留下的那条异常不是页面的问题，是量具的**：后台「系统」那一屏量到「84 个可 Tab 元素、0 站」，
   真因是**页面那一刻没有系统焦点**（`document.hasFocus() === false`）——CDP 发出去的 Tab 被丢掉，
   `document.activeElement` 一直是 body。补上「走查前先确认页面拿得到焦点」之后：**0 站 → 55 站**，
   55 站全部有可见焦点环、0 黑洞、0 硬切。
2. **同一条原因还让两屏少读了一大截**：同一站连着出现时，第一版当成「绕回开头」收工——
   `模板库·详情抽屉` 12 站、`智能体·对话预设` 14 站。加上「先原地再读一次 + 补焦点重按（最多两次）」
   之后：**12 → 39 站、14 → 37 站**，两屏都是真的绕回（抽屉与预设面板把键盘兜在里面）。
3. 走查总数：**307 站 → 412 站**（r336 → r338，同一批 11 屏、同一份产物），黑洞 0、焦点硬切 0、
   :focus-visible 没匹配 0、读不到 0。
4. **补了一个真的入口**：这个站的外壳（侧栏 + 顶栏 + 页头）在正文之前有 **45 个可 Tab 的目标**，
   键盘用户每翻一页都要先按二十几下 Tab。新增「跳到主要内容」——平时收成 1×1、拿到焦点才现身，
   回车把焦点送到正文（`#vq-main`）。加完之后：**423 站**（每屏 +1），仍 0 黑洞 / 0 硬切。
5. 边界（不假装查清）：后台那一屏按选择器数出 **85 个**可 Tab 元素，走查 **56 站**后停住；
   补焦点、重按、直接聚焦第 57 个元素再按 Tab 都不动。disabled fieldset / details 折叠 /
   content-visibility / inert / aria-hidden / offsetParent 逐个查过，**都不是原因**。
   如实记成边界，不写成「没问题」，也不据一条没查清的现象去改页面。

## 三、量具自己错了三处（都记在脚本头部第 11 条）

1. **页面拿不到系统焦点时，Tab 会被丢掉**。`Emulation.setFocusEmulationEnabled` 会被导航清掉；
   没有焦点时 CDP 的 Tab 直接没有下文，读数与「这一屏没有可 Tab 的东西」一模一样。
   现在：每一趟之前 `ensurePageFocus()`（Page.bringToFront + 重开焦点模拟 + **真读 hasFocus**），
   读不到就报异常、把这一趟作废——**不写成「0 站」**。
2. **「同一站连着出现 / 读回 body」不等于「绕回开头 / 走到头了」**，也可能是「这一下按键被丢了」。
   现在先原地再读一次（页面很长时按键生效了、读数会来早），再补焦点重按最多两次：
   动起来就接着走并记进 `droppedKeys`，还在原地才是真结论；绕回改成按**唯一路径**
   （从 body 数 nth-child 数下来）判，不再比选择器字符串（同一个 `tag.class` 在不同位置会重名，
   r336 里 `/overview` 与 `/settings` 记的「回到开头」其实都是走完了）。
3. **「可 Tab 元素」比站数多时要说得清是哪些**。走查结束后按同一个口径数一遍，
   多出来的进 `unvisited`（是什么、多大、在哪、是不是在 inert / aria-hidden 里），
   并做一次**边界自证**：聚焦第一个没走到的元素、再真按一下 Tab——
   动了说明它在 Tab 序里（走查是被打断的），不动才是真的到此为止。

## 四、补的是什么（跳转站）

- `src/App.tsx`：外壳第一个孩子是 `<a class="vq-skip" href="#vq-main">跳到主要内容</a>`；
  正文容器 `.vq-content` 拿到 `id="vq-main"` 与 `tabIndex={-1}`。
  这个站的地址栏就是路由（`#/overview` 这种），所以**拦住默认行为**、只把焦点送到正文——
  href 直接跳会把路由换掉。
- `src/styles/shell.css`：平时 `1px + clip-path: inset(50%)`（不占位、不进划过那一层的取景），
  `:focus-visible` 时展开、给发丝描边与 3px 焦点环（与 r336 的全站焦点口径同一套），
  颜色 / 底色 / 描边 / 阴影四条都带 120ms 过渡——**不然焦点那一层会把它记成硬切**。

## 八、边界（如实记）

- **后台那一屏：85 个可 Tab 元素、走查 56 站**。补焦点、重按两次、以及「直接聚焦第 57 个元素
  再按一下 Tab」都不动（`boundary.advanced = false`）。disabled fieldset / details 折叠 /
  content-visibility / inert / aria-hidden / offsetParent 全查过，都不是。**原因没查清**，
  所以既不当成页面缺陷、也不当成没问题：这一屏 56 站本身是干净的（0 黑洞 / 0 硬切），
  但那 29 个元素键盘到底能不能走到，这句先不下结论。
- **本地工作区那一趟的划过层依旧 ABORT**：`/local` 空状态里没有 `.lw-composer`（记「没量到」）。
- 跳转站在**线上**只核到 CSS 与入口，没有在真机上按过一次 Tab（本地走查里它是第 1 站，有环）。
- 这一层只判「Tab 到这一站看不看得出焦点」与「站数对不对得上」，不判焦点环长得好不好看。
