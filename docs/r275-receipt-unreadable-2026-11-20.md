# r275 / v0.9.257：回执链接「没读到」不等于「链接不在了」

日期：2026-11-20　范围：收包人那一页（`#/receipt/<token>`）　服务端：0 改动

## 一、结论

发给客户、剪辑的回执链接，收包人那一侧没有账号、也没有「重新读取」这类入口。
以前只要 `/api/receipts/<token>` 没成功，页面就写「这条回执链接不在了」，并让他「找发件人要一条新的」——
断网、服务重启、5xx 全都算进这一句里。于是发件人会被叫去重发一条**本来就没坏**的链接；
而如果服务只是抖了一下，收包人手上根本没有第二次机会（那一屏只有一句话，没有按钮）。

现在分成三档，只有服务端明确说「没有这一条」（404）才说链接不在了：

| 页面看到 | 什么时候 | 收包人能做什么 |
| --- | --- | --- |
| 这条地址已经换成新的了 | 410 / `LINK_RETIRED`（发件人换过链接） | 用最后发来的那条；包不用重下 |
| 这条回执链接不在了 | 404（服务端说没有这一条） | 找发件人要新的；包不用重下 |
| **这一下没打开** | 断网（status 0）、5xx、超时、其它状态码 | **原地「再试一次」**；包不用重下 |

第三档是新加的这一档：同一个 token 重新取一次，不刷新整页、不换链接、也不会多出一条交付记录。

## 二、判据（`src/domain/receipt-link-read.ts`）

| 输入 | 结果 | 细节行 |
| --- | --- | --- |
| 410 或 `code=LINK_RETIRED` | `retired`（沿用换链接那次的时刻） | 不显示 |
| 404 | `gone` | 服务端那句「不在了 / 失效」与标题重复，就不再摆一遍；别的人话保留 |
| 0 / 400 / 401 / 405 / 409 / 418 / 5xx | `unreadable` | `网络没连上` 或 `HTTP 500`（内部错误码不上屏） |
| 抛字符串、抛 null、认不出的对象 | `unreadable` | `网络没连上` |

文案上的两条硬规矩（单测守着）：

1. `unreadable` 那三句里不许出现「不在了」「失效」「换成新」，否则又变成叫收包人换链接；
2. `gone` 那句必须同时写清「找发件人要新的」和「手上的包不用重下」——他最容易做错的两件事各自堵住一边。

## 三、实测（临时实例 8802 + 只在本机用的筛选代理 8801 + 无头 Chrome，0 次上游调用）

代理按 `fail.json` 让 `/api/receipts/` 回 500，其余原样转发；页面从 8801 打开，走同一份 dist。

| 场景 | 实测 |
| --- | --- |
| 服务临时出错（HTTP 500） | 标题「这一下没打开」，正文「链接本身没问题，是这一次没读到：服务临时出了错（HTTP 500）。」，按钮「再试一次」116×36，细节行 `HTTP 500` |

## 四、边界

- 服务端一行没改：404 / 410 的语义、回执比对、打开记录都不动，只改收包人那一屏怎么讲。
- 「再试一次」只重取同一条链接，不换 token、不写任何记录；打开次数仍按服务端规则记。
- 404 仍然叫「不在了」：那是服务端明确说没有这一条；如果哪天服务端用别的状态码表达「没有」，这里的判据要跟着改。
- 截图用的是本机临时实例里的一条样例交付（作品与包都是演练数据），不是生产里真实客户的那一份。
