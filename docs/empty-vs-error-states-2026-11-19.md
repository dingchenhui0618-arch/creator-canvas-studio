# 「读不出来」不许再说成「一条都没有」（r269 / v0.9.251）

日期：2026-11-19 · 本轮没有真实上游调用，0 费用。

## 一、这一类问题为什么值得单列

数据读失败和「真的没有」长得一模一样：列表为空。用户看到的却是一句**确定的假话**——
「还没有运行记录」「没有检索到内容」「模板库还是空的」。他照着这句话做下一步（去建一条、
换个关键词、去检索），做的全是白工，而且会以为数据被删了。

r267 修掉的是视觉评审页那一处。这一轮把用户侧剩下的同类写法扫了一遍。

## 二、这一轮改了哪几处

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 运行记录页 | 上面一句「数据读不出来」，下面还写「还没有运行记录」；四个统计全写 0 | 报错时不再出现空状态文案；四个数字显示「—」 |
| 爆款雷达（检索失败） | 上面一条红色错误，下面还写「没有检索到内容」+「0 条已加载 · 示例数据」 | 报错时两者都不出现，只留一句说明 |
| 爆款雷达（积分不足） | 同样会叠一句「没有检索到内容」 | 同上 |
| 爆款雷达页头 | 配了 Key 就写「检索服务已连接」 | 改「检索通道已配置」——配了凭证不等于这一刻通 |
| 爆款雷达报错文案 | 直接把 `fetch failed；fetch failed` 甩给用户（英文、念两遍） | 「连不上检索服务（网络或上游暂时不可用）」+「这一次没有扣积分」；两个平台同一句去重 |
| 工作台 · 最近运行 | 读失败仍写「还没有运行记录」 | 「运行记录这次没取到」，并说明原因在顶部那条红字里 |
| 工作台 · 模板库 | 读失败仍写「模板库还是空的」，还给一个「去检索」的假出口 | 「模板库这次没取到」，不给假出口 |
| 工作台 · 交付 / 分享 | 读失败仍写「还没交出去过」「还没有分享出去的链接」 | 各自换成「这次没取到」 |

已核对**不用改**的：作品页（`!loading && !error && !items.length`）、创作成果流、模板库页、
对话预设列表——这几处 r265 / r266 已经带着 `!error` 条件。

服务端另加两个小修：`server/redfox.mjs` 把网络类失败统一翻成一句人话（`fetch failed` /
ECONNREFUSED / 证书错误…），并把两个平台重复的同一句去重后再拼。

## 三、验证（临时实例，真实渲染）

临时实例把一个坏掉的 `runs.json` 放进去（`GET /api/runs` 返回「数据读不出来」），
爆款雷达把 RedFox 指向一个没人监听的端口（不产生任何真实上游调用），再用无头 Chrome 真点一次检索：

- 运行记录页 1440：四个统计是「—」，只有一句错误说明，**页面里没有「还没有运行记录」**。
- 运行记录页 390：同一句话折行，`innerWidth = scrollWidth = 390`。
- 工作台 1440：最近运行写着「运行记录这次没取到」；同一屏的模板库照常写「模板库还是空的」（那一块读成功了）——按块判断，不搞一刀切。
- 爆款雷达 1440：页头「检索通道已配置」，红色一条「连不上检索服务…这一次没有扣积分」，**没有「没有检索到内容」**，也没有「0 条已加载」。

新增 `test/redfox-search-error.test.mjs` 1 条：上游连不上时错误码是 `REDFOX_ERROR`、
正文不许出现 `fetch failed`、必须说「连不上检索服务」、且两个平台重复的话只出现一次。

## 四、边界

- 这一轮只修「说了假话」的地方，没有做统一的错误组件；各页仍是自己的样式（`.runs-note`、
  `.radar-banner`、`.vq-note`），要统一得另开一轮。
- 爆款雷达的「检索通道已配置」只表示凭证配了；上游这一刻通不通，仍以点一次检索的结果为准
  （页面没有做后台探活轮询）。
- 工作台的区块失败判断按错误前缀（`运行记录：` / `模板库：` …）匹配，前缀文案改了要同步改这里。
