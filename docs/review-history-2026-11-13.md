# 评审历史：查看全部（v0.9.18）

结论：视觉评审页左侧的「最近评审」不再只是 6 条死数——标题行右侧多了「查看全部 N 条」，点开是一个 720px 的弹层：按结论筛（全部 / 通过 / 需人工确认 / 不通过，每枚带真实计数）、按作品筛（作品名 + 条数，含「没记入作品」），一页 20 条往下翻，点一条就回到那次评审的证据页。历史存 200 条，现在全部翻得到。

## 之前是什么样

| 之前 | 现在 |
| --- | --- |
| 「最近评审」只露 6 条，历史存 200 条，剩下的 194 条只在作品页按作品看得到 | 标题行「查看全部 N 条」进弹层，200 条一页 20 条翻到底 |
| 想找「上个月那条不通过的评审」只能凭记忆翻作品 | 按结论筛：结论胶囊即筛选器，每枚带条数 |
| 看不出哪条作品评得多、哪条一次都没评 | 作品下拉列出每条作品的评审数，另有「没记入作品 · N」 |
| 筛选后不知道还有多少、翻到底还有没有 | 页脚写「已显示 X / 共 Y 条」，不够就「再看 N 条」 |
| 窄屏 300px 的侧栏塞不下这么多东西 | 弹层在 390 宽占满屏、行结构与桌面同一份 |

## 三个实现决定

1. **弹层，不是新页面。** 路由 `#/review/<评审 id>` 已经被「某一条评审」占用；`#/review/history` 会被解析成一条不存在的评审 id，得额外加保留字。弹层不开新地址，就不会动上一轮刚立起来的「地址即入口」：在弹层里点一条，仍然是 `#/review/<评审 id>`，后退照旧回到评审页。
2. **筛选与翻页在服务端做。** 200 条记录本身不大，但每条带着几十 KB 的结论正文；`GET /api/reviews` 增加 `offset` 与 `orphan`，`limit` 上限仍是 50。返回里同时给 `total` 与 `facets`：**结论计数按当前作品筛选算，作品计数按当前结论筛选算**——换一个筛选，另一排数字仍然对着真实结果，不会出现「筛了作品以后结论计数还是全站数字」的假计数。
3. **一行只有一份实现。** 侧栏的「最近评审」和弹层共用 `ReviewHistoryRow`：结论胶囊、标题、时间、`作品 · 第几版`、正在看的那条标记，两处不会慢慢长得不一样。

## 口径

- **版次**：评审发生在作品的第几版，是记录里自己的 `version`；作品后来开新版，这条评审仍记在原来那一版。`version 0`（版本划分之前的老记录）在版本对照里折进第 1 版，历史行里如实写「未记版次」。
- **归属**：服务端按 `projectId` 现算标题。作品改名，历史跟着改口；作品删掉，评审保留但写「没记入作品」（`orphan` 筛选能一次挑出来）。
- **顺序**：按 `createdAt` 倒序，不看 `reviews.json` 里数组怎么排。这条有测试盯着：把一条 2025 年的记录故意放在数组中间，它必须落到列表最后。

## 顺手修的四点

1. **结论胶囊占固定一列（96px）**：短标签「通过」与长标签「需人工确认」后面，标题从同一条竖线开始；胶囊加 `white-space: nowrap`，不再被挤成两行 40px 高。
2. **零结果时筛选下拉仍显示正在筛什么**：原来筛着的作品在这一结论下一条都没有时，选项消失、触发器退回占位文案「按作品筛选」——看见 0 条却不知道是哪个筛选在起作用。现在补一条「毛衣折叠收纳法 · 0」，并给「清除筛选」。
3. **「查看全部」提到标题行**：原来在 6 行列表下面，窄屏要滚到底才看得见。
4. **结论文案收进 `domain/review.ts`**：作品页、分享页、评审页、历史行原先各写一份「通过 / 需人工确认 / 不通过」，现在一处 `REVIEW_VERDICT_LABEL`。

## 生产实测（只读，真实数据）

生产有 3 条评审：`prj_f38d68c6`「毛衣折叠收纳法」v2 两条（11-12 18:03、11-12 17:37），一条 11-11 15:44 的画布截图评审没记入作品。

| 量了什么 | 结果 |
| --- | --- |
| 评审页「最近评审」标题行 | 「查看全部 3 条 →」，下面 3 行 |
| 弹层尺寸（1440×1120） | 720×413，内容多高就多高；3 行，每行 55px |
| 筛选胶囊 | 全部 3 · 通过 0 · 需人工确认 3 · 不通过 0（各 30px 高） |
| 作品下拉 | 全部作品 / 毛衣折叠收纳法 · 2 / 没记入作品 · 1 |
| 筛到「毛衣折叠收纳法」 | 2 条，均为「需人工确认」；出现「清除筛选」 |
| 再叠一个「通过」 | 0 条：空状态 + 「看全部评审」+ 下拉仍写「毛衣折叠收纳法 · 0」 |
| 390 宽（374×505） | 弹层占满可视宽，两档 `scrollWidth == clientWidth`，无横向滚动 |
| 点一条 | 弹层关闭、地址变 `#/review/rev_af034805`，记录页照上一轮的样子打开 |
| Esc / 点背景 | 两种都能关，关了不留残影 |

本地另用 `.tmp-qa` 的 24 条演示数据验翻页：第一页 20 条，页脚「已显示 20 / 共 24 条 + 再看 4 条」，点一次变 24 条、按钮消失；筛「需人工确认」→ 8 条且计数同步；筛作品 → 10 条、清除筛选出现。生产只有 3 条，翻页这一档只能在本地演示数据上量——上面的数字如实来自本地演示，不是生产。

## 边界

- 历史存储上限 **200 条**（`MAX_REVIEWS`），超出的最旧记录会被丢掉；弹层翻的是这 200 条。
- 一页最多 50（服务端），弹层一页 20。
- 只读：打开历史、筛选、翻页都不会跑评审、不扣积分。
- 没有按时间范围筛、没有关键字搜索；筛选条件不写进地址（刷新回到「全部 / 全部作品」）。
- 每枚结论胶囊的计数是「在当前作品筛选下」的数字；「全部」不是全站总数，这一点在页面文案里也用「按结论或作品筛」说明了。
