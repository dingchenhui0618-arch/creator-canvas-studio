# 删掉的作品能找回来（r271 / v0.9.253）

## 一句话

作品以前是「一删到底」：脚本、分镜、版本、交付记录、评审当场蒸发，只有浏览器一个 confirm 挡着。
从 r271 起，删掉的作品进回收站留 30 天，**恢复时连删除那一下被一起收走的评审、已看过、拍板都按原样放回来**；
过了 30 天或点「彻底删除」才真的清掉，交付包文件也跟着清。

## 为什么挑这一项

按「发现 → 复刻 → 模板 → 作品 → 画布 → 评审 → 交付」逐段体检，这一轮落到最疼的一段：**作品**。

- 作品是整个产品的主线对象：一条内容的脚本、分镜、版本、评审、交付全挂在它身上。
- 模板早就有一套 30 天回收站（编导误删一条解析了很久的模板，不必再花 10 积分拆一遍），
  **作品反而没有**——而作品比模板贵得多。
- 删除入口只有一个「删除」按钮 + 一句 window.confirm，点错了没有任何补救路径。
- r270 刚把「写到一半不许悄悄丢」做完，这一条是同一类问题：**用户的东西不该因为我们少留一手而消失**。

## 做法

### 服务端（server/projects.mjs）

- 新增 `projects-trash.json`（单独一份文件，不往 projects.json 里塞 deleted 标记）：
  作品列表、作品流、模板使用统计、评审候选全读 projects.json，一处漏过滤就会有人看见「已经删掉的作品」。
- `deleteProject` 现在做三件事：
  1. 从 projects.json 里摘掉这一条；
  2. 把评审、已看过、拍板一起摘下来（`takeReviewsForProject` / `takeAcksForProject` / `takeDecisionsForProject`）；
  3. 连同作品记录写进回收站条目（`{ project, deletedAt, deletedBy, reviews, acks, decisions }`）。
  **交付包文件先留着**——否则恢复回来的是没有交付记录的空壳。
- `restoreProject`：作品记录原样放回（`updatedAt` 记为恢复时刻），
  评审按 id 补回 projectId（评审记录本身删除时只是摘了关联、没从库里删掉，所以是「补关联」不是「重新插入」），
  已看过与拍板重新插回；已经存在的号跳过。
- `purgeProject`：删包、删条目，之后不能恢复。
- `listProjectTrash`：只回这个账号看得见的条目，最新删的在前；顺手把过期的清掉（30 天），
  过期条目连同它的交付包一起删——不靠人记得回来点「彻底删除」。
- `deleteProjectsByOwner`（注销账号）：名下回收站条目一并清掉，回收站不算「账号还在」。

### 接口（server/routes/projects.mjs）

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| GET | `/api/projects/trash` | 回收站列表（`items` + `days`） |
| POST | `/api/projects/:id/restore` | 恢复；不存在 404、别人的 403、已存在/超上限 409 |
| DELETE | `/api/projects/trash/:id` | 彻底删除 |

三个入口都排在 `/api/projects/:id` 的正则前面——`trash` 本身会被那条正则当成一个作品号。

### 界面

- `TrashModal` 改成通用的（读什么、恢复什么由调用方给），模板库与作品共用同一套界面与样式，
  不再各写一份：`TrashSource` 里放 kicker / 标题 / 说明 / 空状态 / 两个提示语 / load / restore / purge。
- `deletedLabel` / `leftDays` 两个说法挪到 `src/domain/trash.ts`（组件文件只导出组件，否则 fast-refresh 规则会拦）。
- 作品页页头新增「回收站」，行上写清「v2 · 删于 11-20 10:31 · 29 天后清空 · 恢复带回评审 2 条 · 交付 1 份」。
- 作品页删除文案改了：以前写「工作流与评审不会被删掉，只解除关联」（其实并不准确），
  现在写「脚本、分镜、版本、交付记录和评审会一起进回收站，30 天内可以恢复」；
  删除成功提示也直接说去哪里恢复。

## 验证

- 单测 `test/project-trash.test.mjs` 7 条：过期条目读一次就清掉、删完不在列表但在回收站（带件数）、
  评审仍留在评审库只是不挂作品、恢复把四样一起带回、不会重复插入、别人的看不见也恢复不了、彻底删除后恢复 404。
- 既有用例按新行为更新：`test/projects.test.mjs`（删作品那条）与 `test/delivery-package.test.mjs`
  （封存目录在回收站期间保留、彻底删除才清）。
- 门禁：1778 条测试、lint 0 error / 25 warning（641 文件）、`tsc -b` 干净、build 入口见发布记录。

## 边界

- 回收站**没有单独页面**，入口在作品页页头；一次最多留 60 条，超出的按最旧挤掉。
- 恢复不还原「工作流」本身（工作流是独立对象，从来没被删除影响过）；
  如果这条作品的工作流在别处被删了，恢复回来的作品仍然只带着那个 flowId。
- 30 天是硬编码常量 `TRASH_DAYS`，后台没有开关。
- 评审「已看过」与「拍板」在回收站期间不可见（已经摘下来了），恢复后一起回来。
