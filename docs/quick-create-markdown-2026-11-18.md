# 快捷创作：回答按 Markdown 排版（r220 / v0.9.204）

## 为什么改

平台对话的回答一直是**纯文本**：模型写 `## 结构`、`**结论**`、`| 时间段 | 动作 |`，
界面上就原样吐出这些符号。段长一点（拆结构、列分镜、给对照表）就读不动——
用户的原话是「字体这种都有点小了 放大点 至少让我看得清楚字是啥」。

自建智能体那边的回答本来就有极简 Markdown 渲染（标题 / 列表 / 表格 / 加粗 / 行内代码 / 代码块），
只是写在 `AgentsPage.tsx` 里，平台对话用不到。于是把它抽出来两边共用，
顺手补上模型真正常用、原来缺的几块：引用、分隔线、站内外的链接。

## 怎么做

- **解析与渲染分开**：`src/lib/markdown-parse.ts` 只把文本拆成数据（块 + 行内 token），
  `src/lib/markdown.tsx` 再把数据画成 React 节点。这样解析能用 `node:test` 单测，不用起浏览器。
- **不引入依赖、不用 `dangerouslySetInnerHTML`**：模型写什么都是文本节点，
  `<script>` 不会被当 HTML 执行（r219 读链接时也按同一原则处理页面正文）。
- **链接只放行 http / https / mailto**：其余（`javascript:`、`data:`）按原文显示，不当成链接。
- **用户自己发的话不解析**：仍按纯文本显示，避免「你打的星号被吃掉」。
- **字号**：助手气泡从 14px 提到 15px（配合 r214 的整体放大），行高 1.75。
- **窄屏**：`nav.css` 早先给对话预设的表格压了 `min-width: 480px`（那页是在容器里横滚），
  在 390 宽的气泡里会撑出一条横向滚动条。快捷创作用 `@media (max-width: 560px)` 显式收回下限、
  改 `table-layout: fixed`、字号 12px，宁可排两行。

## 拿到的东西

| 输入（模型原文） | 界面 |
| --- | --- |
| `## 三秒钩子脚本` | H3 标题（一、二级标题统一降为 H3，三级往下 H4） |
| `**结论**` / `\`hook()\`` | 加粗 / 行内等宽代码 |
| `1. …` `- …` | 有序 / 无序列表 |
| `| 时间段 | 动作 |` + 分隔行 | 表格（表头小字大写、单元格可读） |
| `> 前 3 秒没有信息` | 引用块，左侧一道细线 |
| `---` | 分隔线，不再显示成三个短横 |
| `\`\`\`js …` | 代码块（等宽、保留缩进、块内横滚） |
| `[说明](https://…)` | 可点链接，新标签打开 |

## 边界（照实说）

- **不是完整 CommonMark**：嵌套列表、图片、脚注、表格对齐、HTML 直出都不做；长文本只按上面这些块排版。
- **流式过程中仍是纯文本**：边生成边显示的是原文（未闭合的 ``` 与 `**` 会先露出来），
  回答结束才排版。这样不会因为半截代码块把整段跳来跳去。
- **代码块在窄屏内部横滚**：代码折行更难读，宁可让那一块自己能滑。
- 表格只按「第一行是表头、第二行是分隔行」识别；模型写的表格缺分隔行时按普通段落显示（不猜）。
