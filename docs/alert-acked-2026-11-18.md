# 确认不该等于删除：告警列表分「未确认 / 已确认 / 全部」（2026-11-18，0.9.182）

## 结论

后台「系统 → 告警」原来只有一个视图：未确认的。点一次「确认」，那条告警就从界面上消失了——`ackAt` / `ackBy` 一直落盘，却没有地方能看。等于把「确认」做成了「删除」，事后想查「这条 5xx 是谁在什么时候确认的」只能去翻数据目录。

现在列表按口径取：`GET /api/admin/alerts?status=open|acked|all`，界面三个标签带计数——未确认 / 已确认 / 全部。已确认的行显示「已确认 时间 · 谁」，行上不再有「确认」按钮。别的 `status` 值一律按「未确认」，按钮拼错不会把已确认的混进待办。

顺带修了 390 宽的一条挤压：一条告警横排只剩约 150px 文本列，徽标、说明、按钮挤成一列字。窄屏（≤560px）改成单列，按钮跟着内容走。

## 为什么现在做

生产上还挂着 13 条未确认告警（6 条 5xx、8 条里另有 2 条 model-blocked 402，另有 3 条 test）。要不要确认是用户的决定，但「确认完就看不见」本身就是个缺陷——不修这个，用户确认完就失去了回看的能力。

## 改了什么

服务端：

- `server/alerts.mjs` 新增并导出 `parseAlertStatus(raw)`：只认 `open` / `acked` / `all`，其余（含空、`OPEN`、`hacked`）一律 `open`；
- `alertCounts()` 多回一个 `acked`（`total - open`），页面不必自己减；
- `GET /api/admin/alerts` 接受 `?status=`，并在响应里回显 `status`。

界面：

- 告警卡片加三个标签（复用后台已有的 `.admin-tabs / .admin-tab` 发丝线标签，和审计页同一套）；
- 已确认的行：徽标转中性色，多一行「已确认 11/17 12:35:24 · 后台管理员」，没有「确认」按钮；
- 空状态按口径分别说话（没有未确认的告警 / 还没有确认过的告警 / 还没有任何告警），不再一律说「没有未确认的告警」。

## 验收

服务端测试 **4 / 4**（`test/admin-alerts-status.test.mjs`）：三个口径各回什么、别的值按未确认、确认后原始告警还在且 `ackBy` 留得住、重复确认只刷新时间不多出一条、确认不存在的 id 返回 `null` 不造数据。

界面端到端（临时实例 + 无头 Chrome 真点，4 条样例告警）：

```
未确认 2（2 个「确认」按钮）
点第一条的「确认」
未确认 1（1 个按钮） · 已确认 3 · 全部 4        ← 行从待办挪走，但没有消失
切到「已确认」：3 行，0 个「确认」按钮
每行都带「已确认 11/18 11:39:31 · …」
切到「全部」：4 行，只有未确认那条有按钮
390 宽：innerWidth 390 / scrollWidth 380，行宽 256 单列
```

部署后在生产上按接口核对（真实数据）：13 条告警里 `open` 10 / `acked` 3 / `all` 13——
那 3 条早就确认过，在旧界面上再也看不到；现在「已确认」标签能翻回来，且每条都带 `ackBy`。
`status=bogus` 回 10 条并回显 `open`（坏值按未确认）。

## 边界

- 口径只影响「看」，不自动清理：确认过的告警一直留在 `DATA_DIR/alerts.json`（最多 200 条），不会因为确认就删。
- **没有「退回未确认」**：确认是一次性标记，点错了只能靠「全部」视图看到它，改不回去。要不要加撤销，等用户定。
- 没有批量确认：一次只能确认一条。（「把某一类历史告警一键确认」需要用户明确授权，本轮不做。）
- `ackBy` 记的是确认时登录的管理员邮箱；样例数据里写的是显示名，不是邮箱。
- 本轮 0 次真实上游调用、0 费用。
