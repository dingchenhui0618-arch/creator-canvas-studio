# 队列翻得完：一页 20 条，翻到底才说都列出来了（v0.9.27）

**结论**：工作台的「评审等你看的」以前只取最近 20 条，第 21 条以后只剩一句「只列了最近 20 条，还有 N 条更早的等你改」——话说得对，但没有任何东西可点。这一轮给它出口：服务端多一个 `offset`，工作台写「已列 20 / 27 条 · 再看 7 条」，一页一页往后取，翻到底才写「全部 27 条都列出来了」。顺手修掉一个数字对不上的老毛病：展开按钮原来按「已取回的行数」算，屏上写「还有 17 条」，实际队列还有 24 条；现在按队列总数算，3 + 17 = 20 与 `已列 20 / 27 条` 接得上。

- 提交：`（待填）`；CI run `（待填）`；测试 `288/288`，oxlint `0 error / 6 warning`，构建通过。

## 一、这一轮补的是哪块空

队列这三轮是这么长起来的：v0.9.24 让第 4 条以后不再凭空消失（点开排到 20 条）、v0.9.25 加时间范围与标题搜索、v0.9.26 把「拍板」变成有历史的记录。但「一页最多 20 条」这道上限一直没出口：等你看的攒到 27 条时，界面诚实地说「还有 7 条更早的等你改」，然后就没有然后了——那 7 条在数据里，页面上永远见不到。

工作台的定位是「下一步点哪里」，所以首屏仍然只排 3 条；但「翻得完」是它的底线：承认还有几条，就得能走到那几条。

## 二、三个决定

1. **offset 算在服务端，页面只负责拼页**。`reviewQueue(user, { limit, offset })` 仍是一页最多 20 条，但可以从第 N 条开始取；返回里多两个字段：`offset`（夹到总数上，不写出比总数还大的页码）与 `hasMore`（后面还有没有）。`total` / `allTotal` / `facets` / `lead` 全部按整份列表算，不跟着页变——否则翻到第 2 页，工作台主卡那个「下一步」会跟着换人。
2. **写数字，不写形容词**。「已列 20 / 27 条」能被核对；「还有 7 条」只能被相信。翻到底之后把按钮收起来，只留一行淡字「全部 27 条都列出来了」——不然用户会以为还能再点。
3. **翻几页就取几页，按作品去重**。第 2 页之后刷新一次（有人点了「已看过」、或拍了一版）也要把前几页一起取回来，否则某一行被拿掉、后面的行整体前移，拼出来的列表会缺一条；相邻两页真返回同一行时按 `projectId` 去重。上限 10 页（200 条）：真到那儿了，用上面的搜索或时间范围收窄比继续翻更省事，界面把这句话直接写出来（`一次最多列 200 条：用上面的搜索或时间范围收窄`）。

## 三、界面

| 状态 | 屏上写什么 |
| --- | --- |
| 收着（默认） | 3 行 + 「还有 24 条等你改 →」：数字按队列总数算（27 - 3） |
| 点开 | 已取回的 20 行 + 一行发丝线盒子：左边 `已列 20 / 27 条`，右边 `再看 7 条 →` |
| 翻到底 | 27 行 + 淡字「全部 27 条都列出来了」，按钮收起 |
| 筛过之后（7 天内 8 条 / 搜「咖啡」6 条） | 没有第二页，翻页行不出现；只留「还有 N 条等你改」 |
| 正在取 | 按钮禁用、写「正在取…」，防连点 |

翻页行与下面「已看过」「拍过板」两行同一套形状：一条发丝线、12px 字、11px 的等宽数字，不抢作品名的注意力。收着的时候它不出现——屏上只有 3 行时写「已列 20 条」会是一句假话。

390 窄屏：翻页行 290px 一行排得下（`已列 20 / 27 条` 与 `再看 7 条 →` 分居两端），页面 `scrollWidth == clientWidth`。

## 六、验收清单

- [x] `offset` 越界夹到总数上、非法值当第一页、负数不往回排（新增 4 条用例，含路由一条）
- [x] `hasMore` 与 `total` 分开算：一页装得下时 `hasMore: false`
- [x] 翻页不换 `lead`：工作台的「下一步」主卡不被翻页带走
- [x] 筛过之后再翻页，`offset` 按筛出来的列表算，不按全量
- [x] 收着的时候翻页行不出现；翻到底收起按钮、写「都列出来了」
- [x] 生产只读：1 条待办时既不出现「还有 N 条」也不出现翻页行
- [x] 测试 `288/288`、oxlint `0 error / 6 warning`、`tsc -b` 干净、构建通过
- [x] 生产实拍 2 张 + 本地实拍 5 张，README 已引用

## 七、边界

- 一页仍是 20 条；一次最多 10 页（200 条），到顶后界面写明用搜索或时间范围收窄。
- 不记住「翻到第几页」：换筛选、刷新页面都回到第一页。
- 只有一种顺序：按那次评审的时间倒序；没有「按作品名排」「按版次排」。
- 没有缓存：每翻一页都把队列现算一遍（作品 + 评审计数 + 已看过 + 拍板），打的是同一个 `GET /api/reviews/queue`。
- 翻页不改变「哪条等你改」的判断：`pendingRow` 一行没动，只是把同一份列表切开给你看。
