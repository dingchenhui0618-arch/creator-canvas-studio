# r343：对话里接着说一句改参数 + 模型自称（master，未发布）

2026-11-27。生产 v0.9.314 的两个缺口：

1. **对话里接着改参数没做**。r342 自己的边界里就写着「多轮修改（改成 8 秒 / 换个比例）仍没做」。
   生产上的表现：出完一条图 / 视频之后接着说「改成 8 秒」「换成 16:9」「画质改高清」，
   这句话被当成普通聊天——参数一个都没变，还白扣了对话那 1 积分。
2. **模型自称**。系统提示词第一句是「你是平台里的创作助手」，被问「你是什么模型 / 是不是 DeepSeek /
   哪家的 / 什么版本」时可能把上游厂牌或型号说出来。用户明确要求只认 **VisionQA 通用模型** 这一个名字。

## 判定与写入优先级（实现口径）

- **生成时合并**：会话 \`mediaDefaults\`（长期记忆，低） < 这条消息里解析出的显式参数 / 对话框里选的（本次覆盖，高）。
- **写回**：这次明确说 / 选的键才写回 \`mediaDefaults\`；没说的键即使借了会话设置也不回写——
  「没带任何参数时不许凭空塞值」就落在这条。
- **「只改参数」的判定**（\`parseParamChange\`）：没有生成动词（\`parseMediaIntent\` 为 null），并且值前面有改参数的说法：
  - 强动词：改成 / 改为 / 换为 / 换成 / 调成 / 调到 / 调整为 / 调整为 / 设为 / 设置成 / 变成 / 弄成 / 搞成……
  - 弱动词：参数名 + 改 / 换 / 调 / 用 / 来 / 要（「画质改高清」「比例用 9:16」）；
  - 句首只有「我要 / 用 / 来 / 要」且整句就说到值（「我要 16:9」），值后面还跟着东西（「要 8 秒的背景音乐」）不算。
  - 问句 / 征求意见（「…怎么剪」「…是什么意思」「…会不会更好」）不算。
- **「上一版」**：会话上存 \`lastMediaTask = { id, kind, prompt, params, refIds, at }\`，只在对话里真的开出生成任务时写入；
  \`at\` 记的是那条用户消息的 id，**最近 6 条消息**里找得到才算「上一版」（会话超 200 条会裁头，所以不用下标）。
- **类型不兼容**：图片没有时长 / 分辨率，视频没有画质 → **不建任务**；这一档仍按「这条对话的当前设置」记下
  （下一段视频会用 8 秒），回答里说清不兼容。
- **重出一版**：同一个提示词、新任务、沿用上一版的参考素材；扣费 / 退款走生成管线原来的「先扣后调、失败全额退回」。

## 已知边界（说实话）

- **认不出来的说法**：
  - 值后面还带宾语的：「我要 16:9 的封面」按普通聊天（宁可不改，也不误扣）。
  - 尺寸 / 4K 不在「改参数」的四项里：「改成 2048x2048」「改成 4K」认不出来。
  - 中文数字：「改成八秒」认不出来（只认 1–60 的阿拉伯 / 全角数字）。
  - 只在下拉里选了参数、嘴上没说改（例如只说「这样呢」）：这条消息按普通聊天走，不会触发重出；
    选择本身会随生成指令生效，也会在生成指令那条路上写进会话设置。
- **「上一版」的范围**：只认在对话里开出来的任务（\`lastMediaTask\`）。在「图片 / 视频」页签里生成的不算；
  超过最近 6 条消息、或那条消息已被裁掉（按 id 找不到）就当没有上一版，只记设置。
- **花钱的地方**：重出一版会再扣一次生成积分（先扣后调、失败全额退回）；同一档重复说不会重出。
  「只记设置」和「类型不兼容」这两条一分钱都不扣（连对话那 1 积分都不扣）。
- **参考素材**：重出沿用上一版那张参考图（文件还在才用）；不在了会在扣费之前报「原图读不到了」，
  不会静默降级成纯文生图。
- **会话设置是「这条对话」的**，不是账号全局；换一条会话不继承。
- **图片画质**仍是「选才传」，上游收不收没真调过；沿用 r342 的「上游不收就失败全额退回」。
- **误判的残余风险**：普通聊天里如果恰好出现「改 / 换 / 调 + 参数值」（例如「我把标题改成 16:9」）
  会被当成改参数——这是有意的取舍，目前没有二次确认。
- **前端还没接**：这条链路返回的是普通 \`done\`（没有逐字输出），界面按「一次性回答 + 卡片」显示即可；
  \`body.media\` 的非空键在「只改参数」这一轮也会作为本次覆盖参与合并。
