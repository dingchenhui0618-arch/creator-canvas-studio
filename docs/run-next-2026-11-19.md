# 跑完之后往哪走：抽屉底栏直接给下一步（r250 / v0.9.233）

## 结论

工作流页此前只在**跑之前**给出口：另存为模板在顶栏、去评审在「在帮《作品》」那一条上。
一按「运行流程」，重心就全跑到右边的运行结果抽屉里——跑完那一刻，抽屉里除了逐节点状态
什么都没有，页面上唯一的结论是右下角一条「运行完成 · 0.0s」。想知道下一步，得先关抽屉再回顶栏找。

这一轮把「接下来」钉进抽屉底栏：结果在哪，下一步就在哪。

| 这次运行 | 底栏写什么 | 给哪几个出口 |
| --- | --- | --- |
| 全跑完、挂在作品上 | 「这次跑完了」+ 全部 N 个节点跑完了，花 M 积分；这一版已经记在《作品》第 K 版下 | 送去评审这一版 · 存成模板 · 打开作品 |
| 全跑完、没挂作品 | 同上，但说明「还没挂到作品上，存成模板后能在别处套用这段结构」 | 存成模板 |
| 跑的是归档旧版 | — | 存成模板 · 打开作品（不拉旧版去评审） |
| 有节点失败 / 被进程打断 | 「这次没跑完」/「这次被中断了」+ N/M 个节点跑完，X 个失败 | 存成模板（+ 作品出口） |
| 自己按了停止 | 「你停下了这次运行」+ N 个留了结果、M 个没跑 | 存成模板（+ 作品出口） |

挑哪几个出口、每个字怎么写都在 `src/domain/run-next.ts`，组件只负责画——文案与出口顺序被
`test/run-next.test.mjs` 的 14 条用例钉住。

## 顺手修的两个真问题

1. **绑好的运行被说成「没挂到作品上」**。流式那条路（页面真正用的那条）推的 `run-end` 里没有
   `project`，只有 `GET /api/runs/:id` 会补；探针实测：页面上明明写着「在帮《毛衣折叠收纳法》第 1 版」，
   抽屉底栏却说「这次运行还没挂到作品上」。现在路由层在开跑时查一次索引，`run-end` 与非流式响应
   都带上 `project`（没挂就是 `null`，不留给前端猜），`test/run-end-project.test.mjs` 两条盯住。
2. **完成提示条压住新按钮**。`.vq-toast` 固定在右下 24px，正好落在底栏那排按钮上；提示条是 div，
   压着的那两三秒点下去是点在它身上。底栏出现时（`body:has(.cv-next)`）提示条上移到 152px
   （窄屏 264px），提示不丢、按钮点得到。

## 证据（本机临时实例 + 无头 Edge 真鼠标，不碰上游）

临时实例里建了一条只含「输入 → 输出」两条节点的工作流（不调用任何上游），绑到一条作品上，
打印口自己的账号点「运行流程」：

| 项 | 结果 |
| --- | --- |
| 1440 底栏 | 「这次跑完了 / 全部 2 个节点跑完了，花 2 积分；这一版已经记在《毛衣折叠收纳法》第 1 版下。」三个出口顺序：送去评审这一版 → 存成模板 → 打开作品 |
| 真点「送去评审这一版」 | 地址变 `#/review/project/prj_270c5bd4`，落在「视觉评审」页 |
| 真点「存成模板」 | toast「已存为模板：毛衣折叠 · 复刻（可在模板库套用回工作流）」，`GET /api/templates` 里出现该流程条目 |
| 溢出与小字 | 1440：溢出 0、整页宽 1440 = 视口 1440；390：溢出 0、整页宽 390 = 视口 390；底栏正文 14px、标题 15px |
| 提示条 | 底栏出现时提示条上移，三个按钮全程无遮挡（截图里可核） |

两张截图都在仓库里：`docs/run-next-1440.png`、`docs/run-next-390.png`。

## 边界

- 底栏只做「跑完之后」这一屏。**交付**（封包、回执）仍在作品页，这一轮没搬过来。
- 归档的旧版工作流不给「送去评审这一版」——那会让评审记到已经不在当前这一版的工作流上。
- 抽屉里停着的若不是当前这条工作流（很少见），不给「存成模板」：存下去会是另一条。
- 版本号还没编过的作品（`version: 0`）不写「第 0 版」，只写《作品》。
- 本轮 0 次真实上游调用：临时实例里跑的是「输入 → 输出」两条节点，只用到本地积分记账。
