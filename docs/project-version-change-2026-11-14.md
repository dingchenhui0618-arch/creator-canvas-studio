# 每一版比上一版改了什么，旧版脚本还能翻开看（v0.9.114，2026-11-14）

## 结论

版本对照原来只回答「这一版评得怎么样」：比上一版少几个阻塞、最近一评什么结论。可人真正想确认的第一件事是**这一版到底改了什么**——脚本换了哪一段、画布动了哪个节点。这一轮把这件事写到版本行上，并让开新版时存下的脚本快照能点开看原文。

两句话概括：

- 作品页每个版本多一行「比 vN：画布改 1 个（输入主题）；脚本多 1 段（收尾）、1 段口播改过、钩子换过」。
- 归档版本的「N 段脚本」是可点的：只读弹窗里是**开新版那一刻的原文**，不是现在的脚本。

## 为什么现在做

v0.9.84 起，版本对照按严重度看评审问题数；v0.9.85 / v0.9.86 补了交时评审与交付后漂移。但「为什么变好/变差」只能靠人回忆改动。开新版时服务端其实已经把脚本快照存进归档（archiveProjectVersion），只是页面只用了段数，没把内容放出来；交付稿里也早就有「v3 比 v2」的句子，只是要导出才看得到。

所以这一轮没有新造差异算法，而是把交付稿里已经验证过的那套「节点指纹 + 脚本按段名对」抽成 server/version-diff.mjs，让页面、接口和交付稿读同一份实现。

## 做了什么

### 1. 一份差异实现

新增 server/version-diff.mjs：

- fingerprint(nodes)：节点按 id 认，比 type + data.config；位置、标题、选中态不算改动。
- canvasDelta / canvasText：多 / 少 / 改，点名节点标题。
- scriptText：脚本按段名对口播；多段、少段、改词、换钩子分开说。
- versionChangeText：两侧都能比时合一句；都没动时收成「画布与脚本都没动」；缺一侧只写能比的那一侧。
- versionChangesOf(rows)：整条作品按相邻版次算，当前版也有一句。

server/project-deliverable.mjs 改为从这里取函数，交付稿的句子与页面不会分叉。原有交付稿测试全部保持通过。

### 2. 作品详情多一张变更表

GET /api/projects/:id 新增：

~~~json
{
  "versionChanges": {
    "2": "画布改 1 个（输入主题）；脚本多 1 段（收尾）、1 段口播改过、钩子换过",
    "3": "画布改 1 个（输入主题）；脚本多 1 段（结尾）、钩子换过"
  }
}
~~~

键是版次（字符串），值是给人看的一句话；没有可比对的一侧就没有这一项，不硬写「没改」。节点数组只在服务端参与计算，不进响应——普通详情里仍然只有 versions[].nodes 计数与 scriptBeats。

### 3. 旧版脚本快照接口

GET /api/projects/:id/versions/:n/script：

- 当前版：读作品现在的脚本（scriptView，自己的版本优先，否则跟随模板）。
- 归档版：只读 versions[n].script 快照；没有快照时 200 + script: null + 一句原因。
- 登录态与作品归属照旧；未登录 401，没开过的版次 404。
- 只读，不扣积分、不改画布。

### 4. 作品页

- 每个「有上一版」的版本多一行：比 v2 画布改 1 个（输入主题）；脚本多 1 段（结尾）、钩子换过。
- 归档版本的「N 段脚本」变成可点入口（虚线下划线 + 箭头），打开只读弹窗：比上一版改了什么、开头钩子、逐段口播与屏幕字、来源说明。
- 当前版不重复开弹窗：当前脚本本来就在页面下方的脚本区。
- 弹窗 Esc 关闭、背景不滚动；长脚本在弹窗内滚动，不撑破视口。

## 八条坑

1. **CSS 类名撞车**：新弹窗最初也叫 .vq-script-head / .vq-script-note，和作品页脚本区重名，弹窗顶部凭空多出一大段空白。整套改成 vq-verscript-* 前缀后才对齐。
2. **测试节点字段被归一化吃掉**：用 llm 节点的 config.prompt 造差异，服务端只保留 model / temperature / systemPrompt，两边指纹一样，测试误报「画布没动」。改用 systemPrompt 才测到真差异。
3. **快照不是每版都有**：升级前开的版本没有脚本快照。页面写「脚本没存快照」，接口 200 + 原因，不拿当前脚本冒充历史。
4. **缺一侧不写「没改」**：上一版画布被删，画布这一侧比不了；上一版没存快照，脚本这一侧比不了。只写能比的那一侧；两侧都没有就不显示这一行。
5. **当前版也要算**：只算归档版会漏掉「现在这版比上一版改了什么」。当前画布与当前脚本要一起放进差异表。
6. **详情别塞节点数组**：十来个版本 × 每版几十个节点的配置会把首屏拖慢。计算留在服务端，响应只给一句话；节点与快照正文只在导出或点开时取。
7. **「脚本1 段口播改过」读不通**：以数字开头时补一个冒号，写成「脚本：1 段口播改过」；交付稿与页面共用这一个句子。
8. **390 要卡两层**：页面不能横向溢出，弹窗正文也不能；长脚本用 max-height + overflow-y 在弹窗内滚，不把视口撑破。

## 发现但没做

- 不做脚本逐字 diff：只到段级（多 / 少 / 哪段口播改过 / 钩子换过），不标出句子里改了哪几个字。
- 不提供「从旧版恢复脚本」或编辑旧版：快照只读；要改去当前版。
- 不记录「这一版为什么改」的人工备注：现在只有机器比出来的改动，没有人的一句话。
- 只比相邻版本：v1 与 v3 没有直接一句；要看这两版得自己开两次弹窗，或去运行对照。
- 只比画布节点与脚本：模板分镜、评审结论、交付状态不进入这句改动。
- 不把版本改动放进只读分享页：甲方看到的是脚本与评审，不是内部版本流水。
- 没有在真实模板/真实运行上验证：本地作品没有绑定模板，脚本是作品自己的；生产也没有真实运行授权。
