# r293：对话框里说「帮我出个视频」就出；写死的参数照原样提交（v0.9.275）

## 用户要的两件事

1. 在「快捷创作」的对话框里说「帮我出个视频」，**我不用改口成命令**，系统把提示词写好、直接提交；
2. 用户在提示词里**写死**图片尺寸 / 视频分辨率 / 秒数时，按写死的值走对应提交通道，
   不要再被默认档位悄悄顶掉。

## 三块改动

### 1. 触发词：从「词表」到「正则族」（`server/media-intent.mjs`）

原来靠一张 `NATURAL_LEADS` 词表逐条列举，漏了「出个」「做条」这类量词就整句不认——
这就是「帮我出个视频」被当聊天的原因。现在补两层：

- `VERB_LEAD`：动词 + 量词 + 名词贴着（「出个视频」「做条短视频」「来一段」）；
- `LOOSE_VERB`：名词被参数隔在后面（「做一个 30 秒的…视频」），名词离动词超过 24 字就不算。

保护规则一条没放松：自然语言触发词后面必须有断点；名词后面接「的…」不算；问句开头（要 / 会 / 怎么 / 多久…）不算。
所以 `做个视频的脚本`、`生成视频教程的文案`、`帮我出个视频吗` 仍然走普通对话。

### 2. 只说了要图 / 要视频：先把提示词写出来（新增 `server/media-prompt.mjs`）

以前 prompt 太短就报错「后面写清要拍什么」，等于把活推回给用户。现在标记 `needsPrompt`，
由对话层调一次文本模型（平台现成的 DeepSeek 通道）把这句意愿写成 40–120 字的画面提示词：

- 输入带上最近几句对话，所以「再来一条刚才那种」能接上语境；
- 输出 JSON `{"prompt": "..."}`，失败或写得过短就回空——**绝不拿空提示词去扣 15 积分**，
  而是回一句「补一句画面再发一次」；
- 提示词写出来后原样写进回答里，用户想改直接说「改成…」。
- 参数（比例 / 秒数 / 清晰度）不写进提示词：那是系统的事，写进去等于让上游把「12 秒」当画面描述。

### 3. 写死的参数：原样提交（`server/media-models.mjs` 的 locked）

`locked` = 用户在句子里明确写死的值。带 locked 的值不再被白名单顶掉：

- 图片：`宽x高` 直接当 size（64–4096）；`2K/4K` 按比例展开（2K 竖屏 → 1152x2048）；
  表里没有的比例按比例算尺寸（4:5 → 1232x1536，长边与 1024x1536 同档）。
- 视频：任意 1–60 秒、任意 `\d{3,4}p`、任意 n:m 比例都原样提交；`1920x1080` 换算成 16:9 + 1080p。
- 界面下拉那条路**没有放宽**：不带 locked 的越界值仍然 400（界面根本传不出这种值，能传到就是拼错了）。
- 回答里会写明「这几个参数是你写死的，我按原样提交」；上游不接受就按失败全额退回，
  卡片上写上游原话，回答里再补一句「换回默认档再试一次」。

  提示词改写的 JSON/纯文本/失败兜底/带上下文、locked 参数原样发给上游、只写指令不扣钱）。
- lint 0 error / 24 warning（668 文件）、`tsc -b` 干净、`npm run build` 通过、密钥扫描无命中。

  文字没有被裁（clip 全 0）。
- 集成验收只用本地假上游：口语那句「帮我出个视频，咖啡店门口的雨夜」真的建出视频任务、
  aspect_ratio 9:16、扣 15 积分；`1080p 12 秒` 与 `2048x2048` 都断言了**真的发到上游请求体里**。

## 边界（下一轮要补的）

- 提示词改写只用**注入的假 call** 验过；真调一次 DeepSeek 看质量要 ¥0.00x，等用户点头。
- `1080p` / `12 秒` / `4:5` / `2048x2048` 都**没有真调上游**：上游到底收不收未知，
  不收就是失败全额退回（失败不收费），所以这不是「已经能出 1080p」的承诺。
- 视频仍只有 4 秒 / 8 秒是已知可用的；1:1 视频与 480p 也仍未真调（老的待办）。
- 多轮修改（「改成 8 秒」「换个比例」）还没做：那要 function calling / 结构化输出，属于下一轮。
