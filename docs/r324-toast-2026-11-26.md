# r324：全局提示条（toast）四处小改（v0.9.296，2026-11-26）

提示条是全站最高频的一条反馈：复制、保存、撤销、失败，每一次动作都靠它回话。
它原来只有一个行为——「挂上、停 2.4 秒、直接摘掉」。这一版把它拆成四件事，
全部按真渲染量出来的数字改，不是拍脑袋调的。

## 一、改了什么

| 原来 | 手感上的问题 | 现在 |
| --- | --- | --- |
| 固定 2.4 秒后直接摘掉 | 一条报错（「复制失败：浏览器没给剪贴板权限」）还没读完就没了；消失是硬切 | 停留 = **2.4 秒 + 60ms × 字数**，封顶 6 秒；收尾**淡出 + 下沉 8px（180ms）**走完再卸载 |
| 连按同一个动作没有任何反应 | 第二次点「保存」，屏幕上跟第一次一模一样——看着像没点上 | 每次提示换一个 key，**进场动画重放**一次（同一套 8px 上浮 + 淡入） |
| 长文案只能挤成一行 | 窄屏上会被视口挤掉 | `max-width: min(560px, 100vw - 48px)`，窄屏换行、不贴边 |
| 开了「减弱动态效果」也照样等 180ms | 白等一段看不见的收尾 | 收尾时长按媒体查询给 0，**停满就收**，不留尾巴 |

真源：`src/domain/toast.ts`（纯函数：`toastDuration` / `toastExitDelay`）；
计时器在 `src/App.tsx`（`notify`）；收尾样式在 `src/styles/shell.css`（`.vq-toast.is-leaving`），
进场那条 `vq-toast-in` 仍在 `src/styles/motion.css`。

另外几组：

- **收尾真是过渡**：29 字那条从 4656ms 起，页面自己的 rAF 采样读到
  `1 → 1 → 0.4914 → 0.2570 → 0.1423 → … → 0.0039`，其中 0<opacity<1 有 5 帧（约 18ms 一帧）。
- **连按不会按第一次的时间消失**：第一次挂上到两条都走完 = 4669ms（1.3s + 2.76s + 0.18s）；

- **减弱动态效果**：整段生命 2776ms ≈ 停留时长，半透明帧 0 个，`is-leaving` 一次都没出现

- **390 宽**：那条 29 字提示宽 342px（= 390 − 48）、2 行、矩形 24–366 / 764–820 全在视口内，

- **1440 宽**：宽 446px（`max-width: 560px` 未触发裁切）、单行；`position: fixed`、`bottom: 24px` 没变。

## 四、这一轮学到的两条

1. **「有没有出现」和「是不是按新的一次重算」是两件事。** 连按那一段，第一次的节点会在换 key 时先被摘掉，
   日志里出现一条 `removed` 就收工，会把第二条当成已经走完（第一版脚本就量成了 1905ms）。
   要看的是「最后一条 removed 减最后一次 added」，并且等两条都走完。
2. **超时/动效的时长写在 JS 里时，CSS 的 `prefers-reduced-motion` 管不到它。** 收尾那 180ms 是
   JS 计时器给的，媒体查询只能把过渡压成 1ms；所以 `toastExitDelay(true) === 0` 必须在 JS 里判一次，
   否则开了「减弱动态效果」反而要多挂 180ms 的空壳。

## 六、边界（写清楚，不留想象空间）

- 停留时长是**启发式**（每字 60ms、打底 2.4 秒、封顶 6 秒），不是按人眼阅读实验测出来的；超过 60 字一律 6 秒。
- 提示条仍然**只有一个**：后一条直接顶掉前一条。连按同一个动作时旧节点会被换掉（这正是「重放」的实现方式），
  不是两条叠在一起；也不是队列，没有「上一条」可翻。
- 没有手动关掉（×）——2.4~6 秒之间它会自己走。
- **图标仍然是 ✓**：失败提示（「复制失败：浏览器没给剪贴板权限」）也挂着那个勾。
  改它要给 `onToast` 加一个显式的 tone 参数：全站 119 处提示、18 处类型声明，属于下一轮的事，
  这一版没有顺手改（顺手改会让一半失败提示带 tone、一半不带，比现在更不一致）。
- 收尾那 180ms 里如果又来了新提示：新提示直接顶上（旧的那条不再淡出）。
