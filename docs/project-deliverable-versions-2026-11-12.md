# 交付稿把每一版都写全（v0.9.4，2026-11-12）

## 一、这一片补的是哪条缝

v0.9.2 的交付稿写当前这一版：脚本、分镜、这一版的评审、最近 8 次运行。
v0.9.3 让它能印成 A4。两份都缺同一个东西：**历史版本**。

以前版本对照只有一张表——每版几个节点、评过几次、跑过几次、最后结论。
编导把这版和上一版一起发过来时，收到的人只能看到「v1 评过一次，通过」，
看不到那一版当时说了什么、为什么没过、上次是怎么改的。要查就得回作品页，
一版一版点「打开画布」。

这一轮把「每一版」写成稿子里的一节：脚本、画布变化、评审结论、运行结果。

## 二、现在一份稿子里有什么

| 位置 | 内容 |
| --- | --- |
| 版本对照 · 表 | 全部版本一行一版：画布名、节点、脚本段数、评审次数、运行次数、最近结论、归档时间 |
| 版本对照 · 一句 | 「v3 比 v2：画布多 1 个（出图）；脚本少了 1 段（挑豆）、钩子换过」 |
| 版本对照 · 每版一段 | 从新到旧，每版 4 行：归档、画布变化、脚本快照、评审结论、运行结果 |
| 打印版 | 同一份 Markdown 渲染，不需要额外做任何事 |

示例（生产实测，两版的项目）：

```
### v1 · 毛衣快速折叠收纳法

- 归档：2026-11-12 17:36 · 画布 2 个节点
- 脚本：这一版没存快照（开版时还没有快照功能），当时的口播找不回来了
- 评审：没评过
- 运行：3 次，2 次失败（最近一次 2026-11-12 17:56 失败：「复刻脚本：模型这次没写完输出……」）
```

## 三、脚本快照：这一片真正的数据改动

版本对照以前最说不清的一件事：**「v1 的脚本是什么样」根本查不到。**

原因是数据模型：脚本只有一份，挂在作品上（copy-on-write，第一次改脚本才复制模板的版本）。
开新版本只归档画布指针，脚本继续沿用、继续被改。所以翻回 v1，看到的是**现在的**脚本。

这一版开始，开新版本时把这一版的脚本存进归档（`archiveProjectVersion` 收一个 `script`）：

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 归档条目 | `{ n, flowId, name, archivedAt }` | 多一个 `script` 快照（钩子 / 每段口播 / 屏幕字 / 目的 / 起止与预计时长） |
| 快照来源 | — | 归档那一刻的作品脚本（没改过就是模板脚本，标 `source: template`） |
| 旧版本 | — | 没有快照就是没有：稿子里写「这一版没存快照」，不拿现在的脚本冒充 |
| 页面 | 只显示节点 / 评审 / 运行 | 多一项「N 段脚本」；旧版本显示「脚本没存快照」 |

一个量级：一段快照约 1 KB，20 版最多 20 KB 一个作品。存的是已经归一化的形状（拼接、超长都截断过）。

### 快照能比出什么

```
脚本：4 段，钩子「手冲咖啡三分钟讲完」；比 v1 多 2 段（挑豆、收尾）、1 段口播改过、钩子换过
```

- 多段 / 少段：按段名对集合，点名是哪几段。
- 改口播：同名段落按出现顺序比文本；只改名不改词不算改动。
- 钩子：换过 / 没变。
- 一样：写「跟上一版一样」，不硬找差异。

画布同理：复制版本时节点 id 沿用，按 id 比内容指纹，给出「多 / 少 / 改」并点名节点标题。

## 四、三条边界

1. **只写发生过的事。** 没快照就说没快照；快照在就照当时的样子比，不拿当前脚本补一份。
   版本 0（版本划分之前记的评审）按页面同一套规则折进 v1。
2. **不写凭证。** 分享 token 仍然不进稿；快照是内容，不是能打开作品的钥匙。
3. **版数多时只写最近几版。** 每版明细最多 6 版（`DELIVERABLE_LIMITS.versions`），
   更早的只在表里；表永远全量（一条作品最多 20 版）。运行与评审明细各自另有上限，
   总数比明细多时写清楚「明细只留最近 N 次」。

## 六、顺手修的两处

1. **打印页在本地演示下打不开。** 打印路由原来一律要求登录态，本地 `VQ_REQUIRE_AUTH=0` 打开只有一张
   「登录已过期」，没法验排版。现在与其它接口同一套规则：生产必须登录，本地不认人但照常可用。
2. **版本 0 的评审全文导不出来。** 导出时找「当前版的最近一次评审」只认版本号相等，
   老作品的评审记在版本 0 上，v1 会显示「记录的正文没读到」。改成与页面同一套折进规则。
