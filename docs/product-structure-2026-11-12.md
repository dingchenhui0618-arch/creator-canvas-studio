# 网页产品结构：目标模式与改法（2026-11-12）

结论先行：**现在是「8 个各自不错的页面」，目标是「一条内容从发现到审片的流水线」。**
纵向（单页质量）8 分，横向（页面之间）5 分。差的不是功能，是**缺一个把页面串起来的主线对象**。
本文件定下目标模式与分批改法，后续按 P0 → P1 → P2 推进；桌面端（Electron + 本地 agent loop）在这之后。

## 一、现状的五个结构问题（有据可查）

1. **导航是能力清单，不是工作路径。**
   侧栏六个平级入口：工作台 / 爆款雷达 / 模板库 / 智能体 / 画布 / 视觉评审。真实价值链是
   「找选题 → 拆结构 → 改成我的 → 编排/生成 → 审片 → 沉淀模板」，界面把它切成了六个互不相连的目的地，
   第一次进来的人得自己知道先去哪。

2. **首页是仪表盘，不是工作台。**
   `01 画布 / 02 最近运行 / 03 模板库` 编号在暗示顺序，实际是三个并列清单；内容全是「你已经有什么」，
   没有「你现在该做什么」。页头与页脚重复同一句「都在你的账号下」。

3. **主 CTA 指向的不是主价值。**
   右上角「新建」打开「开始一个新项目 / 你想先创建什么？」，选项只有 **智能体** 与 **资产画布**——
   没有「从一条爆款开始」。而「项目」这个词在产品里并不存在，只是个弹窗标题。

4. **模板库止步于「看」，没有「改」。**
   模板详情是只读抽屉 + 复制/导出。「拿到模板之后的下一步是改成我的」，现在只能复制出去。
   同时 5 张统计卡里 2 张（待解析、画布工作流）是运营口径，用户不需要在第一屏看到。

5. **三个页面在生产同一种东西，彼此不通。**
   模板详情、智能体对话、画布节点都能产出脚本/分镜，但：智能体输出不能存为模板、不能送到画布；
   模板不能把脚本带进画布继续改；评审是单向入口，评完不回模板也不回画布；
   （智能体这两个出口已在 v0.5.2 补上，见第三节 P0-3。）
   画布页还套了两层 chrome（我们的侧栏+面包屑 + BD Canvas 自己的工具栏与品牌行）。

## 二、目标模式

### 2.1 一条主线：作品（Project）

> 一条作品 = 它从哪来（来源）+ 用的哪条模板 + 现在这版脚本/分镜 + 画布 + 评审结论 + 运行记录。

- 作品是**所有页面共享的对象**，其他页面都是它的某个视角，而不是并列的目的地。
- 从雷达「一键复刻」、模板「套用」、画布「新建」都**落进同一张作品**；
  评审、运行、导出都挂在作品下，随时能回到「这条内容现在到哪一步了」。
- P0 阶段先不建表：用 `projectId` 贯穿现有对象（模板改编产物、画布 flow、评审、运行记录都带上它），
  项目页在 P1 落地。**先打通引用关系，再谈页面。**

### 2.2 页面职责（每个页面只回答一个问题）

| 页面 | 唯一职责 | 回答的问题 |
| --- | --- | --- |
| 工作台 | 下一步做什么 | 我现在该点哪里？ |
| 作品（新） | 这条内容到哪一步了 | 脚本、画布、评审、运行都在这条上吗？ |
| 发现（原爆款雷达） | 有什么值得抄 | 今天有什么选题/结构？ |
| 模板库 | 有哪些可复用的结构 | 这条结构能直接拿来改吗？ |
| 模板详情 = 改编工作区 | 改成我这一版 | 改哪几段、套到哪个画布？ |
| 画布 | 把它跑出来 | 节点怎么连、这次跑得怎么样？ |
| 视觉评审 | 这版能不能发 | 按标准逐帧过不过？ |
| 智能体 | 帮我想/写 | 这一段能不能让它先起草？ |

### 2.3 导航（v0.6.0 已落地）

一级：**工作台 / 作品 / 发现 / 模板库**
工具区（次一级，仍是独立路由）：**智能体 / 画布 / 视觉评审 / 运行记录**
底部：**设置**（后台仍只从 `#/admin/<section>` 进，普通用户侧栏不出现）。

理由：智能体、画布、评审都是「能力」，从作品的某一步被带进去；把它们和「发现 / 模板」并列，
等于告诉用户「这些是同一类入口」，是当前混乱的根。

落地方式（v0.6.0）：侧栏按本表渲染（`src/nav.ts` 是唯一真源，侧栏与命令面板共用），
「爆款雷达」改名「发现」（路由 `#/radar` 不变）；工具页的面包屑多一段「工具」；
收起侧栏或窄屏时工具区标签变成一道发丝线，仍能一眼分出主线与工具；
另加 Ctrl / ⌘ + K 快速跳转（清单由导航真源生成 + 三个真动作）。

## 三、分批改法

### P0（约 4 天，不动服务端数据口径）

1. ✅ **工作台改成「下一步」**（v0.1.5 已上线）：主卡 = 最近改动的那块画布 + 一条主 CTA；
   下面三个场景化入口（从爆款 / 从模板 / 空白画布）；统计压进主卡右侧三数；删掉重复的页脚句与旧「新建」二选一弹窗。
2. ✅ **模板详情 = 改编工作区**（v0.1.5 已上线）：脚本段落与分镜可编辑；底栏在改编态只留「存为我的模板 / 取消」；
   服务端新增 `POST /api/templates/:id/adapt`，产物是个人新模板（`kind: adapted` + `adaptedFrom`），官方模板永不覆盖，
   也不复制原片互动数据与抽帧。实测：改一版 → 存下 → 列表出现「改编版」条目，原模板不动。
3. ✅ **智能体输出两个出口**（v0.5.2 已上线）：先让智能体按结构输出——正文之后强制附一个 ```draft JSON
   （标题 / 钩子 / 段落口播 / 分镜画面），服务端按口播字数算时长、整理成「段 + 镜」草稿；回复下面出现草稿卡，
   两个按钮「存为模板」（落成 kind=agent 的新模板）与「送到画布」（建 input → 复刻脚本两节点，提示词就是这份脚本）。
   两个出口都不扣积分（没有模型调用）；草稿上限 12 段 / 24 镜，没有草稿块就不给出口（不存假结构）。
4. ✅ **画布专注模式**（v0.1.5 已上线）：工具条「专注」收起侧栏与顶栏，只留 42px 状态条 + 画布；
   离开画布自动恢复，退出按钮常驻。
5. ✅ **模板卡片给主操作**（v0.1.5 已上线）：卡片常驻「用这条改编」；改编版不显示原片互动数据；
   统计卡 5 → 3（模板总数 / 已解析 / 累计复用）。

### P1（1–2 周）

引入作品对象与作品页：`#/projects/<id>`，聚合来源、模板、脚本、分镜、画布、评审；
画布与评审成为作品内视图（保留独立路由以便直接打开）。同期做项目级「下一步」推荐。

**第一片已上线（v0.1.7，2026-11-12）**：

- ✅ 作品对象与两条路由：`#/projects`（列表）、`#/projects/<id>`（作品页）；服务端 `/api/projects` 五条路由。
- ✅ 作品**只存引用**：`templateId`（脚本与分镜仍在模板上）、`flowId`（画布仍是流程）、`status`。
  评审用 `projectId` 反向关联，删作品只解绑、不删评审。作品不复制脚本分镜，改模板作品跟着变。
- ✅ 作品页按「下一步」组织：没画布 → 套用模板开画布（真建流程并绑定）；有画布没评审 → 送评审；
  评过 → 继续改；交付 → 收尾。主卡与工作台读同一个函数，两处口径不分叉。
- ✅ 入口：模板抽屉「用它做作品」（主操作）、作品列表空状态、工作台主卡优先显示最近作品。
- ✅ 评审可记入作品：`#/review/project/<id>`，页头写明「记入作品：X」，落库带 `projectId`；
  作品不存在时**先拒绝、不扣积分**。
- ✅ 作品改名：作品页标题就地编辑（点笔 → 输入 → 回车保存 / Esc 取消），服务端拒空名。
- ✅ 多版本（v1/v2 对照）：`POST /api/projects/:id/versions` 复制当前画布、旧画布归档成 vN，
  作品只前进不改写；作品页「版本对照」一行一版，列出画布节点数、评过几次、最近结论，
  旧版画布仍可打开。评审落库时按当时版本记账（`version`），v1 兼容版本划分之前的记录。
- ✅ 修正：地址里点名了内置流程（`#/canvas/<flowId>`）时画布默认进内置编排，
  不再先显示画布服务的另一块画布。
- ✅ 运行归属集（v0.2.4，2026-11-12）：作品详情一次取回当前版 + 归档版的全部运行（按开始时间倒序、
  摘要不带逐节点输出），每条带 `version` 与「画布还在不在」；作品页新增「运行记录」区块，
  版本对照每行多一个「N 次运行」，列表卡第四格显示运行次数。运行仍存在画布服务里，作品不复制运行数据。
- ✅ 顺手修掉上一片记下的评审 500：根因是 `max_tokens` 给太小（画布节点 1200、评审 3000），
  推理型模型的思考把预算吃满，正文被截断。现在评审提示词与服务端都限死条数（问题 ≤5、修正 ≤3），
  被截断时把预算放宽 1.6 倍重试一次，画布节点起点抬到 6000；生产两版画布都真跑通（22.6 秒 / 27.2 秒）。
- ✅ 作品页直接改脚本（v0.3.0，2026-11-12）：脚本 copy-on-write——默认跟随模板，第一次保存才复制成作品自己的版本
  （钩子 + 段落 / 口播 / 屏幕字，按口播重算「要念几秒」），模板与别的作品不动；「恢复模板脚本」回到跟随。
  开画布改用作品脚本生成输入 + 复刻节点；已有画布保存脚本时同步「复刻脚本」提示词（手改过的不覆盖）。
  顺手修掉结构串取错字段（`title` → `beat`）导致生产提示词结构为空的问题。

- ✅ 作品级只读分享（v0.4.0，2026-11-12）：作品页生成 `#/share/project/<token>` 只读链接，不登录可看；
  公开视图逐字段白名单（不带账号、画布、模板 id），分镜帧走带 token 的地址；停止分享即失效、重开换 token。
- ✅ 智能体结构化输出与两个出口（v0.5.2，2026-11-12）：回复附 ```draft 块 → 服务端整理成「段 + 镜」草稿
  （时长统一按口播字数估），回复下方草稿卡给「存为模板 / 送到画布」；存出 kind=agent 的模板（模板库标「智能体」、
  不显示原片互动数据、详情写来自哪个智能体），送到画布建 input → 复刻脚本两节点。没有草稿块就没有出口。

**P1 完成（2026-11-12）**：作品对象、作品页、改名、多版本、运行归集、脚本 copy-on-write、只读分享、
智能体结构化输出与两个出口都已上线。作品页现在是日常入口；下一阶段已进 P2，导航先行落地。

### P2（已开工，导航先落地）

**桌面端形态定案**：先做「桌面优先的网页外壳」（固定左侧栏 + 顶栏 + 内容区），
Electron 只负责把同一外壳套进本地窗口、多一个「本地工作区」。这样 P2 不必等 Electron，
导航也不会做两遍——本地 agent loop、审批与压缩协议之后接在这套外壳后面。

**导航收敛已上线（v0.6.0）**：

- ✅ 一级 4 项（工作台 / 作品 / 发现 / 模板库）+ 工具区 4 项（智能体 / 画布 / 视觉评审 / 运行记录）+ 底部设置；
  导航真源是 `src/nav.ts`，侧栏与命令面板共用，不再各抄一份。
- ✅ 爆款雷达改名「发现」，路由 `#/radar` 不变（旧链接、收藏、分享都不失效）。
- ✅ Ctrl / ⌘ + K 快速跳转：页面 / 工具 / 设置 / 动作四组，↑↓ 选择、Enter 打开、Esc 关闭并还原焦点；
  输入框内不抢键。
- ✅ 工具页面包屑多一段「工具」；窄屏与收起态只剩图标，按钮保留可访问名与 tooltip。

**桌面外壳与本地工作区已上线（v0.7.0）**：

- ✅ Electron 外壳（`electron/main.cjs`）：单实例、窗口位置记忆、中文菜单、外链交系统浏览器、同源导航限制；
  页面刷新时中止挂起的审批。网页版不受影响。

  一轮最多 8 步；有副作用的工具走审批，拒绝会写回上下文。
- ✅ 四个本地工具：`list_dir` / `read_file`（只读）、`write_file` / `run_command`（必须批准，命令 60s 超时）；

  摘要失败不动历史。
- ✅ 密钥不下发：桌面端用账号会话调 `POST /api/local-agent/complete`，一轮只扣一次积分（按 `turnId`），

- ✅ 渲染侧 `#/local`：会话栏 + 对话流 + 工具卡（参数按路径/内容摊开）+ 审批卡 + 压缩提示；
  网页版打开同一地址会如实说明不可用。

**本地工作区的长期记忆与两个新工具已上线（v0.8.0）**：

- ✅ 跨会话长期记忆：按工作区落盘（`userData/local-agent/memory/<工作区哈希>.json`），
  智能体用 `remember` 工具记、用户发「记住：…」直接记（不调模型、不扣积分）；
  召回按词语重合度排序、最多 8 条 / 1600 字、满 40 条先淘汰最少召回的；面板可看原文与召回次数、可单条删、可清空。
- ✅ 更多本地工具：`search_text`（只读，跳过依赖与产物目录，最多 60 处命中）、
  `edit_file`（必须批准，原文需在文件里唯一，拒绝时让你多带上下文）。
- ✅ 落盘加固：所有 JSON 走 `writeFileAtomic()`，Windows 上 rename 被占用时退避重试，避免「新建会话后再存一次」偶发失败。
