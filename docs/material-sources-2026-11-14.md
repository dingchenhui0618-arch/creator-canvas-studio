# 公共模板的素材来源与下架通道（v0.9.82，C4）

上线就绪清单里 C4 那一行写的是：「25 条含第三方平台封面与作者名，对外收费前出一页『素材来源与下架通道』说明；举报下架已有」。
举报与下架的执行链路早就有了（v0.9.x 的举报队列 + 下架收回公共模板 + 停分享链接），缺的是**被收录的人能找到的那一面**：
他得先知道我们存了什么、存在哪、怎么让我们撤掉，而不是先注册一个账号去猜。

## 一、问题

| 现象 | 后果 |
| --- | --- |
| 素材从哪来、存了什么，只有内部知道 | 被收录的人问「你们凭什么有我的片子」时没有可指的页面 |
| 下架只能「知道自己是哪条模板」才能报 | 大多数权利人只知道「你们库里有我这条」，卡在第一步 |
| 页面里的条数如果写死 | 三个月后就是一句假话（写 25 条、库里 31 条） |
| 发布公共模板不检查出处 | 一条没有原片链接的记录放进去，被侵权的人连「是哪条」都指不出来 |

## 二、三条路，为什么选这条

| 方案 | 结论 |
| --- | --- |
| 写一篇静态说明（帮助中心第 4 篇 / 条款页加一段） | **否**：数字会过期；被收录的人要的是「怎么撤」，一段说明里没有可提交的入口 |
| 在后台加一页「素材清单」给运营看 | **否**：外面的人看不见，等于没有 |
| 公开页 + 现算数字 + 页内直接提交下架 | **选**：一个地址讲清口径，数字从库里算，提交不用注册；「指名不了具体是哪条」也收 |

**放弃的东西**：不做「公开列出 25 条模板的标题与链接」——那是把别人平台的封面、作者名在匿名页面上再放一遍，方向恰好相反；
也不做人工申诉工单系统（现有举报队列 + 审计够用）。

## 三、做法

1. **公开页 `#/sources`**（不进工作台外壳，不登录可读）：素材从哪来（三类来源各自存什么）、存了什么 / 不存什么、现在库里有多少、
   怎么要求下架、处理之后会怎样。页脚、条款页、帮助中心、登录页、工作台首页、模板抽屉都有入口。
2. **数字现算** `/api/sources/summary`（公开只读）：只回计数与平台分布——公共模板条数、留着原作品地址几条、记着作者几条、
   解析过 / 只存链接各几条、加入时间区间、已处理下架几条。**不回标题、作者与原链接**：那属于登录后的模板库。
3. **出处闸**（`publicPublishBlocked`）：平台素材（`saved/replica/adapted`）没有原作品地址就不许发布进公共模板；
   画布与智能体自己产出的模板本来没有原片，不受这条限制。判断按「这次保存之后的样子」，所以「补链接 + 打开发布」一次提交能过。
4. **未指名也能报**：举报目标新增 `target.kind = material`（素材页提交、指名不了具体条目）。后台显示「素材页 · 未指名模板」，
   处理时提醒去模板库把那条收回；管理员点「下架」对这种举报只改状态，避免误以为收回了一条不存在的模板。
5. **顺手修**：举报成功那一屏原来用 flex 排「已收到受理编号 rep_x（…）」，图标、编号、括号说明各自成了 flex item，
   在 480px 宽的弹窗里被压成窄条竖着断行；改成正常段落流，编号能整句读、能抄下来。

## 四、本地验收（真渲染 + 真请求）

演示库：6 条公共模板（抖音 4 / 小红书 2），另有 1 条私有、1 条已删的公共模板（都不该进数字）。

| 检查 | 结果 |
| --- | --- |
| `/api/sources/summary` | `total 6 · 抖音 4 / 小红书 2 · 有原片链接 6/6 · 有作者 6/6 · 解析过 2 · 只存链接 4 · 加入 2026-11-02 至 2026-11-07 · 已处理下架 1` |
| 私有与已删条目 | 不进数字（total 6，不是 8） |
| 出处闸（HTTP，管理员会话） | 清空原链接 → 发布 `400 NO_SOURCE`（提示「先在『原链接』里补上再发布」）；**同一次提交**补链接 + 发布 → `200 shared:true`；收回 → `200` |
| 下架申请（页面真点） | 弹窗 → 填情况 → 提交：页面顶条「举报已提交，受理编号 `rep_95a4cb95`」，弹窗留在「已收到受理编号」那一屏；落在 `reports.json` 的 `target.kind = material`、状态 `open` |
| 数字没读到 | 接口失败时页面写「数字没读到（/api/sources/summary 没有响应）」而不是摆 0 |

## 六、踩到的坑（如实记）

1. **出处闸一开始只看库里的旧值**：本地真跑才发现「补链接 + 打开发布」一次提交会被 400 拦住——正当操作被当成违规。
   改成按「这次保存之后的样子」判断，并把这条写进测试。
2. **举报成功那一屏是坏的**（上面第 5 点）：DOM 断言和接口 201 都看不出来，真截图才看到一句话被压成窄条。
3. **设计栅格测试抓到两个随手数字**：`margin-top: 3px` 与 `padding-left: 20px`。仓库本来就有这条测试（4/8 栅格、圆角四档、字号 ≥11），
   改成 4px / 24px 才过——这条测试的价值在于它不会因为「只差 1px」放过。

## 七、边界

- 这一页说明的是**公共模板**；用户自己上传、抽帧与生成的素材按「隐私说明」走，两份文档不重叠。
- 下架 = 从公共模板收回 + 停掉分享链接 + 留处理记录，**不物理删除**；证据与申诉核对都靠它。
- 没写「48 小时内处理」这类时限：运营人手还没定，写上去就是编 SLA。页面写的是「按队列处理 + 留联系方式会收到结果」。
- 匿名提交仍受 IP 限流（每分钟 5 条）与 10 分钟同对象去重；恶意举报同样进队列、进审计。
- 出处闸只管「发布进公共库」这一步，不追溯历史：存量公共模板的链接覆盖率由页面数字自己暴露（生产见下一节）。

## 八、回退

旧的举报/下架链路没被改动，回滚只影响这一页与出处闸。

## 九、下一步

被收录的人这条路已经通了；收费前还缺的仍是外部输入：定价 + 商户号、配额数字、客服邮箱与主体信息。
工程侧可选：模板库列表里按平台筛「来源」，或把下架处理结果回给举报人（等 SMTP）。
