## 三、A 类：上线阻断项（必须做，按顺序）

### A1. 任务与扣费的最终一致性（P0，现在就在漏）

**状态：已修（v0.9.48，2026-11-13）**

- 任务落进 SQLite `replicate_jobs`（与账号、积分同库），状态 / 步骤 / 进度 / 日志 / 错误 / 模板 / 说明 / 积分 / 是否已退 / 时间一行记全；重启后 `GET /api/jobs/:id` 仍有记录，不再 404。
- 先落草稿再扣费（账本 `ref` = jobId）；新增 `outstandingCharge()` 按账本净额退款，启动恢复 / 停机收尾 / 路由兜底共用一条幂等退款，连续重启不会多退。
- `SIGTERM` / `SIGINT` 先标中断 + 退款再退出；启动时把上次的 `queued` / `running` 标失败、退款、清临时目录；流水线 `aborted` 守卫避免已退款任务再建模板。
- 生产实测：任务停在「解析链接」时 `systemctl restart visionqa`，停机日志 `shutdown SIGTERM interrupted:1`，重启后 `error` + `refunded:true`，余额 9954 → 9954、流水 −10 / +10（ref 同为 jobId）。见 [复刻任务落库与扣费一致](job-recovery-2026-11-13.md)。
- 流程运行那一半已在 v0.9.59（2026-11-13）补上：运行开始先落盘、扣费 `ref` = 运行 id、启动恢复与停机收尾都按账本净额退，失败 / 中断 / 幂等退三条路径共用 `refundRunCredits()`。生产实测：重启后 `runs.recovered {recovered:1, refunded:1}`，运行状态 `interrupted`，余额 9948 → 9950。见 [画布运行的钱与记录](flow-run-recovery-2026-11-13.md)。

**修之前的现状证据（留档）**
- `server/jobs.mjs:12` 任务表是进程内 `Map`，上限 40 条；进程退出即全部消失。
- `server/index.mjs:628` 先扣 10 积分再起任务；退款只挂在 `startReplicate` 的 `onSettled` 回调里（`:634-637`），进程被杀则回调永不执行。
- `scripts/deploy.sh:42` 每次发版 `systemctl restart visionqa`；全仓 `grep SIGTERM|SIGINT` 无命中，Node 默认直接终止。
- 生产 systemd 未设 `MemoryMax`，机器 1.86 GB 内存 + 6 GB swap 已用 1.5 GB；一次复刻同时跑 ffmpeg 与逐帧视觉，重启/OOM 都可能杀在中途。

**影响**：用户被扣 10 积分，`GET /api/jobs/:id` 永远 404，模板不入库、也没有任何退款流水。发一次版就可能发生一次；内测用户第一次遇到就是「这产品骗钱」。

**怎么做**
1. 任务落盘：`data/jobs/<id>.json` 记录状态机（queued/running/done/error/interrupted）、owner、ref、credits、时间戳；写入走已有 `enqueueWrite` 串行化。
2. 启动对账：服务启动时扫 `data/jobs/*.json`，把 `running` 改成 `interrupted`，按 `job.id` 幂等退款（先查 `credit_ledger` 里有没有同 ref 的 `replicate-refund`）。
3. SIGTERM/SIGINT：停止接新任务，给 8–10 秒收尾，把未完成任务写 `interrupted` 并退款，再 `exit(0)`；部署脚本等待服务真正退出再换文件。
4. 前端：`/api/jobs/:id` 返回 `interrupted` 时显示「任务被系统中断，积分已退回」，不再只有一句 404。
5. 顺带把流程运行（`/api/flows/:id/run`）也纳入同一套对账——它同样只靠进程内回调退款。

**验收**：起一个真实复刻，中途 `systemctl restart visionqa`；重启后该 job 返回 `interrupted`，余额 +10，流水多一条 `replicate-refund` 且 ref=jobId；连续重启两次不重复退；单测覆盖「运行中重启」「已完成后重启」「退款幂等」三种。

**估算**：1.5–2 人日。

### A2. 备份一致性与异地（P0）— 代码部分已修（v0.9.49），异地仍缺目的地

**已修（v0.9.49，2026-11-13）**
- 每个 `*.db` 用 `VACUUM INTO` 生成一致性快照，归档不再含 `-wal`/`-shm`；manifest 记行数与 integrity_check。
- 归档整体加密（scrypt + AES-256-GCM，`.tgz.enc`），口令在 `/etc/visionqa/backup.key`（`root:visionqa 0640`），状态文件只留指纹。
- 每次备份后立即做恢复演练（解密→解包→integrity_check→账号/模板条数→真解一把 Key），失败退出码 5 让 systemd 标红；异地副本失败退出码 4。
- `--offsite` / `VQ_BACKUP_OFFSITE` 已实现（复制 + sha256 校验 + 独立保留份数），线上尚未配置目的地。
- 后台「系统与版本 → 数据备份」可见最近时间/大小/耗时/加密/演练结果/异地副本/在盘份数。
- 生产实证：18,918,389 字节加密归档、演练 `users 1 / templates 28 / keys 2 / keyDecrypt ok`、独立 `restore-backup.mjs` 还原到 `/tmp` 通过、错口令退出 6；5 份旧明文归档在新归档演练通过后删除。
- 细节见 [备份一致性、加密与可恢复性](backup-consistency-2026-11-13.md)；验收 442/442、oxlint 0/6、tsc 干净。

**现状证据（修前）**
- `scripts/backup.mjs:30` 直接 `tar` 活数据目录（含 SQLite 的 `auth.db` 与 `-wal`/`-shm`），没有先做一致性快照。
- 备份目录 `/var/backups/visionqa` 与数据同机、同盘（`/` 只有一块 vda3）；机器没了两份一起没。
- 备份包含 `.model-keys.secret`，目前是明文 tar，一旦异地存放等于把 Key 池的钥匙也带出去。
- 恢复校验 `scripts/verify-restore.mjs` 只能手工跑，备份失败/损坏不会有人知道。

**怎么做**
1. SQLite 用一致性快照：`VACUUM INTO '/tmp/vq-snap/auth.db'`（node:sqlite 直接支持），JSON 走现有原子写；再把快照目录 tar，不再 tar 活库。
2. 整包加密：`age`（或 `openssl enc -aes-256-cbc -pbkdf2`），密钥离线保存，不落在同一台机器。
3. 异地：备份完成后 `rclone copy` 到对象存储（阿里云 OSS / 腾讯 COS），本地留 7 天、异地留 30 天。
4. 自动校验：每日备份后解包到临时目录跑 `verify-restore`，比对 users/keys/templates 计数，不一致或上传失败直接进告警队列并外推。
5. 记录 RPO/RTO：当前 RPO 24h、RTO 约 30 分钟，写进运维文档，别口头承诺。

**验收**：删掉本地数据目录 → 从对象存储拉最近一份 → 解包 → 起服务 → 登录、模板 25 条、两把 Key 都能解出明文；备份包内无明文密钥；把备份文件截断一半，自动校验必须失败并告警。

**估算**：1 人日 + 一个对象存储桶。

### A3. 邀请制闭环（P0，内测就要）—— 已修（v0.9.50，2026-11-13）

**现状证据**：全仓无 `invite` 实现；`VQ_REGISTRATION` 关闭；开号路径是后台「新建账号」+ 一次性临时口令（`docs/launch-remediation-2026-11-11.md`）。10–30 人内测能靠手工顶住，但每来一个人都要管理员在线，且无法追踪来源与赠送额度。

**怎么做**
1. `invites` 表：`code / created_by / max_uses / used / expires_at / credits / note / revoked_at`。
2. `POST /api/admin/invites` 生成（默认 1 次、7 天、100 积分），后台可见已用/剩余/撤销。
3. `/#/register?code=xxx` 自助注册：校验码有效、邮箱唯一、口令策略、**勾选条款并留痕**（D1 已有能力，复用即可）；成功后绑定邀请人、按配置发积分。
4. 反滥用：同 IP 24h 限 3 个号；新账号前 24h 复刻并发 1；赠送积分可配置「首次成功任务后解锁」，避免批量注册白嫖模型额度。
5. 邀请码一次性展示、可复制；被撤销后立即失效（410）。

**验收**：生成 1 个 1 次码 → 无痕窗口注册 → 登录 → 积分到账 → 同码再用返回 410；后台撤销一个未使用的码 → 立即失效；注册记录里能看到邀请人。

**估算**：1.5 人日。

**已修（v0.9.50，2026-11-13）**：`invites` / `invite_uses` 落 `auth.db`；码形如 `VQ-XXXX-XXXX`，大小写/空格/缺前缀都能认；占用是条件更新（并发只有一个人能拿到最后一次），撤销立即 410；注册关闭时 `#/register?code=…` 可自助开号，注册页预填并实时验码，后台「账号」页可签发/复制链接/撤销并看到已用次数与最近使用者；赠送积分按码配置、账本单独记 `kind=invite`；同来源 24h 限 3 个邀请号（IP 只存哈希），公开验码 10 分钟 20 次尝试限流。

**进展（2026-11-14，v0.9.81）**：「单次成本 vs 售价表」这半件做成了只读的「按次算账」（`server/pricing.mjs` + `GET /api/admin/pricing/estimate` + 后台「计费」页卡片）：汇率取档位（手填 > 指定档位 > 最便宜的一档），每次收入 = 积分 × 汇率；上游成本仍取 `usage_events` × 估算单价，分母只数「带用量」的调用，回填不进分母。算不出来就写「未定价 + 为什么」，**不写 0.00**；画布出图 / 出视频不扣积分但有成本，单独成行标「倒贴」并按张 / 秒摊。本地演示数据：复刻毛利 30%（收费动作里最低）、画布运行 −20%（收钱还倒贴）、画布出图 ¥0.28/张纯倒贴。生产实测：临时一档 ¥0.05/积分时折算收入逐行算出来，但 **89 条用量全是被回填的「只有次数」，所以成本一行都算不出来**——再填一组临时估算单价结果也不变（不把 0 token 摊成 0 成本）；验完清场（`plans 0`、`priced false`），余额 9950 未变，没有真实调用。剩下的：**配额的数**（等你定）、**10 次真实复刻的平均成本**（要真跑，需授权）——后者一跑，这张表就会第一次出现真实毛利率。见 [按次算账](unit-economics-2026-11-14.md)。

**现状证据**：积分单价与现金的换算不存在；复刻一次的真实成本（18 帧视觉 + 下载 + ffmpeg + 人工）从未测算；新账号 100 积分约等于 10 次复刻。（用量已从 v0.9.58 起逐次可查；v0.9.81 起「积分 × 档位汇率」能折成钱、与上游估算成本放在同一张表里，但生产还没有带用量的真实调用，成本仍算不出来。）

**怎么做**：给每次任务记 token 用量与耗时（网关已有任务台账，补 `usage` 字段）；跑 10 次真实复刻算平均成本；据此定价并加日/月配额（防单账号刷爆）。

**验收**：一张「单次成本 vs 售价」表；后台能看到每账号的消耗与配额；超配额返回 429 且给出可执行提示。

**估算**：0.5–1 人日。
