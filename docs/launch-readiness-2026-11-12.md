## 一、结论先行

**工程主干已经够用，剩下的阻断项集中在「钱、数据、进人、收钱、出事有人知道」五件事上，其中两件是现在就在漏的。**

- **立刻要修（每次发版都在漏）**：复刻任务只存在内存里，部署或 OOM 一杀进程，任务消失、已扣的 10 积分不退——用户看到「任务不存在」，钱没了。
- **上线前必须补**：备份与数据同机且是 tar 活库（整机故障=数据+备份一起没）、没有邀请闭环（开号靠管理员手工）、没有邮件通道（找回口令只能找人）、没有支付与定价（收不了钱）、没有外部告警（夜里挂了没人知道）、备案号与主体信息缺失。
- **不是缺口的**：账号安全（2FA/限流/会话）、计费一致性（同进程内扣退）、发布回滚、日志保留、CI、举报与下架、数据导出与删号、模板导出/分享/回收站/版本、检索历史——这些已经做完，不要再列进待办。

一句话：**离「30 人邀请内测」还差 A1、A2 两条硬修 + A3 的工程部分；离「公开收费」还要加 A4–A8 与一批外部输入。**

## 三、A 类：上线阻断项（必须做，按顺序）

### A1. 任务与扣费的最终一致性（P0，现在就在漏）

**现状证据**
- `server/jobs.mjs:12` 任务表是进程内 `Map`，上限 40 条；进程退出即全部消失。
- `server/index.mjs:628` 先扣 10 积分再起任务；退款只挂在 `startReplicate` 的 `onSettled` 回调里（`:634-637`），进程被杀则回调永不执行。
- `scripts/deploy.sh:42` 每次发版 `systemctl restart visionqa`；全仓 `grep SIGTERM|SIGINT` 无命中，Node 默认直接终止。
- 生产 systemd 未设 `MemoryMax`，机器 1.86 GB 内存 + 6 GB swap 已用 1.5 GB；一次复刻同时跑 ffmpeg 与逐帧视觉，重启/OOM 都可能杀在中途。

**影响**：用户被扣 10 积分，`GET /api/jobs/:id` 永远 404，模板不入库、也没有任何退款流水。发一次版就可能发生一次；内测用户第一次遇到就是「这产品骗钱」。

**怎么做**
1. 任务落盘：`data/jobs/<id>.json` 记录状态机（queued/running/done/error/interrupted）、owner、ref、credits、时间戳；写入走已有 `enqueueWrite` 串行化。
2. 启动对账：服务启动时扫 `data/jobs/*.json`，把 `running` 改成 `interrupted`，按 `job.id` 幂等退款（先查 `credit_ledger` 里有没有同 ref 的 `replicate-refund`）。
3. SIGTERM/SIGINT：停止接新任务，给 8–10 秒收尾，把未完成任务写 `interrupted` 并退款，再 `exit(0)`；部署脚本等待服务真正退出再换文件。
4. 前端：`/api/jobs/:id` 返回 `interrupted` 时显示「任务被系统中断，积分已退回」，不再只有一句 404。
5. 顺带把流程运行（`/api/flows/:id/run`）也纳入同一套对账——它同样只靠进程内回调退款。

**验收**：起一个真实复刻，中途 `systemctl restart visionqa`；重启后该 job 返回 `interrupted`，余额 +10，流水多一条 `replicate-refund` 且 ref=jobId；连续重启两次不重复退；单测覆盖「运行中重启」「已完成后重启」「退款幂等」三种。

**估算**：1.5–2 人日。

### A2. 备份一致性与异地（P0）

**现状证据**
- `scripts/backup.mjs:30` 直接 `tar` 活数据目录（含 SQLite 的 `auth.db` 与 `-wal`/`-shm`），没有先做一致性快照。
- 备份目录 `/var/backups/visionqa` 与数据同机、同盘（`/` 只有一块 vda3）；机器没了两份一起没。
- 备份包含 `.model-keys.secret`，目前是明文 tar，一旦异地存放等于把 Key 池的钥匙也带出去。
- 恢复校验 `scripts/verify-restore.mjs` 只能手工跑，备份失败/损坏不会有人知道。

**怎么做**
1. SQLite 用一致性快照：`VACUUM INTO '/tmp/vq-snap/auth.db'`（node:sqlite 直接支持），JSON 走现有原子写；再把快照目录 tar，不再 tar 活库。
2. 整包加密：`age`（或 `openssl enc -aes-256-cbc -pbkdf2`），密钥离线保存，不落在同一台机器。
3. 异地：备份完成后 `rclone copy` 到对象存储（阿里云 OSS / 腾讯 COS），本地留 7 天、异地留 30 天。
4. 自动校验：每日备份后解包到临时目录跑 `verify-restore`，比对 users/keys/templates 计数，不一致或上传失败直接进告警队列并外推。
5. 记录 RPO/RTO：当前 RPO 24h、RTO 约 30 分钟，写进运维文档，别口头承诺。

**验收**：删掉本地数据目录 → 从对象存储拉最近一份 → 解包 → 起服务 → 登录、模板 25 条、两把 Key 都能解出明文；备份包内无明文密钥；把备份文件截断一半，自动校验必须失败并告警。

**估算**：1 人日 + 一个对象存储桶。

### A3. 邀请制闭环（P0，内测就要）

**现状证据**：全仓无 `invite` 实现；`VQ_REGISTRATION` 关闭；开号路径是后台「新建账号」+ 一次性临时口令（`docs/launch-remediation-2026-11-11.md`）。10–30 人内测能靠手工顶住，但每来一个人都要管理员在线，且无法追踪来源与赠送额度。

**怎么做**
1. `invites` 表：`code / created_by / max_uses / used / expires_at / credits / note / revoked_at`。
2. `POST /api/admin/invites` 生成（默认 1 次、7 天、100 积分），后台可见已用/剩余/撤销。
3. `/#/register?code=xxx` 自助注册：校验码有效、邮箱唯一、口令策略、**勾选条款并留痕**（D1 已有能力，复用即可）；成功后绑定邀请人、按配置发积分。
4. 反滥用：同 IP 24h 限 3 个号；新账号前 24h 复刻并发 1；赠送积分可配置「首次成功任务后解锁」，避免批量注册白嫖模型额度。
5. 邀请码一次性展示、可复制；被撤销后立即失效（410）。

**验收**：生成 1 个 1 次码 → 无痕窗口注册 → 登录 → 积分到账 → 同码再用返回 410；后台撤销一个未使用的码 → 立即失效；注册记录里能看到邀请人。

**估算**：1.5 人日。

### A4. 收钱：定价、支付、发票（P0，公开收费）

**现状证据**：`billing.enabled=false`，`PLANS` 空数组，充值按钮 disabled；没有任何价格；`/api/billing/orders` 返回 501。

**怎么做**
1. 先定口径：`1 积分 = ¥?`，三档（体验 / 标准 / 团队），每档给积分与并发；价格由你定，我不编。
2. 支付：企业主体 + 已备案域名 + 商户号，接支付宝当面付或微信 Native 扫码；订单表 + 回调验签 + 幂等键 + 日对账。
3. 发票：先人工（用户申请 → 管理员开票），不接自动化开票。
4. 退款：未消费积分可退，已消费不退，写进条款。

**验收**：沙箱下单 → 支付 → 回调 → 积分到账；同一回调重放不重复加积分；后台能看到订单与状态；对账脚本能列出「支付成功但未加积分」的异常单。

**估算**：3–5 人日 + 通道审核周期。**依赖：定价与商户号。**

### A5. 邮件通道（P0，公开运营）

**现状证据**：生产环境无任何 SMTP 变量；忘记口令只有「联系管理员重置」一句文案（`LoginPage.tsx:439`）。

**怎么做**：接 SMTP（阿里云邮件推送 / 企业邮箱）→ 一次性 token（只存 hash、30 分钟、单次）→ 重置页；注册验证码可选；关键事件通知（充值到账、口令修改）。发信失败进告警。

**验收**：忘记口令 → 收信 → 重置 → 其他设备会话全部失效；同一 token 第二次使用失败；伪造/过期 token 拒绝。

**估算**：1 人日。**依赖：SMTP 凭据。**

### A6. 外部告警与拨测（P0）

**现状证据**：告警只落 `data/alerts.json` + 后台队列；生产环境没有 `VQ_ALERT_WEBHOOK`；没有任何外部拨测。

**怎么做**：配飞书/钉钉机器人 webhook；加三条外部探测（首页 200、`/api/health` ok、登录 POST 200），用 UptimeRobot 或服务器 cron；补两类告警：「服务刚重启过」「备份失败/校验失败」。

**验收**：`kill -9` 主进程 → 5 分钟内收到告警；把磁盘阈值调到必然触发 → 收到告警；备份脚本故意失败 → 收到告警。

**估算**：0.5 人日。**依赖：webhook 地址。**

### A7. 合规公示与主体信息（P0）

**现状证据**：`VQ_ICP`、`VQ_SUPPORT_EMAIL` 未配置，页脚与条款页不显示；隐私页没有运营主体全称、地址、统一社会信用代码、第三方处理者清单（只写「平台配置的大模型服务商」）。

**怎么做**
1. 配 `VQ_ICP`、`VQ_SUPPORT_EMAIL`（代码已支持，填环境变量即显示）。
2. 隐私说明补：处理者全称/地址/联系方式、第三方清单（DeepSeek 文本与视觉、SeeAPI 生成、红狐检索）、保存期限与实际清理策略对齐、投诉渠道。
3. 公安备案（网站上线 30 日内）、生成式 AI 服务登记/算法备案（属地网信办）——流程动作，不是代码。
4. AI 生成内容标识：导出的脚本/评审结论带「AI 生成」标注，符合《人工智能生成合成内容标识办法》（2025-09-01 施行）。

**验收**：页脚有备案号；隐私页能读到主体与第三方清单；导出文件带 AI 标识。

**估算**：0.5 人日 + 流程时间。**依赖：备案号、主体信息。**

### A8. 单位经济与配额（P0，决定能不能卖）

**现状证据**：积分单价与现金的换算不存在；复刻一次的真实成本（18 帧视觉 + 下载 + ffmpeg + 人工）从未测算；新账号 100 积分约等于 10 次复刻。

**怎么做**：给每次任务记 token 用量与耗时（网关已有任务台账，补 `usage` 字段）；跑 10 次真实复刻算平均成本；据此定价并加日/月配额（防单账号刷爆）。

**验收**：一张「单次成本 vs 售价」表；后台能看到每账号的消耗与配额；超配额返回 429 且给出可执行提示。

**估算**：0.5–1 人日。

## 八、怎么复验

```bash
# 1. 任务中断退款：跑一次复刻，中途重启，看 job 状态与积分
curl -s -b cookie.txt https://visionqa.wavisionai.cn/api/jobs/<jobId>
# 2. 备份可恢复：从对象存储拉一份，解包后跑校验
DATA_DIR=/tmp/vq-restore node --experimental-sqlite scripts/verify-restore.mjs
# 3. 邀请码：生成、注册、复用、撤销四条路径
# 4. 告警：kill -9 / 备份失败 / 磁盘阈值三条各触发一次
```

---

**一句话交接**：先做 39 批，它不需要你给任何东西；40 批开始需要备案号、客服邮箱与告警 webhook；41 批要定价与商户号。
