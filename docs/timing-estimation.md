# 分镜时长与台词对账（hypit P0-1 / P0-2 摸底）

> 2026-11-11 落地并上线，同日按 vendor 口径校准。对应 `docs/research/hypit-2026-11-11.md` 的 P0-1。

## 一、要解决的问题

一键复刻把一条视频拆成「脚本结构 + 分镜表」，用户是**照着这份表去拍/去改**的。
但视觉模型出表时有两个习惯，合起来就自相矛盾：

1. 把片长**平均切**给镜头（18 秒 8 个镜头 → 每镜 2.3 秒）；
2. 每段口播按 20–25 字写（它并不知道 2.3 秒只够念 10 来个字）。

结果：分镜表看起来完整，照着念却每段都超时。生产实测的那条 18.26 秒教程，
8 段口播合计 25.5 秒，仍比片长多 7.5 秒。

## 二、语速口径：直接对齐 hypit，而不是自己拍一个数

第一版我们自己取了「中文 4.5 字/秒 + 标点停顿」。做完才发现 hypit 有现成的
`@hypit/speech-estimate@0.1.1`（商业授权已到位），把它装下来对比了一次：

| 样本（同一条真实模板的 8 段口播，共 135 字） | 我们 4.5 字/秒 | hypit 慢 4.2 | hypit 中 5.25 | hypit 快 6.5625 |
| --- | --- | --- | --- | --- |
| 合计 | 34.5s | 32.1s | **25.7s** | 20.6s |

我们比 vendor 的中速**慢了 17%**。既然要长期向 hypit 借语义，口径就该一致，
否则同一句话在两个系统里得出两个结论。于是整段换成 vendor 的表：

```
zh: 慢 4.2 / 中 5.25 / 快 6.5625   单位每秒（单位 = 汉字）
en: 慢 4.2 / 中 4.6  / 快 5.6      单位每秒（单位 = 音节）
ja: 慢 6   / 中 7.5  / 快 9.375
```

三个随之而来的口径决定：

- **不再额外加标点停顿**：vendor 的密度本身是「含正常停顿的交付密度」，再加一次就是重复计算；
- **英文按音节**（启发式切分，没有 CMU 词典），数字按 1 个单位；
- **语速档位跟着模型对节奏的判断走**：`analysis.pacing` 的快/中/慢 → fast/normal/slow，
  复刻出来的口播密度才对得上原片节奏。

`tight` 阈值同时从 1.35 收到 **1.2**：一个镜头里台词多出 20% 就已经是多半秒到一秒，听得出来。

## 三、做法

| 出口（`server/speech.mjs`） | 作用 |
| --- | --- |
| `estimateSpeechDuration(text, {pace})` | 一段台词念完要几秒；空文本返回 0（没有台词可估，不是 0 秒）；有文本时下限 0.8 秒、上限 60 秒 |
| `speechUnits(text)` | 汉字 + 假名 + 英文/数字音节 |
| `speechFit(expected, actual)` | `tight`（>1.2）/ `loose`（<0.55）/ `untimed` |
| `reconcileTimeline(segments, {totalSec, pace})` | 逐段补 `expectedSec` + `fit` 并顺排；模型没给时长就按估算补齐 |
| `describeTiming(summary)` | 一句人话，界面直接显示，不出现「语速系数」这类术语 |

接入点：

- `server/vision.mjs`：段落（口播）与镜头（字幕）各跑一遍；**整条以段落口播为准**
  （那才是真念出来的内容，镜头字幕常只是屏幕上一行短字）；镜头没字幕时才退回镜头层。
- `server/templates.mjs`：`timing` 随模板落库（含 `pace` 与 `rate`）。
- `src/pages/TemplateLibraryPage.tsx`：分镜表上方一条对账，写明「按语速档「中」估（5.25 字/秒）」，
  念不完的镜头单独标出。
- `server/index.mjs`：复用此模板时提示词逐段写「这句要念 X 秒」，并声明语速口径。
- `scripts/recalc-timing.mjs`（新）：**换口径不用重新花积分复刻**，直接按已落库的脚本/分镜重算
  `expectedSec`、`fit`、`timing`；默认只试算，加 `--write` 才写回。

## 四、生产实测（2026-11-11，https://visionqa.wavisionai.cn）

真实检索「收纳」→ 抖音 18.26 秒教程 → 一键复刻 → 8 段 8 镜：

| 项 | 结果 |
| --- | --- |
| 台词合计 vs 片长 | **25.5 秒 vs 18 秒**（中速 5.25 字/秒） |
| 判定 | `tight`，超 7.5 秒；8 个镜头里 7 个台词偏多 |
| 每段 | 2.3 秒镜头里塞 3.0–3.4 秒口播 |
| 界面上 | 「台词约需 25.5s　原片 18s · 按语速档「中」估（5.25 字/秒）· 台词量比原片长，照着念完大约要多 8 秒」 |
| 复用提示词 | `#1 0s–2.3s（这句要念 3.4s）：毛衣别再乱塞了…` + 语速口径 |

### 第一版的一个 bug（已修）

抽帧最后一帧落在 16.1 秒，而视频长度是 18.26 秒。第一版拿「最后一帧」当总时长，
于是抽屉里同时出现「0:18」和「原片 16.1s」。现在总时长以 `meta.duration` 为准。

## 五、P0-2（hypit CLI 借壳）依赖摸底：生产机现在跑不了

只读探测（`root@139.196.123.28`，2026-11-11）：

| 项 | 实测 | hypit 要求 | 结论 |
| --- | --- | --- | --- |
| Node | **v22.12.0** | `>=22.15.0` | ❌ 差 3 个 patch |
| ffmpeg | 系统无（项目内有 `ffmpeg-static`） | 需要 | ⚠️ 可用项目自带那份 |
| Chromium | 无 | 需要（渲染管线） | ❌ 要装 |
| 内存 / CPU | **1.8 GB / 2 核** | README 提到 64 并发 Chromium | ❌ 产能差两个数量级 |
| 磁盘 | 12 GB 可用 | — | ⚠️ 够装，但 Chromium + yt-dlp + whisperx 体积未实测 |
| npm registry | 200（比 GitHub raw 通） | — | ✅ 装包这条路是通的 |
| 包 | `@hypit/hypit@0.3.2`，解包 1.49 MB，**136 个依赖** | — | ⚠️ 真装是几十万文件级别 |

**结论：现阶段不在生产机上硬装。** 三条可选路，按性价比排：

1. **单开一台 worker**（2 核以上 + 4 GB）跑 hypit，VisionQA 通过内部 token 调它——不影响现有服务，
   也和「生产机只跑 Node 服务」的现状一致；
2. **先只借语义**（已经做了：语速表、单位口径、复用语义），执行侧继续用现有 FFmpeg 链路；
3. 升级生产 Node 到 22.15+：风险低但不够——真正卡住的是 Chromium 池的内存。

另外：hypit 真正出片要靠 HypiHub / HiAPI / Pollo 这类 Provider 凭证，我们**一个都没有**；
所以即使装上，也跑不出一次真实 build。这一步要么买额度，要么就停在「只借语义」。

## 六、验收

- `scripts/test-speech.mjs`：**39 项断言**——vendor 三档密度、标点不加时、单位口径（汉字/音节/数字）、
  上下限、三档判定、缺时长补齐与顺排、整条汇总带档位、
  接进 `normalizeResult` 后每镜带 `expectedSec`/`fit`、片长以真实时长为准、快节奏估算更短。
- 回归 keyvault / model-routes / gateway / model-keys-e2e / canvas-admin / canvas-session / judge 全过；
  `npm run build` 通过、`npx oxlint` 0 错误。
- 生产：存量 1 条模板用 `recalc-timing.mjs --write` 重算（34.5s → 25.5s），
  重算前备份到 `/root/templates-backup-*.json`。

## 七、没验到的地方

1. **语速仍是「作者侧交付密度」，不是对真实人声的测量**。vendor 的文档口径如此；
   我们自己也没有做过语音转写语料的对账。
2. 这条教程原片可能没有人声（模型给的是「建议口播」），
   所以「台词比片长多」应读作**建议稿放不进这条时间轴**，不是原片主播语速。
3. `analysis.pacing` 由视觉模型判断，它自己也可能判错档位；判错一档，估算差约 25%。
4. 只有一条真实样本。等复刻累积到十几条，可以用「转写口播字数 / 镜头秒数」的实际分布来校准密度表。
5. P0-2 的产能（多少并发 Chromium、一条 15 秒片多久、多少钱）**完全没测**，因为跑不起来。
