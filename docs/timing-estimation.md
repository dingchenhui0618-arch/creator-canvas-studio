# 分镜时长与台词对账（hypit P0-1）

> 2026-11-11 落地并上线。对应 `docs/research/hypit-2026-11-11.md` 的 P0-1：
> 借鉴 hypit `estimateSpeechDuration` 的语义，用「这段台词念完要几秒」给复刻出来的分镜表做对账。

## 一、要解决的问题

一键复刻把一条视频拆成「脚本结构 + 分镜表」，用户是**照着这份表去拍/去改**的。
但视觉模型出表时有两个习惯，合起来就自相矛盾：

1. 把片长**平均切**给镜头（18 秒 8 个镜头 → 每镜 2.3 秒）；
2. 每段口播按 20–25 字写（它并不知道 2.3 秒只够念 10 个字左右）。

结果：分镜表看起来完整，照着念却每段都超时。生产实测的那条 18.26 秒教程，
8 段口播合计 34.5 秒，超出一倍。

## 二、做法

`server/speech.mjs`：

| 出口 | 作用 |
| --- | --- |
| `estimateSpeechDuration(text, opts)` | 一段台词念完要几秒；空文本返回 0（表示「没有台词可估」，不是 0 秒） |
| `speechFit(expected, actual)` | 三档：`tight`（念不完，>1.35 倍）/ `loose`（镜头空转，<0.55 倍）/ `untimed`（模型没给时长） |
| `reconcileTimeline(segments, opts)` | 逐段补 `expectedSec` + `fit`，并汇总整条；模型没给结束时间就按估算补齐、按上一段结束时间顺排 |
| `describeTiming(summary)` | 一句人话，界面直接显示，不出现「语速系数」这类术语 |

语速口径（`SPEECH_RATE`）：中文 4.5 字/秒（240–300 字/分钟取中位）、英文与数字 2.8 词/秒、
句末停顿 0.35 秒、句内停顿 0.18 秒、最短 0.8 秒、封顶 60 秒。

接入点：

- `server/vision.mjs`：段落（口播）与镜头（字幕）各跑一遍 `reconcileTimeline`。
  **整条以段落口播为准** —— 那才是真的被念出来的内容；镜头字幕往往只是屏幕上的一行短字，
  拿它估整条会系统性偏短。段落没有口播时才退回镜头层。
- `server/templates.mjs`：`timing` 随模板落库。
- `src/pages/TemplateLibraryPage.tsx`：分镜表上方一条对账提示；「念不完」的镜头单独标出。
- `server/index.mjs`：复用此模板时，提示词里逐段写「这句要念 X 秒」，并声明 4.5 字/秒的口径，
  复刻脚本不会再写出一份对不上时长的分镜。

## 三、生产实测（2026-11-11，https://visionqa.wavisionai.cn）

真实检索「收纳」→ 抖音 18.26 秒教程 → 一键复刻 → 8 段 8 镜：

| 项 | 结果 |
| --- | --- |
| 台词合计 vs 片长 | **34.5 秒 vs 18.3 秒**，差 16.2 秒 |
| 判定 | `tight`，8 段全部「念不完」 |
| 每段 | 2.3 秒镜头里塞 4.1–4.5 秒口播 |
| 界面上 | 「台词约需 34.5s　原片 18.3s · 台词量比原片长，照着念完大约要多 16 秒」 |
| 复用提示词 | `#1 0s–2.3s（这句要念 4.5s）：毛衣别再乱塞了…`，并写明「中文口播约 4.5 字/秒」 |

![模板详情抽屉：分镜表上方的时长对账，每段标出「台词约需 Xs」](screenshot-template-timing-2026-11-11.png)

### 第一版的一个 bug（已修）

抽帧最后一帧落在 16.1 秒，而视频长度是 18.26 秒。第一版拿「最后一帧」当总时长，
于是抽屉里同时出现「0:18」和「原片 16.1s」。现在总时长以 `meta.duration` 为准，
镜头时间按它 clamp。

## 四、验收

- `scripts/test-speech.mjs`：**31 项断言**——字速线性（45 字=10 秒、90 字=20 秒）、
  标点停顿、英文/数字不归零、上下限、三档判定、缺时长补齐与顺排、整条汇总、
  接进 `normalizeResult` 后每镜带 `expectedSec`/`fit`、片长以真实时长为准。
- 回归 `test-keyvault` / `test-model-routes` / `test-gateway` / `test-model-keys-e2e` /
  `test-canvas-admin` / `test-canvas-session` / `test-judge` 全过；`npm run build` 通过；
  `npx oxlint` 0 错误。

## 五、没验到的地方

1. **4.5 字/秒没有用真实人声语料校准**。它是中文短视频口播的常识取值（240–300 字/分钟）。
2. 这条教程片**原片可能根本没有人声**，模型按提示词给了「建议口播」。
   所以「8 段全 tight」应读作「这份建议稿放不进这条时间轴」，
   **不是**对原片语速的测量，也不能据此断言原片主播念得太快。
3. **节奏没有分档**。`analysis.pacing`（快/中/慢）已经有了，按 快 5.6 / 中 4.5 / 慢 3.6 分档更贴近实际，
   但没有真实样本校准前不调参，避免拿一个未验证的系数换掉另一个。
4. 只有一条真实样本（模板库此前是 0 条）。样本会随复刻次数累积，下一批可以统计
   「原片转写口播字数 / 镜头秒数」的实际分布，用数据替换这个常量。
