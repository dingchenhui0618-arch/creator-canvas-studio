## 1. 第 5 条把产品改成了什么

v1 的前提是「房间里跑平台的智能体，用我们的 Key，按轮扣积分」。你说的是反过来的：**用户把自己已有的智能体接进来**。这个改动不是换个计费口径，它把三个地方都改了：

| | v1（平台智能体） | v2（自带智能体） |
| --- | --- | --- |
| 模型与额度 | 我们的 Key 池，扣我们积分 | 用户自己的订阅或 Key，我们**不收对话费** |
| 平台的成本 | 每次发言都有真金白银 | 只有消息存储、转发与工具（生图/生视频/评审） |
| 冷启动 | 新用户 50 积分就能聊 | 新用户得先有一个智能体；所以**默认给 1 个平台智能体**兜底，开箱能聊 |
| 差异化 | 「又一个 AI 聊天」 | 「把你手上那几个智能体拉进同一个房间，一起做一条内容」 |

一句话定位：**VisionChat 不是再卖一个模型，是把用户已经在用的智能体请进平台，让它们能碰到平台里的东西（模板、作品、资产、生图、评审）。**

新用户 50 积分仍然有用：开箱聊（平台智能体 1 积分/轮）、生图（5）、评审（5）。

## 2. 权限模型：agent 是你的代理，不是特权主体

### 2.1 一句话定义

**工具表 = 这个账号在界面上能点的东西，一一对应，多一个都不给。**
判断标准不是「这个 API 安不安全」，而是「人在浏览器里点得到吗」——点得到才进表，点不到就不进。

### 2.2 对照表（这张表就是验收标准）

| 人在界面能做 | agent 对应工具 | 服务端复用的东西 | 花钱 |
| --- | --- | --- | --- |
| 模板库看 26 条模板 | `templates.list` | `server/templates.mjs` 的 `listTemplates({...}, user)` | 0 |
| 我的作品看自己那几条 | `projects.list` / `projects.get` | 同一 `canAccess`（`server/owner.mjs`） | 0 |
| 素材库挑商品图/人像 | `assets.list` | `server/assets.mjs`，同一归属过滤 | 0 |
| 粘贴一条链接让平台读 | `web.read` | `server/webread.mjs` 的字节/字数上限与超时 | 0 |
| 点「生成图片」 | `media.image` | `POST /api/media/generate`（kind=image） | 5（需批准） |
| 点「生成视频」 | `media.video` | 同一路由（kind=video） | 15（需批准） |
| 点「视觉评审」 | `review.run` | `POST /api/review` | 5（需批准） |
| 打开别人的作品 / 后台某页 | **没有这个工具** | —— | —— |

### 2.3 墙外（写死，任何提示词都改不了）

| 不认 | 原因 |
| --- | --- |
| 服务器文件系统、`.env`、`model-keys.json`、`auth.db`、`/opt/visionqa` | 你的原话：绝对不允许探到服务器 |
| 内部端口（5312 画布 API、6677 画布前端、3210 演示站） | 那些不是这个账号的界面 |
| `/api/admin/*` 全部 | 后台运维数据不是「人能点的功能」 |
| 跨账号读数据、任意 shell、任意路径写 | 与「人只能看自己的」同一条线 |

实现上不靠自觉：工具注册表里每个条目必须写明 `route`（方法 + 路径）与 `ui`（界面上哪个按钮），缺一个就不许进表；再加一条单测扫全表——路径不许以 `/api/admin` 开头，且必须在 `server/routes/` 里找得到同方法同路径的处理器。谁想偷偷加一个「只有 agent 能做」的工具，测试先红。

### 2.4 一条我主动加的护栏（请你确认）

你是管理员，后台那些按钮你点得到。但如果照字面「你能点它就能点」，agent 就能调 `/api/admin/users` 删账号、读所有人的会话——这跟第 1 条的后半句「绝对不允许探到服务器等所有服务内容」直接打架。

**我的处理：工具表对所有角色一致，只含用户侧功能；管理员身份不扩权。** 管理员要查运维数据，用后台，不用 agent。这条比你说的更严一档，理由是可逆性：删账号不可逆，聊天里一句被带偏的提示词就可能点下去。

### 2.5 审批：默认只读，写与花钱逐次点

| 档位 | 谁批 | 行为 |
| --- | --- | --- |
| 只读（默认） | 不用批 | 4 个读工具直接执行，结果标「来自模板库/你的作品…」注入上下文 |
| 写与花钱 | 房间成员逐次点「允许/拒绝」 | 工具卡停在「待批准」，90 秒无人处理按**拒绝**；服务重启、房间被改成只读，也按拒绝 |
| 完全授权 | —— | **一期不给这个开关**（你同意的默认档位只有前两档） |

拒绝不花钱、不执行、留一张灰卡说明原因；批准才扣费、才调上游。

## 3. 智能体怎么接进来（本期核心）

### 3.1 你举的四个，现实差别很大

| 智能体 | 有没有可编程入口 | 能不能拿到 API Key | 一期接法 |
| --- | --- | --- | --- |
| 豆包（火山方舟） | OpenAI 兼容 `/chat/completions` | 能（Ark API Key） | 直连 |
| Claude | Anthropic Messages API；或 Claude Code 命令行 | 两者都常见（订阅没有 Key） | 直连（有 Key）／连接器（只有订阅） |
| codex | Codex CLI；也有 API | 订阅登录最常用 | 连接器（`codex exec`）；有 Key 时也可直连 |
| workbuddy | 本机客户端，模型配置在 `/~/.workbuddy/models.json` | 要实测，默认按「只能在你的机器上跑」对待 | 连接器 |

结论：**只做直连会漏掉一半人**（订阅制没有 Key），**只做连接器会让豆包这种纯 API 用户多装一个东西**。所以两条都做。

### 3.2 方式 A · 直连（BYOK）

用户在「我的智能体」里填三样：`baseUrl` + `apiKey` + `model`（OpenAI 兼容或 Anthropic 兼容二选一），可加一句「职责」。

- **存哪**：新文件 `DATA_DIR/user-agents.json`，key 用 AES-256-GCM 加密，密钥沿用 `server/keyvault.mjs` 那套（`VQ_KEY_SECRET` 或 `.model-keys.secret`，0600），但**与平台 Key 池物理分开**，接口只回 `sk-••••1234`。
- **谁去调**：服务端代调（浏览器直连会被 CORS 挡，且 Key 不能下发前端）。这一层只做转发，**不扣积分**，但要记一条 `user_agent_calls`（谁、哪个智能体、多少 token、耗时）。
- **出口白名单**（防 SSRF，必须有）：只允许 `https://`；域名解析后再校验 IP，拒环回/私有网段/链路本地（`169.254.169.254`）；不跟随跳转到内网；连不上 10 秒、整体 120 秒超时。
- **失败文案**：401 = Key 无效（不重试）、429 = 对方限流（退避一次）、超时 = 「你的智能体没在 120 秒内回话」。都不扣积分。

### 3.3 授权与连接：配对码 + MCP + 连接器（照 Pachat 的做法，把工具口收窄）

Pachat 的接入文档（`https://pachat.ai/install.md`，2026-11-25 实读）有一套很成熟的「owner 授权一个 agent」的机制。我们照抄它的形状，但**把「能说话」和「能花钱」分开**——这是它不需要、我们必须有的一刀。

#### 3.3.1 抄来的六件事

| Pachat 的做法 | VisionChat 落成 | 为什么抄 |
| --- | --- | --- |
| 配对码（如 `7KQ2-LMZ9`）：24 小时内有效、最多 10 个 agent、一次性 | 设置页「接入一个智能体」生成 `XXXX-XXXX`，同为 24 小时 / 最多 10 次 / 一次一换 | **人只给一个码，接入动作由 agent 自己完成**——这正是「用户接入自己的智能体」最省事的样子 |
| `POST /api/v1/pair {code, name, platform}` → token **只返回一次** | `POST /api/agent/pair {code, name, provider}` | 令牌不走浏览器、不留历史 |
| `GET /me` 查令牌归属；`DELETE /token` 撤销；同名重连回 `member_exists` → 带 `reclaim: true` 接管，旧令牌立刻失效 | `GET /api/agent/me`、`DELETE /api/agent/token`，同名 `reclaim` 同语义 | 换机器、丢令牌不用重建房间成员，也不会「一个人两个分身」 |
| 远程 MCP：`https://pachat.ai/mcp`，Streamable HTTP + `Authorization: Bearer` | `https://visionqa.wavisionai.cn/mcp`，同协议 | Claude Code / Codex / Cursor 一行 `claude mcp add --transport http` 就接进来，**不用装我们的任何东西** |
| `GET /inbox?since=<cursor>&wait=25`，没事时回 `idle: true` | `GET /api/agent/inbox?since=&wait=25`，同语义 | 不装常驻进程也能「被叫到就回话」；装了就升级成秒回 |
| 令牌纪律：落盘 0600、不打印、不贴群、不进 URL、泄露就撤销重配 | 同一套写进我们给 agent 的接入说明 | 这类事故一次就够毁掉信任 |

第 1 件事还有一个额外用处：Pachat 让 **agent 自己读 install.md 自己接**。我们提供 `https://visionqa.wavisionai.cn/visionchat.md`，用户把「配对码 + 这个链接」发给自己的 codex / Claude / workbuddy，它自己读、自己配、自己进房间，我们不做接入向导。

#### 3.3.2 不抄的四件事

| Pachat 有 | 我们为什么不要 |
| --- | --- |
| agent 以**自己的身份**入群，群里能看见别人的话，靠 `onOwnerSide` 区分敌我 | 一期是「1 人 + N 个智能体」，房间归属一个账号，成员天然同侧；二期做多人时再把 `onOwnerSide` 那套搬过来 |
| 用 **owner 邮箱** `/connect` + `/connect/verify` 连接 | 我们已有 `vq_session` + 积分 + 实名，多开一条身份通道就多一份权限真源 |
| 公开群、按类目搜索、陌生人凭链接加入 | 与「内容不公开、账号要积分」冲突，三期再谈 |
| webhook 唤醒（Grok 那种没有本地 shell 的平台才需要） | 我们的用户都有本地电脑，一期只做 listener，不做 webhook |

#### 3.3.3 一刀：令牌是「说话权」，不是「付费权」

| 令牌能做 | 令牌不能做 |
| --- | --- |
| 读自己所在房间的消息、发消息、查未读、看成员与规则 | **直接调扣费工具**（生图/生视频/评审）——只能**申请**一次工具调用，房间成员在界面上点「允许」之后，才由服务端**以那个账号的身份**执行 |
| 拿到「待批准的工具请求」卡片 | 拿 `vq_session`、改账号资料、进后台、读别人的房间 |
| 被 @ 时回话、在自己的房间里发起讨论 | 读账号的模板/作品之外的数据（读工具仍以账号身份走 `canAccess`） |

为什么必须这么切：Pachat 的工具只有收发消息，风险低；我们能花钱、能读创作资产。**一个放在用户电脑上、可能被提示词注入的令牌，绝不能等价于「可以一直花这个账号的积分」。** 令牌限房间、批准限次、执行才扣费——三道闸门，任何一道被绕过，最坏结果是「房间里多了一句错话」，不是「余额被刷空」。

#### 3.3.4 连接器（listener）还要不要

要，但降级成**可选加速器**：`scripts/visionchat-connect.mjs`（零依赖），用同一个 `vqc_` 令牌在本机长轮询，收到「被点名」就交给 `codex exec` / `claude -p` / workbuddy，把输出回传。

```
你电脑                                     我们服务器
┌───────────────┐   长轮询 inbox(25s)     ┌────────────────┐
│ visionchat-   │ ──────────────────────▶ │ /api/agent/... │
│ connect       │ ◀────────────────────── │  (Bearer 令牌)  │
│  ├ codex exec │   回传文本 / 工具申请    └────────────────┘
│  ├ claude -p  │
│  └ workbuddy  │   ▲ 只带房间令牌，不是登录态
└───────────────┘
```

不装它也能用（靠 MCP 或 `inbox` 轮询），装了才有「提到我就秒回」。这和 Pachat 把 listener 列为「需要 owner 同意的可选一步」是同一个判断：**常驻进程是用户的机器资源，得用户点头**。

- **谁执行**：连接器在自己机器上决定跑什么命令，平台只发消息、只收结果。所以**平台永远不会把 shell 下到用户机器**，用户机器也不会被平台探到。
- **形态**：设置页给一行可复制的启动命令 + 令牌，粘进终端就跑。
- **并发**：一个令牌同时只处理 1 条消息；同一房间同一时刻 1 个回合（与平台智能体同一条闸门）。

### 3.4 房间成员变成三类

| 类型 | 来源 | 有令牌吗 | 对话扣费 | 能不能被 @ |
| --- | --- | --- | --- | --- |
| `platform` | `DATA_DIR/agents.json`（现有智能体） | 不需要 | 1 积分/轮 | 能 |
| `byok` | 用户填的 `baseUrl/key/model` | 不需要（服务端代调） | **0** | 能 |
| `connector` | 配对码换来的一个 `vqc_` 令牌 | **有，可单撤销** | **0** | 能 |

`room_members` 加 `provider` 与 `token_id` 两列；`agents.json` 的既有定义一行不迁、不改。

## 4. 计费：自带智能体免费聊，平台出资源才扣分

| 动作 | 扣多少 | 为什么 |
| --- | --- | --- |
| 自己的智能体（直连/连接器）说一句话 | **0** | 模型与额度是你的，我们不收过路费 |
| 平台智能体（`agents.json`）说一句话 | 1（`chat`） | 用的是平台 Key，有真成本 |
| 发一条消息本身（存储、转发） | 0 | 不值当，也容易让人觉得被收两遍 |
| 生成图片 | 5（`image_gen`） | 平台上游成本，失败全退 |
| 生成视频 | 15（`video_gen`） | 同上 |
| 视觉评审 | 5（`review`） | 同上 |
| 4 个读工具 | 0 | 不碰上游 |

口径写死一处：`server/config.mjs` 的 `credits.prices`，不新增价目表；房间相关 `ref` 用 `room:<id>:call:<callId>` 前缀，失败 `refund` 同 `ref`（`outstandingCharge` 已能防重复退）。

被刷怎么办：对话免费不等于没有闸门——每账号 20 条/分钟、每房间同时 1 个回合、连接器令牌每 10 秒最多取 1 次；真正贵的三个工具仍然逐次扣费 + 逐次批准。

## 5. 工具：一期全上（7 个）

| 工具 | 类 | 批准 | 扣费 | 对应界面 |
| --- | --- | --- | --- | --- |
| `templates.list` | 读 | 自动 | 0 | 模板库列表 |
| `projects.list` / `projects.get` | 读 | 自动 | 0 | 我的作品 / 作品详情 |
| `assets.list` | 读 | 自动 | 0 | 我的资产 |
| `web.read` | 读 | 自动 | 0 | 快捷创作里「读链接」 |
| `media.image` | 写·花钱 | 逐次 | 5 | 快捷创作·图片 |
| `media.video` | 写·花钱 | 逐次 | 15 | 快捷创作·视频 |
| `review.run` | 写·花钱 | 逐次 | 5 | 视觉评审 |

**去掉 v1 里的 `export-json`**：它会往服务器写文件，属于「产出物」而不是「人能点的操作」，且与第 1 条撞车。要下载 JSON，房间消息里直接复制即可。

一期全上的代价与收口：每个工具都是薄包装（一个函数、一张参数 schema、一条单测），**出问题按单个工具下线**（注册表里 `enabled: false`），不回滚整个功能。上线前 7 个工具各跑一次假上游端到端，不做真实上游调用。

## 7. 三期路线

| 期 | 范围 | 一句话验收 |
| --- | --- | --- |
| 一期 | 1 人 + N 个智能体（平台/直连/连接器混合）、7 个工具、审批、SSE | 同房间 3 个智能体（一个豆包直连、一个 codex 连接器、一个平台智能体），@ 谁谁回，生图走审批并扣 5 分 |
| 二期 | 多人 + 多智能体：同工作区成员、邀请链接、席位、房主代批 | 邀请令牌一次有效；被邀请者只能读自己能看的；房主可代批工具调用 |
| 三期 | 社交属性（形态待定） | —— |

三期的三个候选，等你想清楚了再选，现在不写死：

1. **房间可被订阅**：别人的房间只读可见，能「复制成一个新房间」来用（模板 + 智能体配置一起复制）。
2. **作品流里的房间卡**：房间产出的成品进公共作品流，点进去看它怎么被做出来的（只有过程摘要，不是聊天全文）。
3. **智能体可以被别人借用**：你配置好的智能体以「只读模板」形式公开，别人一键加入自己的房间（凭据永不出你的账号）。

三个都涉及公开内容与权限外溢，等一期跑起来有真数据了再定。

## 8. 一期拆解与验收

| 工作面 | 内容 | 验收（可测） |
| --- | --- | --- |
| 1a 房间骨架 | `rooms` / `room_members` / `room_messages` / `room_reads` 建表、房间 CRUD、消息 `seq`、历史分页、未读、SSE + 断线续传 | 断线 30 秒重连不重不漏；非成员 403；390 不横向溢出 |
| 1b 接入 | 直连（加密存 Key、出口白名单、失败文案）+ 配对码与令牌（`pair`）+ `me` + `reclaim` + MCP 端点 + 可选连接器 | 配对码 24 小时、第 11 次拒绝、用过即废；同名 `reclaim` 后旧令牌立刻 401；`claude mcp add` 接进来能收能发；**令牌直调 `POST /api/media/generate` 必须 403** 并提示「要房间成员批准」 |
| 1c 工具 | 注册表 + 7 个工具 + 角色裁剪 + 单测扫表 | 7 个工具在假上游下全部成功；`/api/admin` 零命中；跨账号读作品 403 |

顺序：1a → 1b → 1c → 1d；1b 的直连比连接器先落（用户最多）。每一步都先假上游、后真调；真实上游调用**等你点头**。

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 提示词注入让 agent 把用户自己的 Key 说出去 | Key 只在服务端解密、永不下发前端；消息里出现 `sk-` 形状的串做打码；输出前扫一遍 |
| 连接器令牌泄露 | 只绑定一个房间、可撤销、只存 sha256；撤销即 401；不写进任何日志；**令牌本身无权调扣费工具**，只能申请、必须房间成员批准 |
| 转发放大（拿我们的服务器打别人的接口） | 出口白名单 + 每账号每分钟 20 条 + 每房间同时 1 回合 + 单次 120 秒超时 |
| 「工具全上」面太大 | 7 个薄包装、单个可下线、假上游端到端、逐次批准 |
| 双真源 | 智能体定义仍只 `agents.json`；接入信息只 `user-agents.json`；房间只引用 id |
