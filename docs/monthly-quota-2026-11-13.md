# 每月额度：一个账号一个月能花多少，由你定（v0.9.64）

> 口径：这篇只回答三件事——**配额拦在哪一步、数字由谁定、生产上真的拦住了什么**。
> 所有数字来自 2026-11-13 的生产实测（v0.9.64，入口 `index-Ct9_Io7v.js`），不是估算。

## 一、为什么要有这一层

余额只回答「还有没有钱」，回答不了「一个月最多花多少」：

- 一个账号被脚本连着刷，余额会在几小时内见底，事后从流水里看得出来，但上游的钱已经花出去了；
- 内测期共用账号时，一个人把额度用光，其他人第二天就什么都做不了；
- 上线收费之后，「每月上限」是报价单里的一行（哪档含多少积分/月），没有它连档位都没法定。

所以配额要拦在**扣费之前**：超了就是 429，不扣积分、也不调用上游。

## 二、做了什么

| 位置 | 内容 |
| --- | --- |
| `server/quota.mjs`（新增） | `DATA_DIR/quota.json`（0600）：`monthlyLimit`（默认 0 = 不限）+ `overrides`（按账号覆盖）。`checkQuota()` 在扣费前判定；`monthlySpend()` 只读积分账本；`quotaOverview()` 给后台一屏看用量 |
| `server/credits.mjs` | `charge()` 在余额检查之后、改余额之前过配额闸门；拒绝时返回 `MONTHLY_QUOTA` + 上限/已用/还需要多少/重置时间 + 一句能照着做的中文；`/api/credits` 带上 `quota` 视图 |
| 五处扣费调用点 | 检索/复刻（`beginPaid`）、评审、智能体对话、本地工作区对话、画布运行：超配额统一写 **429** 与同一份字段，退出并发闸门，不进入上游调用 |
| 后台「计费 → 每月额度」 | 默认上限（0 = 不限）与「给某个账号单独设上限」；「账号用量与额度」表按本月消耗降序列出花过钱或设过额度的账号，行内可改、可恢复默认 |
| 设置页「积分余额与消耗」 | 新增「本月用量」一行：设了上限就显示「已用 / 上限」+ 一条细进度条（80% 变黄、满格变红），不限就如实写「管理员没有设每月上限」 |
| 审计 | `admin_audit` 新增动作 `quota.save`（改默认额度、设/清单独额度都记，含目标账号与数值） |

**口径**（页面与文档写同一句）：

- 一个自然月按 **UTC** 算，和后台「成本」页的日口径一致；每月 1 日 00:00 UTC 重置。
- 「本月已用」= 本月扣费 − 本月退款；管理员扣减与赠送**不算**消耗。
- 默认 **0 = 不限**：额度数字是商务决定，没定之前不替用户设上限。

| 动作 | 结果 |

| 真打一次检索 `GET /api/search?q=额度验证` | **429** `{ code: 'MONTHLY_QUOTA', limit: 1, used: 349, remaining: 0, cost: 2, resetAt: '2026-12-01T00:00:00.000Z' }`，error 里写明「本月额度用完了…管理员可以在后台「计费 → 每月额度」给这个账号单独提额」 |

> **临时改动已复原**：上面「默认 1 积分」只是为了让 429 可复现（并且保证不会真的调用上游、不花一分钱），验证完立刻改回 0 = 不限。生产现在**没有设置任何额度上限**，等你定数字。

## 四、测试

`test/quota.test.mjs` 新增 **10 条**（全仓 **569/569**）：

1. 默认不限时照常扣费，`remaining` 是 -1 而不是编出来的数字；
2. 设了上限后超额整单拒绝：余额与流水都不动；免费调用（单价 0）不受限；
3. 额度是数据：改完立刻生效，负数 / 小数 / 非数字都被拒绝并给中文原因；
4. 按账号覆盖只影响一个人，0 表示这个账号不限，清掉覆盖回到默认；
5. 本月消耗口径：退款抵回、管理员扣减与赠送不算消耗；
6. UTC 月份边界：上月的扣费不算这个月；
7. 后台视图只列「花过钱或设过单独额度」的账号，按消耗降序；
8. 429 拒绝体字段齐全（`code / limit / used / remaining / cost / month / resetAt` + 可执行文案）；
9. 后台路由：非管理员 403、坏输入 400、改默认与单独额度都通、清两次 404；
10. `/api/credits` 带额度视图：不限写 `unlimited:true`，设了上限给数字与剩余。

## 五、边界（都是实话）

- **没有按档位自动配额度**：档位（A4）和每月上限（本轮）现在是两件独立的事，买档位不会自动改这个账号的上限——真要联动，等支付通道接上再说。
- **没有「下个月自动恢复」之外的宽限**：超了就是 429，管理员手动提额或等下个自然月。
- **额度单位是积分，不是钱**：真实成本要靠后台「成本」页的单价折算；单次成本 vs 售价那张表仍缺（A8 的测量部分已在 v0.9.58 做完）。
- **没有按 IP / 设备维度限流**：只按账号。
- **默认 0 = 不限**：生产现在不拦任何人，等你定价之后再填。
