# 「等你看」看得见，也走得完（v0.9.24，2026-11-13）

结论先行：**评审待办原来只活在工作台那一屏里，这一轮把它推到全站可见、也补完它自己的尾巴**——
侧栏「工作台」带一枚真实数字（几条评审等你看）；工作台不再静默吞掉第 4 条以后；打开某条作品就能原地「已看过 / 撤销」，
不必再退回工作台。三个入口一套口径：数字来自 `reviewQueue().total`，与队列、作品页读到的是同一份。

## 一、为什么做这一片

- **待办只在工作台那一屏成立**：在作品、模板库或评审页，看不见「还有几条等我」；产品说「工作台回答下一步点哪里」，
  可这条答案只有走回工作台才看得见。
- **队列会静默截断**：工作台只排 3 条，`total` 却没地方写。5 条待办时，人只看到 3 条，会以为就这 3 条——
  不是 UI 不漂亮，是它在撒谎。
- **「已看过」的出口只在队列里**：从队列点进作品改一版，看完了必须退回工作台再点一次「已看过」；
  而「拍板」已经在作品页了，两个出口分居两页，人会漏掉其中一个。
- 侧栏 `NavItem` 早有 `badge` 参数，但没有任何东西喂给它——这是现成的、没接上的 UI。

## 二、规则

1. **角标的数字只数「没看的」**：等于 `reviewQueue().total`，不含已看过、不含拍过板；0 不渲染，取不到队列时也不渲染
   （宁可没有，不拿 0 冒充「没有等你改的」）。
2. **数字与队列同源**：外壳调 `GET /api/reviews/queue` 读 `total`，不在前端另算。评出新结论、已看过、撤销、拍板
   都由 `vq:queue-changed` 事件当场对一次数，不轮询。
3. **「已看过」是便利贴，不是结论**：作品页可以直接记、直接撤；胶囊、下一步、评审记录、交付稿一个字不改。
   按「哪一版、哪一次评审」认（`version + reviewAt`），同一版再评出新结论或开了新版，它自动作废。
4. **队列不静默截断**：首屏先排 3 条，多出来的写「还有 N 条等你改」，点开排到服务端上限（20 条）；
   总数超过上限时如实写「只列了最近 20 条，还有 N 条更早的等你改」。
5. **角标只在主线导航上**：管理后台那套导航不显示「等你看」；窄屏与收起侧栏放不下数字，换成图标右上角一个 6px 的点，
   条数写进 `aria-label` 与 tooltip（「工作台，4 条评审等你看」），不让一个点变成谜语。
6. **作品详情带「这一版看过了没有」**：`GET /api/projects/<id>` 返回 `ack`（版次 + 评审时间对得上才非 null），
   作品页据此显示按钮或「你 11/13 03:22 看过这一版 · 先不改 + 撤销已看过」。

## 三、界面

- 侧栏「工作台」右侧一枚 18px 小胶囊：等宽数字、正文墨色、描边一档；数字是今天还剩几件事，不该比标签更淡。
- 工作台队列底部：「还有 2 条等你改 →」是 12px 文字链；超过 20 条时多一行 11px 等宽说明「只列了最近 20 条」。
- 作品页「评审」卡里，拍板按钮下面用一条虚线隔开第三个出口：「已看过 · 这一版先不改」；
  记下之后同一行写「你 X 看过这一版 · 先不改」并给「撤销已看过」（11px，读起来是备注，不是第三个拍板按钮）。
- 收起侧栏 / 390 宽：数字换成图标右上角的点，`aria-label` 仍带条数。

## 五、本地演示数据（9 条作品 / 4 条模板，非生产）

- 预置：5 条待办（咖啡店探店三分钟 / 换季护肤三步 / iPhone 15 开箱 / 夏季冰茶三分钟 / 春季新品开箱）+ 1 条已看过（工位改造 30 秒）。
- 侧栏：「5」，可访问名「工作台，5 条评审等你看」；工作台队列 3 行 + 「还有 2 条等你改」。
- 点「还有 2 条」：5 行全部排出，「还有」消失；`total` 仍 5。
- 打开「春季新品开箱」：评审面板有「已看过 · 这一版先不改」；点下去后同一行变成「你 11/13 03:22 看过这一版 · 先不改 + 撤销已看过」，
  角标当场从 5 变 4（走事件，不靠换页）。
- 回到工作台：队列 3 行 + 「还有 1 条等你改」，顶部「已看过 2 条」。
- 收起侧栏：数字消失、圆点出现，`aria-label` 仍带 4；390 宽同样只有点，队列 290×561，无横向滚动（`scrollWidth == clientWidth` 390）。

## 六、边界

- 不做推送、不弹通知、不做红点脉冲；角标只在你打开的工作台里出现。
- 队列上限仍是 20（服务端），超出如实写「只列最近 20 条」，不做分页 / 无限滚动。
- 作品列表**不新增**「等你看」筛选：v0.9.23 已定「结论不进筛选」，待办由工作台回答；这一轮只把待办说清楚。
- 「已看过」不影响任何结论、交付稿与两张纸；它只是待办上的便利贴。
- 角标只算当前账号的队列，不跨账号、不含已删除作品。

## 八、文件

- `server/review-acks.mjs`：新增 `ackFor(acks, { projectId, version, reviewAt })`——版次与评审时间都对上才算「看过」，纯函数。
- `server/routes/projects.mjs`：作品详情多返回 `ack`（当前这一版对得上的那条，否则 null）。
- `src/domain/project.ts`：`ProjectAck` 类型 + `ProjectDetail.ack`。
- `src/api/review.ts`：`noteReviewQueueChanged()`；评审、已看过 / 撤销、拍板 / 撤销都广播 `vq:queue-changed`。
- `src/components/ui.tsx`：`NavItem` 支持 `badge` / `badgeLabel`，收起态渲染圆点，可访问名带条数。
- `src/App.tsx`：外壳读队列 total、换页与事件各对一次、把数字交给「工作台」；管理后台不显示。
- `src/pages/OverviewPage.tsx`：一次取 20 条、首屏排 3 条、「还有 N 条」展开、超上限如实说明。
- `src/pages/ProjectPage.tsx`：评审面板第三个出口「已看过 / 撤销已看过」。
- `src/styles/shell.css` / `overview.css` / `projects.css`：角标、圆点、队列尾巴、已看过那一行。
- `test/review-ack.test.mjs`：+2 条（`ackFor` 三样都得对上；作品详情带 ack、撤销就没了、胶囊不变）。
