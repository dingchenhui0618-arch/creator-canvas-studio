# 用量与成本台账：先有真实数字，再谈定价（v0.9.58）

日期：2026-11-13 · 生产 v0.9.58 · 目标 A8（单位经济）的测量部分

## 为什么要做

A8 在缺口清单里一直写着「复刻成本与配额未定」。但之前连「一次复刻花多少钱」都没有数字：
积分是对用户的虚拟倍率（检索 2 积分、复刻 10 积分），和上游真实成本没有换算关系；
模型路由日志只记「成没成、用了哪把 Key」，不记 token；画布出图走的是平台通道，
平台只知道「转发成功了」，不知道「这次花了几张图的钱」。

所以这一版先把**测量**做出来：每次真实调用落一条事件，带能力、模型、真实用量、
作品或单据号。定价（A4）与配额（A8 后半）等有了这些数字再定，不再拍脑袋。

## 记什么，在哪记

| 能力 | 单位 | 记账位置 | 失败怎么记 |
| --- | --- | --- | --- |
| 文本模型 | token（入 / 出） | server/chatcall.mjs 拿到上游 usage 时 | 不记：没有 usage 的成功事件才落库 |
| 视觉模型 | token（入 / 出） | 同上（capability=vision） | 同上 |
| 判断模型 | 次（附 token） | server/judge.mjs 判断成功时 | 判断层失败不记，评审照常返回 |
| 出图 | 张 | server/gateway.mjs 同步 / 异步出图地址回来时 | 记一条 ok=false、0 张、不折钱 |
| 出视频 | 秒 | server/gateway.mjs 建任务成功时（提交口径） | 建任务失败记 ok=false |
| 检索 / 复刻 / 画布运行 | 次 | 从积分流水回填（历史）与后续真实写入 | 回填没有失败口径 |

存储：复用现有 SQLite（`DATA_DIR/auth.db`）的 `usage_events` 与 `usage_meta` 两张表，
不再单开一个数据库文件——备份、迁移、权限都跟着账号库走。

## 三条设计决策

1. **积分不参与成本**：积分是产品内倍率，成本是上游账单。两者混在一起，
   定价时永远算不清一次复刻真花了多少钱。页面把两者分开写（余额在「账号」页，成本在「成本」页）。
2. **失败不折算金额**：上游失败到底计不计费、退不退款，没有依据就不写金额。
   失败事件只进「失败次数」，不进 token / 张数 / 金额。
3. **历史回填只补次数**：计量上线前发生过的调用，按积分流水补成一条「次数」事件，
   标 source=backfill、`tokensKnown=false`，页面显示「历史回填」，且**不折算金额**。
   回填只跑一次（`usage_meta.backfilled` 记账），不会每次打开页面越补越多。

## 单价怎么定

- 后台「成本」页有一组单价输入框（输入/输出 token 每百万、出图每张、出视频每秒、
  判断/检索/复刻/画布运行每次），保存后写 `DATA_DIR/usage-prices.json`（0600），
  改动进审计（`usage.prices.save`）。
- 全是 0 时页面显示「未定价」，只统计用量；填了才按「真实用量 × 单价」折算金额。
- 页面明说：这是估算口径，不是上游账单；折扣、赠金、退款不会自动同步。

## 接线测试（不花上游额度）

`test/usage-wiring.test.mjs` 用本地假上游走完整链路，4 条：

1. 聊天调用 → 事件带 `prompt_tokens=1234 / completion_tokens=567`、作品与单据号；
2. 出图 `n=2` → 事件 2 张、单据号就是幂等键；
3. 出视频 `duration=6` → 事件 6 秒；
4. 失败出图 → ok=false、0 张、汇总 `failedCalls=1`、`images` 只算成功的 2 张、金额 0。

`test/usage-meter.test.mjs` 6 条盯汇总口径：单价校验、回填只跑一次、
窗口外事件不计入、失败不折钱。

## 还没有做（如实列出）

- **画布服务端自己的模型调用不在表里**：画布只把出图 / 出视频转发到平台通道，
  它自己节点里的 LLM 调用不经这里。要按作品算「一次复刻」的完整成本，还得让画布把
  作品标识带进转发请求，或者把它的模型调用也接过来。
- **出视频退款不冲回**：目前按提交时长记；上游失败后退款要人工按账单核对。
- **没有按作品归属的出图成本**：出图请求里目前没有作品字段，作品维度的成本只看得到
  评审（`project:<id>`）。下一步是让画布在请求里带 `projectId`。
- **没有接账单**：平台不拉上游对账单，金额全是「用量 × 单价」的估算。
- **历史回填没有 token**：计量上线前的调用只有次数。
