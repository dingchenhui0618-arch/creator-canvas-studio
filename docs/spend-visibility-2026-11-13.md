# 钱花在哪：账号按动作、作品按自己（v0.9.65，2026-11-13）

> 前一版（v0.9.64）回答了「这个账号这个月还能花多少」。这一版回答上半句：
> **这个月花掉的积分具体花在哪种动作上、这条作品一共花了我多少。**
> 全部数字来自已有记录（积分账本、评审记录、运行记录），不新增一份统计副本，也不估算。

## 一、为什么先做这件事

- 账本本来就有每条流水，但界面只给一页列表（20 条一页），要回答「钱主要花在哪」得自己加法。
- 作品是产品主线：一条作品的成本分散在「评审几次」与「画布跑几次」里，作品页只显示单次金额，没有合计。
- 商业化的下一个问题就是成本与定价，先把「花在哪」摆出来，定价才谈得上按动作定价。

## 二、口径（两个视角各自诚实）

### 账号：本月花在哪

| 项 | 口径 |
| --- | --- |
| 数据源 | `credit_ledger`，与每月额度、余额同一个库 |
| 月份 | UTC 自然月，每月 1 日 00:00 重置（与 v0.9.64 完全一致） |
| 消耗 | 扣费绝对值 **减** 本月退款；管理员扣减（`deduct`）与赠送（`grant` / `welcome` / `invite`）不算消耗 |
| 拆分 | 按账本 `kind`：检索 / 一键复刻 / 视觉评审 / 智能体对话 / 画布运行 |
| 合计 | 与每月额度的「本月已用」是同一个数（同一份账本、同一笔退款只抵它自己那个动作） |

### 作品：这条作品花了多少

| 项 | 口径 |
| --- | --- |
| 数据源 | 评审记录（自己记着 `credits.cost`）+ 运行记录（`credits.cost`） |
| 归集 | 评审按 `projectId`；运行按作品的当前画布与归档画布（跨版本，只认 `flowId`） |
| 退款 | 退过款的运行不算——失败的钱已经退回，再算一遍等于把退回的钱又花一次 |
| 不摊 | 检索、复刻、智能体对话记在账号上：**账本里没有作品，就不硬摊过来**（页面上写明） |
| 一致 | 作品列表卡片上的花费与作品详情同一份数（同一次请求里算两处） |

## 六、边界

- 花费单位是**积分，不是钱**：真实上游成本在后台「成本」（按单价折算，且单价是后台手填的）。
- 只有评审与画布运行能归到作品；检索、复刻、智能体对话只到账号。
- 删掉作品会解绑它的评审（`detachReviewsFromProject`）：那几笔花费仍在账号账本里，但不再挂在任何作品上。
- 没有按月拆「作品」的花费（作品页给的是累计）：要做「本月这条作品花了多少」得再按记录时间分桶，这轮没做。
- 作品花费不含画布节点里调模型的真实成本（那是成本页的口径，不是积分账本）。
