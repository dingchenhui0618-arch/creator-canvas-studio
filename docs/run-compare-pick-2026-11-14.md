# 自己挑两条运行来对照：最早那条也不再是死路
v0.9.111 · 2026-11-14

## 起因

v0.9.110 把「这次和上次」摆到了一起，但入口只认更早的那一条：最早的一条运行只能看到一句「没得对照」，想比较第一次和第三次也没有地方点。运行记录页里明明已经选好了某一条，还是要先进只读回看，再点「对照上次」。

这一轮把对照对象交回给人：默认仍是上一条，但可以在弹窗里点名同一条画布上任意一条已结束运行；最早那条也能回头挑之后的一次。运行记录页多一个「对照」按钮，直接在记录页打开同一个弹窗。

## 做了什么

- **候选一起返回**：`GET /api/runs/:id/compare` 的响应多带 `options`、`optionsTotal`、`optionsTruncated`。候选是同一条画布上除自己以外、已结束的运行，按开始时间倒序，最多列最近 20 条；正在跑和排队中的不列。
- **默认仍是上一条**：不传 `with` 时仍取更早的最近一条。最早那条没有更早的，但候选里可能有之后的运行——页面不再直接判死，而是把候选摆出来让人挑。
- **「对照对象」选择器**：弹窗标题下多一行。默认项写「自动：上一条已结束运行」，其余每项带时间、状态、耗时、实际扣费与运行 id 后 8 位。选中后带 `?with=<runId>` 重新取，表格、总差、画布说明一起换。
- **说清方向**：既然可以挑更晚的一条，「上一条 / 这一条」就不准确了。卡片、表头、390 的分段标签统一改成「对照运行 / 当前运行」；页脚写「差值 = 当前 − 对照」。耗时差和扣费差因此永远有方向，不用猜谁减谁。
- **运行记录页直接对照**：详情操作里多一个「对照」，不用先「查看这次运行」。弹窗打开时地址仍在 `#/runs`，关闭后回到记录。
- **最早一条也能对照**：默认响应仍是 `comparable: false`，但不渲染对照表；候选区域还在。挑一条之后的运行后，弹窗从 620 宽回到 960，表格正常出现。
- **样式单独一份**：`RunCompareModal` 现在被运行记录页引用，如果继续 import `canvas.css`，整份画布样式会被打进主包。把 `rc-*` 拆到 `src/styles/run-compare.css`，主样式只多这一小份，画布样式仍留在画布分块里。

## 接口

```
GET /api/runs/<runId>/compare
GET /api/runs/<runId>/compare?with=<anotherRunId>
```

可对照时：

```json
{
  "ok": true,
  "comparable": true,
  "flowId": "flow_...",
  "flowName": "画布名",
  "current": { "id": "run_...", "status": "success", "durationMs": 718, "cost": 5, "finished": 3, "total": 3 },
  "previous": { "id": "run_...", "status": "success", "durationMs": 520, "cost": 5, "finished": 3, "total": 3 },
  "options": [
    { "id": "run_...", "status": "success", "startedAt": "...", "durationMs": 524, "cost": 5, "total": 3, "finished": 3, "failed": 0 }
  ],
  "optionsTotal": 2,
  "optionsTruncated": false,
  "graph": { "changed": true, "unknown": false, "currentRevision": "...", "previousRevision": "..." },
  "nodes": [],
  "totals": { "changed": 3, "durationDelta": 198, "costDelta": 0 }
}
```

最早一条、默认没有更早的运行：

```json
{
  "ok": true,
  "comparable": false,
  "reason": "这是这张画布上最早的一条运行；默认没有更早的可对照，可以从下面挑一条之后的运行。",
  "current": { "id": "run_..." },
  "options": [ ... ],
  "optionsTotal": 2,
  "optionsTruncated": false
}
```

候选超过 20 条时 `optionsTotal` 仍是全量，`optionsTruncated: true`；页面写「这里列最近 20 条」。

## 踩到的坑

1. **下拉面板被第二次点击关掉。** E2E 先开面板截图，`pickRun` 里又点了一次触发器；自绘 Select 的触发器是开关，第二下把面板收起来了。`openPicker` 先看面板在不在，开着就不再点。
2. **差值方向不能按「更晚减更早」写死。** 当前运行是用户打开的那条；从最早一条挑之后一条时，当前减对照是负数。E2E 第一版拿「第一条减第三条」当期望，页面显示 +218ms，实际是当前第三条减第一条。应按「当前运行 − 对照运行」单独取一次期望。
3. **组件被记录页引用后，CSS 跟着进主包。** `RunsPage` import `RunCompareModal`，而弹窗 import 了 `canvas.css`；构建后主样式从 276,467 B 涨到 312,499 B，画布样式分块消失。拆出 `run-compare.css` 后主样式 283,574 B、画布样式 28,926 B，画布 CSS 不再被记录页拖走。
4. **候选和默认上一条不能各查一遍。** 先取候选，再从候选中找更早的最近一条；否则同一请求读两遍运行表，逻辑也容易在并发追加时不一致。
5. **「上一条」在能挑更晚的运行后就是假话。** 卡片、表头、390 分段标签统一成「对照运行 / 当前运行」；差值说明写进页脚，避免用户以为永远是「上次减这次」。
6. **最早一条的空状态不能直接判死。** 只要候选里有之后的运行，就不该只写「再跑一次」；选择器要留在空状态里，挑完能从 620 平滑回到 960。
7. **候选项太长会把弹窗撑开。** 自绘 Select 的选项默认 `white-space: nowrap`；候选标签带时间、状态、耗时、扣费与 id，必须允许换行，面板宽度也要限制在视口内。390 下选择器占满整行，面板宽度按 `100vw - 48px` 收。
8. **记录页入口不能改地址。** 「对照」只打开弹窗，不能顺手导航到只读回看；否则用户关掉弹窗会落在另一页。E2E 直接断言 `location.hash` 仍是 `#/runs`。

## 发现但没做

- 候选只列最近 20 条，没有分页、搜索或按状态筛；更早的候选要再跑一次或等下一版。
- 不能跨画布版本对照：分版后的旧版画布有自己的 `flowId`。
- 没有 A/B 交换按钮；想从另一条作「当前」看，去那条运行的只读回看或记录页再开一次。
- 不做逐字差异、不做差异导出，也不把两次完整输出并排铺开。
- 旧运行没有画布快照与节点指纹时，只能比状态、耗时与输出；不补写快照。
- 还没做分享链接与真实评审回归。
