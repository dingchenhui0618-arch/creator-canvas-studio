12px 与 11.5px 的元信息 5–30 处、不到 40px 的点按区 11–26 处，另外量出三处真的坏了的地方。
这一轮只动 CSS 与一处文案，接口、计费、真实上游调用零改动。

## 量出来的三处真问题

### 1. 预设分类条在 390 宽根本够不着最后两个分类

内容列只有 290px，5 个页签要 397px；`nav.css` 在窄屏把它们设成 `flex-wrap: nowrap` +
`overflow-x: auto`，滚动条是 overlay 的、看不见，所以「脚本分镜 / 投放素材」被裁在屏幕外
（改前 320 / 390 的截图里能直接看到右边被切一半）。页签长大了之后更够不着，所以这一轮必须处理：

- ≤560 改 `flex-wrap: wrap` + `gap: 8px` + `overflow-x: visible`，390 排成两行（全部 + 内容复刻 + 视觉评审 / 脚本分镜 + 投放素材）；
- 换行后下划线会浮在第一行按钮底下，所以窄屏把激活态从下划线换成胶囊底色（`is-active::after { display: none }`）。

### 2. 历史弹层在 390 有一半在屏幕外

`.agx-popover` 是 `position: absolute; right: 0; width: 352px`，挂在「历史」按钮右边。
桌面页头动作区靠右，所以没问题；窄屏页头左对齐、按钮在 x≈80–165，弹层左边缘算出 **−187px**，
屏幕上只剩一条「话记录」，关不掉也选不了。改成窄屏贴底浮层：`position: fixed; left/right: 8px;
bottom: 8px; max-height: 70vh; z-index: 60`（背景的 `.agx-backdrop` 还是 15，点在浮层外照样关）。

### 3. 对话数为 0 时，左栏孤零零一个「0」

`QuickChat` 左栏是「新对话 ｜ 0 ｜ 历史对话」，那个 0 是会话条数，没有单位也没有标题，
读起来像按钮上的残字。改成 `items.length > 0` 才渲染，文案写成「共 N 个」。

## 桌面为什么没变

- 全部覆盖都在 `max-width` 媒体查询里，1081px 起不匹配。
- 同一条探针脚本在 1440 量到的值仍是基样式：`.agx-mono` 12px、`.agx-surface-note` 11px、
  `.agx-capsule` 30px（里面按钮 28px）、创作方式页签 28px、分类页签 31px、`.vq-tag` 12px/20px、
  `.qc-tool` 28px、`.qc-new` 32px、图标按钮 32×32。
- 1440 的「<13px / <40px」从 **43/37 → 42/37**，唯一少的就是上面那个「0」（它本来就是 12px 的独立元素）；
  图片面板 1440 是 **40/38 → 40/38**，一个没变。

## 顺手记下的一条经验

参数胶囊自己带 1px 边框，里面那枚按钮的实测高度是 `胶囊高 − 2`。所以「点按区 40px」不能把胶囊
写成 40（里面只有 38，768 上就是这么被量出来的），要写 **42 / 46**。这条写进了测试，防止下次改回 40。

## 边界

- 只量 Chromium 无头、1x；量了 320 / 390 / 768 / 1024 / 1440，561–767、769–1079 没有逐档量。
- 「对话预设 + 历史弹层」只量了改后（0/0），改前的数没单独取；它和平台对话共用同一批规则。
- 图片面板的「有参考素材」「生成中」「生成完成」「最近生成」四种状态、以及预设对话里有消息时的
  消息时间行，只由样式规则与单测保证，**没有实拍**（要实拍就得真调一次上游，本轮没有授权）。
- 320 的内容列只有 186px（侧栏 68 + 页内两层各 16px 内边距），参考素材那一行的「上传 / 素材库」
  两个按钮仍会折成两行；这是 320 的固有宽度问题，本轮没有动外壳内边距，留作下一轮候选。
- 判据只有「宽或高 < 40px」，没有做点按区互相遮挡的几何检测。
- 截图里的账号（窄屏探针）、4 个预设、0 条对话都是临时实例的样例数据；没有碰生产账号，本轮 0 次真实上游调用。
