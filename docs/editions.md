# VisionQA 的三个形态

日期：2026-11-04 · 状态：外壳与导航已落地，后台版与内测版页面首批接完

同一套设计语言（ink 单色、发丝线、Geist + Noto Sans SC），三份不同的工作面。侧栏顶部的「形态」开关切换，选择记在 localStorage（`vq.edition`），刷新后保持。

## 用户生产版 / PRODUCTION

给内容团队日常用，就是这一版工作台：

| 分组 | 页面 |
| --- | --- |
| 主层 | 工作台 / 爆款雷达 / 模板库 / 智能体 / 画布 / 视觉评审 |
| 设置层（横线下） | 资产库 / 运行记录 / 设置 |

## 后台管理版 / ADMIN

给运营与管理员用，导航换成六项：

| 分区 | 内容 | 数据来源 |
| --- | --- | --- |
| 总览 | 用户数、模板数、运行数、依赖状态 | 本地账号常量 + `/api/templates` `/api/runs` `/api/health` |
| 账号与配额 | 本地演示账号列表、角色、最近登录 | `src/auth/session.ts`，页头明确「未接后端用户表」 |
| 模型 Key | 红狐 Key 状态、视觉模型、只会显示「已配置」不显示值 | `/api/health` |
| 模板治理 | 模板列表、关键词过滤、删除 | `/api/templates`（DELETE 真实生效） |
| 运行审计 | 运行记录倒序、逐节点输出 | `/api/runs` |
| 系统 | 版本、启动时间、VisionQA Canvas 三端口、危险操作占位 | `/api/version` `/api/bdc/status` |

## 内测测试版 / LAB

给自己和测试同学用，四项：

| 分区 | 内容 |
| --- | --- |
| 接口体检 | 并发探测 8 个接口，状态码 / 耗时 / 关键字段，可全部重测；失败不兜底 |
| 样例对照 | mock 示例数据与真实接口返回并排，标注哪些是示例 |
| 功能开关 | localStorage 开关，每条标明「是否真的被代码读取」 |
| 诊断导出 | 版本 + 浏览器信息 + 控制台记录，导出 JSON |

## 为什么这样切

1. **用户不该看见审计和 Key。** 生产版导航里没有任何管理项，权限语义靠形态隔离，而不是靠隐藏按钮。
2. **后台版必须能追责。** 模板治理、运行审计都是真实读写，删除模板会真的删（有二次确认）。
3. **内测版要能证明真伪。** 每一条都写着数据从哪来，避免「看起来在跑」的假象——这是 VisionQA 的产品主张（有证据的判断）在外壳上的延伸。

## 还没做的

- 三个形态目前共用一个登录会话；真正的角色权限（管理员/普通用户）要等后端用户表。
- 后台版的「账号与配额」只能读本地演示账号，新建/禁用是占位按钮并写明未实现。
- VisionQA Canvas 同机部署后，用户生产版的画布会切到 VisionQA Canvas（见 `docs/visionqa-canvas-integration.md`），后台版的系统页会显示三端口状态。
