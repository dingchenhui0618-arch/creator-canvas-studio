# 工作流页：空状态从「三颗跳走的按钮」改成「从手上的东西起手」（r249 / v0.9.232）

## 结论

用户那句「工作流这个页面有点鸡肋，试着联动起来」指得很准，而且比看上去更严重：

1. **那三颗按钮本来就点不动。** 空状态挂在 `.cv-overlay` 里，这一层是 `pointer-events: none`（当初是为了让节点还能直接拖到画布上），
   按钮继承了去，桌面上一个都收不到点击。实测（把旧标记放回同一块浮层）：
   按钮 `pointer-events` 计算值是 `none`，`elementFromPoint` 落在按钮中心命中的是
   `DIV.react-flow__pane`（画布），`hitIsButton: false`。也就是说「去爆款雷达找一条」这一排从来只是个装饰。
2. **就算能点，它们也只是跳走。** 人站在画布上，手上明明有作品和模板，却得先跑去别的页面按一遍再回来。

这一轮把空状态改成**从你手上的东西起手**：作品（按脚本开一条 / 打开已有那条）与来自工作流的模板（套用成新工作流）
直接摊在画布上，点了**就地建好，不离开这一页**；三颗跳走的按钮沉到最后一行当兜底。

## 契约

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 空状态可点吗 | `.cv-overlay` 的 `pointer-events: none` 被按钮继承，**一个都点不动** | `.cv-start` 自己把点击收回来（`pointer-events: auto`），实测命中 `BUTTON.cv-start-row`、`inRow` 为真 |
| 空状态给什么 | 三颗「跳走」的按钮 | 作品两条 + 模板两条（各最多 2 条）+ 兜底一行 |
| 点「按它的脚本开一条」 | — | `POST /api/projects/<id>/canvas` → 拿到新流程 → 就地 `applyFlow`，地址变成 `#/canvas/<flowId>`，画布上出现输入 + 复刻两个节点，toast 说「已按《作品》的脚本开了工作流：2 个节点」，顶部出现「在帮《作品》· 第 1 版」 |
| 点「打开那条」 | — | `GET /api/flows/<flowId>` → 就地打开 |
| 点「套用成新工作流」 | — | `POST /api/templates/<id>/apply` → 原样建回一张新画布 |
| 列谁 | — | 只列**自己**的作品（公共示例作品 `ownerId` 是空串，点了绑不上，直接不列）；模板只认 `kind === 'flow'` 且节点数 > 0（套出来还是空画布的不列）；当前正打开的那条不列 |

挑哪几条、行上写什么字都在 `src/domain/canvas-start.ts`（组件只负责画），所以文案改了单测会跟着报：
「还没开过工作流 / 按它的脚本开一条」「已经有工作流 / 打开那条」「来自工作流 · N 个节点 / 套用成新工作流」。

## 顺手修的两处

- **`.cv-overlay--empty` 会溢出**：清单加进来以后这块比画布还高，1440×900 上底部被切掉。改成
  `overflow-y: auto` + `justify-content: safe center` + 底部留 48px（躲开左下角那条「拖动节点右侧圆点连线」提示），
  同时把空状态的三段说明压成一行标题 + 一行费用说明。
- **字号**：清单行标题 14px、说明与动作 13px，桌面也不缩到 12px（用户 2026-11-19 的要求）。

## 证据（本机临时实例 + 无头 Edge 真点，不花上游额度）

素材：临时 `DATA_DIR` 副本 + 一个探针账号，塞了 2 条作品（1 条还没开过工作流、1 条已经有）与 2 条来自工作流的模板。

## 边界

- 只做了「从内容起手」这一半。**跑完之后的结果怎么回流**（一键进评审 / 存成模板 / 交付）仍在原来的位置：
  运行结果抽屉、作品页、`另存为模板`。
- 模板库那条 `?type=` 参数是**内容类型**（脚本 / 图集），不是 `kind`；这里改成拉全量再由
  `canvasStartPlan` 按 `kind === 'flow'` 挑，没有动接口。模板很多时多拉一些数据，和模板库页本来就是全量拉一致。
- 作品必须**已经有了脚本**才开得出工作流；没有脚本的作品点了会得到服务端 409 的那句原文（本轮没有改这条口径）。
- 本轮 0 次真实上游调用：开工作流只建草稿、不跑节点、不扣积分。
