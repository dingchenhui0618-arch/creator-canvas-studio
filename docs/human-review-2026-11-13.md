# 人拍板这一版：人工复核与它的四张纸（2026-11-13）

结论：v0.9.21 起，模型结论之上多一层**人工复核**。当前这一版最近一次结论是「需人工确认 / 不通过」时，人看过证据可以拍板「通过 / 不通过」；拍板**不改评审记录一个字**（模型写了什么还在评审历史里），但它会写进状态胶囊、下一步、工作台、交付稿、A4 打印稿、评审对照纸，以及分享出去的同一张纸。

一句话分工：模型回答「按标准看有没有问题」，人回答「这一版发不发」。

## 一、为什么是这一片

上一轮给待办加了出口（「已看过」），但它只把待办挪开，不产生结论：人看完证据，既不能说「可以发」，也不能说「不行」。当时只剩两条路——

- 去点「标记交付」：把「交付」与「通过」混成一件事，胶囊变「已交付」，但没有人说过这版通过；
- 去改一版再评：等于让模型继续拍板，人永远只是旁观者。

产品叫视觉质检，却没有任何地方记「这一版是谁拍的板」。这一片补的就是这一层。

## 二、口径（七条，测试逐条钉住）

| # | 规则 |
| --- | --- |
| 1 | 只有当前这一版最近一次结论是「需人工确认 / 不通过」才能拍板；模型说通过的一版不需要人再确认（要否决就再评一次）。判定与队列共用 `pendingRow()`。 |
| 2 | 拍板记在「哪条作品 + 哪一次评审」上：`reviewAt` 是那次评审的 `createdAt`，由服务端现算，不信客户端传的时间。 |
| 3 | 同一版又评出新结论、或开了新版再评，时间对不上——拍板自动失效，这条回到待办，胶囊回到模型结论。人拍的是那一次，不是「这条作品永远通过」。 |
| 4 | 拍板后胶囊写人的结论：「评审 · 人工通过」（ok）/「评审 · 人工不通过」（fail）；悬停写「你 11/13 02:37 拍板通过 · 备注」。 |
| 5 | 下一步跟着换：人工通过 →「下一步 · 交付 / 交付这一版」；人工不通过 →「下一步 · 继续改 / 继续画布」。作品页主卡与工作台读同一个函数。 |
| 6 | 工作台：从「评审等你看的」待办里挪走，下面留一行「你拍板过 N 条 · 最近：作品（第 N 版 · 通过 · 时间）· 撤销在作品页」；撤销只能回作品页做。 |
| 7 | 纸：交付稿抬头写 `- 人工复核：人工通过 · 时间 · 备注`（没有拍板就写「没有（结论由模型给出，还没人拍板）」）；评审对照纸每版纸脚把「框是谁给的」与「有没有人复核过」分开写，有人复核就写「这一版人工复核：通过 · 时间 · 备注」，没有才写「不是人工复核」。 |

与「已看过」的区别：已看过只是待办上的便利贴，结论、胶囊、纸一个字不改；拍板是人的结论，会盖过模型结论出现在所有出口。两者互斥：拍过板的不再算「已看过」。

## 三、界面

作品页「评审」卡顶上一块「人工复核」，三种状态：

1. **还没拍板**：写「模型结论：需人工确认 · 还没人拍板」+ 一句话备注（可选，≤80 字，会印在纸上）+ 两个动作「拍板通过 / 这一版不行」。
2. **已拍板**：写「你 11/13 02:37 拍板通过」，输入框里就是那条备注（改判时不用重打），动作换成「撤销拍板 / 改判为不通过」。
3. **模型说通过**：只写「模型说通过，不需要人工确认」，不给按钮——不给「否决一个已经通过的结论」这种自相矛盾的操作。

为什么拍板只在作品页：需要证据（评审原图、问题锚点、修正建议）就在这一页，离开证据去拍板等于拍空气。工作台只留一行交代它去了哪。

尺寸（实测）：1440 宽下卡 387px、未拍板 209px 高 / 已拍板 191px 高，按钮 98×32、114×32、130×32；390 宽下卡 240px、249 / 267 高，两个按钮上下排；两档都没有横向滚动。

## 四、四张纸与两份导出

- **交付稿（Markdown）**：抬头多一行「人工复核」；评审小节在「最新一次」下面多一行「人拍板：通过 · 时间（备注）」；状态行写「评审 · 人工通过」。
- **A4 打印稿**：由同一份 Markdown 渲染，抬头与状态自动一致，不用另改。
- **评审对照纸（`/print/projects/<id>/review`）**：每一版纸脚原来固定写「框是评审当时给出的位置，不是人工复核」——有人拍过板这句就变成假的，现在拆成两句：框仍是模型给的位置，复核是人的结论。
- **分享出去的评审对照纸**（`/print/share/project/<token>/review`）：同一份渲染，同样印。链接本身还是凭证，纸上不出现作品 id。
- **交付包 zip**：里面那份 `评审对照页.html` 与线上同源，解压后照样写清谁拍的板。
- **账号导出**：多一份 `reviewDecisions`，人做过的判断跟着账号走。

## 七、边界（这一轮明确不做）

- **不改评审记录**：模型写的结论、问题、框、判断层都在评审历史里原样；人这一层单独存。也不做人工评分与长文复核意见（备注上限 80 字）。
- **不能否决模型说通过的一版**：要否决就再评一次（或先改）。避免「通过」与「人工不通过」同时成立。
- **拍板不是永久状态**：它只对那一次评审成立；再评出新结论、开新版，都要重新拍板。
- **不显示拍板者姓名**：当前是单账号部署，界面统一写「你」；纸与导出也不写账号（只有时间与备注）。
- **不做会签 / 多人审批流**：一个作品一条拍板记录、上限 200 条/账号，新的拍板盖掉同一次评审上的旧判断。
- **分享页正文不写拍板**：分享页只显示评审次数与结论摘要；谁拍的板只印在那张纸上。
- **已看过与拍板互斥**：拍过板的从「已看过」里消失，不再占两行。
