# 快捷创作：手机输入框再收一档，四个能力挤进一行（r223 / v0.9.207）

日期：2026-11-18

## 问题

r222 之后手机上输入框贴在屏幕底部了，但它常驻 **201px**，844 高的屏占 24%。拆开看是两块：

- 能力行 **88px**：四个按钮（联网搜索 / 读链接 / 思考模式 / 附件）在 390 宽折成两行，余额那行还单独占 16px；
- 文本域 **87px**：`rows={3}` 撑出来的三行，但手机上只是随手问一句，用不到三行。

读回答时这 201px 一直在，等于是「一个评论区被输入框吃掉四分之一屏」。

## 改法（只动 ≤560 / ≤360 两档，桌面不动）

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 能力按钮 | 四个字标签，390 宽折两行 | 手机上两个字（联网 / 链接 / 思考 / 附件），一行放得下；完整名称留在 `title` 与 `aria-label` |
| 触摸目标 | 28px 高、12px 字 | **32px 高、13px 字**——收高度不靠抠小的 |
| 余额 | 跟着按钮行，11px | 独立一行、12px（仍然一直看得见） |
| 文本域 | `rows=3` → 87px | 固定 **64px**（两行）；提示语缩到两行放得下 |
| 320 窄机 | 提示语第三行被切一半 | 文本域给到 88px（三行），完整显示 |
| 末尾留白 | `scroll-margin-bottom` 272px | ≤560 给 **200px**（输入框 148 + 离底 8 + 16px 空隙） |
| 桌面 >560 | — | 全称标签、文本域 87px、提示行都在，一点没动 |

## 验收（本机临时实例 + 无头 Edge，0 次真实上游调用、0 元）

一条会话（提问 + 带表格与列表的回答），三个宽度实测：

| 宽度 | 输入框高 | 能力行 / 文本域 | 位置（自动滚到最新回答时） | 文本域是否切字 |
| --- | --- | --- | --- | --- |
| 390×844 | **201 → 148px**（−26%） | 58px（一行按钮 + 余额）/ 64px | composer 668–816，最后一段回答 bottom 631（37px 空隙） | 否，`scrollHeight = clientHeight = 64` |
| 390×844（滚到顶） | 148px | — | composer 688–836，仍在视口内 | 否 |
| 320×720 | 186px（能力行折两行） | 72px / 88px | composer 526–712，在视口内 | 否，`scrollHeight = clientHeight = 88` |
| 1440×900 | 165px（与改前一致） | 28px（全称标签）/ 87px | `position: static`，桌面照旧 | 否 |

- 页面高度（空状态）2053 → 1999px；有会话时 2720px，`innerWidth = scrollWidth`（390 与 320 都没有横向溢出）。
- 门禁：`npm test` **1467/1467**（首轮 `test/media-gen.test.mjs` 冷却用例在并发下假失败「任务一直是 processing」，单跑 18/18、重跑全绿）、
  `npx tsc -b` 干净、lint **0 error / 26 warning**（597 文件）、`npm run build` 通过（入口 `index-ZfWxBo-X.js`）、密钥扫描 920 文件无命中。

## 边界

- 148px 仍占一屏约 17.5%。余额那一行（26px）还能再挪进会话条，但会话条在 390 宽已经很挤（新对话 + 条数 + 标题），这轮没动。
- 平台对话时，页面下方仍列着「对话预设」卡片库：滚到卡片区输入框会自然松开（不在对话面板里了，设计内）。
- 文本域固定两行：写长文在里面滚动，手机上不能再拖高（桌面仍可拖）。
- 只改前端样式与提示语，没有新接口、没动服务端与计费。
