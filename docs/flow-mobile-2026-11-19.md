# 工作流页窄屏收口：小字 13px、点按区 40/44px，修顶栏溢出与工具条互压（r242 / v0.9.226）

2026-11-19。上一轮把快捷创作收完之后，按清单扫工作流页（\`#/canvas/<flowId>\`）。
结论：**320 / 360 / 375 / 390 / 768 / 1024 六档、三种状态（默认 / 节点面板打开 / 首次上手引导）
下，小于 13px 的字与不到 40px 的点按区都清零；1440 桌面一位小数都没改。**
同时量出并修掉三处真问题，其中两处是这次才暴露的布局缺陷，不是字号问题。

## 一、量出来的三处真问题

| 问题 | 现象与数字 | 根因 | 改法 |
| --- | --- | --- | --- |
| 顶栏把整页撑宽 | 375 宽整页 \`scrollWidth\` 381、320 宽 346（横向可拖）；搜索键被挤到 36px；顶栏图标键 1024 宽时 37px | 顶栏右侧「内部测试」胶囊（76px）+ 模型切换（48–178px）都是不收缩的 nowrap 内容，右侧那格只能给 221–239px | 480 以下胶囊让位、模型键只留图标 + 箭头（补 aria-label）；1080 以下右侧那组不参与收缩、模型名收窄到 148px |
| 工具条文字互压 | 768 宽：内容 444px 挤进 366px 的格子，\`+ 节点\`、\`5 节点 · 4 连线\`、\`适应工作流\` 直接盖在一起；1024 宽 499px 挤进 454px | \`.cv-toolbar\` 只在 ≤760 换行，761–1024 这一段是 nowrap + space-between | ≤1080 允许换行（768 分成三行、1024 两行），顺手把 \`min-height\` 抬到 52/56px |
| 上手引导的关闭键 32px | 首次打开时它是整屏唯一能点的键 | 骨架层没跟上 r237 那一档 | 1080 以下 \`.vq-guide .vq-button--icon\` 40×40 |

判据用四个数：小字（<13px 的叶子文字）、点按区（宽或高 <40px 的可点元素）、
同容器兄弟重叠、内容溢出自己的盒子（\`scrollWidth > clientWidth\` 且 overflow 可见）。
React Flow 的画布视口与节点盒子天生比内容窄 2px，量的时候整棵子树排除，否则永远是噪音。

## 三、改了什么

和运行记录页、快捷创作页同一套做法：所有覆盖写在 \`canvas.css\` 末尾的 ≤1080 / ≤560 两段里、
选择器带 \`.cv-page\`，1081 以上一条规则都不进。

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 工具栏计数、缩放百分比、节点类型 / 状态 / 耗时 | 12px | **13px** |
| 检查器小标题、等宽取值、范围值、只读页脚 | 12px | **13px** |
| 步骤清单序号 / 依赖 / 状态、空状态备注 | 12px | **13px** |
| 运行抽屉的序号 / 耗时 / 状态 / 输出 | 12px | **13px** |
| 状态胶囊、节点面板标签、项目条说明 | 12 / 22px | **13px / 24px** |
| 工具条按钮 | 27px | **40 / 44px** |
| 工作流名输入框 | 30 / 37px | **40 / 44px** |
| 流程切换下拉、检查器输入框 | 32 / 35px | **40 / 44px** |
| 画布缩放键（React Flow controls） | 26×26 | **40×40** |
| 节点面板关闭键 | 22×22 | **40 / 44px** |
| 页内所有 \`.vq-button\` / 胶囊 | 32 / 22px | 跟 \`--btn-h\` / \`--chip-pill-h\` 走（40 / 44、24 / 26） |

页内只抬 token 而不是逐个改按钮，是上一轮就验证过的写法：\`.cv-page { --btn-h: 40px; --btn-h-sm: 40px }\`
一句话就让页头那排「新建 / 另存为模板 / 保存 / 运行流程」和抽屉里的按钮一起长高。

## 七、边界

1. 只量 Chromium 无头、1x；320 / 360 / 375 / 390 / 768 / 1024 / 1440，561–767 与 769–1079 没逐档量。
2. 运行抽屉是**关闭态**（元素在 DOM 里、带真实尺寸）量的；抽屉打开后的进度条与运行列表没有单独实拍。
3. 「运行中」相关状态（排队胶囊、失败红条、节点跑动）需要真跑一次流程，本轮没跑、也没花积分，
   只有样式规则与单测保证。
4. 判据只看四种：小字、点按区、兄弟重叠、内容溢出。对比度、焦点环、读屏顺序没量。
5. 顶栏胶囊在 480 以下不显示——生产版不是内部测试模式，普通用户看不到它；
   内部测试时想确认环境，看侧栏底部的版本行。
6. 手机上模型键只剩 Bot 图标 + 箭头：48px 宽时模型名本来就被压成省略号，留着等于什么也没说；
   读屏靠新加的 \`aria-label\`。
