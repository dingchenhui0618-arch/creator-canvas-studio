# 开工作流之后，那条工作流真的会出画面了（r277 / v0.9.259，2026-11-20）

## 一句话

作品页点「开工作流」，以前建出来的是一条**只会写字**的工作流：输入（钩子）→ 复刻脚本（LLM 提示词）。
分镜那 8 镜明明就在旁边，却一镜都没有进工作流——跑完一次运行，用户拿到的是一段文字。
r277 起，服务端按分镜给**每一镜建一个出图节点**：跑一次 = 复刻脚本 + 每镜一张画面，产物落在这次运行自己的目录里。

## 之前 / 现在

| | r276 及之前 | r277 |
| --- | --- | --- |
| 开工作流建了什么 | 输入 + 复刻脚本（2 节点） | 输入 + 复刻脚本 + 每镜一个出图节点（8 镜 = 10 节点） |
| 跑一次得到什么 | 一段复刻文字 | 复刻文字 + 8 张分镜画面（都在运行记录里，可下载） |
| 开工作流花钱吗 | 不花 | 不花（节点本身不计费，钱在运行时的出图节点上） |
| 跑一次多少钱 | 2 积分 | 2 + 8 × 5 = 42 积分（运行前顶栏逐项写明，余额不够按钮直接按住） |
| 分镜提示词谁拼 | 作品页「出这一镜」 | 同一个口径：服务端 `shotPrompt` 与前端逐字一致，有比对单测守着 |

## 规则（都在 `server/script-draft.mjs` 里）

- **一镜一个节点**：id `n_shot_01…`，标题「第 01 镜 · 出图」，说明写这一镜的画面与机位（分镜原话，不改写）。
- **上限 12**：分镜最多能解析出 60 镜，全建出来画布会变成一片卡片。超过 12 镜时只建前 12 个，
  工作流描述里如实写「还有 N 镜没建，一张工作流最多 12 个」。
- **比例跟平台**：模板平台认得出横屏（B 站 / YouTube）就是 16:9，其余按竖屏 9:16；认不出平台不猜。
- **模型留空**：跟随平台统一路由（图片主路由 gpt-image-2），不把模型 id 写死进流程数据。
- **接在复刻脚本下游**：复刻节点失败时这些图跟着「跳过」，不会拿半截结果去画；跳过不扣钱。
- **没有分镜就没有这些节点**：老作品（模板被删/没解析过分镜）开工作流仍是两个节点，行为不变。

## 提示词为什么不能各写一份

作品页「出这一镜」（r276）用 `src/domain/shot-prompt.ts` 拼提示词；服务端跑的是 node，import 不了 `.ts`。
所以服务端有一份逐条镜像 `server/shot-prompt.mjs`——**两份必须逐字一致**，否则「工作流画的」和「点出这一镜画的」会是两张不同的图。
`test/shot-prompt.test.mjs` 把 8 个平台 × 4 组脚本 × 6 个镜头 × 3 种来源全跑一遍逐字比对，改一边忘了另一边会直接红。

同时补上平台字段：作品页原来读的是 `模板来源.平台`（只有带原片链接的模板才有），
模板自己的 `platform` 反而没读，于是「明明标着小红书」的模板也不写「竖屏 9:16」。
现在两边都读 `模板.platform`，作品详情多带一个 `platform` 字段。

## 顺手修的三处旧话术

1. `src/domain/shot-prompt.ts` 的「复制全部」抬头还写着「生成时按顺序贴进无限画布的生图框」——
   r276 起作品页自己就能出图了，改成「每镜可以点「出这一镜」就地画一张（花你自己的积分），也可以复制走去别处出图」。
2. 作品页主卡「下一步 · 开工作流」的说明还写着「输入节点带钩子、复刻节点带完整提示词」，补上「每镜一个出图节点」。
3. `src/domain/canvas-start.ts` 的注释同步（工作流页空状态起手清单）。

## 边界与没做的

- **出图节点不看上游文本**：提示词是开工作流那一刻按分镜写死的（模型留空、比例跟平台）；改脚本/改分镜后要更新，
  重新开一条工作流或直接在节点检查器里改提示词。
- **模板库「套用模板」那条路仍是两个节点**：它走的是服务端另一段代码（`/api/templates/:id/apply`），本轮没合并进 `buildReplicateDraft`。
- **运行画出来的图还没回贴到分镜**：产物在运行记录里（`/api/runs/<runId>/assets/<node>.png`，只有运行主人能读），
  要贴到作品的分镜仍需手动「贴画面」——这是下一轮最该补的一格。
- **12 镜一次跑完要排队等**：节点是顺序执行的，真出图按每张 20–90 秒算，8 镜大约 3–10 分钟；中途停止只结算已跑完的节点。
- 假上游每次回的是同一张渐变图（8 张缩略图长得一样），这是本地假上游的产物，不是真出图结果；真出图仍待用户点一次（5 积分/张，约 ¥0.44）。

## 踩坑

1. **模板不属于当前账号时，开工作流会静默退化成两个节点**：`getTemplate` 返回 null → 没有分镜 → 2 节点。
   验收时 fixture 模板归在管理员名下、作品却给了普通账号，第一次就是这么"通过"的。要验证这条链路，模板归属必须对齐。
2. **画布上没有「运行」字样的唯一按钮**：侧栏「运行记录」也以「运行」开头，脚本按 `startsWith('运行')` 点下去直接跳到运行记录页，
   请求一次都没发出。按按钮文案选目标要写全（`=== '运行流程'`）。
3. **新 profile 的 Chrome 没有登录态**：换一个 `--user-data-dir` 就等于换了浏览器，cookie 要重新种，否则页面停在登录墙，
   所有选择器都「MISSING」。
4. **PowerShell 里跑长脚本会把 run_code 的 120 秒预算吃满**：浏览器验收要落到后台任务里，别在前台等。
