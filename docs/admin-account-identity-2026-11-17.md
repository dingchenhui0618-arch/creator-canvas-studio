# 后台改账号身份（0.9.174，2026-11-17）

## 为什么做

0.9.171 把手机号变成登录标识后，有两个账号是靠**一次性脚本**补的真实邮箱；后台原先只能停用、改角色、重置口令、删除。
「给某个账号补一个能收信的邮箱」「把登录手机号换掉」这两件最常见的客服动作，必须找助手跑脚本，既慢又留不下痕迹。

这一轮把它收进后台：账号表每行多一个「改身份」。

## 服务端

| 文件 | 改动 |
| --- | --- |
| `server/auth.mjs` | 新增 `updateUserIdentity(id, { email, loginName, name })`：只写传进来的字段，返回改后的整行 |
| `server/routes/admin.mjs` | 扩展 `PATCH /api/admin/users/:id`：接受 `email` / `username` / `name`，与原有的 `active` / `kind` 共用一个补丁 |
| `server/audit.mjs` | 新动作 `user.identity`（「修改账号身份」），进操作日志，可筛 |

### 校验与守卫（全部在写库之前）

1. **邮箱**：`^[^\s@]+@[^\s@]+\.[^\s@]{2,}$`；`@login.visionqa.local` 占位域直接拒（那是内部占位，不是能收信的邮箱）；被别的账号占用 → 409。
2. **登录手机号（用户名）**：4–32 位、不含空格与 `@`；被别的账号占用 → 409；**清空表示只能用邮箱登录**。
3. **不许把账号锁在门外**：清空登录手机号后如果邮箱还是 `@login.visionqa.local` 占位，这个账号就再也登不进来了 → 400，一个字段都不写。
4. **空值 = 不改**：显示名清空不会把名字抹掉；邮箱留空不会把邮箱清掉（占位邮箱本来就不外露）。
5. **先校验后落库**：同一请求里只要有一项不合格，前面合格的项也不写（有测试盯这条）。

### 会话与生效时机

`sessions` 按 `user_id` 关联，登录查询（`findUserByEmail` / `findUserByLoginName`）与后台列表用的是同一张 `users` 表：
改完**下一次请求就按新身份认人**，已登录的会话不掉线，也不用重新登录。

## 前端

- 账号表每行末尾多一个「改身份」，点开在**表格上方**展开一条编辑条（不弹窗、不跳页），三栏：邮箱 / 登录手机号（用户名）/ 显示名；保存后提示「已保存：邮箱 …」并刷新列表。
- 表下说明补一句：补真实邮箱、改登录手机号用「改身份」；改了邮箱，找回密码的信才发得出去。
- 编辑条在 390 宽自动落成单列，与新建账号那张卡同一套栅格（`.admin-edit-grid`），没有横向溢出。

## 边界

- 只动 `users` 表三列：不改积分、不动模板 / 工作流 / 运行记录的归属、不重发邀请码。
- 这是**管理员直接改**，没有「原邮箱确认」这一步，也不给用户自助改邮箱的入口；改完**不会自动发信通知本人**。
- 生产上没用真实账号试过这条接口（试了就会改到真实账号），生产只验了版本、入口与未登录 401；行为验证在本机实例完成。
- 后台表单在手机上仍是单列栅格自动折行，没有专门为手机重排。
