## 0. 先解决「libtv」到底是哪个站

- **事实**：`libtv.ai` 请求会 301 跳到 `https://www.liblib.tv`（2026-11-26 实测，抓取器报 cross-origin redirect 到 www.liblib.tv）。也就是说 **libtv.ai 与 liblib.tv 是同一个站**，不存在「另一个 libtv」。【A，实测】

- **判断**：用户口中的「libtv」= LibTV（liblib.tv），不是第三个站。所以本文把「LiblibAI 社区侧（liblib.art）」和「LibTV 视频侧（liblib.tv）」当同一家公司的两层来写：**底层是模型社区与风格/模型资产，上层是视频创作工作台**——这恰好是我方「找爆款→拆结构→复刻」最直接的同类。

## 2. LibTV（liblib.tv）：十个维度

### ① 定位与目标用户
- **事实**：自称「专业视频创作工具 / 新一代全能 AI 创作平台」，首页主叙事是「一万字剧本，直出 80 集爆款短剧」「6 大场景模板」，场景分为**短剧、漫剧、影视、自媒体、TVC 广告、游戏**六类。【A，S1/S2】
- **事实**：核心差异化是**双入口**——一面给专业创作者（无限画布），一面把 Agent 当「新型用户」，为 Agent 提供可直接调度的视频生产能力。【B，S11/S12】
- **事实**：背靠 LiblibAI：DAU 400 万、总用户约 2500 万、孵化超 2000 万 AI 创作者、2025 年 10 月完成 1.3 亿美元 B 轮。【B，S14】
- **判断**：它的目标用户是**「一人剧组」式的短剧/漫剧团队与投放素材团队**，不是「做一条商品短视频」的中小商家。这与我方「自媒体 / 电商产品生产 / 品牌代运营」三类身份有交集，但它的重心明显偏**叙事型长内容**。

### ② 输入与产出形态
- **事实**：输入支持**剧本文本、角色图像、参考视频**三种起手；脚本节点可「上传剧本 / 上传角色图 / 上传参考视频」生成分镜脚本。【B，S13】
- **事实**：产出覆盖**图片、短视频（分镜级）、长视频（视频合成支持 20 分钟）、数字人说话视频（OmniHuman 1.5）、音乐与音效（Mureka V8）、TTS（Eleven V3）、带文字版式的海报/封面（Qwen Image / Seedream 4.5 文本渲染）**。【B，S13】
- **事实**：站点导航含 **LibTV 3D-BOX**、插件、资产、社区、学院。【A，S4】
- **判断**：「图文」它是用图像模型绕过去的（海报/封面/组图），不是公众号长图文工作流；**音乐/音效是内置的**，这点比我方彻底。

### ③ 生成能力清单（模型 / 时长 / 比例 / 分辨率 / 批量 / 失败退款）
- **事实**：视频模型清单（S13 逐条列出）：StarVideo 2.0、Kling O3 / 3.0 / 3.0 动作迁移 / O1 / 2.6 / 2.5 / 2.1、Shot V2（720p，最长 12s）/ Shot V2 Pro（1080p）、Video 3.1 / 3.1 Fast / 3 / 3 Fast、Wan 2.6 / 2.5 / 2.2、Seedance 1.5 Pro / 1.0 Pro / 1.0 Lite、Hailuo 2.3 / 2.3 Fast / 02、Vidu Q3 Pro（1–16s）/ Q2 Pro（2–8s）/ Q2 Turbo / Q2、PixVerse V5.5 / V5、OmniHuman 1.5（数字人）、MJ Video。【B，S13】
- **事实**：图像模型：LibNano 2 / LibNano Pro（2K/4K 直出）、Seedream 5.0 Lite / 4.5 / 4.0、Midjourney V7 / Niji 7、Z Image Turbo、Qwen Image / Qwen Image Edit、Shock Image 2。【B，S13】
- **事实**：语言模型 GVLM 3.1 / 3.1 Flash、Qwen3 VL Flash（视频理解可达 20 分钟）；音频 Eleven V3、Mureka V8。【B，S13】
- **事实**：分辨率档位覆盖 720P / 1080p / 4K（首页明写「Kling 4.0 原生 4K 视频直出」）；扩图支持 1K/2K/6K、生成 1–4 张。【A，S1；B，S13】
- **事实**：极端画幅比 1:4 / 4:1 / 1:8 / 8:1（LibNano 2）。【B，S13】
- **事实**：批量：脚本列表支持**勾选单条或批量**转分镜图，顶部有「批量生成视频」。【B，S13】
- **事实**：StarVideo 2.0 单次最多 **12 个参考文件**（图 ≤9、视频 ≤3、音频 ≤3）。【B，S13】
- **事实**：**失败退款：未核实**（官网/帮助/协议中均未抓到失败退积分的规则）。
- **判断**：模型覆盖是「**别人家模型的超级货架**」——它自己不训模型，靠 LiblibAI 的渠道与定向优化拿到低价（如 Seedance 2.5 720P 0.16 元/s）。我方只有 seedance-2.0 / 2.0-fast 与 gpt-image-2.x 两三个型号，这一维度不是「弱一点」，是「不在一个量级」。

### ④ 编辑与二次加工
- **事实**：无限画布有 **5 类基础节点：文本 / 图片 / 视频 / 音频 / 脚本**；可连线搭工作流、可打组、可「创建工作流」保存进「我的工具箱」、可「整组执行」。【B，S13】
- **事实**：图像工具：增强（2/4/6 倍，5 种模式）、扩图、多角度（8 水平 ×4 俯仰 ×3 景别）、打光（26 主光点位 + 9 轮廓光 + 智能模式）、重绘、擦除、抠图、宫格切分（9/25 宫格）、标注、裁剪、焦点编辑、镜头聚焦、摄像机控制。【B，S13】
- **事实**：视频工具：**视频高清**（2/4/6 倍 + 30/60/90fps）、**视频解析**（对成片做分镜拆解，输出画面内容、景别、图像提示词、运镜提示词、时长、**音乐节奏、人声**的表格）、**视频剪辑**（≤10min、≤1080P，I/O 出点入点、0.01s 精度）、**视频合成**（多片段顺序拼接、原声 + 独立音频轨 BGM/配音、一键静音、时间轴编辑、实时预览、**20min 长视频导出**）。【B，S13】
- **事实**：运镜 20+ 预设、可自定义、可收藏。【B，S13】
- **事实**：**导出剪映 / 工程包：未核实**（未见任何剪映工程或 XML/AAF 导出）。
- **判断**：**「视频解析」是全场最该被我方抄走的一条**——它就是「拆结构」，而且带音轨、带音乐节奏、带人声。我方的抽帧链路用 `-an` 丢掉音轨、口播是看着画面编的（`server/frames.mjs:58`、`server/vision.mjs:21`），在同一个动作上是**假拆解**。

### ⑤ Agent / 工作流 / 自动化
- **事实**：站点一级导航里有独立的 **「LibTV Agent BETA」** 入口。【A，S4】
- **事实**：官方开源仓 `libtv-labs/libtv-skills` 提供 Agent 技能包，走 **LibTV OpenAPI**：环境变量 `LIBTV_ACCESS_KEY`，脚本含 `create_session / query_session / change_project / upload_file / download_results`；交互模型是「**Agent-IM 会话**」——Agent 建会话、发生成指令、轮询进展、批量下载；遵循 OpenClaw 技能规范，可 `npx skills add libtv-labs/libtv-skills` 一键安装。【A，S5】
- **事实**：Agent 生成出来的项目落地为画布链接 `/canvas?projectId=...`，即**人和 Agent 共用同一份画布产物**。【A，S5】
- **事实**：工作流可在画布内保存、复用、整组执行；跨项目复用靠「我的工具箱」。【B，S13】
- **事实**：**工作流市场 / 公开 API 计费 / MCP 协议：未核实**（有 OpenAPI，但未见公开 API 价目表，也未见官方 MCP server）。
- **判断**：LibTV 真正的护城河不是模型，是**「Agent 是第一等用户」这件事被做成了产品形态**：Agent 不是外挂，它走的是与人相同的画布与会话。我方聊天室里已经能让平台智能体回话、也发了 `vqc_` 令牌与 MCP 端点（`README.md` 第 362 节 + 缺口审计），但**我们还没有把 Agent 的产物和人的产物放在同一张画布上**，这是架构级的差距。

### ⑥ 素材与资产
- **事实**：资产体系：节点右键「创建资产」→ 命名 / 分类 → 存进画布左栏「我的资产」；已保存的工作流进「我的工具箱」。【B，S13】
- **事实**：**主体库**（标注「待完善」）：针对可灵、Vidu 等模型开放，可用 2–3 张多视角图或 3–60s 单段视频创建「主体」（角色/商品/宠物/人物），**可为主体设置音色**，主体描述会转成提示词增强参与生成。【B，S13】
- **事实**：参考体系完整：参考图、参考视频、首尾帧、多模态全能参考（@素材名 指定用途，最多 12 个文件）。【B，S13】
- **事实**：风格库（含 Lib 独家风格）+ 自定义风格模板：上传 5–20 张同风格图训练，发布到 `liblib.art/ai-tool/upload-template` 审核通过后可在风格库调用。【B，S13】
- **事实**：数字人：OmniHuman 1.5（音频驱动静态人物图成说话视频，可生成全身动作）。【B，S13】
- **判断**：它的「主体库 + 音色」是把**角色一致性**做成了可复用资产；我方「数字人资产」目前只是几张定妆参考图，不做唇形驱动，却仍然叫「数字人」（`docs/platform-gap-audit-2026-11-26.md` 第 5 条）。**同一个词，两种东西**，对外会直接挨打。

### ⑦ 模板与社区
- **事实**：6 大场景模板（短剧/漫剧/影视/自媒体/TVC/游戏）+ TV Director（按题材给导演风格、优化分镜语言）。【A，S2；B，S13】
- **事实**：社区侧：画布可一键「分享」（对方能看到画布及后续操作）、可「发布」到 LibTV 社区首页（**发布且通过审核后曝光**）、有消息中心看点赞评论。【B，S13】
- **事实**：导航含 社区 / 学院 / 名导亲授 / 创作精选 / 全网爆款 / **创作者挑战赛**；挑战赛有「百万奖金」。【A，S4；B，S13】
- **事实**：**创作者分成（按作品/模板持续分钱）：未核实**；目前能确认的是**赛事奖金**与社区曝光，不是长期分成。
- **判断**：它的社区是「**作品墙 + 赛事**」，不是「**模板货架 + 同款复刻**」。我方主线里的「模板库 + 同款复刻 + 模板来源足迹」反而是**更工程化、更可交付**的一套；但它的曝光位与赛事带来的创作者拉新，我方完全没有。

### ⑧ 商业化
- **事实**：计费结构 = **会员（年卡 / 月卡） + 积分 + 单独购买算力**；个人中心可看会员等级、积分余额、购买记录、订阅计划、**开票**。【B，S13】
- **事实**：官方横幅价（今日首页仍在挂）：**Seedance 2.5 720P 低至 0.16 元/秒；年卡每秒最低 5 分钱；月卡 0.24 元/秒；年卡最高减 1300，得 15 个月 + 送超 20 万积分**。【A，S1/S2/S3】
- **事实**：**会员档位表本身未核实**（`/pricing`、`/vip`、`/member` 均 404，价目需登录）。第三方口径：至尊 92K 积分原价 40999、双 11 价 16999；Seedance 2.5 720P 按量 0.17 元/秒；每日登录送 20 积分且当天零点清零。【C，S16】
- **事实**：租号市场口径：至尊 66000 积分/月 ≈ 1250 元；Seedance 2.0 满血 ≈ 6 元/条、Fast ≈ 4 元/条。【C，S16 之外的小红书转租帖，未列为正式出处，仅作量级参考】
- **事实**：**失败退款、API 计费、发票税率：未核实。**
- **判断**：它把「秒」做成对外唯一计价单位（0.16 元/s），用户心智极简单；我方现在是「上游成本 ×1.1 ×10 积分/元」的内部公式（`server/media-pricing.mjs`），**对外说不出「一条多少钱」**，且支付通道未接。这不是价格高低问题，是**没有对外价格语言**。

### ⑨ 平台化
- **事实**：账号维度有会员等级、积分余额、UUID 一键复制、购买记录、水印设置、开票。【B，S13】
- **事实**：分享 = 画布级协作式分享（对方可见后续操作），不是只读快照。【B，S13】
- **事实**：发布到社区需**审核**后才曝光。【B，S13】
- **事实**：合规硬限制：**StarVideo 2.0 暂不支持上传含写实真人脸部的素材（图与视频均不行），系统自动拦截**。【B，S13】
- **事实**：**多用户 / 团队 / 席位 / 权限 / 企业版：未核实**（未见团队账户概念）。
- **判断**：「自动拦截真人脸」这条比很多竞品都狠，说明它把**合规前置到了上传口**；我方目前只有 AI 生成标识（`docs/ai-label-2026-11-13.md`），没有上传口的人脸/版权拦截。**团队与权限我方可收割**——LibTV 看起来没做，RunningHub 做了。

### ⑩ 能直接借鉴 / 必须避开
- **借鉴 1**：把「**秒**」当对外计价单位，并在首页直接挂「低至 X 元/秒」。
- **借鉴 2**：**视频解析**（成片 → 分镜表，含运镜/音乐节奏/人声）——这是「拆结构」的正确实现，且天然接我方评审。
- **借鉴 3**：**Agent-IM 会话 + OpenAPI + 官方 skill 包**三件套；Agent 的产物直接落在人类同一张画布 / 同一个 projectId 上。
- **借鉴 4**：**主体库 + 音色绑定**做角色一致性；**风格模板**用 5–20 张图训练并审核入库。
- **借鉴 5**：上传口**自动拦截真人脸**的合规前置。
- **避开 1**：别学它把「画布分享」做成**可继续操作**——我方分享链接已经永久有效且无口令（缺口审计第 4 条），再叠加可写权限会直接变成越权入口。
- **避开 2**：别学「积分当天清零」（第三方口径，S16）这类促活设计，它已经在黑猫上产生会员积分投诉。
- **避开 3**：别在没做失败退款规则前就对外卖积分——LibTV 的退款规则查不到，这在我方是**必须比它更清楚**的地方。

## 3. RunningHub（runninghub.cn / runninghub.ai）：十个维度

## 4. 与我们相比的差距

### A. 我们完全没有（按「不补就谈不下去」排序）
1. **支付与真实计费闭环**：竞品都有可下单的会员/积分；我方 `plans.mjs` 只定义「多少钱换多少积分」，付款通道未接，且缺口审计指出 `VQ_BILLING_MODE` 默认 auto 会在无回调下直接到账白送积分。
2. **对外价格语言**：竞品说「0.16 元/秒」「一条 0.22 美元」；我方只有内部公式（上游成本 ×1.1 ×10 积分/元），说不出单条价。
3. **音轨/ASR/BGM 能力**：抽帧 `-an` 丢音轨，口播与 `audio` 字段是模型猜的；LibTV 的「视频解析」直接产出含音乐节奏与人声的分镜表。
4. **数字人视频（唇形驱动）**：LibTV 有 OmniHuman 1.5；我方「数字人资产」只是定妆参考图。
5. **音乐/音效/TTS 生成**：LibTV 有 Mureka V8 / Eleven V3；我方媒体生成只有图与视频。
6. **主体库 + 音色绑定**：竞品把角色一致性做成可复用资产（2–3 视角图或 3–60s 视频建立主体）；我方无。
7. **参考视频 / 多模态混合参考 / 首尾帧**：LibTV 单次最多 12 个参考文件；我方目前是参考图。
8. **团队账户（席位、团队钱包、成员额度、审批、按成员留痕）**：RunningHub 已完整实现。
9. **模型货架**：竞品数十个视频模型 + LoRA 训练 + 超分/续写/帧率增强；我方 2 个视频型号 + 3 个图片型号。
10. **4K 与长视频**：LibTV 4K 直出、20 分钟合成；我方 480p/720p/1080p。
11. **创作者分成与市场交易**：RunningHub 有 creator-reward / my-income、工作流市场；LiblibAI 有官方「收益榜」与「视频作者收益」；我方模板库只做复用，无收益。

14. **对外 API 售卖体系**：竞品有任务型 API + 三类 Key + 按秒计费；我方 API 只服务自家前端。
15. **自助注册**：竞品手机号即可注册；我方 `VQ_REGISTRATION=0`，开号靠邀请码或管理员，手机号只能登录不能注册/找回。

### B. 有但明显更弱
1. **工作流**：我方 9 节点 + 真扣费 + 失败退款 + 断点续跑，但只对管理员 beta、无市场、无对外 API；RunningHub 是「节点生态 + 市场 + API」三件套。
2. **画布**：无限画布只有 iframe + 120 秒票据，能力与失败无法审计；LibTV 的画布是人机共用的主战场。
3. **Agent 接入**：我方有房间智能体、`vqc_` 令牌与 MCP 端点，但工具只开了 `templates.list` 一个、写操作全关、无逐次批准；LibTV 官方 skill 已能建会话、上传、批量下载并把产物落回同一 projectId。
4. **模板与复刻**：我方有模板库与来源足迹，但没有社区曝光、没有同款复刻的「一键成片」，也没有创作者分成。
5. **剪辑与成片**：我方评审→交付→回执闭环很强，但**不做剪辑**；LibTV 有 0.01s 精度裁取与 20min 时间线合成。
6. **定价可运营性**：档位可后台改是优点，但无支付、无对账、无发票。
7. **评审证据**：我方有锚点与版本对比，但评审不参与「交付是否放行」的判定；竞品虽无评审，却用「发布需审核」把质量门放在了出口。
8. **模型路由**：我方有 key 池与路由（`model-routes.mjs`、`keyvault.mjs`），但可选模型太少，路由再聪明也换不出货。

### C. 我们更强
1. **「复刻 → 评审 → 交付 → 回执 → 版本对比」是闭环的**：zip + sha256 + 回执打开次数 + 项目版本 diff，竞品都没有同等交付物。
2. **视觉评审是真能力**（service / local-model 两种 provider + 证据锚点 + 评审队列），竞品只有「发布审核」这种二元门。
3. **失败退款与断点续跑**已实现（工作流真扣费、失败全额退回、run resume / queue），RunningHub 的失败退款规则反而查不到。
4. **聊天室里能接用户自己的 codex / Claude**（连接器 + `vqc_` 令牌），竞品的 Agent 是平台自营、不可替换。
5. **爆款检索（红狐）+ 来源足迹 + 未占用来源**：LibTV 有「全网爆款」栏目但那是自家作品精选，不是可检索的爆款库。
6. **无限画布不自己造**：把外部 Source-Available 画布用票据 + 排队位接进来，比自己从零做节点编辑器省了半年——这是选择而非缺陷（代价是审计不到）。
7. **单位经济学有模型**：成本 → 加价 → 积分一条公式可改（`media-pricing.mjs`），竞品是黑箱点数。

## 5. 一句话结论

**LibTV 赢在「模型货架 + 人机同画布 + 视频解析」，RunningHub 赢在「工作流 API 化 + 团队与算力 SKU」；两者共同暴露的是我方「没有对外价格、没有音轨、没有组织实体」三件事。而「复刻→评审→交付→回执」这条链，是它们都没有、也不像是短期会做的。**
