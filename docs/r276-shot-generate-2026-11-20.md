# r276 / v0.9.258：分镜的每一镜，现在能就地出一张画面

## 结论

作品页的「分镜」这一块，以前是整条创作链里唯一一处**要换个应用自己干**的活：
分镜提示词在这一页现拼（v0.9.164），拼好了只能「复制」，然后自己去无限画布或快捷创作里出图、下载、再回到这一页「贴画面」。
四步里有两步是产品自己的活。这一版把出图收回到每一镜下面：

**「出这一镜 · 5 积分」→ 出图中 NN% → 画完自动贴到这一镜。** 只点一下，钱也只花这一次。

## 之前是什么样

- 分镜提示词面板底下那句说明写着「贴进无限画布的生图框就能出图，出图会花你自己的额度」——那是 v0.9.164 的实情。
- 后来（v0.9.210 起）平台自己有了出图通道：快捷创作的「图片」页签走我们自己的网关与积分，同一次出图也记在「最近生成」里。
- 但作品页没有跟着改：界面上仍然只有「复制提示词」与「贴画面（上传）」两条路，中间那一段留给用户手工搬。

## 现在这一下做了什么

| 段 | 具体动作 | 失败时说什么 |
| --- | --- | --- |
| 出图 | 用这一镜的提示词（分镜画面 + 机位 + 这一段的口播）调 `/api/media/generate`，模型与单价读 `/api/media/models`（与快捷创作同一份真源） | 服务端原话 + 钱退没退 |
| 等 | 每 2.5 秒读一次任务，最长 4 分钟（服务端出图超时 240 秒） | 4 分钟没回来：说明它还会画完、去哪儿找，**不叫人重试** |
| 取回 | 从 `downloadUrl` 取字节 | 画好了但取不回来：说图在「最近生成」，别当失败 |
| 贴 | 传成自己账号下的素材（`uploads/<账号>/…`），再记到这一镜 | 说清「图在、钱花了、只是没记上」，并给「贴画面」这条路 |

只点一下才花钱：进页面、展开提示词、切页签都不出图。余额不够时按钮直接写「还差 N 积分」并按住，不让点下去才 402。
按钮上的价格与模型名来自服务端，不在前端写死。

## 验收（本机临时实例 + 筛选代理，0 次上游调用、0 费用）

代理只拦 `/api/media/generate`、`/api/media/tasks/task_fake001`、`/api/media/tasks/task_fake001/file` 三条路径，
其余（登录、上传、作品详情、静态资源）原样转发；「画好的那张图」是代理用 zlib 现造的一张 96×96 PNG。
所以：界面、扣费字段、轮询、上传、记账全是真代码，只有上游那一段是假的。

| 场景 | 实测 |
| --- | --- |
| 打开作品页 | 8 镜各一颗「出这一镜 · 5 积分」，title 写明模型（GPT Image 2）与单价 |
| 点一次（正常） | 出图中 40% ×7 次轮询 → 按钮回到「出这一镜 · 5 积分」、标签变「你的画面」、作品 `shots["1"].media` 落盘 |
| 点一次（上游忙 + 已退款） | 行下出现「上游忙，这一下没出图 本次 5 积分已原样退回，没有产生消耗。」，标签仍是「原片帧」 |
| 390 宽 | 按钮 141×44，整页 `scrollWidth 380 ≤ innerWidth 390`，最小字号 13px |
| 控制台 | 0 条报错 |

## 单元测试守住的几句话

`test/shot-generate.test.mjs`（9 条）+ `test/shot-prompt.test.mjs` 的说明文案：

1. 处理中只到 99%：服务端说 100% 但还没 succeeded 时，不显示成「好了」；
2. 「画好了」必须带得回下载地址，否则说清去「最近生成」拿；
3. 失败按服务端记的账说钱退没退——花了钱没退时**不许**出现「没有产生消耗」；
4. 余额不足单独一档：去充值，不是「再试一次」；
5. 任务号都没回来时，不许叫人直接再点一次（可能已经在画、可能已经扣过）；
6. 比例只挑上游认的（9:16 → 1:1 → 列表第一个），绝不硬传；
7. 作品页里出图请求只挂在点击上，页面里没有花钱的原生确认框。

## 边界

- 这次只做了「一镜一张、即时出图」：没有批量、没有自动重试（重试就是再扣一次）、没有参考图。
- 出图本身走我们自己的网关，真调一次 5 积分（上游约 ¥0.44）。本轮**没有**发起任何真实出图：等用户点头再验一张。
- 图片模型只有一个（gpt-image-2）：换模型、加方舟 Seedream 备通道仍待用户决定。
- 分镜本身还是模板的；这一版只改「这一镜挂哪张画面」，模板一个字没动。

## 坑

- 390 第一版溢出到 429px：新按钮让分镜动作行撑破格子。修法是给 `.vq-shot-actions` 补 `min-width: 0`，并在 ≤760 的横排里允许 `flex-wrap`。
- 验证时 cookie 设好以后不能只改 hash（同一文档不会重新加载，App 还停在「未登录」那一屏），必须真 reload 一次。
- 新 profile 会弹上手引导遮罩，截图前要先点掉 `button[aria-label="关闭引导"]`，否则截图上盖一层。
