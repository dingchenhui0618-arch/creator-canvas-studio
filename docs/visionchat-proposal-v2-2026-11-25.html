1. 第 5 条把产品改成了什么

v1 的前提是「房间里跑平台的智能体，用我们的 Key，按轮扣积分」。你说的是反过来的：用户把自己已有的智能体接进来。这个改动不是换个计费口径，它把三个地方都改了：

v1（平台智能体）v2（自带智能体）
模型与额度我们的 Key 池，扣我们积分用户自己的订阅或 Key，我们不收对话费
平台的成本每次发言都有真金白银只有消息存储、转发与工具（生图/生视频/评审）
冷启动新用户 50 积分就能聊新用户得先有一个智能体；所以默认给 1 个平台智能体兜底，开箱能聊
差异化「又一个 AI 聊天」「把你手上那几个智能体拉进同一个房间，一起做一条内容」

一句话定位：VisionChat 不是再卖一个模型，是把用户已经在用的智能体请进平台，让它们能碰到平台里的东西（模板、作品、资产、生图、评审）。

新用户 50 积分仍然有用：开箱聊（平台智能体 1 积分/轮）、生图（5）、评审（5）。

2. 权限模型：agent 是你的代理，不是特权主体

2.1 一句话定义

工具表 = 这个账号在界面上能点的东西，一一对应，多一个都不给。 判断标准不是「这个 API 安不安全」，而是「人在浏览器里点得到吗」——点得到才进表，点不到就不进。

2.4 一条我主动加的护栏（请你确认）

你是管理员，后台那些按钮你点得到。但如果照字面「你能点它就能点」，agent 就能调 /api/admin/users 删账号、读所有人的会话——这跟第 1 条的后半句「绝对不允许探到服务器等所有服务内容」直接打架。

我的处理：工具表对所有角色一致，只含用户侧功能；管理员身份不扩权。 管理员要查运维数据，用后台，不用 agent。这条比你说的更严一档，理由是可逆性：删账号不可逆，聊天里一句被带偏的提示词就可能点下去。

2.5 审批：默认只读，写与花钱逐次点

3. 智能体怎么接进来（本期核心）

3.1 你举的四个，现实差别很大

智能体有没有可编程入口能不能拿到 API Key一期接法
豆包（火山方舟）OpenAI 兼容 /chat/completions能（Ark API Key）直连
ClaudeAnthropic Messages API；或 Claude Code 命令行两者都常见（订阅没有 Key）直连（有 Key）／连接器（只有订阅）
codexCodex CLI；也有 API订阅登录最常用连接器（codex exec）；有 Key 时也可直连
workbuddy本机客户端，模型配置在 /~/.workbuddy/models.json要实测，默认按「只能在你的机器上跑」对待连接器

结论：只做直连会漏掉一半人（订阅制没有 Key），只做连接器会让豆包这种纯 API 用户多装一个东西。所以两条都做。

3.2 方式 A · 直连（BYOK）

用户在「我的智能体」里填三样：baseUrl + apiKey + model（OpenAI 兼容或 Anthropic 兼容二选一），可加一句「职责」。

  • 存哪：新文件 DATA_DIR/user-agents.json，key 用 AES-256-GCM 加密，密钥沿用 server/keyvault.mjs 那套（VQ_KEY_SECRET 或 .model-keys.secret，0600），但与平台 Key 池物理分开，接口只回 sk-••••1234。
  • 谁去调：服务端代调（浏览器直连会被 CORS 挡，且 Key 不能下发前端）。这一层只做转发，不扣积分，但要记一条 user_agent_calls（谁、哪个智能体、多少 token、耗时）。
  • 出口白名单（防 SSRF，必须有）：只允许 https://；域名解析后再校验 IP，拒环回/私有网段/链路本地（169.254.169.254）；不跟随跳转到内网；连不上 10 秒、整体 120 秒超时。
  • 失败文案：401 = Key 无效（不重试）、429 = 对方限流（退避一次）、超时 = 「你的智能体没在 120 秒内回话」。都不扣积分。

3.3 方式 B · 本地连接器（Connector）

给「只有订阅、没有 Key」的人：在自己电脑上跑一个小程序，它连平台、收消息、交给本地 CLI 执行、把结果回传。

你电脑                                     我们服务器
┌───────────────┐   长轮询取消息(25s)     ┌──────────────┐
│ visionchat-   │ ──────────────────────▶ │  /api/rooms  │
│ connect       │ ◀────────────────────── │   :id/...    │
│  ├ codex exec │   回传文本/工具请求      └──────────────┘
│  ├ claude -p  │
│  └ workbuddy  │   ▲ 只带房间令牌，不是登录态
└───────────────┘
  • 令牌：vqc_ 前缀，绑定「账号 + 房间 + 该智能体成员」，只存 sha256（照 server/sms-login.mjs 存验证码的做法），设置页可随时撤销；权限 = 收发这一个房间的消息 + 转交工具请求，不是 session cookie，拿不到别的东西。
  • 谁执行：连接器在自己机器上决定跑什么命令，平台只发消息、只收结果。所以平台永远不会把 shell 下到用户机器，用户机器也不会被平台探到——和你第 1 条的边界同向。
  • 工具请求怎么走：房间要生图时，平台自己执行（那是我们的资源）；「读我电脑里的文件」这种工具一期没有（人的界面上也没有这个按钮）。
  • 形态：一个零依赖的 scripts/visionchat-connect.mjs（node 直接跑），设置页给一行可复制的启动命令 + 令牌。
  • 并发：一个令牌同时只处理 1 条消息；同一房间同一时刻 1 个回合（与平台智能体同一条闸门）。

7. 三期路线

期范围一句话验收
一期1 人 + N 个智能体（平台/直连/连接器混合）、7 个工具、审批、SSE同房间 3 个智能体（一个豆包直连、一个 codex 连接器、一个平台智能体），@ 谁谁回，生图走审批并扣 5 分
二期多人 + 多智能体：同工作区成员、邀请链接、席位、房主代批邀请令牌一次有效；被邀请者只能读自己能看的；房主可代批工具调用
三期社交属性（形态待定）——

三期的三个候选，等你想清楚了再选，现在不写死：

  1. 房间可被订阅：别人的房间只读可见，能「复制成一个新房间」来用（模板 + 智能体配置一起复制）。
  2. 作品流里的房间卡：房间产出的成品进公共作品流，点进去看它怎么被做出来的（只有过程摘要，不是聊天全文）。
  3. 智能体可以被别人借用：你配置好的智能体以「只读模板」形式公开，别人一键加入自己的房间（凭据永不出你的账号）。

三个都涉及公开内容与权限外溢，等一期跑起来有真数据了再定。

9. 风险

风险缓解
提示词注入让 agent 把用户自己的 Key 说出去Key 只在服务端解密、永不下发前端；消息里出现 sk- 形状的串做打码；输出前扫一遍
连接器令牌泄露只绑定一个房间、可撤销、只存 sha256；撤销即 401；不写进任何日志
转发放大（拿我们的服务器打别人的接口）出口白名单 + 每账号每分钟 20 条 + 每房间同时 1 回合 + 单次 120 秒超时
