# 失败的那条能直接再来一次（r283 / v0.9.265）

## 为什么做这条

生产上真实出现的 6 条生成记录里，**4 条是失败**：上游超时、HTTP 500 read_response_body_failed、模型没接入。r282 给了这些行一个「删掉」的出口，但删掉只是把痕迹抹了——用户真正想要的是**再试一次**。

没有「再来一次」的时候，重试的代价是：把提示词、模型、方式、比例、时长、清晰度、参考素材全部重填一遍。多数人填到一半就不试了，于是失败记录只剩删除这一条路。

顺带修掉一个名不副实的按钮：结果卡上原有的「再生成」，点下去只是把结果收起来，**并不会真的再跑一次**（标题却写着「按同样的提示词再来一次」）。

## 规则（4 条）

| 问题 | 结论 |
| --- | --- |
| 重试带什么参数 | 原样搬这条任务记下的：提示词、模型、方式、比例、时长、清晰度、参考素材 |
| 在哪能点 | ① 失败结果卡「再来一次 · N 积分」② 最近生成的失败行「再来一次」③ 成功结果卡「再生成一次 · N 积分」 |
| 点了扣多少 | 按**当前**模型价再扣一次；失败照旧全额退回。按钮上直接写清数字，不点开才看见 |
| 什么情况不重试 | 这条用的模型已经下线（说清是哪个模型，不偷偷换模型扣钱）；上一条还在跑（先等它跑完） |

三条入口走的是同一段提交代码 runGeneration(input, priced)：参数由调用方给死，**不读闭包里的 state**——否则「把旧参数填回输入框、紧接着提交」会拿到还没生效的上一帧，等于用错参数又扣一次积分。

参数怎么搬由 src/domain/media-retry.ts 一个纯函数算（planTaskRetry），页面只负责调用与画按钮；模型下架、方式改名、比例 / 时长 / 清晰度已经不在当前规格里的兜底都在那一个函数里，能单测。

## 实测（临时实例 + 本地假上游，0 次真实上游调用、0 费用）

假上游是本机 8899 上的一个小服务，按 OpenAI 兼容格式回一张自己画的 512×768 渐变 PNG；生产 Key 一个没碰。

| 检查 | 结果 |
| --- | --- |
| 失败行 | 「再来一次」66×24、13px；「删掉」在最右；原因行改成「失败 · 已退 5 积分 · 上游超时：等了 240 秒没有返回（timeout）」 |
| 失败结果卡 | 「生成失败 / 原因 / 已全额退还 5 积分（任务号 …）」下面一枚「再来一次 · 5 积分」（161×32） |
| 点重试后 | 输入框被填成那条任务的提示词；POST /api/media/generate 正文里 kind=image、prompt=那只橘猫那一句、model=gpt-image-2、mode=text、ratio=9:16、assets=[] —— 与那条任务逐字一致 |
| 上游收到的 | model=gpt-image-2、同一句提示词、size=1024x1536、n=1（比例 9:16 变成了 1024×1536） |
| 积分 | 余额 300 → 295（只扣一次） |
| 结果卡 | 四枚动作一行站下：看大图 / 用作参考 / 下载图片 / 再生成一次 · 5 积分 |
| 点「再生成一次」 | 第二次请求正文与第一次逐字相同（regenCalls: 1），确实又跑了一次 |
| 390（按 390 重载） | 「再来一次」74×32、行宽 272、页面 390 = 390、字号 13px |

## 边界（都是实话）

- 重试**会再扣一次积分**：这是又跑了一次生成，不是「续跑上次那单」。扣费失败仍全额退回。
- 参考素材按 id 重发，服务端仍按「自己名下」校验；素材已经被删掉的，会在结果区报「这个参考素材不在了，请重新上传一次」。
- 模型下线的老任务只能看不能重试（会明说是哪个模型），不会静默换成别的模型。
- 视频那条的「再来一次」**没在假上游上跑通**：假上游只实现了出图，视频通道会当场失败并全额退回。视频参数怎么搬由 domain 单测覆盖（时长 / 清晰度 / 方式），页面同一段代码，但真实上游那段路这轮没走。
- 结果卡上的「清掉结果」被去掉了：那是 r283 之前「再生成」实际在做的事；留着就变成第五枚按钮，1440 上会折到第二行。要空面板，下一次生成会替换它。
- 最近生成里成功行仍然没有「再来一次」：那一行只有 190 来 px 宽，再塞一枚会把「用作参考 / 下载 / 删掉」挤散；成功行要再抽一张，打开它、点结果卡上的「再生成一次」。
