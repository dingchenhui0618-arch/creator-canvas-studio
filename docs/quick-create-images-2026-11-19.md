# 快捷创作对话支持发图片（r245 / v0.9.228）

日期：2026-11-19 · 版本：0.9.228 · 轮次：r245

## 结论

快捷创作的对话现在能直接丢截图/照片问问题：**原图随这一轮交给模型看，图里的字由模型自己读，本地不做 OCR。**
这也是「一页 DeepSeek」最后一个缺口——之前只能读脚本、Word、Excel、PDF，遇到一张「这张封面哪里不行」的截图只能让用户去描述。

三件事刻意做得跟以前不一样：

1. **图片只在发送那一轮参与理解**。追问时历史里只剩一行说明（「这一轮带过 1 张图片（xxx.png）：后面只按文件名记住」），
   不会每问一句就再付一遍图片的输入费，也不会让模型以为自己还看得见那张图。
2. **带图的一轮走一次性回答**（不逐字）。多模态 + 流式在不同上游并不都成立，一条 400 会让整次对话失败并退款；
   一次性拿到整段再一次性推给界面，行为是确定的。界面上明说「带图这一轮整段给，不逐字」。
3. **必须走视觉模型链**（`visionChain()`）。文本链里常是纯文本模型，图片会被静默丢掉，回答装得像看过了——
   这个坑在 llm.mjs 里已经踩过一次（评审返回「未提供可分析的截图图像」）。

## 契约

| 项 | 规则 | 为什么 |
| --- | --- | --- |
| 认什么 | 按文件头认 jpg / png / webp / gif（与参考素材同一套签名） | 改名的 html、svg、exe 进不来；不信扩展名 |
| 一条几张 | 最多 2 张 | 一张 1024 宽截图按 high 细节约 1.1k token，两张够看清一张稿子 |
| 多大 | 单张 ≤ 8 MB（与文字附件同一个上限） | 原图要读成 base64，再大就是几份副本 |
| 原图在哪 | `DATA_DIR/chat/files/<账号>/cf_xxx.png`（0600），meta 是同名 .json | 只读列表/文字的路径不会把原图读进内存 |
| 谁能看 | 只有上传的人；`/api/chat/files/:id/raw` 按归属校验，只发 image/*、带 nosniff | 不公开、不进分享页、不进交付包 |
| 留多久 | 每人 20 份，超了顶掉最旧的（顶掉时连原图一起删） | 没有清理入口时，无上限等于把磁盘交给上传的人 |
| 删了 | 删附件连原图一起删 | 不留没人能再引用、却仍占磁盘的截图 |
| 失败 | 原图读不到 → 扣费前就 422；超 2 张 → 400；不是图 → 415 | 读不出来一分钱都不该扣 |

## 怎么验的

三层，全部 0 费用：

1. **单测**（`test/chat-send.test.mjs`，本地假上游，新增 6 条）：
   认图 / 改名 .txt 仍认得出 / 带图这一轮正文是多模态数组且 detail=high / 追问不再带图 / 3 张被拒且不扣费 / 原图只给本人且删附件连原图一起删。
   全量 **1620/1620**。
2. **真浏览器端到端**（Edge 无头 + CDP，上游是 8894 的假服务，故意慢 2.5 秒）：
   真的通过 `<input type=file>` 选了一张真实截图 → 缩略图出现 → 发送 → 截到「正在看图并回答…」→ 整段答案一次出现 → 点缩略图看原图。
   假上游日志确认收到的是 `image_url` 的 data URL，不是文件名。
3. **窄屏量测**（重载页面后点开会话再量，隐藏的 0×0 元素不算点击目标）：

| 宽度 | 小字 < 13px | 点按区 < 40px | 内容溢出容器 | 整页宽度 |
| --- | --- | --- | --- | --- |
| 390 | 0 | 0 | 0 | 390 = 390 |
| 320 | 0 | 0 | 0 | 320 = 320 |

第一轮量出 390 下附件 chip 只有 **26px 高**、移除键 **24×28**，补了 ≤560px 的 `min-height: 40px`（chip 与移除键）后归零。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `server/chat-files.mjs` | 收图片：按文件头认、原图与原 meta 分开存、顶掉/删除时连原图一起删、`readChatFileBytes()`、`resolveChatFiles` 给图片留一行说明、上限 `imagesPerMessage: 2` |
| `server/chat.mjs` | `imageParts()` 把原图读成 data URL（detail=high）；只把「当前这一条」换成多模态正文；带图走 `visionChain()` + 一次性回答；`meta.vision` 记一笔 |
| `server/chat-store.mjs` | 历史里的图片消息追加一行占位说明，避免模型以为自己还看得见 |
| `server/routes/chat.mjs` | 新增 `GET /api/chat/files/:id/raw`（归属校验、只发 image/*、nosniff、private 缓存） |
| `src/api/chat.ts` | `ChatFile.kind` 加 `image`、加 `mime`、`imagesPerMessage`、`chatFileRawUrl()` |
| `src/components/QuickChat.tsx` | 附件入口接受图片；chip 显示缩略图与体积（图片没有「多少字」）；点开看原图；「正在看图并回答…」；空状态与 title/提示语同步 |
| `src/styles/agents.css` | `.qc-file-thumb`、`.qc-preview-img`；≤560px 下 chip/移除键 40px |

## 边界（写清楚，别让人以为验过了）

1. **一次真实的多模态调用都没有发生**：单测与截图用的都是本地假上游。生产上第一次真发图会不会被上游拒（`deepseek-flash` 是否收 `image_url`）**未验证**——要花约 ¥0.01，等用户点头。
2. **没有本地 OCR**：模型看不出来的字就是看不出来，界面也这么说（「本地不做 OCR，读错了以原图为准」）。PDF 扫描件仍然按「读不出字」拒绝。
3. **只在当前这一轮带图**：更早的轮次只剩文件名。想再问那张图，要重新发一次（或等做「引用历史图片」）。
4. 图片不进分享页、不进交付包、不进模板；会话删除不删附件文件（仍受 20 份轮转约束）。
5. 只测了 320 / 390 / 1440；平板 768 未逐屏量；只 Chromium 无头 1x。
6. 缩略图 24×24 是居中裁切，长截图看到的是中间那一块，点开才是全图。
