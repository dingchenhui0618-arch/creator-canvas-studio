# 画布出图 502：平台漏发幂等键（2026-11-13，v0.9.55）

## 一句话

画布 16:51 那张图没出来，不是余额不足、不是模型名写错、也不是 Key 坏了：SeeAPI 的**同步出图属于计费请求，必须带 `Idempotency-Key`**，画布本来会发，接到平台生成通道后由平台代发，而平台在转发时把这个头丢了；后台还把它误报成「上游凭证无效（HTTP 400）」，把排查方向带偏了一轮。

## 证据链

| 来源 | 原文 | 说明 |
| --- | --- | --- |
| 网关路由日志 r112（`DATA_DIR/model-routes.json`） | `HTTP 400 {"error":{"code":"invalid_idempotency_key","message":"Idempotency-Key is required for synchronous billable requests."...}}` | 出图 661 ms、同一分钟视频 200；说明是出图这一路的参数问题，不是网络或额度 |
| 画布生成记录 `generation-record-6.json` | `CGCM Image2 request failed: HTTP 502`，内嵌网关回包 `出图失败：上游凭证无效（HTTP 400）` | 画布如实记下了网关的措辞；问题在于这句措辞是错的 |
| 画布直连 SeeAPI 的源码 `generation_image2.py:158-162` | `headers = {..., "Idempotency-Key": stable_idempotency_key(payload)}` | 画布原本就发这个头，换成平台通道后应由平台发 |

三段一对：**画布会发 → 平台代发时丢了 → 上游 400 → 平台包成 502**。

## 改法（`server/gateway.mjs`）

| # | 问题 | 现在 |
| --- | --- | --- |
| 1 | 幂等键没转发 | 画布放在正文里的 `idempotency_key`（或 `idempotencyKey`）提到请求头上；正文里删掉，不再当业务字段转给上游；调用方没给就补一个 `vq-<uuid>`。这条只对 SeeAPI（CGCM）形态发，方舟没有这个要求 |
| 2 | 换把重试会重新提交 | 一次请求一个幂等键，换下一把 Key 也沿用同一个值——同一次生成不会被扣两次 |
| 3 | 上游「接单了但没确认结果」被当成普通失败 | `502/503/504 + provider_submit_outcome_unknown`：拿同一个键重放一次（SeeAPI 保证同键同 body 回原结果、不重复扣费）；仍然不明就回 `UPSTREAM_OUTCOME_UNKNOWN`，**绝不换 Key**——换一把就是新的一次提交，可能重复扣费 |
| 4 | 拒绝原因看不出该修哪 | 报错固定带上游 code：`上游要求带幂等键，平台这次没带上（HTTP 400 invalid_idempotency_key）`；`invalid_idempotency_key` 不再被宽匹配成「凭证无效」 |
| 5 | 后台对账表没有画布真在用的模型名 | 出图对账补 SeeAPI 的 4 个名字：`image-2-pro`、`image-2.5`、`nano-banana-flash`、`nano-banana-pro`（画布 CGCM 渠道发的是这些，不是方舟名） |

## 生产验收（v0.9.55，本机假上游，未调用真实 SeeAPI）

在生产起一个本机假上游（`127.0.0.1:2588`，收请求、记头、按 SeeAPI 的规则卡幂等键），加两把只认 `vq-r67-canary` / `vq-r67-reject` 的临时 Key，走真实的平台通道：

| 场景 | 结果 |
| --- | --- |
| 画布同款请求（正文 `idempotency_key: bd-canvas-r67-canary`） | **200 / 59 ms**；假上游收到 `idempotency-key: bd-canvas-r67-canary`，正文里**没有**这个字段 |
| 不带给 | **200 / 12 ms**；平台补的键是 `vq-4576510c-d1da-4de0-96be-89bfefbfe9bb` |
| 假上游回 `400 invalid_idempotency_key` | **502**，`error` = 「出图失败：上游要求带幂等键，平台这次没带上（HTTP 400 invalid_idempotency_key）」，`upstreamCode` 一并带回 |

验完清场：两把临时 Key 删除、假上游 `pkill`、`/tmp` 里的脚本与日志删掉；生产没有留下任何多余 Key（仍是 2 把：DeepSeek 文本 + SeeAPI 出图出视频）。

**没做的一步**：没有对真 SeeAPI 发出图调用（你的规则：不自行消耗上游额度）。所以「改完真能出图」还差一次真实出图；你点头我就跑一次，只出一张。
