# 画布出图 502：平台把幂等键丢了（2026-11-13，v0.9.56）

## 一句话

那张图没出来，不是余额不足、不是模型名写错、也不是 Key 坏了：SeeAPI 的**同步出图是计费请求，必须带 `Idempotency-Key`**。画布自己在请求头里发了这个头，换成平台通道后平台只转了正文、把头丢了，上游回 `400`，平台再把它包成 502；后台还把这次拒绝误报成「上游凭证无效」，把排查方向带偏了一轮。

## 证据链

| 来源 | 原文 | 说明 |
| --- | --- | --- |
| 网关路由日志 r112（`DATA_DIR/model-routes.json`） | `HTTP 400 {"error":{"code":"invalid_idempotency_key","message":"Idempotency-Key is required for synchronous billable requests."...}}` | 出图 661 ms、同一分钟视频 200：不是网络、不是额度 |
| 画布生成记录 `generation-record-6.json` | `CGCM Image2 request failed: HTTP 502`，内嵌网关回包 `出图失败：上游凭证无效（HTTP 400）` | 画布如实记下网关的措辞；错在这句措辞 |
| 画布源码 `enterprise_server/generation_image2.py:151-162` | 请求体只有 `model / prompt / size / n / response_format / quality / output_format / moderation`；请求头里带 `Idempotency-Key: stable_idempotency_key(payload)` | **幂等键只在请求头里**，正文里没有；平台收到这个头却没往下传 |

三段一对：**画布发头 → 平台丢头 → 上游 400 → 平台包成 502**。

## 改法（`server/gateway.mjs` + `server/routes/gateway.mjs`）

| # | 问题 | 现在 |
| --- | --- | --- |
| 1 | 调用方的 `Idempotency-Key` 请求头被丢掉 | 路由层把请求头交给生成通道，通道按「正文 `idempotency_key` → 调用方的头 → 平台补 `vq-<uuid>`」取键，再发给 SeeAPI；正文里若混进这个字段会被删掉，不当业务参数转发。方舟（Ark）没有这个要求，不发 |
| 2 | 换把重试会重新提交 | 一次请求一个幂等键，换下一把 Key 也沿用同一个值——同一次生成不会被扣两次 |
| 3 | 上游「接单了但没确认结果」被当成普通失败 | `502/503/504 + provider_submit_outcome_unknown`：拿同一个键重放一次（SeeAPI 保证同键同 body 回原结果、不重复扣费）；仍然不明就回 `UPSTREAM_OUTCOME_UNKNOWN`，**绝不换 Key**——换一把就是新的一次提交，可能重复扣费 |
| 4 | 拒绝原因看不出该修哪 | 报错固定带上游 code：`上游要求带幂等键，平台这次没带上（HTTP 400 invalid_idempotency_key）`；`invalid_idempotency_key` 不再被宽匹配成「凭证无效」 |
| 5 | 后台对账表没有画布真在用的模型名 | 出图对账补 SeeAPI 的 4 个名字：`image-2-pro`、`image-2.5`、`nano-banana-flash`、`nano-banana-pro`（画布 CGCM 渠道发的是这些，不是方舟名） |

## 生产验收（v0.9.56，本机假上游，未调用真实 SeeAPI）

在生产起一个本机假上游（`127.0.0.1:2588`，记请求头与正文、按 SeeAPI 的规则卡幂等键），加一把只认 `vq-r67-canary` 的临时 Key，走真实的平台通道：

| 场景 | 结果 |
| --- | --- |
| 画布同款请求（键**只在请求头** `Idempotency-Key: bd-canvas-r67-header`，正文里没有） | **200 / 55 ms**；假上游收到 `idempotency-key: bd-canvas-r67-header`，正文里没有这个字段 |
| 头也不给 | **200 / 12 ms**；平台补的键是 `vq-b84728d3-b86b-479f-bfe8-fadcdce4a6e1` |
| 假上游回 `400 invalid_idempotency_key` | **502**，`error` = 「出图失败：上游要求带幂等键，平台这次没带上（HTTP 400 invalid_idempotency_key）」，`upstreamCode` 一并带回 |

> 两次上线：v0.9.55 只做到「平台自己生成一个键」，上线后回读画布源码才确认**画布本来就会发这个头**；少了透传，画布重试时会换成平台的新键，上游认不出是同一次提交，仍可能重复扣费。v0.9.56 把「透传调用方的头」补齐，并用同一套假上游复验。两次都没有调用真实 SeeAPI。

验完清场：临时 Key 删除、假上游停掉、`/tmp` 里的脚本与日志删掉；生产仍是 2 把 Key（DeepSeek 文本 + SeeAPI 出图出视频）。

**没做的一步**：没有对真 SeeAPI 发出图调用（你的规则：不自行消耗上游额度）。改动让「请求带上了 SeeAPI 要的头、错误也说得清」，但真机出图仍要一次真实调用确认——你点头我就跑一次，只出一张。
