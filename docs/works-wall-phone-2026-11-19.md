# 作品流在手机上：卡片正文抬到 15/14px，动作与胶囊换成 44/40px 触控区（r233 / v0.9.217）

**结论先说**：「作品」页默认打开的就是这条作品流（快捷创作的成品 + 工作流运行 + 无限画布的画布合成一条），
390 下两列卡片只有 139px（320 下 106px）。这一版只抬字号与触控区：标题 15px、工作流摘要 14px、时间与
来源标签 13px；卡片上的「用作参考 / 下载」从 24px 高抬到 44px 并让下划线贴着字；筛选胶囊从 12.5px / 29px
抬到 14px / 40px；大图关闭按钮 32×32 → 44×44、说明 12.5px → 14px。**列数与按比例排版没动**（9:16 优先、
1440 四列 / 1080 三列 / 768 与 390 两列），桌面 1440 / 1024 / 768 实测一个数字都没变。

## 两个值得记的点

1. **44px 的盒子会让下划线脱开**：`.works-action` 是「文字 + 1px 下划线」的文字链接，`min-height`
   抬到 44 之后字在盒子中间、线在盒子底部，两者之间空出 ~12px，看着像断开的。改成
   `align-items: flex-end` + `padding-bottom: 2px`：字坐在底部、线贴着字，触控区仍然向上撑满 44px。
2. **两列口径不能被「卡片太小」说服着改掉**：390 下 139px 确实窄，但「按作品比例排版、9:16 优先、
   390 两列」是定过的排版口径（1440 四列）。这轮只动字号与触控，列数交给
   `test/works-wall-mobile.test.mjs` 里那条断言锁住，免得下次有人顺手改成整宽一列。

## 边界（照实说）

- 截图来自**本机临时实例**（`DATA_DIR=.tmp-r233-data`，临时账号 + 4 条示例任务 + 1 条示例运行，**0 次真实上游调用**）：
  缩略图是纯色占位 PNG，不是真图；那条「视频」是按 video 任务写的 PNG，浏览器解不出来，大图里只显示播放器黑框。
- 只逐屏量 390 / 320，另加 1440 / 1024 / 768 三档回归；**641–760 与 768 平板没有改**，那一档动作仍 24px。
- 320 下两列只有 106px：「用作参考 / 下载」会折成两行（各 44px），这是宽度决定的，不是回归；
  胶囊在 320 上折成 3 + 2 两行，「共 5 条」落到第三行右对齐。
- 卡片高度仍按作品比例（`align-items: start`），同一行里 9:16 与 1:1 的卡片底部不齐——这是「按比例排版」的代价，
  这一版没改成等高。
- 这一轮没碰「作品项目」那个视图（`vq-project-card`，780px 以下已是单列 + 3×2 数据格），它作为下一条 UX 待办。
