# r311：注册后先建自己的资产（身份引导 + 产品/数字人资产）

日期：2026-11-24　接口契约：[r311-asset-onboarding-contract.md](./r311-asset-onboarding-contract.md)

## 结论

这一轮只做一件事：**让新注册的人先拥有属于自己的东西** —— 一件商品的资产图，或者一张自己的定妆照。
不做成片渲染、不做一键复刻改造、不做桌面端。理由是上一轮实测出来的：服务器只有 2 核 / 1.8 GB，
一条 30 秒的 1080p 成片要 45–70 秒 CPU，同时只能跑一条；把这台机器当渲染农场，用户量一涨 API 先崩。

而且用户指出了一件比算力更要紧的事：
**「一键复刻」不是痛点。没有自己的商品图和自己的脸，复刻出来的东西跟他没关系。**
所以顺序反过来了 —— 先有资产，再谈复刻。

## 做了什么

### 1. 身份引导（注册 / 首次登录后）

- 三步：选身份（自媒体创作者 / 电商产品生产 / 品牌代运营）→ 选类目 + 填方向 → 建资产
- 身份不可跳过；资产可以「以后再说」，但每次进工作台仍会提示
- 状态存在 `DATA_DIR/onboarding.json`，不进 users 表：它是引导过程状态，不是登录身份，
  坏了最坏是再弹一次，不该影响登录
- 只有普通账号（`kind === 'account'`）会看到；管理员不弹

### 2. 产品资产与数字人资产

| | 产品资产 | 数字人资产 |
|---|---|---|
| 来源图 | 1–3 张（实拍 / 白底图） | 1 张正脸照 |
| 生成 | 白底主图 / 场景图 / 细节特写 / 成套平铺 | 正面定妆 / 半身景别 / 侧脸角度 / 场景中使用 |
| 尺寸 | 1024×1024 | 1024×1536 |
| 上限 | 6 套 / 账号 | 3 套 / 账号 |

- 建资产**不调上游、不扣积分**，只落一份 draft；生成要用户再点一次（花钱的那一下必须他决定）
- 生成是后台任务：先扣费、落 `generating`、立刻回，界面每 2.5 秒轮询；关页面照样跑完
- 失败按张退（账本净额决定退多少，重复调用不会多退）；进程重启后卡在 `generating` 的会标中断并退款
- **新手首套免费**：每个账号第一个产品资产与第一个数字人资产的 4 张图不扣积分，失败作废不算用掉
- 付费档按 `limits.paidCreditsPerImage` 下发（当前 3 积分/张，与快捷创作同价）

### 3. 提示词（真正的产品质量开关）

四张图能不能「还是同一件商品 / 同一张脸」，取决于提示词写得够不够死。三条约束逐个槽位都写：

1. 明写「严格保持参考图中商品的形状、轮廓、颜色、材质、纹理、logo 与包装文字完全不变」，
   人像则点名「脸型、五官比例、眼睛、鼻子、嘴型、发型、肤色」；
2. 明写「画面里不出现任何文字、水印或叠加的 logo」—— 电商图最容易被模型顺手加一排小字；
3. 每张只改一个变量（背景 / 视角 / 景别 / 场景），四张一起改模型守不住主体。

参考图先压到长边 1024 的 JPEG 再发（复用 `server/image-scale.mjs` 的缓存），
一张手机原图几 MB，四张都带原图既慢又没必要。

## 数据落点

```
DATA_DIR/onboarding.json                      # 引导状态（按钮背后就这一份）
DATA_DIR/assets/<ownerId>/<asst_id>/meta.json # 资产元数据：来源、槽位、状态、免费标记
DATA_DIR/assets/<ownerId>/<asst_id>/hero.jpg  # 生成出来的资产图，按槽位命名
DATA_DIR/media/assets/<ownerId>/<ast_id>      # 来源图（复用参考素材库）
```

## 安全边界

- 目录第一层就是账号 id，读的时候按归属校验；别人的资产一律 **404**（不解释「存在但你没权限」）
- 生成只能拿**自己账号**上传的素材做参考；别人账号的素材 id 传进来当不存在
- 资产图预览走 `/api/assets/:id/files/:slot`：登录 + 归属 + 每次回源（`sendAuthImage`）
- 槽位名只认 `[a-z]{3,10}`，资产号只认 `asst_…`；路径不拼接外部输入
- 注销账号时资产目录整个删掉；导出账号时带资产元数据（不带图片本体）

## 成本

| 项 | 单次成本 |
|---|---|
| 一套资产图（4 张，主通道 gpt-image-2.6 @ $0.028） | ≈ ¥0.80 |
| 新账号首套免费 | ≈ ¥0.80（产品）+ ¥0.80（数字人）= ¥1.60 最坏 |
| 新账号赠送积分 | 50 积分（¥5 零售，成本约 ¥1.5–2） |

也就是说，一个注册用户把「首套资产 + 50 积分」全用完，平台成本约 **¥3.5**，对应零售 ¥5 的额度。

## 怎么验的

- 单测 `test/assets.test.mjs`（11 条）：提示词必须逐个槽位写死「保持主体不变 / 不出现文字」、
  归属（别人的资产与素材都当不存在）、建资产不花钱、没素材不许生成、重启恢复、注销清理。
- 端到端 `scripts/assets-smoke.mjs`（22 项）：起临时实例 → 真登录 → 引导接口 → 传图 → 建资产 →
  列表 → 删资产 → 未登录 401。**不点生成**（会花钱）。
- 截图 `scripts/shot-real.mjs`：同一个临时实例里真建账号、真开会话、灌进浏览器 cookie 再按视口拍。
  `docs/r311-onboarding-1440.png` / `-390.png` 是引导第 1 步，`docs/r311-assets-1440.png` /
  `-390.png` 是资产库空状态 —— 都是真实后端渲染，不是固定响应。
  出图后的样子只能靠真调，本轮没有。
