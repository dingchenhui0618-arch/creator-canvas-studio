# 上手引导改讲「一条作品的主线」（v0.9.41）

结论先行：第一次进工作台弹出来的那张引导，讲的还是**没有作品之前的产品**——三步「找 → 拆 → 验」，
最后一脚落在「视觉评审」这个工具上，「作品」一次都没提。这一版把它改成主线四步
**找 · 发现 → 拆 · 模板库 → 做 · 作品 → 交 · 交付**，四张卡分别落在一级导航里；
画布与视觉评审不再各占一步，而是写成「作品里的两个工具」。引导还会读你账号的真实进度，
告诉你现在走到哪、下一步该点哪一张。

上一版引导改在 v0.6.0（P2 导航收敛，`73a967d`）——那时「作品」这条主线还没立起来；
之后 30 多个版本都在往作品上收，引导却一直没跟着改。

## 一、口径：引导讲的是「一条作品的主线」，不是页面清单

目标模型里一级只有四个去处：工作台（下一步点哪里）、作品（一条内容从脚本到评审走到哪了）、
发现（去哪找原片）、模板库（可复用的结构）。智能体、画布、视觉评审、运行记录是**能力**，
从作品的某一步被带进去，不是目的地。

引导如果按页面清单讲，就会把人送进工具区——所以这一版：

| | 之前（v0.6.0 起） | 现在（v0.9.41） |
| --- | --- | --- |
| 步数 | 三步：找 / 拆 / 验 | 四步：找 / 拆 / 做 / 交 |
| 落点 | 发现 → 模板库 → **视觉评审**（工具区） | 发现 → 模板库 → 作品 → 作品（都在一级导航） |
| 作品 | 一个字都没提 | 第 3 步就是它：改脚本、进画布、送评审都在这一条上 |
| 交付与分享 | 没有 | 第 4 步：作品页「交付」出四种产物，只读链接发给甲方 |
| 顶部说明 | 「把一条爆款变成能给编导直接拍的方案」 | 先讲结构：一级四个地方、工具区装什么 |
| 卡片脚注 | 只有单价 | 单价 +「已有 N 条 / 已交 N 次」 |
| 主按钮 | 「开始使用」（只是关掉弹窗） | 落到你还没做完的那一步（去发现 / 去模板库 / 去作品） |

## 二、引导跟着你的进度走

打开时并行读四路真实接口：`/api/credits`（单价与余额）、`/api/templates`（总条数、已解析条数）、
`/api/projects`（作品条数）、`/api/deliveries`（交付次数）。按「先缺的那一步」分四档：

| 读到的事实 | 底部那一句 | 主按钮 |
| --- | --- | --- |
| 模板库 0 条 | 账号下还没有模板：先去「发现」挑一条加进模板库，再点「去解析」 | 去发现挑一条 |
| 有模板、没作品 | 模板库已有 N 条（其中 M 条只存了链接 → 先点「去解析」，解析完原地升级），点「用这条改编」开出第一条作品 | 去模板库挑一条 |
| 有作品、没交付 | 手上有 N 条作品，还没交出去过：先在工作台「下一步」接着做，出画面、评一次，再回作品页「交付」 | 去作品接着做 |
| 交付过 | 手上有 N 条作品，已经交出去 D 次：工作台「交出去的」按时间排，开过新版也查得到 | 去作品接着做 |

三路计数里**只要一路没读到就整体不写状态**（只剩余额与一句「单价与余额以设置 · 积分为准」）：
引导上写错状态，人会照着错的那一步走，宁可少说一句，也不拿 0 冒充「你还没有模板」。

## 三、钱的说法对得上计费表

服务端只对这些按次扣积分：检索（`search`）、解析（`replicate`）、跑画布（`flow_run`）、
视觉评审（`review`）、智能体对话（`chat`，引导里不出现）。开画布、导出交付稿、生分享链接都不计费——
卡面上把「不计费」的两件事明说出来，免得人以为点进画布就开始烧积分：

| 卡片 | 脚注 |
| --- | --- |
| 01 找 · 发现 | 检索每次 N 积分 |
| 02 拆 · 模板库 | 解析每次 N 积分 · 已有 M 条 |
| 03 做 · 作品 | 跑一次 N 积分 · 评审 N 积分 · 已有 M 条（卡面文案另写一句「开画布不扣积分」） |
| 04 交 · 交付 | 导出与分享不扣积分 · 已交 D 次 |

单价全部来自 `/api/credits`，不写死数字；读不到就写「按次计费」。

## 四、顺手修的两处

1. **窄屏主按钮够不着**：四张卡在 390 宽度下放不进一屏（弹窗自己滚，`scrollHeight` 1096 > `clientHeight` 810），
   原先「下一步」那句话和主按钮在最底下，要先滑到底才看得到。改成弹窗内 `position: sticky; bottom: 0`，
   主按钮永远在屏幕里（390 下按钮 `top 770 / bottom 802`，视口 844）。桌面端没有溢出，样子不变。
2. **脚注右边要么箭头、要么计数**：一开始读到计数就顶掉了箭头，结果第一张卡有箭头、其余三张没有，
   看起来像「有数据的卡不能点」。现在箭头永远在，计数只加在它左边。

## 七、边界

- 这一轮只改了引导弹窗（组件 + 样式）与它的三条测试；**没有动计费表、没有动接口、没有改任何一屏的一级导航**。
- 生产只做了只读 GET（引导打开时读的四路接口），没有造数据，也没有为了截图去点任何会扣积分的按钮。
- 「作品 1 条、交付 0 次」是线上真实状态：引导如实说「还没交出去过」，不替账号补一条交付记录来让截图好看。
- 引导的「看过一次」标记存在浏览器 localStorage（`vq_welcome_seen:<userId>`），按账号各算各的；服务端不记这件事。
