# 评通过就把这一版沉淀成模板（r252 / v0.9.235）

日期：2026-11-19 · 版本：0.9.235 · 发布标签：20261119-r252tpl

## 结论

主线的最后一站接上了：评审结论是「通过」、且这一版真有脚本与分镜时，结果页的「接下来」直接多一个
**存成模板**——那一刻人正看着「这一版可以往交付走」，这段结构值不值得留下，就在这一屏决定。
沉淀下来的模板会记住它出生时那一次的评审结论（「来自作品《X》· 第 K 版 · 评审通过」），
下一条作品从它开始时，看得见它是怎么来的。

## 这一轮修的是什么

上一轮（r251）把「评完往哪走」钉在了结论下面，但出口只有「回作品 / 回工作流」。
主线的终点是沉淀模板，而这一步在评审页根本不存在：要回作品页往下翻才能找到那张卡片；
更麻烦的是，沉淀出来的模板不会说它是评过什么存下来的——模板库里「来自作品《X》」后面没有结论。

| # | 问题 | 修法 |
| --- | --- | --- |
| 1 | 评审通过那一刻没有「沉淀」的入口，得回作品页找 | 结果页「接下来」多一个 `saveTemplate` 出口：通过 → 回作品 · 存成模板 ·（有工作流时）回工作流 |
| 2 | 能不能存，前端猜不出来（要有脚本、要有分镜） | `POST /api/review` 的响应带 `templatable`，由服务端按同一处判断现算；false 就不给按钮，不给「点了才报错」的入口 |
| 3 | 模板库不知道这条是评过什么存下来的 | 落库时把这一版最近一次的评审结论记进模板：`review { verdict, at, issueCount }`；模板详情两处写「评审通过 / 评审不通过 / 评审需人工确认」 |
| 4 | 存完不知道结果，只能自己去模板库翻 | 按钮就地变成一行结果：「已存成模板《X》（3 段 · 2 镜 · 评审通过），在模板库里能查到。」失败说原话 |

「能不能沉淀」这件事现在只有一个判断：`server/project-template-ready.mjs`。
作品页那张卡片、评审页这个按钮、以及 `POST /api/projects/:id/template` 的第二道闸，读的是同一份 spec。

## 边界

- 只写模板库新的一条：不改作品、不改它绑的模板、不开新版本、不扣积分。
- 评审结论是**快照**：模板记的是「存下来的那一刻」这一版评过什么，之后作品再重评不改它。
- 历史评审记录仍然只读：不给「存成模板」出口，要沉淀就回作品页（那里随时能存）。
- 沉淀的前提没变：没有脚本、没有分镜不落库（服务端 400 SCRIPT_REQUIRED / STORYBOARD_REQUIRED）；
  从工作流起、没有分镜的作品仍然走工作流里的「另存为模板」。
- 本轮 0 次真实上游调用；探测脚本退出后清掉临时实例、临时目录与只属于探针的浏览器进程。
