# 想比哪两版就比哪两版：画布节点与脚本口播逐项列出来（v0.9.117，2026-11-14）

v0.9.116 解决了「回退版要跟底座对账」：版本行有了来源胶囊，也有了一句「比 v1 改了什么」。但一句话只够回答「有没有改」，回答不了「到底改了哪几个节点、哪几段口播」；而且它只比「上一版」或「底座」，想拿 v1 直接对 v3 时没有入口。这一轮补的是**任意两版对照**：只读、不写版本、不扣积分，画布节点和脚本口播逐项列出来。

## 三条路

- **① 现成**：`versionChanges` 已经有一句话，`canvasDelta` / `scriptText` 已有比对口径，版本行已经带 `basedOn`。缺的只是「选两版」和「结构化明细」。
- **② 最省力**：不新写比对引擎，也不把全部节点塞进作品详情。把现有比对拆成可复用的 `canvasDetail` / `scriptDetail`，版本行的一句话继续读老函数；新增一个只读接口，打开弹窗才取这两版。
- **③ 验收**：任意两版都能选；明细逐项列出多 / 少 / 改；方向能交换；缺快照 / 缺画布时说清哪一侧不比；400 / 404 边界明确；1440 与 390 不溢出；浏览器只发 GET。

## 做了什么

### 服务端

- `server/version-diff.mjs` 新增 `canvasDetail`：在节点指纹上比出多、少、改，保留 `id` 与标题；老的 `canvasDelta` 改为从它取标题，版本行与交付稿的口径不变。
- 新增 `scriptDetail`：按段名比口播，重名段落按出现顺序比词；改过的段带 `before` / `after` 两份口播，钩子单独给前后。老的 `scriptText` 改为从它生成一句话，行为与旧测试一致。
- 新增 `versionCompareOf`：同一次调用给出 `summary`、`canvas`、`script`，页面与接口不会各说各话。
- 新增只读接口 `GET /api/projects/:id/versions/compare?base=1&target=3`：
  - 当前版读现在的画布与脚本；归档版读自己的画布与开版时存下的脚本快照；
  - 版次必须是 `1..当前版` 的整数，选同一版返回 **400 `VERSION_COMPARE_SAME`**；
  - 版次越界 / 缺参数返回 **400 `VERSION_COMPARE_INVALID`**；
  - 归档记录找不到返回 **404 `VERSION_COMPARE_MISSING`**；
  - 不写作品、不写版本、不扣积分；缺一侧时 `canvas` / `script` 为 `null`，`notes` 说明哪一侧不比。

### 界面

- 版本区右上新增「两版对照」按钮；当前版没有上一版时禁用。
- 弹窗默认「上一版 → 当前版」；当前版有 `basedOn` 时默认拿底座当基准。两个选择器都能换，中间按钮交换方向。
- 结论条写这一对版本的一句话；下面分「画布 / 脚本」两段：
  - 画布：多 / 少 / 改各一组，节点标题用胶囊列出；
  - 脚本：多 / 少段列出段名，改过的段列出段名与前后口播（最多两行）；
  - 钩子换过时并列 v1 / v3 两句原文；都没动时只写一句「节点没动」「口播与钩子都没动」。
- 缺一侧时写「有一侧画布读不到」「有一侧脚本没存快照」，不用另一版顶替；底部写明只读口径。
- 390 下两个选择器排成一列，弹窗宽 342（左右各 24），页面 `scrollWidth 390`。

## 踩到的坑

1. **不要把全部节点塞进作品详情**：为了一个只读对照把十几版节点都传过去，首屏会白重。单独接口、打开才取，详情只保留节点数。
2. **当前版与归档版读的不是同一份数据**：当前版读现在的画布与脚本；归档版读归档的画布与开版快照。混用会让「v1 到 v3」显示成现在的脚本。
3. **方向必须能反**：交换之后多 / 少要换边，钩子的 before / after 也要换。E2E 专门断言 v3 → v1 是「少一段收尾」，不是照抄正向句子。
4. **缺一侧不能冒充「没改」**：画布被删时 `canvas=null`，无脚本快照时 `script=null`，`notes` 说明；页面不写「跟上一版一样」。
5. **不要在 effect 里同步 setState**：第一版弹窗一打开就 `setBusy(true)`，oxlint 多一条 `react(set-state-in-effect)`。改成按「base:target」键存结果，换选择器时直接看新键有没有结果，异步回来才 setState；warning 回到 15 条基线。
6. **不要拿读了一半的文件写回**：这次改样式时用默认 2000 行 `read` 读 `projects.css`，再整文件写回，把 2528 行截成 2000 行。`git checkout` 恢复后改用 `edit` 在锚点前插入。任何整文件写回之前必须确认读到了全文（`limit` 大于总行数）。
7. **本地内存紧时全量测试要顺序跑**：并行跑 945 条时，waterline 看到机器可用内存偏低，把两条全局名额用例判成 `MEMORY_PRESSURE`；这不是代码退化。用 `--test-concurrency=1` 顺序跑 **945/945**，CI 的 Node 22 / 24 全量也绿。
8. **断言要用归一后的标题**：节点标题在服务端会被裁剪，E2E 一开始拿「输入」去对「输入主题」失败；这不是产品问题，但说明断言要读真实渲染文本，不能按输入参数猜。

## 发现但没做

- 不保存对照结果，也不能把「两版对照」单独分享成链接；分享页仍是作品只读页。
- 不展开节点配置的逐字段 diff，只看节点标题与「改过」；脚本只比段名与口播，屏幕字、时长不参与。
- 不支持跨作品对照，也不做版本删除 / 重排。
- 生产没有真实作品的两版对照；没有在真实模板 / 真实运行上验证。
- 没有把对照结果导出成图片或 PDF。
