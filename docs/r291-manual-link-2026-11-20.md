# r291：自己带一条链接来拆（v0.9.273）

日期：2026-11-20　版本：0.9.272 → 0.9.273

## 为什么做这个

主线的第一步一直是「在爆款雷达里检索到一条 → 点一键复刻」。这条路上只要有一处不成立，整条创作闭环就进不去：

- 检索服务挂了、Key 被禁用、上游额度用完：雷达页只能显示示例数据，示例数据没有原视频，复刻按钮是灰的（`title="示例数据没有原视频，无法复刻"`）；
- 用户手上本来就有一条自己的片子（自己拍的、客户给的、在别的平台看到的），他不需要检索；
- 后台「系统 → 复刻任务」的空状态写着「从「爆款雷达」里选一条内容、**或在雷达页粘贴视频直链发起复刻**」——而雷达页从来没有那个输入口，是一句没兑现的承诺。

服务端其实早就支持：`POST /api/replicate` 的 `body.url` 会作为 `overrideUrl` 覆盖掉 item 里的链接（`server/jobs.mjs` `startReplicate` 的 `targets`）。缺的只是入口和判定。所以这一轮不新建管线，只把已经存在的能力接出来。

## 做了什么

### 1. 一个判定「这条链接是什么」的规则，前后端各一份、由测试钉住不许漂移

新增 `server/video-link.mjs`（服务端真源）与 `src/domain/video-link.ts`（前端镜像，用于边粘边判）：

| 链接 | 判定 | 界面文案 |
| --- | --- | --- |
| `v.douyin.com/…`、`douyin.com/video/…`、`iesdouyin.com/…` | 抖音 | 抖音链接 |
| `xiaohongshu.com/…`、`xhslink.com/…` | 小红书 | 小红书链接 |
| `.mp4 / .m4v / .mov / .webm`（含查询串） | 直链 | 视频直链 |
| 其他 | 拒绝，并说清为什么 | 「认不出这条链接：给抖音 / 小红书的内容页链接，或者 .mp4 / .mov / .webm 直链」 |

细节：整段抖音分享文案（「7.94 复制打开抖音，看看【…】 https://v.douyin.com/xxx/ 复制此链接…」）直接粘进来能捞出链接；漏了 `https://` 的裸域名也接住；`ftp://` 这类给「只支持 http / https」，不是笼统的「先把链接粘进来」；带账号口令的链接直接拒（服务端本来就会拒，界面上先说清）。

### 2. 平台以链接本身为准，不再信客户端声明的 platform

`server/media.mjs` 的 `acquireVideo` 以前是：直链就下载，否则要求 `platform` 必须是 `douyin` / `xiaohongshu`，不然报「无法识别的链接」。自备链接时客户端根本不知道这是什么平台，只能瞎猜，于是好链接被拦掉。现在先按链接判，判不出时才退回客户端声明的平台（老路径行为不变）。

### 3. 两个入口

- 爆款雷达：检索工具条下面一行「手上已经有一条？抖音 / 小红书链接或 .mp4 直链都能直接拆成脚本与分镜（不检索，按复刻计费）」+「拆自己的链接」按钮；
- 模板库空状态：原来只有「去检索一条」，现在并排多一个「拆自己的链接」。

两个入口打开的是同一张复刻弹窗（同一个扣费、退款、入库管线），只是 `manual` 模式下：没有「视频来源」那一块（没有原链接可退）、链接输入框自动聚焦、输入框下面实时显示「识别为……」或认不出的原因、主按钮在链接认不出时是灰的。

### 4. 文案与事实对齐

后台「系统 → 复刻任务」那句「在雷达页粘贴视频直链发起复刻」现在是真的了，不用改。
