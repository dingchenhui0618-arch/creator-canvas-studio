版本 0.9.34 / 发布包 `20261112-224232-2026-11-13-canvas-proj.tar.gz` / 入口 `index-9SIs2xIj.js`（491,325 字节）/

## 一、补的是价值链上最后一处「不知道自己归谁」的页面

作品主线走到 v0.9.33，六个页面里有五个已经认得自己站的那条线上：
模板库说得出每条模板从哪来（v0.9.33），运行记录说得出挂在哪条作品的第几版（v0.9.15），
评审说得出记入哪条作品（v0.9.16），交付稿、交付流水、分享页也都按作品算。

只有画布不知道。从作品页「套用模板开画布」进来，画布只有一块流程：不知道在帮哪条作品、第几版，
也**走不回去**——想回作品只能靠侧栏或浏览器后退。评审页有「回作品」，画布页没有。

这一轮把这一格补上，同时把画布页在中屏与窄屏上一直坏着的三处版式修掉。

## 二、三条口径

### 1. 画布挂在谁身上，按运行 / 评审同一张索引算

服务端不新增字段、不落库：作品的当前版与归档版各记一个 `flowId`，`projectsByFlow()` 建一次索引，
画布接口给每条流程挂一个 `project`：

```json
{ "id": "prj_f38d68c6", "title": "毛衣折叠收纳法", "version": 2, "archived": false }
```

- 没归任何作品的画布（空白画布直接跑）是 `null`——**画布页什么也不写，不编一条「未命名作品」**。
- 归档版写 `archived: true`，横幅改口成「归档画布 · 第 N 版（已归档）」，不给「去评审这一版」——
  那一版已经过去，评审只能评作品当前这一版。
- 口径与 `withRunProject` 共用一处：`server/run-ownership.mjs` 里 `withFlowProject()` 只加一个字段，
  运行的「作品 · 第几版」与画布的「在帮《X》· 第 N 版」永远是同一个答案。

### 2. 列表、详情、保存回来的画布都带同一个字段

`GET /api/flows`、`GET /api/flows/:id`、`PATCH /api/flows/:id` 三个响应都带 `project`。
保存时不带，前端把更新后的流程替换进列表就会把「在帮哪条作品」丢掉——横幅会自己消失。
新建流程 `POST /api/flows` 显式回 `project: null`，前端不用区分「没有这个字段」和「没归谁」。

### 3. 横幅并进画布卡片，不占用页面高度

画布页是「整屏工具」：页头已经是三排按钮，塞两个入口会挤。横幅做成画布卡片自己的第一行
（`.cv-project`），高度由内容决定、跟着画布一起伸缩：

- 左起：`在帮`（等宽小字）→ `《标题》· 第 N 版` → 一句实话（这块画布是不是作品当前这一版）→ 右边两个动作。
- 动作：`打开作品`（`#/projects/<id>`）、`去评审这一版`（`#/review/project/<id>`，仅当前版）。
- 空白画布没有这一行：工具栏直接贴顶，与以前一样。

## 五、边界

- 只读：生产本轮没有写入（含截图与接口核对），没进画布编辑态、没点保存或运行。
- 不新增页面、不新增字段、不落库：画布归属仍是「作品那侧的指针 + 一次纯索引」，运行与评审不受影响。
- 空白画布不编造作品：没有作品就没有横幅，不给「归到作品」的入口（那一步在运行详情里，v0.9.29）。
- 归档版只读地看：不给「去评审这一版」，因为评审只会落在作品当前这一版，按钮点下去会说到做不到。
