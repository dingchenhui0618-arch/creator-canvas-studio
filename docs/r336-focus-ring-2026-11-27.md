# r336 · 键盘焦点那一层：Tab 走查 307 站，焦点环补上 120ms，量具自己修了两次（v0.9.309）

## 一、结论

按下（r331–r334）、划过（r335）两层清零之后，同一套判据换到第四个状态——**键盘焦点**上。
真发 Tab 把每一屏走一遍（11 趟、**307 个 Tab 站**），量三件事：Tab 到这儿看不看得出焦点在哪、
看得出的那一下走不走过渡、以及「看不出焦点」的黑洞有没有。

- **看不出焦点：0 站**（307 / 307 都有可见变化：303 站在自己身上、4 站画在祖先身上）；
- **焦点环硬切：12 → 0**（0.9.308 上 12 站是啪一下出来的，都在运营位关闭键、模板库筛选胶囊、
  模板抽屉那一行和模板库搜索框上）；
- **静态门禁**把两件事扫了一遍：把 UA 焦点框按掉又没补一个看得见的规则 **9 → 1**（允许清单 1 条：
  引导卡的容器、不是控件），画了焦点环却没声明过渡的 **44 → 0**；
- **补掉 1 处真黑洞**：本地工作区的输入框（`.lw-composer textarea:focus { outline: none }`，没有任何补偿）
  —— 静态门禁抓到的，键盘 Tab 进去完全看不出焦点在哪。

## 二、为什么是「焦点」

用户要的是一层一层的小细节：动效、手感、体验。按下和划过两层清完之后，键盘焦点是同一台状态机的
第四个状态（rest → hover → pressed → focus），也是唯一还没量过的一层。桌面端用键盘的人、以及读屏用户，
只有这一层能告诉他们「现在在哪」。

它同时把 r335 报告里那条边界补上了一点：划过那一层的实时读数只覆盖十趟里的 136 颗按钮（表格行、卡片、链接
只有静态门禁兜底）；焦点这一层的目标是**可 Tab 到的全部元素**（这是另一张清单：链接、输入框、select、
tabindex 卡片都在里面），307 站里 136 颗按钮之外的都算新增覆盖。

## 三、怎么量：同一份脚本的 `--focus`

`node scripts/audit-press.mjs --focus --dist dist --out .shots336/focus-after`

1. 每个 pass 打开之后，先 `blur()`、滚回顶部、鼠标停到中性点，**真发 Tab**（CDP
   `Input.dispatchKeyEvent` 的 `rawKeyDown` + `keyUp`）——焦点导航必须由浏览器自己处理这次按键，
   合成事件（`el.focus()`）不会让 `:focus-visible` 成立。
2. 每一站读 `document.activeElement`：它自己 + 最多三层带 class 的祖先，各一份
   **FOCUS_PROPS**（outline 四件套 + box-shadow + border-color + background + color + transform +
   opacity + ::after 那张表 + transition 表）。
3. 走完整条链之后，`blur()` 回「没有焦点」、鼠标重新停到中性点，再读同一批选择器当 **rest 基线**，
   差出来就是这一站有没有可见变化。
4. 三档判定：`ring`（自己有变化）/ `delegated-ring`（只有祖先有变化，就是 `:focus-within` 那一路）/
   `no-visible-change`（看不出焦点）。
5. 硬切用与按下、划过同一个 `hardCutProps`：变化了、但不在 computed `transition-property` 里
   （或 duration 0）就是硬切。
6. 到 body（第 1 下就没落到元素上）或回到开头（Tab 链绕回来了）就停；`--focuscap 60` 是上限。
7. 走查前先数一遍「看得见、`tabIndex >= 0`、没 disabled」的元素（`reachable`）：走完一站都没走到
   而这一屏明明有 84 个可 Tab 的元素——那要报异常，不能静默写成「没问题」（见七）。

焦点这一层读的是**另一张属性表**，没有并进按下/划过那张：输入框一拿到焦点 UA 就会画 outline，
把它塞进 `PROPS` 会把 r331–r335 已经发布的读数改掉，三层就不可比了。

## 四、量具自己修了两次（都是同一个形状的错）

**一：环「从无到有」不是硬切。** 第一版把 rest → focus 的 `outline-width / outline-style / outline-color`
三条差异都按硬切判——工作台那一屏 40 站里 30 站中招。可是 `outline-style` 是离散属性（`none ↔ auto`），
规范里根本不做补间：浏览器给键盘焦点的默认环就是啪一下出来的，**那是平台行为，不是这一页的设计选择**。
现在 `ringAppeared`（两边可见性不同）单独认出来，那一下的 outline 差异不进硬切，只在汇总里报
`focusOutlineAppearances`（307 站里 224 站是这一种）。

**二：环没画出来时，outline 的四条都是数字在变。** `.qc-input` 拿到焦点时
`outline-width 3px → 0px`、`outline-offset 0px → 2px`（`.qc-composer .qc-input:focus-visible { outline: 0 }`
把环按掉，但别的长属性还在变），屏幕上什么都没有。第一版只对 `outline-color` 做了这条推导判定，
于是 `.qc-input` / `.agx-textarea` 两站被算成硬切（14 条里的最后 2 条）。修法与 r335 的 `border-color`
完全同形：`outline-*` 四条一起判——环没画出来就是推导值，不进 `changed`、不进硬切。修完 after 是 0。

**顺带修掉一个 r335 时代就在的静态盲区**：`keyOf()` 里剥状态伪类的正则把 `focus` 写在 `focus-within`
前面，`:focus-within` 被剥成 `-within`，于是 `.vq-search:focus-within` 变成了类名 `vq-search-within`。
悬停那一层没暴露它（那里的目标选择器里没有 `:focus-within`），焦点这一层一上来就撞上：44 条报告里
13 条是这个原因造成的假阳性。顺序改成 `focus-visible | focus-within | focus` 之后干净，并留了一条单测。

**差点踩的同一个坑（第五次），这次是 tag 压 `:where()`**：全局那条最先写成

同时钉住 `:where(.vq-button, …)` 仍然是 `background-color / border-color / color / transform / box-shadow` 五条。

## 七、边界

- **后台「系统」那一屏 Tab 走不起来**：两版都量到「84 个可 Tab 的元素、0 个站」——第一下 Tab 就没落到
  页面元素上（`document.activeElement` 还是 body）。新增的探针把它报成异常而不是「没问题」，
  原因没查（那一屏的按钮在按下巡检里正常，说明页面是活的）。结论里不含这一屏。
- **`.lw-composer` 那处修复只有静态门禁兜底**：`/local` 在空状态下不渲染输入框（走查量到 18 个
  导航/按钮站，没有 textarea），要让那个输入框出现得先有会话。这条不假装量过。
- **焦点环画在祖先身上**的 4 站（模板库/作品流搜索框、智能体两个 composer）是设计如此：输入框把 UA 的框
  按掉、由外层容器给提示，判定单列成 `delegated-ring`。
- 焦点这一层同样**只判「有没有过渡」，不判「该不该有」**；走查覆盖 PASSES 里的 11 屏，其余屏靠静态门禁。
