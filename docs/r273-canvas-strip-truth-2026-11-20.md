# 无限画布状态条：读不到列表，不等于「你没有画布」（r273 / v0.9.255）

日期：2026-11-20 · 版本：0.9.255 · 场景：用户侧「无限画布」#/board

## 一、症状（用户视角）

无限画布是独立应用，宿主管着一条 42px 状态条：在哪块画布 / 通没通 / 换画布 / 新建 / 写笔记。

无限画布的**网页服务**在跑、**数据接口**（画布 JSON 的 5312）没起来时——这是真实会发生的分裂状态，
两个服务本来就是分开的 systemd 单元——状态条上会出现：

```
• 已连接    画布 ▾ 暂无已保存的画布
```

这句话有两个问题：

1. **「暂无已保存的画布」是假话**。用户做过画布，只是这一次没读到。
2. 画布框会退回到画布自己的默认内容——因为内存里那块画布编号被清成了空串，
   `?loadCanvas=` 参数随之消失，本地记忆（`localStorage['vq:bdcCanvas']`）也被一并删掉。
   用户下次再进来，看到的是默认画布，不是自己做的那块。

也就是说：一次接口抖动，把「你上次在哪块画布上」这条记忆也一起丢了。

## 二、根因

服务端 `listCanvases()` 的失败有两种形状：HTTP 层抛错，和 **200 但 `ok:false`**
（`server/bdc.mjs` 已经把英文错误翻成一句能行动的中文，塞在 `error` 里）。

旧代码只处理了前一种（`.catch(() => undefined)`），后一种直接走进了 `.then`：

```ts
const list = res.canvases || []          // ok:false 时是 []
setCanvases(list)                        // → 选择器读成「暂无已保存的画布」
setCanvasId((current) => {
  const wanted = boardId || current
  if (wanted && list.some(...)) return wanted
  return list[0]?.id || ''               // → 空列表 ⇒ 清成空串，记忆被抹掉
})
```

工作台（`OverviewPage`）对同一件事的处理是对的：它用 `Promise.allSettled` 分开认，
失败时写「无限画布列表：…」并保留其余各块。**同一份数据，两个页面两种说法**——这一轮把画布页对齐。

## 三、判据（`src/domain/board-canvas.ts`）

| 读到的情况 | 打开哪块 | 状态条 |
| --- | --- | --- |
| 读到 + 链接点名的那块在 | 那块 | 不提 |
| 读到 + 上次打开的那块在 | 那块 | 不提 |
| 读到 + 上次打开的那块没了 | 列表第一块 | 说「上次那块画布不在了，已先打开「X」」 |
| 读到 + 链接点名的那块没了 | 整页说明 | 「这块无限画布不在了」（沿用旧行为） |
| **没读到** | **照上次那块打开** | 「画布列表没读到」+ 「重试」按钮 |

两条硬规矩：

- **没读到就不许猜**：既不猜「你没有画布」（清记忆），也不猜「列表第一块」（那是别人的画布）。
- **换了一块必须说出来**：说不出名字就说「这个账号下现在没有别的画布」，不写「已打开 X」。

选择器在没读到列表时收成一只只说明现状的框（`disabled`，写「上次那块画布（名字没读到）」），
因为这时候没有名字可挑；「重试」走状态条里同一套按钮，窄屏 40/44px 的点按区。

## 四、真点验收（本机临时实例 + 无头 Chrome，0 次上游调用）

假无限画布拆成两个进程：`--web` 起 7799（网页 / 探活 / iframe），`--api` 起 7798（画布数据 API），
这样才演得出「网页开着、数据接口没起来」的真实分裂。

| 步骤 | 观测量 | 结果 |
| --- | --- | --- |
| 数据接口没起来，进 #/board | 状态条 | 「画布列表没读到」+「重试」；`title` 是完整那句「无限画布暂时连不上：…不影响」 |
| 同上 | 选择器 | 「上次那块画布（名字没读到）」，`disabled` |
| 同上 | `localStorage['vq:bdcCanvas']` | 仍是 `vq-keep`（记忆没被抹掉） |
| 同上 | iframe src | `...?loadCanvas=vq-keep&vqCredit=10`（没退回默认画布） |
| 同上 | 重试按钮 | 1440：60×24；390：**44×44** |
| 把数据接口起起来，点「重试」（不刷新、不重登） | 状态条 / 选择器 | 提醒消失；选择器恢复成「双十一主图 · 12 节点」，可用 |

| 390 重新载入 | 尺寸 | `scrollWidth == innerWidth == 390` |

## 五、边界

- 状态条上的「已连接」探的是**无限画布网页服务**（6677），没读成的是**画布数据接口**（5312）。
  两者分开是事实，这一轮只是让界面把「网页通了、数据没通」说清楚，探活本身没改。
- 读不到列表时选择器是禁用的：这时候确实没有名字可挑，能走的路只有「重试」和「新建」。
- 「上次那块画布不在了」只说一次：换成列表第一块之后，那一块就成为「现在这块」，
  下次再进来不再重复提（原文已经不在，记忆被新的一块替换）。
- 本轮没有改服务端：`/api/bdc/canvases` 的两句中文原本就是人话，缺的是界面肯不肯用。
- 没有真实上游调用、没有改写画布数据；验收用的是假画布（7799/7798）。
