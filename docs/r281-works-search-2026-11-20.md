# 作品流能搜了（r281 / v0.9.263，2026-11-20）

## 为什么要做

r213 把「快捷创作 / 工作流 / 无限画布」三处产物收成一条作品流，之后一路只往里加：图片、视频、运行封面、画布里的图与视频。
问题是**作品流只进不出**——没有删除，也没有搜索。

真实后果不是「体验不够好」，而是：

- 一个用户生成 60 张图之后，想找「上周那张咖啡图」只能一页一页点「看更早的」；
- 图片按最近 400 份扫、运行按最近 50 次扫，再往前的东西在作品流里根本翻不到（这个上限一直存在，只是没人说）；
- 五个栏目（全部 / 图片 / 视频 / 工作流 / 无限画布）只能按**类型**切，没有任何一维能按内容找。

上线前这是硬伤：产品的主线是「找爆款 → 拆结构 → 复刻 → 评审 → 沉淀模板」，而复刻的产物全落在作品流里。
找不到自己的产物，等于这条线的最后一段是断的。

## 做了什么

一句话：**作品流加一个搜索框，搜的是卡片上已经写着的字**。

| 能搜到的 | 从哪来 |
| --- | --- |
| 提示词标题 | 媒体任务的 prompt、运行的流程名、画布节点 prompt、画布名 |
| 摘要 | 运行卡上那段「出图完成：GPT Image 2 · …」 |
| 模型名 | GPT Image 2 / Seedance 2.0（用户界面上看到的名字，不是内部 id） |
| 来源 | 快捷创作 / 工作流 / 无限画布 |
| 栏目名 | 图片 / 视频 / 工作流 / 无限画布（搜「视频」等于把视频那栏捞出来） |

口径上有四件事是刻意这么定的：

1. **不打上游、不扣积分**。过滤发生在服务端已经扫进内存的那批条目里，不调检索、不读模型。
2. **counts 在关键词之后、栏目之前数**。搜「seedance」时四个栏目各自还剩几条，点进去之前就知道；搜不到东西时不会出现「视频 12 条」点进去却是空的。
3. **不假装全库检索**。搜索只在「最近扫进来的那批」里进行（图片 400 份 / 运行 50 次 / 画布 12 块），结果页会明写这一次找了多少条。
4. **关键词跟着会话走**。点开一条作品再回来，刚才搜的词还在（存 sessionStorage，和五个栏目同一个做法）。

翻页沿用原来的游标（`at:id` 位置游标，不用时间戳比较，同一毫秒也不会漏），只是游标现在走的是**匹配集**，所以搜完之后「看更早的」也是接着这次搜索翻。

## 实测（临时实例 + 无头 Chrome，0 次真实上游调用、0 费用）

| 检查 | 结果 |
| --- | --- |
| 打开作品流 | 6 条，栏目计数 全部 6 / 图片 6 / 视频 0 / 工作流 0 / 无限画布 0 |
| 输入「猫」 | 2 条：窗边的橘猫在打盹、橘猫跳上窗台；右上角「匹配 2 条」 |
| 栏目计数 | 跟着变成 全部 2 / 图片 2 / 视频 0 / …（其余四栏压暗） |
| 结果说明 | 「只在最近 6 条里找：图片看最近 400 份、运行看最近 50 次、画布看前 12 块，不是全库检索。」 |
| 输入「火星」（无匹配） | 0 条 + 空状态「没有匹配「火星」的作品」+ 「清掉搜索」；所有栏目计数归 0，不再重复一遍说明 |
| 1440 布局 | 搜索框 340×32，与五个栏目同一行，计数靠右；页面 1440 = 1440 |
| 390 布局（按 390 重载） | 搜索框 290×44、栏目 74×40、卡片 139 宽；页面 390 = 390；输入框字号 15px、说明 13px |

## 边界

- 只在**当前账号**的产物里搜，管理员也不会搜到别人的；
- 只搜**已经扫进来的那批**（上限见上），更早的条目依旧翻不到——这次没有动扫描窗口，因为把 400 份提到几千份会把一次请求拖成扫盘；
- 搜的是文字，不是语义：「咖啡」搜不到只写了「拿铁」的图；
- 没有删除、没有按时间筛、没有排序切换（仍然只按时间倒序）；这三件仍是待办；
- 工作流的运行摘要只在运行卡上有；纯文本流程（没有出图出视频）的产物是那段文字，能搜到，但没有封面。
