# VisionQA 服务器配置建议（内测起步 → 逐步扩大）

日期：2026-11-04 · 决策前提：先内测、视觉模型走 API、BD Canvas 与工作台同机。

## 一、结论

内测阶段**一台 2 核 4G 就够**，但**直接买 4 核 8G 更划算**——同价位差不了几百块/年，却能省掉一次迁移。**不要买 GPU**：评审 60–85s、智能体 20–50s 都是接口延迟，不是本机算力瓶颈。

| 阶段 | 配置 | 用途 | 月成本区间（以云厂商官网为准） |
| --- | --- | --- | --- |
| 内测（现在） | 4C 8G / 100G ESSD / 5M 带宽 | 8787 API + 静态站 + BD Canvas 三端口 + ffmpeg | 约 250–400 元 |
| 扩大（10–30 人） | 同机纵向扩到 8C 16G，素材转对象存储 | 并发 3–5 个解码任务 | 约 600–900 元 + 存储 |
| 对外服务（客户） | 8C 16G × 2 + Postgres + Redis 队列 + 对象存储 | 拆任务队列，画布/复刻分队列 | 1500 元起 |

自建视觉模型要另算：1× RTX 4090 24G（云上按需约 6–12 元/小时，整机约 1.5–2.5 万），只有在「数据不许出境」时才考虑。

## 二、为什么是这个量级（实测）

| 指标 | 实测值 | 出处 |
| --- | --- | --- |
| Node API 常驻内存 | 4 MB | Windows 任务管理器实测 |
| Vite dev 常驻内存 | 18 MB | 同上 |
| 全部 node 进程合计 | 66 MB / 7 进程 | 同上 |
| 一次复刻耗时 | 90–180 s，其中镜头检测要全片解码（单核跑满） | 抽帧参数 scale=480、q:v 3、MAX_VIDEO_MB=160、MAX_FRAMES=18 |
| 帧图体积 | 22 KB/张，18 张 ≈ 0.4 MB | data/frames 实测 40 文件 0.9 MB |
| 7 条模板占盘 | 4.8 MB | data 目录实测 |
| 评审 / 智能体 / 画布 | 本机 CPU ≈ 0，全部等接口 | 实测 59.8–84.2 s / 21.1–52.7 s / 72.8 s |

结论：**内存不是瓶颈，CPU 只在 ffmpeg 解码那几个瞬间吃满，真正的成本是出网带宽和原始视频存储。**

## 三、存储与带宽怎么算

- 帧图要留在本机（小、且画布/评审直接引用）：1000 条模板 ≈ 0.7 GB。
- **原始视频不要长期存**：160 MB/条 × 1000 条 = 160 GB。视频放对象存储（OSS/COS），服务器只做临时下载与解码。
- 出网流量=帧图回看 + 素材下载。1000 次任务 × 2 MB ≈ 2 GB/月，不贵；真正会爆的是「把原始视频挂在服务器上给人回放」。
- 单次复刻峰值磁盘 = 1 个视频（≤160 MB）+ 18 帧；并发 3 个约 500 MB，100G 盘完全够，但要把临时目录放数据盘而不是系统盘。

## 四、同机部署的端口与进程

| 端口 | 服务 | 常驻 |
| --- | --- | --- |
| 8787 | VisionQA API（同时托管前端 dist） | 是 |
| 5191 | Vite dev（只在开发机用，生产不需要） | 否 |
| 5312 | BD Canvas 后端 | 是 |
| 5313 | BD Canvas 后台管理 | 是 |
| 6677 | BD Canvas 网页入口（画布接入条内嵌的地址） | 是 |

同机跑 5 个进程 + 偶发 ffmpeg，4C 8G 的余量足够；BD Canvas 要求 Python 3.10+ 与 Node 18+，和我们的 Node 可以共存。

## 五、系统选择（上服务器前必须先验证的一件事）

我们现在是 Windows 形态：`启动.vbs`、`keep-services.ps1`。BD Canvas 的手册同样只写 Windows（`启动.vbs` + 三端口）。

- 若 BD Canvas 能在 Linux 跑（Python+Node 理论可行，但作者只测过 Windows）→ **Ubuntu 22.04 LTS**，用 systemd + Caddy，最省运维。
- 若只能在 Windows 跑 → **Windows Server 2022**，但同配置贵 30–50%，且要自己处理自动启动与日志轮转。

**验证方法**：拿到源码包后先在 Linux 试 `npm install` + `python` 起 5312/5313，能起就走 Linux；起不来再考虑 Windows。这一步没验证就买服务器，容易买错系统。

## 六、上线前必须改的三件事

1. **Windows 脚本换 Linux 等价物**：`keep-services.ps1` 的价值是「掉了自动拉起」，Linux 用 systemd unit（`Restart=always`）即可，不需要 pm2。
2. **JSON → SQLite**：现在 `data/*.json` 每次全量读写。内测够用，但多人并发写会互相覆盖（尤其 templates/runs）。SQLite + WAL 是零运维的下一步，写入并发 > 5 req/s 或数据 > 50 MB 时切换。
3. **对象存储**：视频落 OSS/COS，返回签名 URL；服务器只留帧图。

## 七、采购建议（现在就能下单）

```
云服务器 4C 8G / 100G ESSD / 5M 带宽 / Ubuntu 22.04（或等 BD 验证结论）
对象存储 50G（存原始视频，按量约 5–10 元/月）
域名 + 备案（境内）= 若只内测可先用 IP + 自签或 Caddy 临时证书
```

预算：**首年约 3000–5000 元**（含服务器、存储、域名），够 10–30 人内测。
