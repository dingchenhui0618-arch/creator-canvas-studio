# 快捷创作：对话框铺满一屏、工作流只留一条入口、字号抬一档（r257 / v0.9.240）

用户这轮三句话：

> 当前情况下快捷创作的对话框排版有问题 你看一下 / 工作流放快捷创作这里干嘛 我也不知道你咋想的 / 工作流别硬塞进快捷创作里，做个入口联动就行，key 和联网搜索相关的配置统一收在一处，别各写各的

这一轮做前两件 + 把「字太小」再抬一档；Key 与联网搜索的配置收口单列，见文末「下一轮」。

## 一、对话排版：输入卡不再掉到屏幕外

**改之前（1440×900）**：`.qc-thread` 上限 56vh（504px），输入卡按文档流排在下面，整页靠文档滚动。
实测输入卡从 753px 开始、底边 ~920px 掉出视口，底部那行「Enter 发送 · Shift + Enter 换行 · 附件最多 5 个」
整行被切掉，要打字得先滚一下。

**改之后**：平台对话把整页收进一屏，只有对话线程自己滚。

```
.page.agx-page--platform        height:100% + flex 竖排
  > .vq-head                    flex:none（页头不参与收缩）
  > .agx-stage                  flex:1, overflow:hidden
    > .agx-composer-wrap        flex:1, 竖排
      > .agx-mode-row           flex:none
      > .agx-surface-switch     flex:none
      > .agx-quickchat          flex:1
        > .qc-root             grid-template-rows:minmax(0,1fr)  /* 行要定高 */
          > .qc-thread         flex:1, min-height:0, max-height:none
          > .qc-composer       flex:none
```

两个坑：

1. **网格行不定高**时线程按自己的内容长出去（实测线程 256、容器 133），输入卡还是被挤到屏幕外——
   所以 `.qc-root` 要 `grid-template-rows: minmax(0, 1fr)` 且 `align-items: stretch`。
2. 平台对话时下面那块「已自建对话预设」原来只在 ≤900 收起；桌面上它占 322px，整页一收高就把输入卡挤下去。
   这一块跟当前这段对话没有关系，桌面也一起收起（要看预设清单就切「对话预设」页签，那里本来就是它的位置）。

实测（无头 Edge，真鼠标）：

| 视口 | 线程 | 输入卡 | 提示行 | 页面纵向溢出 | 输入卡是否完整可见 |
| --- | --- | --- | --- | --- | --- |
| 1440×900 | 341–652（311，自己滚） | 660–828 | 800–819 可见 | 0 | 是 |
| 1440×800 | 341–552（211） | 560–728 | 700–719 | 0 | 是 |
| 390×844 | 324–690 | 675–836（sticky 贴底） | 手机上本来就不显示 | 221（文档滚，正常） | 是 |

空状态那六条说明也收成四条：一屏里说明占太多，真正的输入框就被推走了。

## 二、工作流不再是第四个页签，只在页签右边留一条入口

用户的原话是「工作流放快捷创作这里干嘛…别硬塞进去，做个入口联动就行」——r256 把工作流做成页签，
等于把另一页的清单搬过来，既不是输入，也不是这次创作的上下文。这一轮：

- 页签回到 **对话 / 图片 / 视频** 三个；
- 页签同一行右侧一条 `.agx-flow-link`（133×32 胶囊），文案按情况变：
  - 挂着这条作品的那条流程：「这条作品的工作流」→ 直接打开那张画布；
  - 手上有流程：「工作流 · N 条」→ 进流程列表；
  - 一条都没有：「起一条工作流」；
- 删掉 `src/components/FlowPanel.tsx` 与 `.agx-flowpanel*` 整块样式（约 18 条规则）。

## 三、字号再抬一档（用户第 4 条）

以前 11 / 11.5 / 12 / 12.5px 四种写法散在 13 个样式表里共 358 处，改一处字号要翻五个文件。
现在并到一套字阶：

| token | 旧 | 新 |
| --- | --- | --- |
| `--text-2xs`（新，最小档） | — | 13px |
| `--text-mono` | 12px | 13px |
| `--text-xs` | 13px | 13.5px |
| `--text-meta` | 13px | 14px |
| `--head-kicker-size` | 12.5px | 13px |
| `--head-desc-size` | 13.5px | 14px |
| `--chip-font` | 12px | 13px |

实测（12 个用户页 × 1440、9 个页 × 390，统计可见文字节点的计算字号的分布）：

| 页面 | 改前 <13px 的可见文字 | 改后 |
| --- | --- | --- |
| 工作台 / 快捷创作 / 作品 / 爆款雷达 / 模板库 / 视觉评审 / 运行记录 / 工作流 / 设置 | 208 | **0** |
| 390 宽同样 9 页 | — | **0**，页面无横向溢出 |

## 验收

- 无头 Edge（1440×900 / 1440×800 / 390×844）真点：输入卡完整可见、提示行可见、页面纵向溢出 0；
- `test/quick-composer-unified.test.mjs` 5 条（骨架 240px、输入卡 8px/中圆角、无独立面板壳、工作流只留入口、平台对话铺满一屏）；
- 8 个旧测试里「12px / 11.5px / 12.5px」的断言改成「该值或 `var(--text-2xs)`」，并保留 + 新增 token 断言；
- 门禁见 README 三百一十。

## 边界

- 图片 / 视频页签这一轮没动（仍是 r256 的骨架）；它们没有做「一屏收高」，长结果照样让页面滚。
- 「对话预设」那条输入卡还是 16px 内边距 / 24px 圆角的旧密度。
- 工作流入口只读元数据（`GET /api/flows`），打开不扣积分；入口在图片 / 视频页签也在，但它不属于那两个页签的内容。
- 平台对话收起「已自建对话预设」只发生在平台对话这一面；切到「对话预设」页签它照常出现。
